# 아침 증시시황 브리핑 생성

고객에게 **그대로 읽어줄 수 있는** 수준의 시황 브리핑을 만든다. 뉴스 요약이 아니라,
"왜 움직였는지 / 오늘 무엇을 볼지 / 고객에게 무엇을 말할지"까지 답하는 자료다.

산출물: `briefing/YYYY-MM-DD.html`, `briefing/index.html`(최신), `briefing/archive.html`

## 0. 파이프라인

```
① 수집 (WebSearch / WebFetch)  →  ② briefing/data/YYYY-MM-DD.json 작성
                                →  ③ python3 scripts/render_briefing.py briefing/data/YYYY-MM-DD.json
                                →  ④ 커밋 & 푸시 (claude/auto-market-briefing-necqk2)
```

렌더러는 네트워크를 쓰지 않는 순수 함수다. 수집·판단은 전부 ①② 단계에서 한다.
스키마는 `python3 scripts/render_briefing.py --schema` 로 확인한다.

## 1. 환경 제약 (중요)

이 컨테이너는 **직접 HTTP 호출이 프록시에서 차단**된다(`curl`, `requests` → 403 CONNECT).
금융 API(Yahoo, 네이버 금융, Google News RSS)를 코드로 호출하는 방식은 동작하지 않는다.

- 수집은 **`WebSearch` 를 주 채널로** 사용한다.
- `WebFetch` 는 국내 언론사 대부분(연합·이투데이·뉴스핌·파이낸셜뉴스 등)과
  tradingeconomics·riotimes 등에서 **403** 을 반환한다. 시도해보고 실패하면 즉시 `WebSearch` 로 대체한다.
- 따라서 **한 검색어당 한 번**으로 끝내지 않고, 항목별로 검색어를 나눠 던지는 것이 효율적이다.
  독립적인 검색은 한 번의 응답에 **여러 개를 병렬로** 호출한다.

## 2. 수집 체크리스트

날짜 기준: 브리핑 당일(예: 화요일 아침)이면 **직전 국내 거래일 마감 + 그 밤의 뉴욕 마감**을 다룬다.
검색어에 반드시 **연도와 날짜를 명시**한다("2026년 8월 3일"). 없으면 과거 기사가 섞인다.

| # | 항목 | 검색어 예시 |
|---|------|-------------|
| 1 | 국내 지수 마감 | `코스피 코스닥 마감 시황 2026년 8월 3일` |
| 2 | 수급 (외국인·기관·개인) | `코스피 외국인 기관 순매도 2026년 8월 3일` |
| 3 | 주도 업종·종목 | `코스피 상승 하락 주도 업종 종목 2026년 8월 3일` |
| 4 | 뉴욕 마감 | `뉴욕증시 마감 2026년 8월 3일 다우 나스닥 S&P500` |
| 5 | 금리·유가·환율 | `국제유가 WTI 미국 국채 10년물 달러인덱스 2026년 8월 3일` / `원달러 환율 마감 2026년 8월 3일` |
| 6 | 아시아·유럽 | `니케이 항셍 상하이종합 마감 2026년 8월 3일` |
| 7 | 국내 증권사 시황 코멘트 | `증권사 시황 코멘트 전망 코스피 2026년 8월` |
| 8 | 해외 하우스·매체 시각 | `Korea equities outlook August 2026 Bloomberg Reuters` |
| 9 | 오늘 일정 | `8월 4일 증시 일정 전망 관전포인트 2026` |

권장 참고 소스 (검색 결과에서 우선 채택):
- 국내: 연합인포맥스, 인포스탁데일리(마감체크), 뉴스핌, 이투데이, 파이낸셜뉴스, 전자신문, 뉴시스, 한국경제
- 증권사: 미래에셋증권·삼성증권·NH투자증권·KB증권·하나증권·신한투자증권 리서치 코멘트
- 해외: Bloomberg, Reuters, AP, Investing.com, TradingEconomics, Goldman Sachs / Wellington 등 하우스 인사이트

## 3. 데이터 원칙 — 여기서 품질이 갈린다

1. **확인되지 않은 수치는 쓰지 않는다.** 필드를 생략하면 렌더러가 `—` 로 표시한다.
   달러인덱스·VIX·금값처럼 검색으로 안 잡히는 항목은 **빼는 것이 맞다.** 추정치를 채우면 안 된다.
2. **직접 파생 계산만 허용.** (예: 등락폭 ÷ 전일 종가 = 등락률) 그 외 역산·추정 금지.
3. **최소 두 소스 교차 확인.** 지수 종가·등락률·수급 금액은 서로 다른 언론사 2곳 이상에서 일치해야 한다.
   불일치하면 원문 확인이 가능한 쪽을 채택하고 `note` 에 근거를 남긴다.
4. **검색 요약 도구의 숫자를 그대로 믿지 않는다.** 검색 결과 요약이 밴드·목표치를 그럴듯하게
   제시하는 경우가 있다. 기사 본문에서 확인되지 않으면 버린다.
5. **오피니언과 하우스 투자의견을 구분한다.** Bloomberg Opinion 같은 칼럼은
   `analyst` 에 "오피니언 칼럼"임을 명시한다.
6. **모든 수치의 출처를 `sources` 에 남긴다.** 고객 브리핑 전 원문 확인 경로가 되어야 한다.

## 4. 서술 원칙

- **`headline`**: 그날의 대립 구도를 한 줄로. ("뉴욕은 사상 최고, 코스피는 하루 만에 급등분 반납")
- **`lede`**: 4문장. 무엇이 / 얼마나 / 왜 / 그래서 오늘은.
- **`keypoints`**: 5~6개. 각 항목은 **수치로 시작**하고, `**강조**` 로 핵심 숫자를 굵게.
- **`*_comment`**: 단순 사실 반복 금지. "지수 하락의 진원지는 시장 전체가 아니라 두 종목"처럼
  **해석**을 준다. 인과 사슬(유가↓ → 금리↓ → 밸류에이션 지지)을 명시한다.
- **`views`**: 2~4개. 국내 증권가 종합 / 해외 하우스 / 해외 매체 / 정책 당국 순으로 시각을 대비시킨다.
  같은 방향 의견만 모으지 말고 **반대 시각을 최소 1개** 넣는다.
- **`talking_points`**: 4~5개. 실제로 고객이 묻는 말로 질문을 쓴다("지금이 저가 매수 기회입니까?").
  답변은 **행동 지침**으로 끝낸다(분할 접근, 비중 축소, 확인해야 할 조건).
- **`calendar`**: 시각 + 일정 + **무엇을 확인하면 판단이 되는지**. 일정 나열로 끝내지 않는다.
- `_en` 필드는 전 항목 작성한다. 수치·약자(FOMC, ETF, bp)는 영문판에서도 그대로 둔다.
- **이모지 금지, 이탤릭 금지.** 강조는 `**bold**` 만.

## 4-1. 클릭 드릴다운 (`facts` / `detail` / `links`) — 이 브리핑의 핵심 가치

요약은 짧아야 하고 근거는 깊어야 한다. 이 둘을 동시에 만족시키는 장치가 드릴다운이다.
**모든 항목**(keypoints, markets.*, flows.rows, movers, views, calendar, risks, talking_points)에
아래 3개를 붙일 수 있고, 하나라도 있으면 그 항목이 클릭 가능해진다.

```json
"facts":  [ {"label": "외국인 순매도", "label_en": "Foreign net selling",
             "value": "-2조 8,427억원", "value_en": "-KRW 2,842.7bn"} ],
"detail": ["배경·해석 문단", "..."],  "detail_en": ["...", "..."],
"links":  [ {"title": "기사 제목", "url": "https://...", "publisher": "한국일보"} ]
```

작성 기준:

- **`facts` 는 요약에 넣지 못한 숫자를 담는다.** 요약 문장의 숫자를 그대로 복사하지 말고,
  장중 저점·전일 종가·종목별 세부 금액·누적치처럼 **한 단계 더 들어간 수치**를 넣는다. 3~7개.
- **`detail` 은 "왜"와 "그래서"를 쓴다.** 사실 재진술 금지. 최소 하나는
  **인과 사슬**(유가↓ → 기대인플레↓ → 금리↓ → 밸류에이션 지지) 또는
  **판단 기준**(무엇을 관측하면 어느 해석이 맞는지)을 담아야 한다. 2~4문단.
- **해석이 갈리는 항목은 양쪽을 다 쓴다.** 예: 외국인 매도 → ① 차익실현설 ② 구조적 이탈설,
  그리고 **둘을 구분할 관측 지점**을 제시한다.
- **`links` 는 그 항목의 근거 기사만** 넣는다. 전체 출처 목록을 복사하지 않는다. 1~3개.
- 제도·용어가 나오면 그 자리에서 설명한다(서킷브레이커 발동 요건, 사이드카, 변동성 붕괴 등).
  고객이 되물을 만한 지점이다.
- 하우스 뷰의 `detail` 에는 **그 시각을 실무로 번역한 문장**을 넣는다.
  "원인이 포지션이면 처방은 비중 조정, 원인이 사이클이면 처방은 섹터 이탈" 같은 식이다.
- `talking_points` 는 `a`(응대 스크립트)가 자동으로 펼쳐지므로, `detail` 에는
  **하지 말아야 할 안내 / 할 수 있는 안내**처럼 스크립트를 보강하는 내용을 넣는다.

전 항목에 억지로 채우지 않는다. **근거를 더 보여줄 것이 있는 항목만** 붙인다.
내용이 얕으면 클릭이 배신이 된다.

## 5. 렌더 & 검증

```bash
python3 scripts/render_briefing.py briefing/data/$(date +%F).json
```

검증:
- [ ] JSON 파싱 성공, 렌더러 에러 없음
- [ ] KO/EN 토글 시 잔존 한글 없음 (EN 모드에서 `calendar.time_en`, `facts[].value_en` 누락 주의)
- [ ] 등락 색: 상승 적색(`#C62828`) / 하락 청색(`#043B72`) — 국내 관행
- [ ] 모바일 폭 390px 에서 가로 스크롤 없음
- [ ] 수치가 `sources` 로 추적 가능
- [ ] **드릴다운**: 핵심 요약·지표 카드·표 행·하우스 뷰·일정·리스크·응대 Q&A 가 클릭으로 펼쳐지고,
      `detail` 내용이 요약의 재진술이 아닌지 확인
- [ ] '전체 펼치기' 버튼이 모든 항목(details + 표 행)을 열고 라벨이 '전체 접기'로 바뀌는지
- [ ] **PDF**: '요약 PDF'(상세 접힘) / '전체 PDF'(상세 펼침) 두 버튼이 있고,
      인쇄 후 원래 화면 전개 상태로 복원되는지
- [ ] **사이드바**: 목차가 실제 렌더된 섹션과 일치하고, 스크롤 시 활성 항목이 따라오는지.
      '지난 브리핑' 날짜 목록에 새 날짜가 추가되고 현재 날짜가 표시되는지
- [ ] 1080px 미만에서 사이드바가 가로 칩 줄로 바뀌고 가로 넘침이 없는지 (320px 까지 확인)

## 6. 커밋

```bash
git add briefing/ && git commit -m "시황 브리핑 YYYY-MM-DD" && git push -u origin claude/auto-market-briefing-necqk2
```

## 7. 데이터가 부족할 때

시장 휴장일이거나 검색으로 마감 수치가 확인되지 않으면 **빈 브리핑을 만들지 않는다.**
`briefing/index.html` 을 그대로 두고, 무엇을 확인하지 못했는지 사용자에게 보고한다.
절반만 채운 브리핑을 고객에게 내보내는 것이 가장 나쁜 결과다.
