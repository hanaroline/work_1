# 퇴직급여 수령 의사결정 시뮬레이터

퇴직 시 퇴직급여를 **어느 연금계좌로 받아야 유리한지** 판정하고, 연차별 인출 한도와
세액을 시뮬레이션해 고객에게 A4 1장으로 출력해 주는 상담 도구.

산출물: 저장소 루트의 `retirement-simulator.html` (약 1MB) — **외부 네트워크 없이 열리는 단일 파일**.
React·Tailwind·웹폰트·앱 코드가 모두 인라인되어 있어 지점 PC에서 파일만 열면 동작한다.

## 빌드

이 저장소는 `package.json` 이 `.gitignore` 대상이라 빌드 의존성을 직접 설치해야 한다.

```bash
npm install --no-save react@18.3.1 react-dom@18.3.1 @babel/standalone@7.25.6 \
  tailwindcss@3.4.16 spoqa-han-sans@3.3.0 @fontsource/inter@5.3.0
node scripts/build-retirement-simulator.js
```

| 파일 | 역할 |
|---|---|
| `app.jsx` | 판정 로직 · 시뮬레이션 · React 컴포넌트 (수정은 여기서) |
| `styles.css` | 미래에셋 디자인 토큰 + A4 인쇄 스타일 |
| `tailwind.config.js` | 브랜드 컬러/라운드/폰트 토큰 |
| `shell.html` | 인라인 대상 자리표시자를 가진 HTML 껍데기 |
| `fonts/` | 임베드 폰트의 OFL 라이선스 사본 |
| `../../scripts/build-retirement-simulator.js` | 폰트 인라인 → Tailwind 추출 → JSX 트랜스파일 → 단일 HTML 조립 |

`retirement-simulator.html` 을 직접 고치지 말 것 — 빌드 산출물이라 덮어써진다.

## 임베드 폰트

지점 PC에 승인 폰트가 설치되어 있지 않아도 동일하게 렌더링되도록 woff2 를 base64 로 심는다.

| 폰트 | 용도 | 굵기 | 크기 |
|---|---|---|---|
| Spoqa Han Sans Neo (KS X 1001 서브셋) | 한글·본문 | 400 / 500 / 700 | 약 544KB |
| Inter (latin 서브셋) | 숫자·영문 | 400 / 500 / 700 | 약 72KB |

- 둘 다 **SIL Open Font License 1.1** 이라 임베딩·재배포가 허용된다. 라이선스 사본은 `fonts/` 에 있고,
  저작권 고지는 산출물 CSS 상단 주석에도 들어간다.
- Spoqa 서브셋본은 한글 2,574 음절을 담고 있어 고객명 입력까지 커버한다.
- 표의 숫자 정렬은 Inter 의 `tabular-nums` 에 의존한다. `.num` 폰트 스택은
  `Inter → Spoqa Han Sans Neo` 순서라 숫자 칸에 섞인 한글('전액', '6년차')도 같은 폰트로 떨어진다.
- 서브셋본에 em dash(`—`)와 수학 마이너스(`−`)가 없어 앱 텍스트는 하이픈(`-`)을 쓴다.
  새 문구를 넣을 때 이 두 글자는 피할 것.

## 화면 구성

왼쪽은 입력, 오른쪽은 결과다. 결과는 상담 순서대로 **판정 / 계좌 비교 / 인출 스케줄** 세 탭으로 나눈다.
데스크탑(≥1024px)에서는 입력 패널이 `position: sticky` 로 화면 상단에 붙고 뷰포트 높이를 넘으면 자체
스크롤을 가지므로, 긴 인출표를 보면서 수령 기간·수수료를 바로 조정할 수 있다.

입력은 세 묶음이다.

| 묶음 | 항목 |
|---|---|
| 1 · 고객 및 퇴직 정보 | 고객명, 생년월일, 퇴직제도, 제도 가입일, **퇴직(예정)일**, **DB → DC 전환 여부와 전환 전 DB 가입일**(DC 일 때), 퇴직급여(퇴직금제도는 법정/명예 분리), 이연 퇴직소득세 |
| 2 · 기존 보유 연금계좌 | 계좌를 **개수 제한 없이** 추가. 계좌마다 금융기관(선택), 가입일, 평가액, 세액공제 받지 않은 금액, 연금개시 여부, 연간 수수료, 시뮬레이션 합산 / 과거 연금 수령 횟수 |
| 3 · 시뮬레이션 옵션 | 인출 방식, 수령 기간(5~30년), 운용수익률, 신규 개설 계좌의 연간 수수료 |

### 계좌는 목록으로 받는다

연금저축은 한 금융기관에 여러 개를 둘 수 있고, IRP 도 1사 1계좌가 원칙이지만
금융기관마다 하나씩 가질 수 있어 실제로는 여러 개인 경우가 흔하다. 게다가 이미 보유한
IRP 가 연금개시되었거나 2013.3.1 이전 가입 IRP 에 그 이후 가입 DC 를 넣어야 하는 경우처럼
같은 기관에서도 추가 개설이 되는 예외가 있다.

**연금수령연차는 계좌마다 따로 산정되므로 계좌를 하나로 뭉뚱그리면 판정 자체가 틀어진다.**
같은 사람이라도 2008년에 만든 연금저축은 9년차, 2022년에 만든 IRP 는 1년차라 한도가
몇 배씩 차이 난다. 그래서 종류별 1개가 아니라 목록으로 받는다.

계좌는 종류별 순번으로 이름을 매긴다(`연금저축 1`, `IRP 2`). 금융기관명은 화면 표시에만
붙이고 `aria-label` 에는 넣지 않는다 - 기관명을 타이핑하는 도중 라벨이 계속 바뀌면
그 칸을 다시 잡을 수 없게 되기 때문이다.

**자산 합산**은 계좌마다 체크한다. 예전의 '자산 합산 범위' 4지선다는 계좌가 둘일 때만
성립하던 구조라 없앴다. 연차가 다른 계좌를 합치면 화면에 합산 주의 경고가 뜬다.

예전 형식(종류별 1계좌)으로 저장된 상담은 불러올 때 목록으로 옮긴다. 옛 `scope` 값도
계좌별 합산 체크로 바꿔 준다. 지점 PC 에 남아 있는 상담 이력이 끊기지 않게 하기 위해서다.

**설명은 눌러서 편다.** 판단이 갈리는 항목(퇴직제도, 제도 가입일, 퇴직일, DB → DC 전환, 계좌 목록,
가입일, 세액공제 받지 않은 금액, 연금개시 여부, 시뮬레이션 합산, 과거 연금 수령 횟수, 명예퇴직금,
이연 퇴직소득세, 연금수령한도, 인출 순서)에는
라벨 옆에 `?` 버튼을 달아 근거와 함정을 그 자리에서 보여준다(`Help` 컴포넌트). 상담 중에 고객에게
바로 설명할 수 있어야 해서 별도 문서로 빼지 않았다. 설명은 `.screen-only` 안에만 있어 인쇄물에는
나오지 않고, `aria-label` 과 `role="note"` 를 달아 테스트가 라벨로 잡는다.

**탭은 인쇄에 영향을 주지 않는다.** 인쇄물은 화면 DOM 을 감추고 드러내는 방식이 아니라, 별도의
`PrintSheet` 컴포넌트가 같은 상태에서 처음부터 다시 그린다. 탭 전환은 `.screen-only` 안쪽만 바꾸고
`.screen-only` 는 인쇄 시 통째로 `display: none` 이므로, 어느 탭을 보고 있든 판정·계좌 비교·인출
스케줄이 모두 한 장에 담긴다. 어느 탭에서 인쇄하든 결과물은 글자 하나까지 같다(스펙이 대조한다).
브라우저의 'PDF 로 저장' 도 같은 인쇄 경로를 쓴다.

인쇄물의 지표 카드는 **합산 범위 기준**, 그 아래 계좌별 비교표는 **퇴직급여 단독 기준**이라 같은
'세후 수령액' 이라도 값이 다르다. 화면에는 설명 문장이 있지만 인쇄물만 받는 고객은 오해할 수 있어
비교표 머리에 기준과 단위를 밝힌다.

계좌가 많으면 인쇄물이 길어지므로, 보유 계좌 요약은 3건까지만 적고 나머지는 개수로 줄이며
비교표는 연차가 높은 상위 5개만 싣는다(전체는 화면에서 본다). 비교표가 4행을 넘으면
행 여백도 자동으로 줄여 A4 한 장을 지킨다.

## 저장

입력 패널 맨 위에 저장 도구가 있다.

| 기능 | 저장 위치 | 쓰임 |
|---|---|---|
| **상담 저장 / 불러오기** | 브라우저 `localStorage` (최대 50건) | 같은 PC에서 고객별 상담을 다시 연다 |
| **상담 메모** | 저장 항목에 함께 | 고객 요청사항, 다음 상담 확인사항 (최대 500자) |
| **파일로 내보내기 / 가져오기** | `.json` 파일 | PC 간 이동, 백업, localStorage 가 막힌 환경 |
| **CSV 내보내기** | `.csv` 파일 | 인출 스케줄을 엑셀로 넘긴다 (인출 스케줄 탭) |
| **PDF 저장** | 브라우저 인쇄 경로 | 고객용 A4 1장을 PDF 로 (탭 바의 'PDF 저장' 버튼) |
| **전체 초기화** | - | 화면 입력만 비운다. **저장된 상담은 남는다** |

구현상 주의할 점 두 가지.

- **다운로드 파일명은 ASCII 로만 만든다.** `file://` 로 열면 크롬이 비ASCII 파일명을 통째로 버리고
  확장자 없는 `download` 로 저장해 버린다(실측 확인). 고객명은 파일 안에 넣는다 - JSON 은 `custName`,
  CSV 는 머리말의 고객명 행. 파일명은 `retirement-case_20260922-1430.json` 형태다.
- **CSV 는 UTF-8 BOM 을 붙인다.** 없으면 엑셀에서 한글이 깨진다.

**PDF 저장**은 브라우저 인쇄 창의 '대상 = PDF로 저장' 을 쓴다. 이 경로는 글자가 이미지로 굽히지 않고
텍스트로 들어가 검색·복사가 되고 A4 배치도 정확하다(실측: 1페이지 258KB, 텍스트 드로잉 연산자 2,149개).
PDF 라이브러리를 따로 싣는 방법은 한글 폰트를 한 벌 더 넣어야 해 파일이 수 MB 로 불어나고 인쇄 레이아웃을
두 벌 유지해야 하므로 쓰지 않는다. 인쇄 직전에만 `document.title` 을 `퇴직급여 의사결정_고객명_날짜` 로
바꿔 크롬이 제안하는 PDF 파일명을 잡고, 끝나면 되돌린다(`beforeprint`/`afterprint`). Ctrl+P 로 눌러도 같다.

**상담 메모**는 저장 전에 입력칸에 쓰거나, 목록의 '메모' 버튼으로 나중에 고칠 수 있다(입력값은 건드리지
않는다). 저장 항목과 JSON 내보내기, CSV 머리말에 함께 담긴다.

고객용 인쇄물에는 **기본적으로 넣지 않는다** - 내부 메모이기 때문이다. 메모칸 아래 '고객용 인쇄물에
포함' 을 켜면 인출 스케줄 위에 '상담 메모' 블록으로 들어간다. 이 체크 상태도 저장·내보내기에 따라간다.
메모 블록이 붙으면 A4 한 장을 넘길 수 있어, 표가 18행을 넘으면 행 여백을 자동으로 줄인다
(실측: 수령 30년 + 메모 500자에서 969px / 1,062px, PDF 1페이지).

**전체 초기화**는 실수로 상담 내용을 날리지 않도록 두 번 눌러야 한다. 첫 클릭에서 '입력한 내용이 모두
지워집니다. 저장된 상담은 남습니다' 안내와 함께 확인·취소가 뜬다. 지우는 것은 화면 입력뿐이고 저장된
상담 목록은 건드리지 않는다 - 목록을 지우려면 항목별 '삭제' 를 쓴다.

`localStorage` 는 `file://` 이나 사내 정책에 따라 막힐 수 있어 모든 접근을 try/catch 로 감싸고,
막혀 있으면 안내 문구를 띄우고 파일 내보내기로 유도한다. 가져오기는 `format` 키와 알려진 입력 키
4개 이상을 확인해 우리 형식일 때만 적용한다 - 아무 JSON 이나 받아 폼을 초기화하지 않는다.

## 판정 로직의 근거

### 1. 연금수령연차 — 한도를 가르는 단 하나의 변수

연금수령한도는 `과세기간 개시일 현재 평가액 ÷ (11 − 연금수령연차) × 120%` 다.
연차가 클수록 분모가 작아져 한도가 커지고, **11년차에 닿으면 한도가 사라진다**.
그래서 계좌 선택의 실익은 사실상 '이 계좌에 넣으면 연차가 몇에서 시작하느냐' 하나로 수렴한다.

연차는 **기산연차**(몇 년차로 출발하는가)와 **기산연도**(그 출발이 몇 년도인가) 두 값으로 정해진다.

**기산연차** — 원칙은 1이고, 다음 두 경우에만 6이다(소득세법 시행령 §40의2④).
2013.3.1 전에는 연금수령 요건이 '10년 이상 가입하고 5년 이상 수령'이었기 때문에,
기존 계약자가 5년만 받아도 연금소득으로 인정해 주려는 경과조치다.

| 경우 | 기산연차 |
|---|---|
| 연금계좌 가입일자가 2013.3.1 이전 | **6** |
| 2013.3.1 전 퇴직연금(DB·DC) 가입자가 퇴직급여 **전액**을 **신규 개설** 계좌에 입금 | **6** |
| 그 밖에 (신규 계좌 · 2013.3.1 이후 가입 계좌) | 1 |
| 퇴직금제도의 퇴직금 · 명예퇴직금 | 1 (가입일자 개념 자체가 없다) |

두 번째 줄이 중요하다. **기존 계좌가 없어도 6년차를 받을 수 있다.** 다만 '신규 개설 계좌에 전액'
이라는 조건이 붙어서, 같은 DB 가입자라도 이미 쓰던 계좌에 넣으면 1년차가 된다.
DB → DC 전환자(임금피크제 등)는 DC 가입일이 전환 시점이라 불리해 보이지만,
전환 전 DB 가입일이 2013.3.1 이전이면 그 정보를 반영해 6년차를 적용한다.

**기산연도** — 최초로 연금개시 요건을 갖춘 날이 속하는 해다.
요건은 `만 55세 이상` + `가입일로부터 5년 경과`이고, 계좌에 자금이 들어 있어야 한다.
**이연퇴직소득이 있으면 가입 5년 요건은 면제된다.**

여기가 함정이다. **연금개시를 신청하지 않아도 연차는 이 해부터 해마다 자동으로 누적된다.**
이미 잔고가 있던 구 계좌를 가진 만 58세 고객이라면, 만 55세가 된 해에 이미 요건을 갖췄으므로
기산연차 6에 3년이 더해져 **9년차**로 시작한다. 한도가 6년차의 2.5배다.
초기 버전은 이 누적을 반영하지 않아 구 계좌를 일률적으로 6년차로 봤고, 한도를 크게 과소 계산했다.

```
연금 개시 첫 해의 연차 = 기산연차 + (개시연도 − 기산연도)
한도 내 전액 인출에 필요한 기간 = 11 − 그 연차   (11 이상이면 한도 없음)
```

### 2. 재원별 입금 가능 여부

퇴직급여 재원은 `법정퇴직금` / `명예(법정외)퇴직금` / `DB` / `DC` 로 나뉘고,
재원마다 들어갈 수 있는 계좌가 다르다. 앱은 재원별로 최적 계좌를 따로 배정하므로
**분할 입금**이 자동으로 잡힌다.

출발점은 **소득세법상 '연금계좌'가 무엇인가**다. 연금계좌는 DC · IRP · 연금저축계좌 ·
과학기술인연금 · 중소기업퇴직연금이고, **DB 와 퇴직금제도는 여기 들어가지 않는다**.
이체 제한(시행령 §40의4)은 '연금계좌 간의 이체'에만 걸리므로, DB·퇴직금제도의 지급은
'이체'가 아니라 '퇴직소득의 입금'이라 제한을 받지 않는다. 제한을 받는 것은 DC 뿐이다.

- **만 55세 미만**: 법정퇴직급여는 IRP 로만 지급된다(근퇴법 §17·§20). 2022.4.13 이후로는
  퇴직금제도의 법정퇴직금도 IRP 의무이전 대상이다. 따라서 연금저축계좌 입금 불가.
  명예퇴직금·위로금 등 법정외 퇴직금은 근퇴법상 퇴직급여가 아니라 55세 미만이어도 가능하다.
  (단 법정외 퇴직금이라도 DB/DC 규약에 포함되어 있으면 법정퇴직금과 같은 취급이다.)
- **DC → 연금저축계좌는 연령 불문 불가.** 소득세법이 퇴직연금계좌(DC·IRP·과학기술인연금)와
  연금저축계좌 사이의 상호 이체를 금지하기 때문이다(시행령 §40의4①1). DC 는 그 자체가
  퇴직연금계좌라 여기에 걸린다. 다만 연금수령요건을 갖춘 계좌끼리는 IRP↔연금저축 계약이전이
  허용되므로, **만 55세 이상이면 `DC → IRP → 연금저축계좌` 2단계 경로**가 열린다.
- **2013.3.1 이후 가입한 DC → 2013.3.1 전 가입 연금계좌도 불가**(시행령 §40의4①2).
  구 IRP 도 마찬가지다. 다만 이 경우는 **1사 1IRP 예외사유**에 해당해 IRP 를 추가로 개설하면
  되므로, 앱은 신규 IRP 를 대안으로 제시한다.
- **DB 는 가입일자와 무관하게 어느 계좌로든 입금할 수 있다.** 위 제한이 '연금계좌 간 이체'에만
  적용되는데 DB 는 연금계좌가 아니기 때문이다. 55세 미만의 연금저축 제한만 받는다.
- **연금이 개시된 계좌**는 원칙적으로 추가 입금이 막힌다. 개시 시점에 재원별 금액을 확정해
  국세청에 통보하기 때문이다. 다만 **당사에서 연금개시한 IRP·연금저축계좌는 퇴직금에 한해**
  입금할 수 있고, 타사 계좌라면 수관이 필요한데 연금개시 계좌로의 계약이전은 제한된다.
  단정할 수 없어 '조건부'로 둔다.

각 재원 × 계좌 조합은 세 상태 중 하나다.

| 상태 | 뜻 | 자동 배정 | 수동 선택 |
|---|---|---|---|
| **가능** | 제한 없음 | O | O |
| **조건부** | 경로·계좌 소재에 따라 갈리고 확인이 필요 | X | O (경고 표시) |
| **불가** | 법령상 막힘 | X | X |

### 3. 계좌 간 우열과 동점 처리

**가입일의 선후는 우열을 가르지 않는다.** 기산연차는 2013.3.1 이전이냐 아니냐로만 갈리므로,
2002년 가입 IRP와 2012년 가입 연금저축은 **둘 다 똑같이 6년차 기산**이다.
(다만 만 55세 도달 시점이 같다면 최종 연차도 같다 — 앱은 최종 연차로 비교한다.)

우열은 연금수령연차로만 정하고, 연차가 같으면 이전 절차의 편의로 정한다.

- **DB·DC 지급액**: IRP 우선. 퇴직연금사업자가 IRP 로 직접 이전해 주지만, 연금저축은 퇴직급여를
  수령한 뒤 60일 내에 다시 납입해야 과세이연된다(소득세법 §146). 절차가 번거롭고 기한 위험이 있다.
- **법정·명예퇴직금**: 회사가 직접 지급하므로 어느 계좌든 입금할 수 있다. IRP 를 기본으로 둔다.

연금수령연차가 같은 계좌가 둘 이상이면 추천 카드에 **동점 안내**를 띄운다.

**수수료**는 계좌별로 연 요율(%)을 입력받아 점수에 반영한다. 연 0.3% 차이면 위의 이전 절차 이점(30점)과
맞먹고 0.5% 차이면 뒤집는다. 연차 차이(1년당 200점)는 뒤집지 못한다 - 구조적 차이가 더 크기 때문이다.
**계좌별 비교** 표에서 같은 조건으로 총 수수료·총 세액·세후 수령액을 나란히 보여준다.

**수동 선택**: 추천 카드의 계좌 선택 상자에서 재원별로 다른 계좌를 직접 고를 수 있다. 투자 가능 상품
(IRP 위험자산 70% 한도 vs 연금저축 한도 없음), 중도인출 조건(IRP 법정 사유만 vs 연금저축 자유·기타소득세
16.5%)처럼 앱이 수치화하지 않는 기준으로 판단할 때 쓴다. 바꾸면 시뮬레이션과 인쇄물에 그대로 반영되고
'수동 선택' 표시가 붙으며, '자동 추천으로 되돌리기' 로 복구한다.

### 4. 인출과 세액

**인출 순서**는 바꿀 수 없다(소득세법 시행령 §40의3).

| 순서 | 재원 | 연금수령 시 | 연금외수령 시 |
|---|---|---|---|
| ① | 세액공제 받지 않은 납입액 | 과세제외 | 과세제외 |
| ② | 이연퇴직소득(퇴직금) | 퇴직소득세 × 감면 | 퇴직소득세 전액 |
| ③ | 세액공제 받은 납입액 + 운용수익 | 연금소득세 3.3~5.5% | 기타소득세 16.5% |

**연금수령한도는 인출 한도가 아니다.** 뺀 돈을 연금수령으로 볼지 연금외수령으로 볼지 가르는
기준선일 뿐이고, 한도를 넘겨 인출할 수 있다. 넘은 부분만 위 표의 오른쪽 칸으로 과세된다.
그래서 앱은 균등 분할이 한도를 넘으면 자르지 않고 **초과분을 연금외수령으로 계산해 보여준다**.
(초기 버전은 한도에서 잘라 버려 과도하게 낙관적인 수령액을 냈다.)

- 퇴직소득세 감면(소득세법 §129①5의3): 실제 연금수령 **1~10년차 30%**, **11~20년차 40%**,
  **21년차부터 50%**. 20년 초과 50% 구간은 2025년 세법개정으로 신설되어 2026.1.1 이후
  연금수령분부터 적용된다.
  여기서 '실제 연금수령연차'는 한도 계산용 연차와 **별개**다. 한도용 연차는 돈을 찾지 않아도
  자동으로 쌓이지만, 감면율은 실제로 받은 **횟수**를 센다. 그래서 과거 수령 횟수를 따로 입력받는다.
- 연금소득세: 70세 미만 5.5%, 70대 4.4%, 80세 이상 3.3%.
  사적연금 연 1,500만원 초과 시 종합과세 또는 16.5% 분리과세 선택 대상인데,
  이 1,500만원 판정은 ③ 재원의 연금수령분에만 걸린다(퇴직소득 재원은 금액과 무관하게 분리과세).
- 분할 입금 시 이연퇴직소득세는 계좌 배정액 비율로 안분한다.

```bash
node scripts/build-retirement-simulator.js            # 먼저 빌드
node tools/retirement-simulator/tests/run.js          # 전체 (369건, 약 75초)
node tools/retirement-simulator/tests/run.js verdict  # 이름으로 일부만
```

빌드 산출물 `retirement-simulator.html` 을 그대로 열어 검사한다. 실패가 있으면 종료 코드가 1 이다.

|---|---|

| `accounts` | 계좌 여러 개의 연차가 각각 산정되는지, 계좌별 수수료·합산, 계좌가 많아도 A4 한 장 |
| `verdict` | DC 의 연금저축 입금 차단과 DB 예외, 55세 미만 의무이전, 연금개시 계좌 조건부, 재원별 분할 배정, 동점과 수수료 역전 |

| `print` | 세 탭의 인쇄물이 글자까지 동일, A4 한 장, 메모 인쇄 옵션, PDF 파일명 |

| `offline` | 외부 요청 0건, 임베드 폰트 실사용, 날짜 입력 방어 |

### 선택자 규칙

**인덱스로 컨트롤을 잡지 말 것.** 체크박스를 하나 추가했더니 `$$('input[type=checkbox]')[0]` 으로
계좌를 잡던 테스트들이 엉뚱한 칸을 누르고도 통과한 적이 있다. 통과하는 테스트가 실제로는 아무것도
검증하지 않는 상태였다.

그래서 앱의 모든 컨트롤에 고유한 `aria-label` 을 달고(접근성에도 필요하다), 테스트는
`getByLabel` / `getByRole('button')` 으로만 잡는다. 새 필드를 넣을 때는 `tests/helpers.js` 의
`FIELDS` 에도 넣어 `selectors` 스펙이 고유성을 확인하게 한다.

숨은 탭도 DOM 에 남아 있으므로 표를 읽을 때는 `.screen-only table` 대신 제목으로 섹션을 좁힌다
(`helpers.scheduleRows`).

## 한계

- 이연퇴직소득세는 원천징수영수증 기준으로 **입력**받는다. 근속연수·환산급여 공제를 통한
  퇴직소득세 자체 계산은 하지 않는다.
- 사적연금 연 1,500만원 초과 시의 종합과세·16.5% 분리과세 선택은 화면에 안내만 하고
  세액 계산에는 반영하지 않는다 (분리과세 기준으로 계산).
- 300만원 이하 소액 퇴직급여의 IRP 의무이전 예외는 반영하지 않았다.
- 상담 저장은 브라우저별·PC별로 따로 쌓인다. 여러 PC 에서 쓰려면 파일로 내보내 옮겨야 한다.
  브라우저 데이터를 지우면 저장된 상담도 사라지므로, 보관이 필요하면 파일로 내보낼 것.
- **연금수령한도는 실제로 계좌별로 따로 산정된다.** 자산 합산 시뮬레이션은 선택한 계좌의 연차로
  합산 자산 전체의 한도를 계산하므로, 연차가 같은 계좌끼리 합산할 때만 정확하다. 연차가 다른 계좌를
  섞으면 화면에 합산 주의 경고를 띄운다.
- **퇴직 시점을 '오늘'로 본다.** 과거에 퇴직해 이미 몇 해가 지난 경우는 모델링하지 않는다.
  기산연도가 과거인 것(구 계좌의 연차 누적)은 반영하지만, 퇴직급여 입금 자체는 올해로 가정한다.
- 세액공제 받지 않은 납입액은 **입력받는다**. 모르면 0 으로 두면 되고, 그 경우 세액이
  과대 계산될 뿐 과소 계산되지는 않는다.
- `DC → IRP → 연금저축계좌` 2단계 경로는 판정 사유로 **안내만** 하고, 그 경로를 탔을 때의
  스케줄은 시뮬레이션하지 않는다.
- 계좌 간 동점을 가르는 기준(수수료, 투자 가능 상품, 중도인출 조건)은 상품별로 달라 앱이 판단하지
  않는다. 동점 안내만 띄우고 선택은 상담자에게 맡긴다.
