# 퇴직급여 수령 의사결정 시뮬레이터

퇴직 시 퇴직급여를 **어느 연금계좌로 받아야 유리한지** 판정하고, 연차별 인출 한도와
세액을 시뮬레이션해 고객에게 A4 1장으로 출력해 주는 상담 도구.

산출물: 저장소 루트의 `retirement-simulator.html` (약 1MB) — **외부 네트워크 없이 열리는 단일 파일**.
React·Tailwind·웹폰트·앱 코드가 모두 인라인되어 있어 지점 PC에서 파일만 열면 동작한다.

## 빌드

이 저장소는 `package.json` 이 `.gitignore` 대상이라 빌드 의존성을 직접 설치해야 한다.

```bash
npm install --no-save react@18.3.1 react-dom@18.3.1 @babel/standalone@7.25.6 \
  tailwindcss@3.4.16 spoqa-han-sans@3.3.0 @fontsource/inter@5.3.0
node scripts/build-retirement-simulator.js
```

| 파일 | 역할 |
|---|---|
| `app.jsx` | 판정 로직 · 시뮬레이션 · React 컴포넌트 (수정은 여기서) |
| `styles.css` | 미래에셋 디자인 토큰 + A4 인쇄 스타일 |
| `tailwind.config.js` | 브랜드 컬러/라운드/폰트 토큰 |
| `shell.html` | 인라인 대상 자리표시자를 가진 HTML 껍데기 |
| `fonts/` | 임베드 폰트의 OFL 라이선스 사본 |
| `../../scripts/build-retirement-simulator.js` | 폰트 인라인 → Tailwind 추출 → JSX 트랜스파일 → 단일 HTML 조립 |

`retirement-simulator.html` 을 직접 고치지 말 것 — 빌드 산출물이라 덮어써진다.

## 임베드 폰트

지점 PC에 승인 폰트가 설치되어 있지 않아도 동일하게 렌더링되도록 woff2 를 base64 로 심는다.

| 폰트 | 용도 | 굵기 | 크기 |
|---|---|---|---|
| Spoqa Han Sans Neo (KS X 1001 서브셋) | 한글·본문 | 400 / 500 / 700 | 약 544KB |
| Inter (latin 서브셋) | 숫자·영문 | 400 / 500 / 700 | 약 72KB |

- 둘 다 **SIL Open Font License 1.1** 이라 임베딩·재배포가 허용된다. 라이선스 사본은 `fonts/` 에 있고,
  저작권 고지는 산출물 CSS 상단 주석에도 들어간다.
- Spoqa 서브셋본은 한글 2,574 음절을 담고 있어 고객명 입력까지 커버한다.
- 표의 숫자 정렬은 Inter 의 `tabular-nums` 에 의존한다. `.num` 폰트 스택은
  `Inter → Spoqa Han Sans Neo` 순서라 숫자 칸에 섞인 한글('전액', '6년차')도 같은 폰트로 떨어진다.
- 서브셋본에 em dash(`—`)와 수학 마이너스(`−`)가 없어 앱 텍스트는 하이픈(`-`)을 쓴다.
  새 문구를 넣을 때 이 두 글자는 피할 것.

## 화면 구성

왼쪽은 입력, 오른쪽은 결과다. 결과는 상담 순서대로 **판정 / 계좌 비교 / 인출 스케줄** 세 탭으로 나눈다.
데스크탑(≥1024px)에서는 입력 패널이 `position: sticky` 로 화면 상단에 붙고 뷰포트 높이를 넘으면 자체
스크롤을 가지므로, 긴 인출표를 보면서 수령 기간·수수료를 바로 조정할 수 있다.

**탭은 인쇄에 영향을 주지 않는다.** 인쇄물은 화면 DOM 을 감추고 드러내는 방식이 아니라, 별도의
`PrintSheet` 컴포넌트가 같은 상태에서 처음부터 다시 그린다. 탭 전환은 `.screen-only` 안쪽만 바꾸고
`.screen-only` 는 인쇄 시 통째로 `display: none` 이므로, 어느 탭을 보고 있든 판정·계좌 비교·인출
스케줄이 모두 한 장에 담긴다. 브라우저의 'PDF 로 저장' 도 같은 인쇄 경로를 쓴다.

## 판정 로직의 근거

### 1. 계좌 선택이 갈리는 지점 — 2013.3.1

연금수령한도는 `과세기간 개시일 현재 평가액 ÷ (11 − 연금수령연차) × 120%` 이고,
**2013.3.1 이전에 가입한 연금계좌는 연금수령연차를 6년차부터 기산**한다.

| 계좌 | 한도 기산 | 한도 해제까지 | 최소 권장 수령 기간 |
|---|---|---|---|
| 2013.3.1 이전 가입 (잔고 보유) | 6년차 | 5년 | **5년** |
| 2013.3.1 이후 가입 · 신규 개설 | 1년차 | 10년 | **10년** |

구계좌 특례는 **잔고가 남아 있어야** 인정된다. 잔고 0원 계좌는 신규와 동일하게 본다.

### 2. 재원별 이전 가능 여부

퇴직급여 재원은 `법정퇴직금` / `명예(법정외)퇴직금` / `DB` / `DC` 로 나뉘고,
재원마다 들어갈 수 있는 계좌가 다르다. 앱은 재원별로 최적 계좌를 따로 배정하므로
**분할 입금**이 자동으로 잡힌다.

- **만 55세 미만**: 법정퇴직금·DB·DC 는 IRP 의무이전 대상(근퇴법 §17·§20)이라 연금저축 입금 불가.
  명예퇴직금은 근퇴법상 퇴직급여가 아니므로 55세 미만이어도 연금저축 입금(과세이연) 가능.
- **DB·DC → 구 연금계좌**: 2013.3.1 이후 가입한 DB·DC 지급액은 2013.3.1 이전 가입 연금계좌로
  이체 불가 (소득세법 시행령 §40의4). 신규 개설로 유도한다.
- **법정퇴직금·명예퇴직금**: 연금계좌 간 '이체'가 아닌 퇴직소득 '입금'이라 위 제한을 받지 않는다.
  2013.3.1 이전 가입 계좌에 넣어 6년차 특례를 받을 수 있다.

### 3. 계좌 간 우열과 동점 처리

**가입일의 선후는 우열을 가르지 않는다.** 한도 기산은 2013.3.1 이전이냐 아니냐로만 갈리므로,
2002년 가입 IRP와 2003년 가입 연금저축은 **둘 다 똑같이 6년차 기산**이다. 세법상 동점이다.

동점일 때의 순위는 이전 절차의 편의로만 정한다.

- **DB·DC 지급액**: IRP 우선. 퇴직연금사업자가 IRP 로 직접 이전해 주지만, 연금저축은 퇴직급여를
  수령한 뒤 60일 내에 다시 납입해야 과세이연된다(소득세법 §146). 절차가 번거롭고 기한 위험이 있다.
- **법정·명예퇴직금**: 회사가 직접 지급하므로 어느 계좌든 입금할 수 있다. IRP 를 기본으로 둔다.

세법상 동점인 기존 계좌가 둘 이상이면 추천 카드에 **동점 안내**를 띄운다.

**수수료**는 계좌별로 연 요율(%)을 입력받아 점수에 반영한다. 연 0.3% 차이면 위의 이전 절차 이점(30점)과
맞먹고 0.5% 차이면 뒤집는다. 한도 기산(1000점)은 뒤집지 못한다 - 구조적 차이가 더 크기 때문이다.
**계좌별 비교** 표에서 같은 조건으로 총 수수료·총 세액·세후 수령액을 나란히 보여준다.

**수동 선택**: 추천 카드의 계좌 선택 상자에서 재원별로 다른 계좌를 직접 고를 수 있다. 투자 가능 상품
(IRP 위험자산 70% 한도 vs 연금저축 한도 없음), 중도인출 조건(IRP 법정 사유만 vs 연금저축 자유·기타소득세
16.5%)처럼 앱이 수치화하지 않는 기준으로 판단할 때 쓴다. 바꾸면 시뮬레이션과 인쇄물에 그대로 반영되고
'수동 선택' 표시가 붙으며, '자동 추천으로 되돌리기' 로 복구한다. 계좌 유형별 특성은 비교표 아래에 정리해 둔다.

### 4. 세액

- 인출 순서: 과세제외금액 → **이연퇴직소득** → 세액공제 납입분·운용수익 (소득세법 시행령 §40의3).
- 퇴직소득세 감면 (소득세법 §129①5의3): 실제 연금수령 **1~10년차 30%**, **11~20년차 40%**,
  **21년차부터 50%**. 20년 초과 50% 구간은 2025년 세법개정으로 신설되어 2026.1.1 이후
  연금수령분부터 적용된다.
  여기서 '실제 연금수령연차'는 한도 계산용 연차(구계좌는 6년차 기산)와 **별개로**
  실제 수령 누적 횟수로 센다. 그래서 과거 수령 횟수를 따로 입력받는다.
- 세액공제 납입분·운용수익 인출분: 연령별 연금소득세 (70세 미만 5.5%, 70대 4.4%, 80세 이상 3.3%).
- 분할 입금 시 이연퇴직소득세는 계좌 배정액 비율로 안분한다.

## 검증

Playwright 로 다음을 확인했다.

- 구 연금저축(2013 이전·잔고 보유) 보유 시 6년차 기산 추천, 5년 수령으로 잔액 0 소진
- 2016년 가입 DC → 구 연금저축 이전 불가 판정 후 신규 IRP 추천
- 만 50세: 법정퇴직금 → 신규 IRP, 명예퇴직금 → 구 연금저축 분할 배정
- 수령 기간 30년(표 최대 길이)에서도 인쇄가 A4 단면 1장 (콘텐츠 995px / 1,062px)
- 네트워크 전면 차단(`offline: true` + `file://` 외 요청 abort) 상태에서 마운트·판정·시뮬레이션·인쇄까지
  정상 동작, 외부 요청 시도 0건
- 임베드 폰트가 실제 렌더링에 쓰이는지 측정으로 확인(Spoqa 폭 188px ≠ 시스템 sans 211px),
  `.num` 의 고정폭 숫자 정렬 확인(`111111` 과 `888888` 의 폭이 동일)
- 3단계 감면(30%/40%/50%)을 앱 코드 없이 세법 공식만으로 재현해 일치 확인, 21회차 전환 확인
- **판정 탭만 보는 상태에서 인쇄해도** 판정·계좌 비교·인출 스케줄 30회차까지 모두 포함되고
  PDF 1페이지로 출력됨을 확인
- 입력 패널 sticky 동작 확인(스크롤 400·600·800px 에서 모두 상단 20px 에 고정)

## 한계

- 이연퇴직소득세는 원천징수영수증 기준으로 **입력**받는다. 근속연수·환산급여 공제를 통한
  퇴직소득세 자체 계산은 하지 않는다.
- 사적연금 연 1,500만원 초과 시의 종합과세·16.5% 분리과세 선택은 화면에 안내만 하고
  세액 계산에는 반영하지 않는다 (분리과세 기준으로 계산).
- 300만원 이하 소액 퇴직급여의 IRP 의무이전 예외는 반영하지 않았다.
- **연금수령한도는 실제로 계좌별로 따로 산정된다.** 자산 합산 시뮬레이션은 선택한 계좌의 기산 연차로
  합산 자산 전체의 한도를 계산하므로, 기산이 같은 계좌끼리 합산할 때만 정확하다. 기산이 다른 계좌를
  섞으면 화면에 합산 주의 경고를 띄운다.
- 계좌 간 동점을 가르는 기준(수수료, 투자 가능 상품, 중도인출 조건)은 상품별로 달라 앱이 판단하지
  않는다. 동점 안내만 띄우고 선택은 상담자에게 맡긴다.
