# 퇴직급여 · 연금계좌 판단표 생성 프로세스

"이 고객의 퇴직급여를 어느 계좌로 받을 수 있고, 어느 계좌가 유리한가" 를 조합마다 답하는
판단표를 **손으로 적지 않고 규칙에서 전개해** 만듭니다.

기존 `tools/retirement-simulator` 는 고객 한 명의 수치를 넣고 답을 보는 상담 도구입니다.
이쪽은 그 앞단 - **조합 전체를 한눈에 보는 참조표**이고, 동시에 시뮬레이터가 맞는지
대조하는 잣대입니다. 둘은 서로를 베끼지 않습니다.

## 왜 이렇게 만드는가

판단표를 사람이 적으면 세 가지가 무너집니다.

1. **빠진 칸이 생긴다.** 제도 3종 × 재원 2종 × 연령 2종 × 가입시점 2종 × 대상계좌 6종이면
   벌써 100칸이 넘습니다. 손으로 적으면 반드시 빠집니다.
2. **근거를 잃는다.** 표만 남으면 그 칸이 Q&A 어디서 왔는지, 아직 확인 못 한 것인지 알 수 없습니다.
3. **맞는지 확인할 길이 없다.** 그럴듯해 보이는 표와 맞는 표를 구별할 수단이 없습니다.

## 네 단계

```
① 규칙을 자료로      rules.js      근거(Q번호·조문)와 확인상태를 셀마다 붙인다
② 조합을 전개        build.js      규칙에서 표를 만든다. 표는 산출물이지 원본이 아니다
③ 교차 검증          crosscheck.js 기존 시뮬레이터와 모든 칸을 대조한다
④ 빈칸을 보고        crosscheck.js 화면으로 입력할 수 없는 조합을 따로 모은다
```

### ① 규칙을 자료로 — `rules.js`

판정 규칙을 코드에 흩어 놓지 않고 한 곳에 자료로 둡니다. 규칙마다 `rule` 식별자,
출처(`src`), 법령(`law`), 설명(`text`) 이 붙습니다. 출처 대장 `SOURCES` 는 각 항목이
**원본을 확인한 것(confirmed)** 인지 **아직 못 본 것(unverified)** 인지 구분합니다.

미확인 항목은 표에 **미확인**으로 찍혀 나옵니다. 상담에 그대로 쓰이면 안 되기 때문입니다.

### ② 조합을 전개 — `build.js`

```bash
node tools/pension-decision-matrix/build.js                  # 화면으로
node tools/pension-decision-matrix/build.js --md MATRIX.md   # 파일로
```

`MATRIX.md` 는 산출물입니다. **직접 고치지 마세요** - 규칙을 고치고 다시 만듭니다.

### ③ 교차 검증 — `crosscheck.js`

```bash
node scripts/build-retirement-simulator.js      # 먼저 시뮬레이터를 빌드
node tools/pension-decision-matrix/crosscheck.js
```

규칙표의 답과 상담 화면의 판정을 **모든 조합에서** 맞춰 봅니다. 둘은 서로 다른 데서
나왔으므로(규칙표는 Q&A 원문에서, 시뮬레이터는 상담 화면 요구에서) 같은 답이 나오면
서로가 서로의 검산이 됩니다. 어긋나면 어느 쪽이 틀렸는지는 사람이 Q&A 를 보고 정합니다.

현재: **120칸 대조 · 어긋남 0건.**

### ④ 빈칸 보고

규칙표에는 있는데 상담 화면에서 입력할 수 없는 조합을 모아 보고합니다.

이 검사가 실제로 빈칸을 하나 찾아냈습니다. **DB·DC 가입자의 명예퇴직금을 넣을 칸이
없었습니다** - 화면이 DB·DC 에서는 퇴직급여를 한 칸으로만 받았기 때문입니다.
DC 에서 특히 문제였는데, 규약상 퇴직급여는 연금저축계좌로 못 가지만 규약에 규정되지 않은
명퇴금은 갈 수 있는데도(Q12) 전액을 '불가' 로 판정했습니다.

시뮬레이터에 명예퇴직금 칸을 모든 제도에 열어 메웠고, 그 뒤 대조 칸이 72개에서
120개로 늘었습니다. **현재 빈칸은 없습니다.**

## 원본 확인 상태

사내 Q&A **16장을 모두 확보해 대조를 마쳤습니다.** 규칙표의 미확인 칸은 **0건**입니다.

| 확보 | 다루는 것 |
|---|---|
| Q2 · Q6 · Q9 | 상품 구분 · 세제 · 연금개시 계좌 |
| **Q12** | 재원별 연금저축계좌 입금 가능 매트릭스 |
| **Q23 · Q24 · Q25** | 계약이전 4원칙 · 기존계좌 합치기 · 연금개시 계좌 수관 |
| **Q32 ~ Q38** | 가입일자 적용과 선택 · DC/DB/전환자/퇴직금제도별 |
| Q57 ~ Q68 | 연금개시 요건 · 한도 공식 · 연차 계산과 계산 예제 9건 |
| Q82 | 1사 1IRP 예외사유 |

특히 유불리 판단의 핵심이던 **가입일자 승계**가 Q32 에서 확정되었습니다.
**자동이 아니라 선택**입니다 - 신규 계좌를 열어 잔액 없는 상태에서 전액을 이체받을 때만
보내는 계좌의 가입일자를 고를 수 있고, 고르지 않으면 받는 계좌 것이 적용됩니다.
상담에서 이 선택을 놓치면 6년차가 1년차가 됩니다.

## 파일

| 파일 | 역할 |
|---|---|
| `rules.js` | 판정 규칙 + 출처 대장 (여기만 고칩니다) |
| `build.js` | 조합 전개 → 판단표 |
| `crosscheck.js` | 시뮬레이터와 교차 검증 |
| `MATRIX.md` | 산출물 (직접 고치지 않습니다) |
