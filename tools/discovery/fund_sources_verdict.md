# 펀드 시세·자금흐름 원천 — 조사 결과 총정리

기준일: 2026-08-29 (탐침 15~21차)

이 파일은 **탐침 결과 파일이 아니라 판정 파일**이다. 탐침 파일들은 다시 돌리면
덮이지만 이 파일은 안 덮인다. 근거가 된 탐침 파일 이름을 각 줄에 적어 둔다.

## 왜 이 조사를 했나

"3개월 자금유입 상위"를 내려면 **Δ설정원본**이 필요하다. Δ순자산이 아니다.
순자산은 수익률이 섞여 있어서, 돈이 하나도 안 들어왔는데 값이 오른 펀드가
"유입 1위"로 올라간다. 그건 거짓말이다.

그래서 원천 하나를 판정하는 기준은 셋이고, **셋이 다 있어야** 쓸 수 있다.

| | 없으면 |
|---|---|
| ① 표준코드 | 어느 펀드인지 모른다 → 시장 합계일 뿐 |
| ② 기준일자 (과거 조회) | 오늘치만 있다 → 3개월을 못 만든다 |
| ③ 설정원본·좌수 | 수익률이 섞인다 → 유입 순위가 뒤집힌다 |

## 판정: 셋을 다 주는 원천을 **못 찾았다**

찾다 만 게 아니라, 아래를 하나씩 열어 본 결과다. 그렇다고 "대한민국에
그런 원천이 없다"는 뜻은 아니다. **내가 연 범위 안에는 없었다**는 뜻이다.

### 금투협은 이름 하나에 시스템이 둘이다 — 섞으면 안 된다

"금투협 API 키를 신청하면 되느냐"는 물음의 답이 여기 걸려 있다.

| | `standardDt` 를 시험한 곳 | 인증키를 발급하는 곳 |
|---|---|---|
| 주소 | `dis.kofia.or.kr/proframeWeb/XMLSERVICES/` | `openapi.kofia.or.kr` |
| 정체 | 전자공시 화면이 쓰는 내부 POST (응답 헤더 `pfmAppName=FS-DIS2`) | 오픈API 서비스(CCCQ) |
| 인증 | **키라는 것이 없다.** 공개 화면의 백엔드 | 활용신청 → 심사 → 인증키 |

`standardDt` 를 무시한 것은 **키가 없는 쪽**이고, 키를 주는 쪽은 **다른 시스템**이다.
그러므로 키를 받아도 `dis` 의 `standardDt` 가 존중되게 만들 수는 없다.

**단서 둘. 둘 다 "확인 실패"이지 "확인된 부정" 이 아니다.**

1. 오픈API 서비스 현황(`apiStut/OPENAPISvcStut.jsp`)의 목록을 **끝내 못 읽었다.**
   위 판정의 근거는 **소개 문구 한 줄**뿐이다.

   목록은 페이지가 뜬 뒤 AJAX 두 건이 채운다 — `FS-OPENAPI` /
   `OPENAPISvcStutSO` / `getApiBrnList`·`getApiInfoList` →
   `openapi.kofia.or.kr/proframeWeb/XMLSERVICES/`. 22·23차에서 그 두 건이
   **웹방화벽 차단 페이지**로 회신됐다(HTTP 200, 310바이트,
   "The request / response that are contrary to the Web firewall security
   policies have been blocked"). 23차는 `https://` 로 바꿔 봤지만 3건 중
   2건이 같은 식으로 막혔고, 분류 드롭다운도 `전체` 한 줄뿐이었다.

   즉 **빈 표는 "목록이 비었다" 가 아니라 "러너가 막혔다" 이다.**
   같은 `proframeWeb/XMLSERVICES/` 라도 `dis.kofia.or.kr` 쪽은 러너에서
   정상 응답했으므로(→ `fund_kofia_flow.md`), 호스트별 방화벽 문제로 보인다.
   **더 두드리지 않고 확인 실패로 닫는다.** 사람이 브라우저에서 위 주소를
   열면 목록이 바로 보일 것이다. 근거 파일: `kofia_openapi_list.md`,
   `kofia_openapi_list2.md`
2. 인증 상태로는 시험하지 못했다. 키가 없으니 "키가 있으면 `standardDt` 가
   달라지는가"는 **모른다.** 다만 위 표대로 키가 적용되는 시스템이 다르다.

## 연계 4건은 결국 무엇이었나

공공데이터포털에서 제목만 보면 제일 그럴듯했던 넉 줄이다.

```
권리행사 현황 ; 집합투자증권                 /data/121580/linkedData.do
증권관리현황 ; 집합투자증권 잔고현황          /data/121539/linkedData.do
집합투자증권 설정,환매 및 인수도대금 현황     /data/121576/linkedData.do
예탁증권 보관현황 ; 집합투자증권보관 총괄     /data/121546/linkedData.do
```

넷 다 **연계데이터**라 포털은 항목도 파일도 안 들고 바깥 주소만 걸어 둔다.
그래서 포털 화면으로는 판정을 못 하고, 실물이 있는 광주 쪽을 21차에서 열었다.
넷 다 HTTP 200 으로 받았고, 화면에 이렇게 적혀 있었다:

| dataSetUncd | 화면에서 읽은 제목 |
|---|---|
| `DS000303386` | 증권관리현황 ; 집합투자증권 잔고현황 |
| `DS000303393` | 예탁증권 보관현황 ; 집합투자증권보관 총괄 |
| `DS000303423` | 집합투자증권 설정,환매 및 인수도대금 현황 |
| `DS000303427` | 권리행사 현황 ; 집합투자증권 |

넷이 공통으로 적고 있는 것:

- **제공방식** ☐ 파일 / ☑ 링크 · **제공유형 LINK** — 광주도 파일을 안 들고 있다
- **출처** 국가통계포털(링크) · **제공기관** 국가데이터처
- **원 통계** 한국예탁결제원 「증권예탁통계」 (승인번호 348001, 1994년 승인)
- **조사주기 월 / 공표시기 작성기준 월의 익익월**
- **조사항목** "… 집합투자증권 설정, 환매 및 인수도 현황 … 등 **총 45개 표**"
- OpenAPI 정보 표는 머리글만 있고 **내용이 비어 있다**

즉 이 넉 줄은 포털 → 광주 → 국가통계포털로 이어지는 **링크의 링크**이고,
실체는 예탁결제원의 월간 시장 통계 45개 표 중 일부다. 기관 분류(외국법인·
금융투자업 관계기관·기타)로 나눈 합계 표이지 펀드별 표가 아니다.

판정: **①표준코드 없음 · ③설정원본 펀드별 아님 · 게다가 월간, 익익월 공표.**
①③이 없으므로 ②(월 단위 과거)가 있어도 3개월 자금유입에는 못 쓴다.

### 21차 표를 그대로 읽으면 안 되는 두 가지

`fund_gwangju.md` 의 "한눈에" 표를 근거로 삼을 때 주의할 점이다.

1. 자료 이름이 넷 다 "광주 빅데이터 통합플랫폼" 으로 나온다. `<title>` 태그가
   자료명이 아니라 사이트명이기 때문이다. **표로는 넷을 구별 못 한다** —
   구별되는 것은 URL 뿐이다. (진짜 제목은 위의 표에 본문에서 읽어 적었다.)
2. "기준일자 있음" 은 화면의 `제공일자`(자료를 언제 올렸나)에 걸린 것이지
   **조회 파라미터가 아니다.** 낱말이 화면에 있다는 뜻일 뿐이다.

## 미확인 — 안 열어 봤다. "없다"가 아니다

- 공공데이터포털의 나머지 목록 전체. 검색어 `집합투자`·`수익증권`·`펀드`
  세 개로 훑었고, 열어 본 것은 상위 16건까지다.
- 유료 상용 피드(에프앤가이드·제로인 등). 원문 확인을 안 했으므로 되는지
  안 되는지 **모른다**. 이름으로 판정하지 않는다.
- 금투협 회원 전용 조회 화면. 로그인 뒤 화면은 못 봤다.
- **금투협 오픈API 서비스 목록**(위 단서 1). 방화벽에 막혀 못 읽었다.
  사람이 직접 열어 보면 5초면 끝나는 확인이다.

## 그래서 지금 쓰는 방법

소급 백필은 막혔다. 남은 길은 **오늘부터 매일 쌓는 것** 하나다.

- `data/fund-history.js` 에 매일 설정원본을 적립한다
- `fund-daily.yml` 에서 화면 빌드보다 **앞서** 돌게 이미 걸어 두었다
- 3개월치가 쌓이기 전에는 화면에 "3개월 자금유입"을 **안 띄운다**.
  숫자가 아직 없다고 화면에 적혀 있는 편이 틀린 순위보다 낫다.
