# 종목 통합 리포트 대시보드

주식 종목명 또는 종목코드를 입력하면 해당 종목의 **시세 · 증권사 투자의견/레포트 · 시황(뉴스) · 재무제표**를
**한 장의 리포트**처럼 보여주는 단일 HTML 대시보드입니다. 빌드 도구 없이 `index.html` 하나로 동작합니다.

## 화면 구성

| 섹션 | 내용 |
|------|------|
| **종목 요약** | 종목명·코드·시장(KOSPI/KOSDAQ), 현재가·등락, 시가총액, PER/PBR/EPS, **조회 기준 시각** |
| **시세 · 기술적지표** | 가격 차트(1M/3M/6M/1Y) + **이동평균 MA5/20/60** + **RSI(14)** + 거래량, 52주 최고/최저, **지수 대비 초과수익률** |
| **외국인 · 기관 수급** | 일별 순매수 대금(외국인/기관) 차트 + 외국인 지분율 추이, 5일/20일 누적 순매수 |
| **증권사 투자의견** | 목표주가 밴드(최저·평균·최고 vs 현재가), 상승여력, 매수/중립/매도 의견분포, 최근 레포트 목록 |
| **시황 · 뉴스** | 종목 관련 최신 뉴스 헤드라인 |
| **재무제표** | 연간 손익(매출·영업이익·순이익) 차트 + 표, 재무상태(자산·부채·자본), ROE·부채비율 |

### 주요 기능
- **관심종목 즐겨찾기(★)** — 브라우저에 저장(localStorage), 상단 칩에서 원클릭 조회
- **종목 비교(⇄)** — 최대 4종목을 기준=100 리베이스 차트 + 지표 표로 비교
- **지수 대비 보기** — 가격/지수대비(KOSPI·KOSDAQ 리베이스) 토글, 초과수익률 표시
- **PDF 저장/출력(🖨)** — 화면 그대로 A4 리포트로 저장·인쇄(`@media print`)
- 라이트/다크 테마 전환(◐), 종목명 자동완성, 6자리 코드 직접 입력

## 실행 방법

### 방법 1) 단일 파일 (가장 간단)

`standalone.html` **한 파일**에 CSS·JS·차트 라이브러리·데이터가 모두 인라인되어 있습니다.
별도 서버 없이 파일을 브라우저로 열기만 하면(더블클릭) 바로 동작합니다.

```
standalone.html  ← 이 파일만 열면 됨
```

### 방법 2) 분리 파일 + 로컬 서버 (개발용)

`index.html`은 `data/*.js`, `vendor/*.js`를 외부에서 로드하므로 로컬 서버로 열어야 합니다
(파일 프로토콜로 열면 브라우저 보안정책에 막힐 수 있음).

```bash
# 저장소 루트에서
python3 -m http.server 8000
# 브라우저에서 http://localhost:8000 접속
```

> `standalone.html`은 `index.html` + `data/*.js` + `vendor/chart.umd.js`를 합쳐 생성한 산출물입니다.
> 소스를 수정할 때는 `index.html` / `data/*.js`를 고친 뒤 다시 합치면 됩니다.

## 데이터 소스

무료 공개 소스를 우선 사용하고, 실패 시 **섹션별로 샘플 데이터로 폴백**합니다.
각 섹션에는 `실시간` / `샘플` 배지가 표시됩니다.

| 섹션 | 실시간 소스 | 폴백 |
|------|-------------|------|
| 시세/현재가/차트 | **네이버 모바일 `m.stock.naver.com/api`** 우선, Yahoo `chart` 보조 | 내장 샘플 |
| 외국인/기관 수급 | 네이버 `api/stock/{code}/trend` | 내장 샘플 |
| 지수(KOSPI/KOSDAQ) | Yahoo `chart/^KS11 · ^KQ11` | 내장 샘플 |
| 재무제표 | Yahoo `quoteSummary` (손익/재무상태) | 내장 샘플 |
| 투자의견/목표주가 | Yahoo `quoteSummary` (financialData, recommendationTrend) | 내장 샘플 |
| 시황/뉴스 | Google News RSS(`news.google.com/rss/search`) | 내장 샘플 |
| 증권사 레포트 목록 | (실시간 API 부재) | 예시 데이터 + 네이버 리서치 딥링크 |

모든 소스는 **병렬 호출 + 4초 타임아웃**으로 요청하며, 실패한 섹션만 개별적으로 샘플로 대체합니다(전체 화면은 항상 정상 렌더). 요약 헤더에 조회 기준 시각과 출처가 표시됩니다.

> 증권사 원문 리포트(PDF)는 공개 API가 없어, 목록은 예시로 채우고
> [네이버 금융 리서치](https://finance.naver.com/research/)로 연결되는 딥링크를 제공합니다.

### 브라우저 CORS 안내

순수 브라우저(단일 HTML)에서 위 API를 직접 호출하면 **CORS로 차단**되는 경우가 많습니다.
이를 위해 `index.html`의 `PROXIES` 배열에 **CORS 프록시 폴백**이 설정되어 있습니다.

```js
var PROXIES = [
  function (u) { return u; },                                              // 1) 직접 호출
  function (u) { return "https://corsproxy.io/?url=" + encodeURIComponent(u); },      // 2) 프록시
  function (u) { return "https://api.allorigins.win/raw?url=" + encodeURIComponent(u); } // 3) 프록시
];
```

- 사내망/폐쇄망 등으로 외부 접근이 막히면 세 경로 모두 실패하고 **샘플 데이터**로 표시됩니다(화면은 항상 정상 렌더).
- 안정적인 실시간 연동이 필요하면, 자체 백엔드 프록시(예: `/api/proxy?url=...`)를 만들어 `PROXIES`에 추가하는 것을 권장합니다.
- 미래에셋 **사내 API**가 있다면 `fetchYahoo` / `fetchNews`를 사내 엔드포인트 호출로 교체하면 됩니다.

# ELS 상품 구조 페이지

`els.html` — ELS 상품의 **기초자산 · 조기상환 조건 · 수익 구조**를 고객이 한 화면에서
이해할 수 있도록 만든 페이지입니다. 미래에셋증권 디자인 시스템(오렌지 `#F58220` /
블루 `#043B72`, 1px 섹션 룰, `#FAB072` 테이블 헤더)을 따르며 한/영 토글을 지원합니다.

## 화면 구성

| 섹션 | 내용 |
|------|------|
| **상품 찾기** | **상품코드·상품명·기초자산 검색** + **유형 / 기초자산 / 만기 / 조기상환 주기 / 위험등급** 5개 필터. 조건에 맞는 상품 목록이 바로 아래 표로 나오고, **행을 클릭하면** 그 상품으로 이하 모든 화면이 바뀜. 목록은 **상품 번호 오름차순**이 기본 |
| **30초 요약** | ELS를 결정짓는 세 가지(기초자산 / 조기상환 조건 / 수익 구조)를 카드로 정리 |
| **상품 상세** | 선택한 상품의 전체 스펙 — 코드·기초자산·수익률(연/총액)·만기·평가주기·배리어·낙인·원금지급률·최대손실률·위험등급·청약기간·홈페이지 원문 표기 |
| **조기상환 조건** | 회차별 배리어를 **계단형 사다리 그래프**로 표시. 낙인 배리어, 회차별 누적 수익률, 판정 기준 표. 리자드 상품은 해당 회차에 리자드 배리어를 함께 표기 |
| **수익 구조** | 만기 손익 그래프 2종 — **낙인 미터치 / 낙인 터치**를 나란히 비교. 기초자산 직접투자 대비선 포함 |
| **시나리오 시뮬레이터** | 평가일별 기초자산 수준과 기간 중 최저점을 슬라이더로 지정 → 언제 상환되고 얼마를 받는지 계산 |
| **과거 시뮬레이션** | 과거 10년 실제 종가로 **이 상품이 매 거래일 발행되었다면** 어떻게 끝났을지 계산 — 회차별 조기상환 비율, 원금 손실 비율, 평균 손익 (아래 "과거 시뮬레이션" 절 참고) |
| **확인 사항 / 용어** | 가입 전 점검할 5가지, 청약서 용어 사전 |

상단 우측에 **KO/EN 토글**과 **인쇄·PDF 저장** 버튼이 있습니다.

## 데이터 수집 (매일 자동)

미래에셋증권 홈페이지는 **WebSquare 기반 SPA**이고, 데이터는 `.wjson` POST 엔드포인트로
오갑니다. 정적 HTML에는 상품 정보가 전혀 없어 **헤드리스 브라우저 렌더링**이 필요합니다.
따라서 수집은 GitHub Actions 러너에서 Playwright 로 수행합니다.

| 파일 | 역할 |
|------|------|
| `.github/workflows/els-weekly.yml` | **매일 08:00 KST** 수집 → `data/els.js` 갱신 → 단일 파일 재빌드 → 커밋 |
| `scripts/collect_els.mjs` | 실제 수집기. 상품 목록 화면을 렌더링하고 `.wjson` 응답에서 상품을 추출 |
| `.github/workflows/els-discover.yml` | 사이트 구조 조사용(1회성). 엔드포인트가 바뀌었을 때 다시 돌린다 |
| `scripts/discover_els.mjs` | 위 조사 스크립트 |
| `scripts/collect_history.mjs` | 기초자산 10년치 일별 종가(Yahoo Finance) → `data/els.js` 의 `history` |
| `tools/discovery/rendered_list.json` | 수집할 때 홈페이지 화면에 실제로 그려진 목록 원문. 수집 결과와 대조용 |
| `scripts/reparse_els.mjs` | 파서를 고쳤을 때, 이미 수집된 `data/els.js` 의 일정을 원문 표기에서 다시 계산 |

**위험등급**은 목록 API 응답에 없습니다(`omkt_drvs_risk_gcd` 는 사내 코드값). 화면에만
"매우높은위험" 같은 문구로 렌더링되므로, 수집기가 그려진 표에서 상품명과 함께 읽어
`riskLabel`(원문) / `riskGrade`(1~6) 로 저장합니다.

**과거 시세**는 상품 수집과 분리된 단계입니다. 한쪽이 실패해도 다른 쪽 데이터는
그대로 유지되고, 새 기초자산이 등장했는데 심볼 매핑이 없으면 그 자산만 건너뛰며
`history.missing` 에 남습니다(해당 상품은 과거 시뮬레이션을 표시하지 않습니다).
매핑은 `scripts/collect_history.mjs` 의 `SYMBOLS` 에 추가합니다.

배리어 시퀀스는 홈페이지 원문 표기(`structureDesc`)에서 뽑습니다. 파서를 손봤다면
다음 주 수집을 기다리지 말고 `node scripts/reparse_els.mjs` 로 기존 데이터를 맞춰두세요
(수집기와 같은 파서를 씁니다).

ELS 청약기간은 보통 1주일이라 주 1회 수집으로는 이미 마감된 상품이 며칠씩 남습니다.
그래서 **매일** 수집하고, 페이지는 저장된 청약기간과 **여는 날짜**를 비교해 청약중 /
청약마감 / 청약예정을 다시 판정합니다. 마감된 상품은 기본으로 목록에서 숨기고,
수집한 지 하루라도 지났으면 목록 위에 안내 문구와 홈페이지 링크를 띄웁니다.

**수집이 실패해도 페이지는 깨지지 않습니다.** 워크플로우는 `data/els.js` 를 건드리지 않고
끝나므로 직전 수집 데이터가 그대로 유지되고, 진단 자료는 `els-collect-debug` 아티팩트로
남습니다. 한 번도 수집되지 않은 상태에서는 내장 예시 데이터가 표시되며, 화면에
**"예시 데이터"** 배지가 붙습니다.

## ELS 데이터 스키마

`data/els.js` 는 `window.ELS_DATA` 하나를 정의합니다.

```js
window.ELS_DATA = {
  updatedAt: '2026-08-04T00:00:00Z',  // 수집 시각. null 이면 "미수집"
  source: 'live',                     // 'live' | 'sample'
  sourceNote: '...', sourceNoteEn: '...',
  products: [{
    code: 'ELS31234',
    name: '미래에셋증권 ELS 제31234회',
    type: 'ELS',                      // ELS | ELB | DLS | DLB
    underlyings: ['KOSPI200', 'S&P500'],
    couponRate: 8.4,                  // 세전 수익률 %. 기준은 rateBasis 가 정한다
    rateBasis: 'annual',              // 'annual' = 연율 | 'total' = 만기 기준 총액
    maxLossRate: 100,                 // 조건 미충족 시 최대손실률 %
    maturityMonths: 36,
    schedule: [                       // 조기상환 평가 일정
      { months: 6,  barrier: 90 },    // barrier = 최초기준가격 대비 %
      { months: 12, barrier: 85,      // 리자드 회차면 아래 두 필드가 붙는다
        lizard: 45, lizardRate: 20.5 },//  barrier 를 못 채워도 45% 이상이면 상환
      { months: 36, barrier: 75 },    // 마지막 항목이 만기
    ],
    knockIn: 50,                      // 낙인 배리어 %. null 이면 노낙인
    principalProtection: 0,           // 원금지급률 %. 100 이면 ELB
    riskGrade: 2,                     // 1(매우높은위험) ~ 6(매우낮은위험). 화면에서 수집
    riskLabel: '높은위험',             // 홈페이지 표기 그대로. 없으면 null
    offerStart: null, offerEnd: null, issueDate: null,
    minAmount: 1000000,
    url: null,                        // 상품 상세 링크
  }],

  // 과거 시뮬레이션용 기초자산 시세 (scripts/collect_history.mjs)
  history: {
    dates:  [20160803, 20160804, ...],        // 공통 거래일 축 (전 자산 합집합)
    series: { 'KOSPI200': [100, 99.8, ...] }, // 첫 유효일 = 100 으로 리베이스
    symbols:{ 'KOSPI200': '^KS200' },         // 사용한 Yahoo 심볼
    missing: [],                              // 심볼 매핑이 없거나 수집 실패한 자산
  },
};
```

`schedule` 의 **마지막 항목이 만기**이며, 회차별 누적 수익률은
`만기 총 수익률 × (months / maturityMonths)` 로 계산합니다.

> **수익률 기준** — 홈페이지 API 의 `omkt_drv_frcs_ern_r` 는 **"조건 충족시 연 수익률(세전)"의
> 최대치**입니다. 홈페이지 화면의 컬럼 헤더와 표시값("최대 10.71%")으로 확인했습니다
> (`scripts/verify_rate_basis.mjs`). 원금지급형 ELB 도 10%대가 나오는데, 월지급 쿠폰이
> 조건부라 "최대" 연율일 뿐 확정 수익이 아니기 때문입니다.
> 페이지는 이를 **상한**으로 명시하고 연율과 만기 보유 시 총액을 함께 보여줍니다.
> `couponAnnual` 만 있는 예전 데이터는 연율로 해석합니다.

## 과거 시뮬레이션

투자설명서의 "과거 시뮬레이션(모의실험)"과 같은 방식입니다. 과거 기초자산 종가로
**이 상품이 매 거래일 발행되었다고 가정**하고, 회차별 조기상환 판정과 낙인 터치를
그대로 돌려 결말을 셉니다.

| 항목 | 기준 |
|------|------|
| 판정 가격 | 일별 **종가**. 기초자산이 여럿이면 워스트 퍼포머 |
| 조기상환 | 평가일(발행일 + n개월) 이후 첫 거래일 종가가 배리어 이상이면 상환 |
| 리자드 | 배리어는 못 채웠지만 리자드 선 이상이면 리자드 수익률로 상환 |
| 낙인 | 기간 중 종가가 한 번이라도 낙인 아래로 내려가면 터치 |
| 만기 미충족 | 낙인 미터치면 약속 수익, 터치했으면 하락률만큼 손실. 원금지급형은 0% |
| 발행일 범위 | 시세 시작일 ~ (시세 마지막 날 − 만기). 만기까지 관찰 가능한 날만 |
| 제외 | 세금·수수료·중도상환 비용 |

> **설명서 수치를 옮긴 것이 아니라 이 페이지가 계산한 값입니다.** 데이터 출처
> (Yahoo Finance 종가)와 가정이 발행사 설명서와 달라 수치가 일치하지 않을 수 있습니다.

| **사내 프록시 / 사내 폴더** | ⑩ 에 주소를 넣어 둔 경우에만 함께 점검합니다 |

막힘은 이유를 구별해 적습니다 — 사내 담당자에게 물어볼 말이 달라지기 때문입니다:
`연결이 거부됐습니다(방화벽 차단이거나 CORS 거부)` / `응답 없음(8초, 조용히 버리는 형태)` /
`407 사내 프록시가 로그인을 요구합니다` / `403 프록시나 서버가 거부` / `404 주소에 파일이 없습니다(차단이 아님)`.
아래 **결과 복사** 버튼으로 브라우저·주소까지 담은 요약을 복사해 담당자에게 그대로 보낼 수 있습니다.

버튼을 누르지 않고 눈으로 보는 방법도 있습니다 — **화면 위쪽 배지**입니다.
`실시간` · `시세 N분 전` · `스냅샷 09.08 21:17` 중 하나면 값이 들어오고 있고,
전부 `예시 데이터`로 나오면 모든 경로가 막힌 것입니다(상태줄에도 `예시 데이터 — 실제 시세가 아닙니다`가 뜹니다).

### 인터넷이 안 되는 PC 에서 일반 파일(`us-top100.html`)을 열면

열리기는 하지만 **모든 숫자가 예시 값**입니다. 데이터를 밖에서 받아오는 구조라 받아올 곳이 없으면
화면 구조 확인용 예시 값을 만들어 채우고, 그 사실을 배지(`예시 데이터`)·상태줄·안내 상자에 밝힙니다.
**업무에 쓰면 안 됩니다** — 그 PC 에서는 `us-top100-offline.html`(데이터 내장)을 쓰세요.

### 어느 기능을 써야 하나 (평소 / 오프라인 PC)

**평소(인터넷 되는 PC)** — 화면을 열면 그 시점의 값이 한 번 들어옵니다. 그 뒤로는 `지금 새로 조회`를
필요할 때 누르면 됩니다(회의 직전처럼 *지금 이 순간의 값*을 확실히 받고 싶을 때). 장을 계속 지켜보는
자리라면 **자동 갱신**을 켜 두세요 — 1분마다 새 파일을 확인해 표가 스스로 따라갑니다. 처음부터 켜 두지
않는 이유는, 읽고 있던 숫자가 눈앞에서 바뀌면 방금 본 값과 어긋나기 때문입니다.
`지금 수집 요청`은 미국 장중인데 상태줄이 15분 넘게 묵어 있을 때만(그 링크는 그때만 나타납니다) 쓰면 됩니다.

**인터넷이 안 되는 업무용 PC** — 세 기능 모두 **아무 효과가 없습니다**. 브라우저는 `file://` 로 열린
페이지가 *옆에 있는 json 파일*을 읽는 것조차 CORS 로 막기 때문에(origin `null`), 데이터를 같이
복사해 두어도 소용이 없습니다. 그 PC 에서는 **데이터를 파일 안에 넣은 단일 파일**을 써야 합니다:

```bash
# 인터넷 되는 PC 에서 (데이터가 저장소에 있는 상태)
git checkout origin/us100-data -- data/us100      # 최신 수집분 받기
python scripts/make_offline_html.py               # → us-top100-offline.html (약 4.2 MB)
```

또는 **GitHub Actions 의 수집 실행 페이지 → Artifacts → `us-top100-offline`** 에서 내려받으면 됩니다
(매일 수집 때 자동으로 만들어 14일간 보관). 이 파일 하나만 업무용 PC 로 옮겨 더블클릭하면
100개 기업의 시세·지표·실적·컨센서스·일정·뉴스·차트·종목비교가 **인터넷 없이 그대로** 나옵니다.

| | 인터넷 되는 PC | 오프라인 PC |
|---|---|---|
| 쓸 파일 | `us-top100.html` | `us-top100-offline.html` |
| 자동 갱신 | 장을 지켜볼 때 켜세요 (기본 꺼짐) | 효과 없음(켜도 달라지지 않습니다) |
| 지금 새로 조회 | 필요할 때 | 효과 없음(눌러도 화면은 그대로 유지됩니다) |
| 지금 수집 요청 | 장중에 값이 묵었을 때 | 효과 없음 |
| 값의 신선도 | 스트리밍/10분/30분 | **파일을 만든 시점에 고정** |

오프라인 파일은 배지가 `내장 스냅샷 09.08 17:08`, 히어로가 `이 파일에 내장된 스냅샷`으로
**언제 값인지**를 밝힙니다. 새 값이 필요하면 파일을 다시 만들어 옮기면 됩니다.
(그 파일을 인터넷 되는 PC 에서 열면, 내장본을 먼저 그린 뒤 더 새 파일이 오면 그 위에 덮습니다.)

### 값이 몇 시간 전 것으로 보일 때

미국 정규장은 한국 시간 밤 10:30~새벽 5:00(서머타임 기준)입니다. 그 밖의 시간에는 정규 가격이
**종가에서 멈춰** 있어 아무리 갱신해도 값이 바뀌지 않습니다. 그래서 화면은

- 히어로의 `시세 기준 …` 옆에 **왜 안 바뀌는지**를 함께 적습니다 — `· 프리마켓 (정규장 개장까지 3시간 16분)`,
- **가격 파일이 스냅샷보다 오래되면 쓰지 않습니다.** 두 파일은 따로 도착하고 예약이 밀리면 순서가 뒤집히는데,
  그때 오래된 파일로 덮으면 더 새 값이 헌 값으로 바뀝니다(먼저 도착해 이미 들어간 값도 물립니다),
- 프리마켓·애프터마켓에도 30분 주기로 수집해 **시간외 호가**(`preMarketPrice` / `postMarketPrice`)를 함께 담고,
  종목 요약 헤더에 `프리마켓 $362.19 +1.20%` 로 덧붙입니다(정규 종가를 시간외 값으로 바꾸지는 않습니다).

주소에 종목이 남습니다(`us-top100.html#NVDA`) — 링크로 특정 종목을 바로 열거나 공유할 수 있고,
새로고침해도 그 종목으로 돌아옵니다. 관심종목·선택 종목·비교 담은 종목·비교 조합·비교 기간·보조지표·언어·자동 갱신·스트리밍 설정은
브라우저(localStorage)에 남습니다.

> **처음 여는 파일은 처음 상태로 열립니다.** 브라우저는 `file://` 로 열린 로컬 HTML 을 하나의 저장소로
> 묶기 때문에, 그냥 두면 새로 받은 파일(`ustop100 (4).html`)도 이전 파일이 남긴 관심종목·비교 선택을
> 그대로 물려받습니다. 그래서 화면은 **판 문자열 + 파일 경로**를 스탬프로 남겨 두고, 스탬프가 다르면
> (= 새 판이거나 새로 받은 사본이면) 저장된 화면 설정을 지우고 시작하면서 **무엇을 지웠는지** 목록 위에
> 적습니다(`… 관심종목 · 비교 선택 설정을 지웠습니다`). 같은 파일을 계속 쓰는 동안에는 고른 것을
> 기억하고, 그때는 **무엇을 불러왔는지** 적고(`관심종목 2개 · 비교에 담은 종목 4개(…)`)
> **처음 상태로 초기화** 링크를 함께 둡니다. 같은 초기화는 ⑩ 섹션 고급 설정의 **화면 설정 전체 초기화**
> 버튼에도 있습니다. 판을 새로 내보낼 때는 `us-top100.html` 의 `var BUILD` 문자열을 함께 올립니다.
>
> 비교 섹션은 **처음 열 때 자동으로 채우지 않습니다.** 빈 화면을 피하려고 "선택 종목 + 동일 섹터 상위"로 채워 봤지만, 그러면 목록의 비교 체크박스 3개가 켜진 채 열려서 — 저장하지 않아도 — "지난번 체크가 그대로 남았다"와 똑같이 보였습니다. 지금은 아무것도 담지 않고, 비교 섹션의 **채우기 버튼**과 **기본 조합 칩**으로 안내합니다.

## 데이터 소스 — 네 경로

화면은 **가장 빠르고 확실한 것부터** 그리고, 더 신선한 값이 오면 덮어씁니다.
어느 경로로 그려졌는지는 섹션 배지가 말해 줍니다.

**⓪ 실시간 스트리밍 (WebSocket)** — `wss://streamer.finance.yahoo.com`.
**WebSocket 은 CORS 를 받지 않으므로** 정적 HTML 에서도 붙습니다. 붙으면 10분 주기 파일이
아니라 **틱 단위 실시간**으로 가격·등락률·거래량이 움직이고 배지가 `실시간 스트리밍`이 됩니다.
방화벽이 wss 를 막으면 세 번 시도한 뒤 조용히 포기하고 아래 경로가 화면을 채웁니다.

프레임은 base64 로 감싼 protobuf 라 라이브러리 없이 최소 디코더를 직접 씁니다. 잘못
디코딩한 값이 화면에 나가지 않도록 **두 가지를 검사해 통과한 틱만 반영합니다** —
① 첫 필드가 우리가 아는 심볼 문자열인지(레이아웃이 맞았다는 증거), ② 가격이 이미 아는
기준가의 ±25% 안인지. 걸러낸 건수는 ⑩ 섹션 출처 표에 그대로 나옵니다.
스트리밍은 설정에서 끌 수 있습니다.

**① 가격 파일 (장중 10분 주기)** — 스트리밍이 막힌 곳의 주 경로. `data/us100/quotes.json`. 러너가 25종목씩 묶어
4~5번 요청으로 20~40초에 받아 커밋합니다. 화면은 이 파일을 가격·등락률에 먼저 쓰고
**1분마다 다시 확인**해 새로 올라온 값을 스스로 따라갑니다. 배지에 `시세 7분 전`처럼
**실제 나이**를 적습니다(GitHub 예약은 늦을 때가 있어 주기를 약속하지 않습니다).

**② 저장 스냅샷 (하루 단위)** — `data/us100/latest.json` + `chart/{SYM}.json`.
지표·실적·컨센서스·일정·투자의견·뉴스·시계열이 들어 있습니다. 사내망·CORS 로
브라우저가 야후에 못 붙는 곳에서도 실제 수치가 나오고, 열자마자 100종목이 다 채워집니다.

**③ 실시간 (브라우저 직접 조회)** — 붙을 수 있는 환경이면 위 두 값을 덮어씁니다.
배지가 `실시간` 으로 바뀌는 것으로 구분합니다.

### 사내 프록시가 있으면 진짜 실시간이 됩니다

화면 ⑩ 섹션의 **데이터 경로 설정**에 사내 프록시 주소를 넣으면(예:
`https://intra.example.com/proxy?url={urlenc}`) 그 경로를 **가장 먼저** 시도합니다.
넣는 즉시 브라우저가 직접 야후를 호출해 지연 없는 시세를 받습니다. 스냅샷 파일 경로도
사내 주소로 바꿀 수 있습니다. 주소는 회사마다 달라 코드에 박지 않고 브라우저
(localStorage)에 저장합니다.

> 무료 공개 소스 + 정적 HTML 로 **틱 단위 실시간**을 만들 수는 없습니다(유료 피드는 키가 필요).
> 지금 구조에서 가능한 최선은 ⑴ 브라우저가 직접 붙는 환경이면 실시간, ⑵ 아니면 10분 주기
> 가격 파일, ⑶ 사내 프록시를 넣으면 다시 실시간입니다.

#### 사내 프록시가 없다면 — 개인 프록시 10줄로 만들기

Cloudflare Workers 무료 플랜에 아래를 붙여 배포하고(5분), 나온 주소를
`https://<이름>.workers.dev/?url={urlenc}` 형태로 **데이터 경로 설정**에 넣으면
그 순간부터 브라우저가 지연 없이 시세를 받습니다. 대상 호스트를 두 곳으로 못 박아
아무 주소나 대신 불러 주는 열린 프록시가 되지 않게 했습니다.

```js
const ALLOW = ['query1.finance.yahoo.com', 'query2.finance.yahoo.com', 'stooq.com'];
export default {
  async fetch(req) {
    const target = new URL(req.url).searchParams.get('url');
    if (!target) return new Response('url 파라미터가 없습니다', { status: 400 });
    let u;
    try { u = new URL(target); } catch { return new Response('주소 형식이 아닙니다', { status: 400 }); }
    if (!ALLOW.includes(u.hostname)) return new Response('허용되지 않은 호스트', { status: 403 });
    const r = await fetch(u, { headers: { 'User-Agent': 'Mozilla/5.0', Accept: 'application/json,text/plain,*/*' } });
    const body = await r.arrayBuffer();
    return new Response(body, { status: r.status,
      headers: { 'content-type': r.headers.get('content-type') || 'application/json',
                 'access-control-allow-origin': '*', 'cache-control': 'no-store' } });
  }
};
```

야후 `quoteSummary`(목표주가·컨센서스·일정)는 이 프록시로도 401 입니다 — 쿠키+crumb 이
필요하기 때문입니다. 그 항목은 계속 러너 스냅샷을 씁니다. 프록시로 살아나는 것은
**가격·차트·거래량·배당/분할·뉴스**입니다.

> **야후 `quoteSummary` 는 쿠키 + crumb 을 요구합니다(없으면 HTTP 401).** 실제로 돌려 보니
> 100종목 전부 401 이었고, crumb 핸드셰이크를 넣은 뒤 98/100 이 들어왔습니다. 이 핸드셰이크는
> 쿠키를 물고 다녀야 해서 **브라우저에서는 사실상 불가능**합니다(교차 사이트 쿠키·CORS).
> 그래서 **목표주가·컨센서스·실적발표일·투자의견·서프라이즈는 러너 스냅샷이 사실상 유일한 경로**이고,
> 브라우저 실시간 조회는 **가격·차트·거래량·배당/분할·뉴스**를 갱신하는 역할입니다.

| 항목 | 실시간 소스 | 폴백 순서 |
|------|-------------|-----------|
| 목록 시세(100종목) | **스트리밍**(wss) → Yahoo `v7/finance/quote`(크럼 필요, 브라우저에서는 대개 401) | **가격 파일(10분)** → **스냅샷** → 예시 데이터 |
| 상세 시세·일/주/월 차트·배당·분할 이벤트 | Yahoo `v8/finance/chart` (`events=div,split`) | **스냅샷**(`data/us100/chart/{SYM}.json`) → 예시 데이터 |
| 지표·실적·컨센서스·일정·투자의견 | Yahoo `v10/finance/quoteSummary` (13개 모듈, **쿠키+crumb 필요 → 브라우저에서는 대개 401**) | **스냅샷** → Yahoo `fundamentals-timeseries`(실적·밸류에이션만) → 예시 데이터 |
| 뉴스 | Yahoo `v1/finance/search` | Google News RSS → 딥링크 안내 (스냅샷에 담지 않음) |

### 데이터는 히스토리를 남기지 않는 브랜치에 둡니다

수집 결과는 `main` 이 아니라 **데이터 전용 브랜치 `us100-data`** 에 있고,
갱신할 때마다 **부모 없는 커밋 하나로 갈아끼웁니다**(과거 미보존).

    https://github.com/hanaroline/work_1/tree/us100-data/data/us100

이유는 크기입니다. 차트 100개(약 3MB)가 매일 통째로 바뀌고 가격 파일은 장중 10분마다
바뀝니다. `main` 히스토리에 쌓으면 **1년에 1GB 규모**로 붇습니다. 이 화면에서 의미가
있는 것은 지금 조회되는 값이고 과거에 조회했던 값이 아니므로, 과거를 버립니다.

| | |
|---|---|
| 올리는 절차 | `scripts/publish_us100_data.sh` — ① 브랜치의 현재 파일을 받아 깔고 ② 이번 실행이 만든 파일로 덮고 ③ `data/us100` 만 담은 부모 없는 커밋을 만들어 `--force-with-lease` 로 교체. 경쟁이 감지되면 ①부터 네 번까지 다시 |
| 두 워크플로가 같은 브랜치에 쓰는 문제 | 가격 판(10분)은 `quotes.json` 만 갱신하고 스냅샷·차트는 ①에서 받아 **보존**합니다. 반대도 같습니다 |
| `main` 에 남는 것 | `data/us100/` 에는 `{"movedTo": ...}` **안내 파일**과 REFRESH 트리거만 둡니다. 예전 HTML 을 이미 받아 둔 사람도 그 안내를 따라가 최신 값을 봅니다 |

**리셋의 대가 — 세 가지는 알고 쓰셔야 합니다.**

1. **근거 보관이 안 됩니다.** 대외 자료에 쓴 수치의 "그때 화면에 뜬 값"을 나중에 증빙해야 한다면,
   그 시점 파일을 따로 저장해 두셔야 합니다(브리핑처럼 `docs/` 에 사본을 남기는 식).
   시계열·재무 같은 값은 야후에서 다시 받을 수 있으므로 실제 손실은 이 증빙 용도뿐입니다.
2. **저장소가 즉시 작아지지는 않습니다.** force-push 로 옛 커밋은 접근 불가 객체가 되지만
   회수 시점은 GitHub 의 GC 가 정합니다(며칠~몇 주). 이미 쌓인 3MB 는 남습니다.
3. **raw 캐시가 몇 분 늦을 수 있습니다.** `raw.githubusercontent.com` 은 짧은 캐시를 두므로
   갱신 직후 몇 분간 이전 파일이 나올 수 있습니다. 화면이 **수집 시각과 나이를 그대로
   표시**하므로 오해할 일은 없지만, "10분 주기"가 때로 "13분 전"으로 보일 수 있습니다.

> 주기를 1주일 단위로 리셋하는 방식(그 사이는 히스토리 보존)도 생각했지만, 커밋마다
> 리셋하는 편이 더 낫다고 봤습니다 — "언제 마지막으로 리셋됐나"를 신경 쓸 일이 없고,
> 어차피 일주일치 과거 조회값도 쓰지 않기 때문입니다.

> **Actions 사용 시간** — 10분 주기 가격 갱신은 하루 약 50회 × 30~40초 ≈ 30분입니다.

지금 바로 다시 받고 싶으면 `data/us100/REFRESH` 를 한 줄 고쳐 push 하거나(브랜치 무관),
Actions 탭에서 수동 실행합니다. 수집은 100종목 기준 5분 안팎이 걸립니다.

> 종목 목록은 **`us-top100.html` 의 `COMPANIES` 배열이 유일한 원본**입니다. 수집기가 그 파일을
> 읽어 목록을 만들기 때문에, 종목을 고치면 다음 수집부터 자동으로 반영됩니다.

> **티커가 바뀌어도 멈추지 않습니다.** 야후가 심볼을 404 로 답하면 수집기가
> `v1/finance/search` 에 회사 영문명을 넣어 현재 심볼을 찾고(미국 거래소 보통주 + 회사명 일치
> 조건), 찾은 심볼은 `sources[종목].resolvedSymbol` 에 남습니다. 화면 목록에서 그 종목이
> **조회 불가**로 표시되면 `COMPANIES` 의 심볼을 고칠 때가 된 것입니다.

> 수집기와 화면은 **같은 환산 규칙**을 씁니다(비율 → 퍼센트, 전일종가 짝 맞추기).
> 한쪽만 고치면 스냅샷과 실시간 값이 다르게 보입니다.

수집 결과는 `latest.json` 의 `summary`(`chartOk` / `summaryOk` / `crumb`)와
`sources`(종목별 단계별 성공·실패)에 남습니다. 화면 ⑩ 섹션에서도 확인할 수 있습니다.

- 각 요청은 **직접 호출 + CORS 프록시 5경로를 동시에 시도**해 가장 먼저 성공한 응답을 씁니다(각 6초 타임아웃).
- 섹션마다 응답 시각이 달라, **도착한 섹션부터 즉시 그립니다**. 느린 요청을 기다리며 빈 화면을 보여주지 않습니다.
- 100종목 지표(시가총액·PER·EPS·목표주가)는 종목별 요청이라 **화면에 보이는 행만** 채우고(기본 15개),
  나머지는 `표시 종목 지표 불러오기` 버튼으로 채웁니다(동시 5개 제한).

### 예시(데모) 데이터의 범위

사내망·CORS로 외부 요청이 전부 막히면 화면 구조를 확인할 수 있도록 **예시 값**을 표시하고,
섹션마다 `예시 데이터` 배지와 경고 문구를 띄웁니다. 예시로 만드는 것은 **시세 시계열과 지표·실적·목표주가**뿐이며,
**실적발표일·컨퍼런스콜 일정·투자의견 변경 이력·뉴스는 만들지 않습니다**(사실로 읽힐 항목을 지어내지 않기 위함).
그 항목들은 `미조회`로 남고 원문 확인 링크만 제공합니다.

### 값의 해석에서 주의한 지점

- **전일 대비 등락률** — 현재가와 전일종가를 **같은 응답에서 짝으로** 가져옵니다. 차트 메타의
  `chartPreviousClose` 는 "조회 기간 직전 종가"(1년 차트면 1년 전)라서 전일 종가로 쓰지 않습니다.
  목록의 spark 경로도 5일 창의 마지막 두 종가로 계산합니다. Stooq 폴백은 전일 종가가 없어
  **당일 시가 대비**가 되며, 그 경우 목록 아래에 안내가 붙습니다.
- **비율/퍼센트 혼용** — Yahoo 의 성장률·마진·ROE·서프라이즈는 비율(0.152 = 15.2%)로 옵니다.
  배당수익률은 응답에 따라 비율/퍼센트가 섞여, 주당배당금÷주가와 대조해 판별합니다.
- **실적발표일** — 제공사가 날짜를 두 개 주면(구간) 회사 확정 공지 전 **추정**으로 표시하고 시각은 숨깁니다.
- **컨퍼런스콜 시각** — 이 화면이 쓰는 API 에 콜 시각이 없습니다. 추정하지 않고 IR 딥링크로 안내합니다.
- **목표주가** — 개별 증권사 리포트가 아니라 Yahoo 가 집계한 컨센서스입니다(국내 증권사 의견은 빠질 수 있음).
- **증권사별 목표가는 무료 소스에 없습니다** — Yahoo 의 의견 변경 이력(`upgradeDowngradeHistory`)이 주는 것은
  일자·증권사·변경 전/후 등급·구분뿐이고 **목표가 항목이 없습니다**. 그래서 화면의 `목표가` 열은 비워 두고
  (수집기가 `pt` 로 받을 자리를 만들어 두었으니 제공사가 넣어 주면 그대로 채워집니다), 대신 우리가 가진
  일봉에서 **그 의견이 나온 날의 종가**와 **지금까지의 등락**을 계산해 함께 보여 줍니다. 증권사별 목표가가
  꼭 필요하면 유료·키 발급이 필요한 소스(Finnhub·FMP·Benzinga 등)를 붙여야 하고, 그 키는 저장소가 아니라
  Actions 시크릿에 두어야 합니다.
- **기업 개요의 한글 요약** — 주력사업·개요·사업 키워드(100개 기업)는 공개된 사업 구조를 화면에 정리해 둔
  상수이고, 영문 원문 개요는 제공사의 기업 프로필(`assetProfile.longBusinessSummary`)입니다. 출처가 다르므로
  화면에서도 구분해 적습니다.
- **보조지표** — 볼린저밴드(20, ±2σ)·MACD(12,26,9)·RSI(14)는 정의 그대로 브라우저에서 계산합니다(라이브러리 없음).
  MACD 는 느린 EMA 가 자리 잡기 전 구간을, RSI 는 첫 14봉을 비워 둡니다. 봉이 모자라면 그리지 않고 이유를 적습니다.
- **비교 종목 수를 4개로 둔 이유** — 승인된 시리즈 색이 4색(오렌지·남색·연오렌지·하늘)이고,
  5개 이상이면 뒤 색이 앞 색과 구분되지 않으며 기간별 수익률 막대의 값 라벨이 겹쳐 못 씁니다.
  그래서 종목 수를 늘리는 대신 **조합을 저장해 갈아 끼우는** 쪽으로 풀었습니다.
- **비교 차트의 리베이스** — 고른 기간의 **첫 종가를 100** 으로 맞춥니다. 마지막 점은 지금 가격(스트리밍·가격
  파일·스냅샷 중 가장 신선한 것)으로 맞추고, 배당 재투자는 반영하지 않습니다. 기간별 수익률 비교는 차트 기간과
  무관하게 받아 둔 전체 시계열(월봉 10년 + 일봉 2년)로 계산합니다.

## 대상 100개 기업

`us-top100.html` 안 `COMPANIES` 배열에 `[Yahoo 심볼, 영문명, 한글명, 섹터코드]` 로 들어 있습니다.
종목을 바꾸려면 이 배열만 고치면 됩니다(검색 키워드는 `KEYWORDS`).

> **목록은 고정입니다.** 지수가 아니고, `#` 열의 순서는 순위가 아니며, 시가총액이 바뀌어도
> 자동으로 갱신되지 않습니다. 실제 순위는 정렬을 **시가총액**으로 두면 조회한 값으로 매겨집니다.

### 대상 목록은 고정, 다만 매일 점검합니다

목록을 자동으로 갈아치우지 않는 이유는 화면의 **한글 자산**(기업명·검색 키워드·"기업 한눈에" 개요)이
종목마다 사람이 쓴 것이기 때문입니다. 자동 교체는 *한글이 빈 종목이 조용히 섞여 들어오는* 방식이 됩니다.

대신 매일 수집 때 `scripts/check_us100_ranking.py` 가 **지금 시가총액 상위 100** 과 목록을 견주어
차이만 보고합니다.

- 순위 경로 ① 야후 스크리너(`POST /v1/finance/screener`, crumb 필요, 시총 내림차순 상위 260)
  ② 막히면 S&P 500 구성종목 + `v7/finance/quote` 일괄 조회. 우리 목록의 시총은 방금 수집한
  `latest.json` 값을 씁니다(요청을 아끼고 같은 판의 값으로 순위를 매깁니다).
- **추가 후보**: 상위 100인데 목록에 없는 종목 — 미국에 상장한 외국 기업(ADR)일 수 있어 `assetProfile.country`
  를 함께 적습니다(예: `TSM … 본사 Taiwan(미국 상장 외국 기업)`).

- 점검은 **전체 수집과 따로 도는 가벼운 워크플로**입니다(`.github/workflows/us100-ranking.yml`,
  매일 22:00 UTC · 1~2분). 필요한 것이 데이터 브랜치의 `latest.json` 뿐이라 8분 걸리는

  그리고 **이슈 하나**(`대상 목록 갱신 후보 (미국 100대 기업)`, 매일 같은 글을 갱신).

## 데이터 수집

미국 화면과 **같은 수집기를 씁니다** — 받아오는 방법과 정규화 규칙이 같고 시장마다 다른
것은 여덟 가지(화면 파일·출력 폴더·통화·Stooq 접미사·거래소 코드 등)뿐이므로, 코드를 두 벌
두지 않고 시장 프로필만 갈아 끼웁니다.

| | 파일 |
|---|---|
| 전체 수집(하루 1회) | `scripts/fetch_kr100.py` → `scripts/fetch_us100.py` 의 엔진을 국내 프로필로 호출 |
| 가격 갱신(장중 10분) | `scripts/fetch_kr100_quotes.py` → `scripts/fetch_us100_quotes.py` 엔진 |
| 대상 목록 점검 | `scripts/check_kr100_ranking.py` — **야후 스크리너**(region=kr, 시총 내림차순) 상위 400과 우리 목록을 견줍니다 |
| 데이터 브랜치 업로드 | `scripts/publish_kr100_data.sh` → 시장 중립인 `scripts/publish_data_branch.sh` |
| 오프라인 단일 파일 | `python scripts/make_offline_html.py --market kr` → `kr-top100-offline.html` (수집 워크플로가 매일 만들어 올립니다) |

워크플로는 세 개입니다.

| 워크플로 | 언제 | 하는 일 |
|---|---|---|
| `.github/workflows/kr100-data.yml` | 평일 15:45 KST (마감 뒤) | 전 종목 시세·지표·실적·뉴스 → `latest.json` + `chart/*.json`, 오프라인 파일 Artifact |
| `.github/workflows/kr100-quotes.yml` | 평일 정규장 10분 주기 + 시간외 30분 주기 | 가격만 → `quotes.json` |

데이터는 미국 화면과 같은 방식으로 **히스토리를 남기지 않는 전용 브랜치**(`kr100-data`)에
커밋 하나로 갈아끼웁니다. `data/kr100/` 에는 안내 파일(`{"movedTo": …}`)과 수집을 부르는
트리거 파일(`REFRESH`·`QUOTES_REFRESH`·`RANK_REFRESH`)만 있습니다 —
자세한 것은 `data/kr100/README.md` 를 보세요.

> **예약이 도는 조건**: `schedule` 이벤트는 기본 브랜치(`main`)의 워크플로만 발동합니다.
> 작업 브랜치에서 돌리려면 `data/kr100/REFRESH`(또는 `QUOTES_REFRESH`·`RANK_REFRESH`)를
> 한 줄 고쳐 push 하거나 Actions 탭에서 수동 실행하세요.

## 대상 종목을 바꿀 때

종목 목록은 **`kr-top100.html` 의 `COMPANIES` 배열이 유일한 원본**입니다(수집기가 그 파일을
읽습니다). 교체할 때는 `COMPANIES`·`KEYWORDS`·`PROFILE_KO` 세 곳을 함께 고칩니다 —
새 종목의 검색 키워드와 "기업 한눈에"(주력사업 한 줄·개요·사업 키워드)를 채우지 않으면
그 종목만 화면이 비기 때문에, 목록 점검은 **후보만 알려 주고 자동 교체는 하지 않습니다**.

순위 원천이 응답하지 않으면 목록 점검은 `ranking.json` 을 **쓰지 않고** 경고만 남깁니다.

### 적합 / 부적합은 ELS 에서만 묻습니다

평가표를 상품군별로 대조한 결과입니다.

| 상품군 | 적합 vs 부적합, 상품설명의무 차이 |
|---|---|
| **ELS · DLS** | **다릅니다** — 적합에만 `적합성보고서 발급 및 내용 안내`(−5)와 `적합성보고서 교부`(−5)가 있습니다. 부적합 평가표에는 두 항목 자체가 없습니다. (`설명한 내용 확인 및 직원의 서명` 은 문안·체크포인트가 같고 배점만 −5 / −3 으로 다릅니다) |
| 펀드 (국내) | **같습니다** — 설명의무 10항목의 항목·문안·체크포인트가 완전히 동일 |
| 펀드 (해외) · 원화채권 · 외화채권 · IRP | 평가표가 한 종류뿐이라 고를 것이 없음 |

그래서 **ELS 를 골랐을 때만** 「적합 / 부적합」 선택이 나옵니다. 다른 상품군에서 물어봐야
화면이 달라지지 않고, 안 쓰는 선택지는 창구가 매번 「무엇이 달라지나」 를 다시 생각하게
만들 뿐입니다.

### ELS 적합 — 적합성보고서에 들어가는 값

적합성보고서 발급 안내 문안이 곧 **투자권유 사유**라, 다음 넷을 그대로 읽게 되어 있습니다.

> [투자권유 사유] 고객님의 투자자성향은 **○○형** 이며, 현재 투자자금성향 응답 결과
> 원금보존태도는 **○○**, 손실감내수준은 **○○**, 투자예정기간은 **○○** 으로
> "○○증권 제○○회" 회 상품과 적합하여 추천드립니다. …

그래서 **ELS 적합일 때만** 사이드바에 「2-1 적합성보고서에 들어가는 값」 이 열립니다 —
투자자성향 + 현재 투자자금성향 3항목(원금보존태도·손실감내수준·투자예정기간)입니다.
고르면 스크립트 문장에 바로 들어가고 확인필요가 사라집니다.

- **투자목적은 두지 않았습니다** — 이 문안에 들어가지 않는 값입니다. 안 쓰는 칸을 두면
  무엇이 스크립트에 반영되는지 흐려집니다.
- **신규투자자** 체크가 함께 있습니다. 적합성보고서 발급 대상은 *(적합한) 고령투자자 또는
  신규투자자* 라서, **비고령이면서 신규투자자가 아니면 두 항목이 빠집니다** — 카드에는
  「미해당」 으로 남지만 **읽기 모드와 셀프채점에서는 제외**됩니다. 그래서 화면 위에
  「지금 상담 조건에서 빠지는 항목 N건」 배너를 띄우고, 카드를 열면 무엇을 켜야 살아나는지
  (고령으로 바꾸거나 신규투자자를 켜라고) 적어 둡니다. 조건 때문에 빠진 것을 "스크립트가
  없다" 로 오해하지 않게 하려는 것입니다.
- **부적합을 고르면** 이 칸이 사라집니다 — 평가표에 적합성보고서 항목이 없어 성향을
  말할 일도 없기 때문입니다.

### 부적합이어도 상품 목록은 전부 나옵니다

전체판의 부적합 상담은 상품이 **둘**입니다(먼저 권유하는 적합 상품 + 고객이 지목한
부적합 상품). 그래서 목록에 「성향에 **부적합한 등급만** 보기」 필터가 걸립니다.

설명의무 전용판은 그 필터를 **걸지 않습니다.** 적합성 판정과 부적합확인서는 적합성원칙
단계에서 이미 끝났고, 여기서는 고객이 고른 그 상품을 설명할 뿐입니다. 성향값도
적합성보고서 문안에 쓰려고 받아 둔 것이지 목록을 거르라고 받은 것이 아닙니다.
(필터가 걸리면 「성장형은 1~6등급을 모두 가입할 수 있어 부적합한 상품이 없습니다」 가 되어
목록이 통째로 비어 버립니다.)

같은 이유로 부적합에서는 「시나리오가 맞지 않습니다」 경고도 내지 않습니다. 다만 **적합**
에서는 그대로 둡니다 — 적합성보고서 문안이 "…적합하여 추천드립니다" 라고 말하므로,
성향에 맞지 않는 등급을 고르면 그 문장 자체가 사실과 달라지기 때문입니다.

## 만들기

```bash
# 설명의무 전용판 (배포본)
node scripts/build_sales_script.mjs sales-script-expl-standalone.html --src sales-script-expl.html

# 전체판 (적합성원칙 포함) — 필요할 때만
node scripts/build_sales_script.mjs sales-script-standalone.html

# 소스 상태로 확인
python3 -m http.server 8000   # http://localhost:8000/sales-script-expl.html
```

빌드는 `vendor/*.js` · `data/*.js` · `js/*.js` 를 한 파일에 인라인하고, PDF 판독 워커는
문자열로 심어 앱이 Blob URL 로 씁니다. **웹폰트를 부르지 않습니다** — 망이 막힌 PC 에서
구글 폰트 `<link>` 는 응답이 끊길 때까지 화면을 비워 두기 때문입니다.

## 유의사항 (완전판매 스크립트)

이 화면의 스크립트는 **미스터리쇼핑 평가표를 코드화한 것**입니다. 숫자·일자·요율은
반드시 **해당 상품의 투자설명서 원문**과 대조하십시오 — 부정확한 설명은 부당권유행위로
감점됩니다. 셀프채점은 평가표 배점을 그대로 적용한 계산일 뿐 실제 평가 결과가 아닙니다.
