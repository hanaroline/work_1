# 종목 통합 리포트 대시보드

주식 종목명 또는 종목코드를 입력하면 해당 종목의 **시세 · 증권사 투자의견/레포트 · 시황(뉴스) · 재무제표**를
**한 장의 리포트**처럼 보여주는 단일 HTML 대시보드입니다. 빌드 도구 없이 `index.html` 하나로 동작합니다.

## 화면 구성

| 섹션 | 내용 |
|------|------|
| **종목 요약** | 종목명·코드·시장(KOSPI/KOSDAQ), 현재가·등락, 시가총액, PER/PBR/EPS, **조회 기준 시각** |
| **시세 · 기술적지표** | 가격 차트(1M/3M/6M/1Y) + **이동평균 MA5/20/60** + **RSI(14)** + 거래량, 52주 최고/최저, **지수 대비 초과수익률** |
| **외국인 · 기관 수급** | 일별 순매수 대금(외국인/기관) 차트 + 외국인 지분율 추이, 5일/20일 누적 순매수 |
| **증권사 투자의견** | 목표주가 밴드(최저·평균·최고 vs 현재가), 상승여력, 매수/중립/매도 의견분포, 최근 레포트 목록 |
| **시황 · 뉴스** | 종목 관련 최신 뉴스 헤드라인 |
| **재무제표** | 연간 손익(매출·영업이익·순이익) 차트 + 표, 재무상태(자산·부채·자본), ROE·부채비율 |

### 주요 기능
- **관심종목 즐겨찾기(★)** — 브라우저에 저장(localStorage), 상단 칩에서 원클릭 조회
- **종목 비교(⇄)** — 최대 4종목을 기준=100 리베이스 차트 + 지표 표로 비교
- **지수 대비 보기** — 가격/지수대비(KOSPI·KOSDAQ 리베이스) 토글, 초과수익률 표시
- **PDF 저장/출력(🖨)** — 화면 그대로 A4 리포트로 저장·인쇄(`@media print`)
- 라이트/다크 테마 전환(◐), 종목명 자동완성, 6자리 코드 직접 입력

## 실행 방법

### 방법 1) 단일 파일 (가장 간단)

`standalone.html` **한 파일**에 CSS·JS·차트 라이브러리·데이터가 모두 인라인되어 있습니다.
별도 서버 없이 파일을 브라우저로 열기만 하면(더블클릭) 바로 동작합니다.

```
standalone.html  ← 이 파일만 열면 됨
```

### 방법 2) 분리 파일 + 로컬 서버 (개발용)

`index.html`은 `data/*.js`, `vendor/*.js`를 외부에서 로드하므로 로컬 서버로 열어야 합니다
(파일 프로토콜로 열면 브라우저 보안정책에 막힐 수 있음).

```bash
# 저장소 루트에서
python3 -m http.server 8000
# 브라우저에서 http://localhost:8000 접속
```

> `standalone.html`은 `index.html` + `data/*.js` + `vendor/chart.umd.js`를 합쳐 생성한 산출물입니다.
> 소스를 수정할 때는 `index.html` / `data/*.js`를 고친 뒤 다시 합치면 됩니다.

## 데이터 소스

무료 공개 소스를 우선 사용하고, 실패 시 **섹션별로 샘플 데이터로 폴백**합니다.
각 섹션에는 `실시간` / `샘플` 배지가 표시됩니다.

| 섹션 | 실시간 소스 | 폴백 |
|------|-------------|------|
| 시세/현재가/차트 | **네이버 모바일 `m.stock.naver.com/api`** 우선, Yahoo `chart` 보조 | 내장 샘플 |
| 외국인/기관 수급 | 네이버 `api/stock/{code}/trend` | 내장 샘플 |
| 지수(KOSPI/KOSDAQ) | Yahoo `chart/^KS11 · ^KQ11` | 내장 샘플 |
| 재무제표 | Yahoo `quoteSummary` (손익/재무상태) | 내장 샘플 |
| 투자의견/목표주가 | Yahoo `quoteSummary` (financialData, recommendationTrend) | 내장 샘플 |
| 시황/뉴스 | Google News RSS(`news.google.com/rss/search`) | 내장 샘플 |
| 증권사 레포트 목록 | (실시간 API 부재) | 예시 데이터 + 네이버 리서치 딥링크 |

모든 소스는 **병렬 호출 + 4초 타임아웃**으로 요청하며, 실패한 섹션만 개별적으로 샘플로 대체합니다(전체 화면은 항상 정상 렌더). 요약 헤더에 조회 기준 시각과 출처가 표시됩니다.

> 증권사 원문 리포트(PDF)는 공개 API가 없어, 목록은 예시로 채우고
> [네이버 금융 리서치](https://finance.naver.com/research/)로 연결되는 딥링크를 제공합니다.

### 브라우저 CORS 안내

순수 브라우저(단일 HTML)에서 위 API를 직접 호출하면 **CORS로 차단**되는 경우가 많습니다.
이를 위해 `index.html`의 `PROXIES` 배열에 **CORS 프록시 폴백**이 설정되어 있습니다.

```js
var PROXIES = [
  function (u) { return u; },                                              // 1) 직접 호출
  function (u) { return "https://corsproxy.io/?url=" + encodeURIComponent(u); },      // 2) 프록시
  function (u) { return "https://api.allorigins.win/raw?url=" + encodeURIComponent(u); } // 3) 프록시
];
```

- 사내망/폐쇄망 등으로 외부 접근이 막히면 세 경로 모두 실패하고 **샘플 데이터**로 표시됩니다(화면은 항상 정상 렌더).
- 안정적인 실시간 연동이 필요하면, 자체 백엔드 프록시(예: `/api/proxy?url=...`)를 만들어 `PROXIES`에 추가하는 것을 권장합니다.
- 미래에셋 **사내 API**가 있다면 `fetchYahoo` / `fetchNews`를 사내 엔드포인트 호출로 교체하면 됩니다.

# ELS 상품 구조 페이지

`els.html` — ELS 상품의 **기초자산 · 조기상환 조건 · 수익 구조**를 고객이 한 화면에서
이해할 수 있도록 만든 페이지입니다. 미래에셋증권 디자인 시스템(오렌지 `#F58220` /
블루 `#043B72`, 1px 섹션 룰, `#FAB072` 테이블 헤더)을 따르며 한/영 토글을 지원합니다.

## 화면 구성

| 섹션 | 내용 |
|------|------|
| **상품 찾기** | **상품코드·상품명·기초자산 검색** + **유형 / 기초자산 / 만기 / 조기상환 주기 / 위험등급** 5개 필터. 조건에 맞는 상품 목록이 바로 아래 표로 나오고, **행을 클릭하면** 그 상품으로 이하 모든 화면이 바뀜. 목록은 **상품 번호 오름차순**이 기본 |
| **30초 요약** | ELS를 결정짓는 세 가지(기초자산 / 조기상환 조건 / 수익 구조)를 카드로 정리 |
| **상품 상세** | 선택한 상품의 전체 스펙 — 코드·기초자산·수익률(연/총액)·만기·평가주기·배리어·낙인·원금지급률·최대손실률·위험등급·청약기간·홈페이지 원문 표기 |
| **조기상환 조건** | 회차별 배리어를 **계단형 사다리 그래프**로 표시. 낙인 배리어, 회차별 누적 수익률, 판정 기준 표. 리자드 상품은 해당 회차에 리자드 배리어를 함께 표기 |
| **수익 구조** | 만기 손익 그래프 2종 — **낙인 미터치 / 낙인 터치**를 나란히 비교. 기초자산 직접투자 대비선 포함 |
| **시나리오 시뮬레이터** | 평가일별 기초자산 수준과 기간 중 최저점을 슬라이더로 지정 → 언제 상환되고 얼마를 받는지 계산 |
| **과거 시뮬레이션** | 과거 10년 실제 종가로 **이 상품이 매 거래일 발행되었다면** 어떻게 끝났을지 계산 — 회차별 조기상환 비율, 원금 손실 비율, 평균 손익 (아래 "과거 시뮬레이션" 절 참고) |
| **확인 사항 / 용어** | 가입 전 점검할 5가지, 청약서 용어 사전 |

상단 우측에 **KO/EN 토글**과 **인쇄·PDF 저장** 버튼이 있습니다.

## 데이터 수집 (매일 자동)

미래에셋증권 홈페이지는 **WebSquare 기반 SPA**이고, 데이터는 `.wjson` POST 엔드포인트로
오갑니다. 정적 HTML에는 상품 정보가 전혀 없어 **헤드리스 브라우저 렌더링**이 필요합니다.
따라서 수집은 GitHub Actions 러너에서 Playwright 로 수행합니다.

| 파일 | 역할 |
|------|------|
| `.github/workflows/els-weekly.yml` | **매일 08:00 KST** 수집 → `data/els.js` 갱신 → 단일 파일 재빌드 → 커밋 |
| `scripts/collect_els.mjs` | 실제 수집기. 상품 목록 화면을 렌더링하고 `.wjson` 응답에서 상품을 추출 |
| `.github/workflows/els-discover.yml` | 사이트 구조 조사용(1회성). 엔드포인트가 바뀌었을 때 다시 돌린다 |
| `scripts/discover_els.mjs` | 위 조사 스크립트 |
| `scripts/collect_history.mjs` | 기초자산 10년치 일별 종가(Yahoo Finance) → `data/els.js` 의 `history` |
| `tools/discovery/rendered_list.json` | 수집할 때 홈페이지 화면에 실제로 그려진 목록 원문. 수집 결과와 대조용 |
| `scripts/reparse_els.mjs` | 파서를 고쳤을 때, 이미 수집된 `data/els.js` 의 일정을 원문 표기에서 다시 계산 |

**위험등급**은 목록 API 응답에 없습니다(`omkt_drvs_risk_gcd` 는 사내 코드값). 화면에만
"매우높은위험" 같은 문구로 렌더링되므로, 수집기가 그려진 표에서 상품명과 함께 읽어
`riskLabel`(원문) / `riskGrade`(1~6) 로 저장합니다.

**과거 시세**는 상품 수집과 분리된 단계입니다. 한쪽이 실패해도 다른 쪽 데이터는
그대로 유지되고, 새 기초자산이 등장했는데 심볼 매핑이 없으면 그 자산만 건너뛰며
`history.missing` 에 남습니다(해당 상품은 과거 시뮬레이션을 표시하지 않습니다).
매핑은 `scripts/collect_history.mjs` 의 `SYMBOLS` 에 추가합니다.

배리어 시퀀스는 홈페이지 원문 표기(`structureDesc`)에서 뽑습니다. 파서를 손봤다면
다음 주 수집을 기다리지 말고 `node scripts/reparse_els.mjs` 로 기존 데이터를 맞춰두세요
(수집기와 같은 파서를 씁니다).

ELS 청약기간은 보통 1주일이라 주 1회 수집으로는 이미 마감된 상품이 며칠씩 남습니다.
그래서 **매일** 수집하고, 페이지는 저장된 청약기간과 **여는 날짜**를 비교해 청약중 /
청약마감 / 청약예정을 다시 판정합니다. 마감된 상품은 기본으로 목록에서 숨기고,
수집한 지 하루라도 지났으면 목록 위에 안내 문구와 홈페이지 링크를 띄웁니다.

**수집이 실패해도 페이지는 깨지지 않습니다.** 워크플로우는 `data/els.js` 를 건드리지 않고
끝나므로 직전 수집 데이터가 그대로 유지되고, 진단 자료는 `els-collect-debug` 아티팩트로
남습니다. 한 번도 수집되지 않은 상태에서는 내장 예시 데이터가 표시되며, 화면에
**"예시 데이터"** 배지가 붙습니다.

## ELS 데이터 스키마

`data/els.js` 는 `window.ELS_DATA` 하나를 정의합니다.

```js
window.ELS_DATA = {
  updatedAt: '2026-08-04T00:00:00Z',  // 수집 시각. null 이면 "미수집"
  source: 'live',                     // 'live' | 'sample'
  sourceNote: '...', sourceNoteEn: '...',
  products: [{
    code: 'ELS31234',
    name: '미래에셋증권 ELS 제31234회',
    type: 'ELS',                      // ELS | ELB | DLS | DLB
    underlyings: ['KOSPI200', 'S&P500'],
    couponRate: 8.4,                  // 세전 수익률 %. 기준은 rateBasis 가 정한다
    rateBasis: 'annual',              // 'annual' = 연율 | 'total' = 만기 기준 총액
    maxLossRate: 100,                 // 조건 미충족 시 최대손실률 %
    maturityMonths: 36,
    schedule: [                       // 조기상환 평가 일정
      { months: 6,  barrier: 90 },    // barrier = 최초기준가격 대비 %
      { months: 12, barrier: 85,      // 리자드 회차면 아래 두 필드가 붙는다
        lizard: 45, lizardRate: 20.5 },//  barrier 를 못 채워도 45% 이상이면 상환
      { months: 36, barrier: 75 },    // 마지막 항목이 만기
    ],
    knockIn: 50,                      // 낙인 배리어 %. null 이면 노낙인
    principalProtection: 0,           // 원금지급률 %. 100 이면 ELB
    riskGrade: 2,                     // 1(매우높은위험) ~ 6(매우낮은위험). 화면에서 수집
    riskLabel: '높은위험',             // 홈페이지 표기 그대로. 없으면 null
    offerStart: null, offerEnd: null, issueDate: null,
    minAmount: 1000000,
    url: null,                        // 상품 상세 링크
  }],

  // 과거 시뮬레이션용 기초자산 시세 (scripts/collect_history.mjs)
  history: {
    dates:  [20160803, 20160804, ...],        // 공통 거래일 축 (전 자산 합집합)
    series: { 'KOSPI200': [100, 99.8, ...] }, // 첫 유효일 = 100 으로 리베이스
    symbols:{ 'KOSPI200': '^KS200' },         // 사용한 Yahoo 심볼
    missing: [],                              // 심볼 매핑이 없거나 수집 실패한 자산
  },
};
```

`schedule` 의 **마지막 항목이 만기**이며, 회차별 누적 수익률은
`만기 총 수익률 × (months / maturityMonths)` 로 계산합니다.

> **수익률 기준** — 홈페이지 API 의 `omkt_drv_frcs_ern_r` 는 **"조건 충족시 연 수익률(세전)"의
> 최대치**입니다. 홈페이지 화면의 컬럼 헤더와 표시값("최대 10.71%")으로 확인했습니다
> (`scripts/verify_rate_basis.mjs`). 원금지급형 ELB 도 10%대가 나오는데, 월지급 쿠폰이
> 조건부라 "최대" 연율일 뿐 확정 수익이 아니기 때문입니다.
> 페이지는 이를 **상한**으로 명시하고 연율과 만기 보유 시 총액을 함께 보여줍니다.
> `couponAnnual` 만 있는 예전 데이터는 연율로 해석합니다.

## 과거 시뮬레이션

투자설명서의 "과거 시뮬레이션(모의실험)"과 같은 방식입니다. 과거 기초자산 종가로
**이 상품이 매 거래일 발행되었다고 가정**하고, 회차별 조기상환 판정과 낙인 터치를
그대로 돌려 결말을 셉니다.

| 항목 | 기준 |
|------|------|
| 판정 가격 | 일별 **종가**. 기초자산이 여럿이면 워스트 퍼포머 |
| 조기상환 | 평가일(발행일 + n개월) 이후 첫 거래일 종가가 배리어 이상이면 상환 |
| 리자드 | 배리어는 못 채웠지만 리자드 선 이상이면 리자드 수익률로 상환 |
| 낙인 | 기간 중 종가가 한 번이라도 낙인 아래로 내려가면 터치 |
| 만기 미충족 | 낙인 미터치면 약속 수익, 터치했으면 하락률만큼 손실. 원금지급형은 0% |
| 발행일 범위 | 시세 시작일 ~ (시세 마지막 날 − 만기). 만기까지 관찰 가능한 날만 |
| 제외 | 세금·수수료·중도상환 비용 |

> **설명서 수치를 옮긴 것이 아니라 이 페이지가 계산한 값입니다.** 데이터 출처
> (Yahoo Finance 종가)와 가정이 발행사 설명서와 달라 수치가 일치하지 않을 수 있습니다.
> 고객 대상으로 쓸 경우 설명서 수치와의 차이를 반드시 확인하세요.

# ETF 편입종목 조회

`etf.html` — 국내·미국·홍콩·일본·중국 상장 ETF의 **상위 10개 편입종목과 비중**을
한 화면에서 보는 도구입니다. 국가·기초지수·섹터·테마·기간수익률·설정액·운용사로
걸러 보고, 여러 ETF를 겹쳐 **중복 편입 비율**을 확인할 수 있습니다.
미래에셋증권 디자인 시스템(오렌지 `#F58220` / 블루 `#043B72`)을 따르며 한/영 토글을 지원합니다.

## 화면 구성

| 탭 | 내용 |
|------|------|
| **ETF 찾기** | 통합 검색(ETF명·종목코드·기초지수·**편입종목명**) + **상장시장 / 투자지역 / 자산군 / 기초지수 / 섹터 / 테마 / 운용사 / 설정액** 8개 필터. 열 머리를 눌러 정렬. 행을 누르면 아래에 상세가 열립니다 |
| **상세** | 상위 10종목 표 + 비중 가로 막대, **상위10 합계(집중도)**, 섹터 비중 도넛, **기간 수익률(시장가·NAV 두 기준을 나란히)**, 운용사·기초지수·총보수·설정액·괴리율·추적오차·분배율·상장일 |
| **비교 · 중복도** | 최대 8개 ETF의 상위10을 나란히 놓고, **종목 × ETF 매트릭스**(행=종목, 열=ETF)로 무엇이 겹치는지 한 줄로 보여 준 뒤, 두 상품씩 겹침 비율을 계산. 표의 ETF 이름·코드를 누르면 아래에 상세가 펼쳐집니다 |
| **종목 → ETF** | "삼성전자를 담은 ETF"처럼 개별 종목에서 거꾸로 찾기. 비중 순 정렬이고 **ETF 하나가 한 줄**입니다(여러 종목이 걸리면 합계 비중). 행을 누르면 그 자리에서 상세가 펼쳐집니다. 검색 전에는 **가장 많은 ETF에 담긴 종목** 30개를 보여 줍니다 |
| **랭킹** | 기간수익률 상·하위, 설정액 상위, 3개월 자금유입 상위, 총보수 낮은 순. 행을 누르면 순위표 아래에 상세가 펼쳐집니다 |
| **분류 점검** | 자동 태깅 결과를 훑는 화면. 테마별 종목 수와 **테마가 안 붙은 종목** 목록 |

상단 우측에 **KO/EN 토글**과 **인쇄·PDF 저장** 버튼이 있습니다. 인쇄하면 모든 탭이 한 문서에 담깁니다.

수익률 기간(1일~10년)과 **기준(시장가 / NAV)** 은 목록 위에서 바꿉니다. 바꾸면 표의
수익률 컬럼과 랭킹이 함께 바뀝니다. 레버리지·인버스는 기본으로 숨깁니다 — 켜 두면
수익률 랭킹 위아래를 전부 차지해 화면이 쓸모없어집니다.

### 링크로 공유하기 (아티팩트)

파일을 주고받는 대신 링크 하나로 공유하려면 아티팩트로 올립니다.

```bash
node scripts/build_etf_artifact.mjs        # -> etf-artifact.html
node scripts/test_etf_page.mjs --artifact  # 올리기 전에 브라우저로 확인
```

아티팩트 호스트가 `<!doctype>`·`<html>`·`<head>`·`<body>` 를 직접 씌우므로,
올리는 파일은 **그 안에 들어갈 알맹이만** 담습니다(`<title>` + `<style>` +
`<body>` 안쪽). 온전한 문서를 그대로 올리면 문서 안에 문서가 들어가 화면이
깨집니다. `--artifact` 시험은 그 껍데기를 똑같이 씌운 상태로 확인합니다 —
조각을 그냥 열면 브라우저가 알아서 감싸 주기 때문에 시험이 통과해 버립니다.

폰트는 이쪽에서만 되살립니다. 배포용 단일 파일은 사내망·오프라인을 염두에
두고 폰트 CDN 을 걷어내지만, 아티팩트는 브라우저로 여는 웹페이지이고 호스트가
구글 폰트를 허용합니다(`<head>` 를 못 건드리므로 `@import` 로 넣습니다).

**아티팩트는 기본이 비공개입니다.** 팀에 보이려면 페이지의 공유 메뉴에서
직접 공개 범위를 여십시오. 대외 공유는 준법감시 확인 뒤에 하시기 바랍니다.

## 데이터 수집 (매일 자동)

세션은 사내 이그레스 정책 때문에 네이버·야후·KRX 어디에도 직접 붙지 못합니다
(CONNECT 403). GitHub 러너는 그 정책 밖이므로 수집은 전부 Actions 에서 합니다.

| 파일 | 역할 |
|------|------|
| `.github/workflows/etf-daily.yml` | **매일 16:30 KST / 06:40 KST** 수집 → 병합 → 단일 파일 재빌드 → 커밋 |
| `scripts/collect_etf_kr.mjs` | 국내 수집기 (네이버) |
| `scripts/collect_etf_global.mjs` | 해외 수집기 (야후) |
| `scripts/etf_universe.mjs` | 해외 ETF 유니버스 — **사람이 고치는 목록** |
| `scripts/etf_taxonomy.mjs` | 분류 사전 — **사람이 고치는 규칙** |
| `scripts/build_etf_data.mjs` | 병합 + 분류 태깅 → `data/etf.js` |
| `scripts/build_etf_artifact.mjs` | 아티팩트(링크 공유)용 조각 빌드 |
| `scripts/test_etf_offline.mjs` | 오프라인 동작 검증 (연결을 끊고 file:// 로 연다) |
| `scripts/check_etf_return_basis.mjs` | 수익률 두 계열이 라벨대로인지 검산 |
| `scripts/etf_lib.mjs` | 수집 공용 부품(동시성·재시도·단위 파싱) |
| `scripts/probe_etf_sources*.mjs` | 원천 탐색. 원천이 바뀌었을 때 다시 돌린다 |
| `tools/discovery/etf_probe*.md` | 위 탐색 결과 — **어느 원천이 살아 있는지의 기록** |

### 어느 원천을 왜 쓰는가

탐색으로 하나씩 찔러 보고 정했습니다(`tools/discovery/etf_probe.md`, `etf_probe2.md`).

| 시장 | 원천 | 편입종목 | 비고 |
|------|------|----------|------|
| **국내** | 네이버 `m.stock/api/stock/{code}/etfAnalysis` | ✅ 상위10 | 한 호출로 운용사·기초지수·총보수·순자산·**두 기준 수익률**·섹터·자금유입까지 |
| **미국** | 야후 `quoteSummary?modules=topHoldings,...` | ✅ 상위10 | 섹터 11칸·운용사·총보수·순자산 |
| **홍콩** | 같음 | ✅ 상위10 | 본토(A주) 익스포저도 여기서 |
| **일본** | 같음 | ✅ 상위10 | |
| **중국 본토(상해·심천)** | 야후 | ❌ | 시세만 옴. 화면에 "편입종목 미제공"으로 표시 |

**KRX 정보데이터시스템은 러너에서 열리지 않습니다.** 세션 쿠키를 받아 쥐고 불러도
통계 요청은 전부 `400 LOGOUT` 이고, OTP→CSV 정식 경로는 `403` 입니다. 기관 IP 를
막는 것으로 보입니다. 그래서 국내는 네이버로 갑니다. 한국 종목은 야후에도 편입종목이
없습니다(`069500.KS` → holdings 0개).

**중국 본토 상장은 편입종목 원천이 없습니다.** 같은 지수를 따르는 홍콩 상장
(2823·3188) 이나 미국 상장(ASHR·MCHI) 쪽에는 편입종목이 있으므로 그쪽을 보시면 됩니다.

### 수집이 실패해도 화면은 깨지지 않습니다

수집기는 **수집률이 기준(국내 70%)에 못 미치면 데이터 파일을 아예 쓰지 않고** 끝냅니다.
반쪽짜리 결과로 어제 데이터를 덮는 것이 가장 나쁩니다 — 화면은 멀쩡해 보이는데
내용이 비어 있기 때문입니다. 국내와 해외는 파일이 따로라 한쪽이 실패해도 다른 쪽은
그대로 남습니다. 둘 다 실패하면 워크플로가 빨간불로 끝나 며칠씩 조용히 낡는 것을 막습니다.

한 번도 수집되지 않은 상태에서는 내장 예시 데이터가 표시되며 화면에 **"예시 데이터"**
배지가 붙습니다.

## 분류(테마·지역·자산군)를 고치는 법

ETF 이름에는 그 상품이 무엇인지가 거의 다 들어 있습니다("TIGER 미국나스닥100커버드콜").
분류는 이 이름을 규칙으로 읽습니다. 규칙이므로 **반드시 틀리는 칸이 생깁니다.**

고치는 자리는 `scripts/etf_taxonomy.mjs` 한 곳입니다.

| 증상 | 고칠 곳 |
|------|---------|
| 새 테마가 생겼다 | `THEMES` 에 한 줄 추가 |
| 테마가 엉뚱하게 붙었다 | 그 테마의 `not` 에 단어 추가 |
| 특정 종목만 다르다 | `OVERRIDES` 에 종목코드로 못 박기 (규칙보다 우선) |
| 운용사 브랜드가 바뀌었다 | `KR_BRANDS` / `GLOBAL_FAMILIES` |

고친 뒤에는 **재수집이 필요 없습니다.** 태깅은 수집기가 아니라 빌드 단계에서 붙습니다.

```bash
node scripts/test_etf_taxonomy.mjs   # 회귀 시험 (네트워크 불필요)
node scripts/build_etf_data.mjs      # 다시 태깅
node scripts/build_etf_page.mjs      # 단일 파일 재빌드
```

회귀 시험에는 실제로 겪은 오분류가 사례로 박혀 있습니다. 이름 대조를 단순
부분문자열로 하면 이런 일이 납니다.

- `PLUS 고배당주` → 'US' 가 걸려 **미국 ETF** 로 분류
- `... Dividend Equity ETF` → 'EQUITY' 안의 'IT' 가 걸려 **IT 테마**가 붙음
- `TIGER 금융`·`은행` → '금' 한 글자가 걸려 **원자재**로 분류

그래서 영문·숫자 키워드는 앞뒤가 영문·숫자가 아닐 때만 인정하고, 공백을 지운
형태도 같이 봅니다("S&P 500" = "S&P500"). 공백만 지우면 이번에는 영문 이름의 단어
경계가 사라져 "SPDR Gold Shares" 의 GOLD 를 놓칩니다.

## 오프라인 동작

`etf-holdings-search.html` 은 **인터넷 없이 동작합니다.** CSS·자바스크립트·
ETF 데이터 1,348종목이 모두 한 파일 안에 들어 있고, 외부를 부르는 곳이
하나도 없습니다(폰트 CDN 도 빌드에서 걷어냅니다). 받는 사람은 파일을
더블클릭만 하면 됩니다 — 로컬 서버도 필요 없습니다.

```bash
node scripts/test_etf_offline.mjs
```

"외부 참조가 없으니 될 것이다" 는 확인이 아니므로, 이 시험은 실제로 끊어
놓고 엽니다 — `file://` 로 열고(로컬 서버조차 없는 상태), http/https 요청을
전부 막은 뒤, 하나라도 밖으로 나가면 실패로 칩니다. 그 상태에서 목록·검색·
편입종목·랭킹·역조회가 실제로 도는지 봅니다.

**단, 데이터는 파일을 만든 시점에 멈춰 있습니다.** 오프라인에서는 갱신되지
않으므로, 최신 수치가 필요하면 새로 빌드한 파일을 다시 받아야 합니다.
화면 상단의 "기준" 날짜가 그 파일의 데이터 시점입니다.

폰트는 시스템 글꼴로 떨어집니다(맑은 고딕·Apple SD 고딕 등). 사내 PC 에
Spoqa Han Sans Neo 가 깔려 있으면 그것을 씁니다.

**아티팩트 링크는 인터넷이 있어야 합니다.** claude.ai 에서 받아오는
웹페이지이기 때문입니다. 오프라인 환경에는 단일 파일을 쓰십시오.

브라우저로 열어 눌러 보는 시험을 둡니다.

```bash
node scripts/test_etf_page.mjs            # etf.html

```

목록·필터·정렬·상세·비교·역조회·랭킹·영문 전환·반응형 가로넘침·콘솔 오류까지 봅니다.
수집 워크플로도 커밋 전에 이 시험을 돌려, 깨진 화면이 배포되지 않게 합니다.

## ETF 데이터 스키마

`data/etf.js` 는 `window.ETF_DATA` 하나를 정의합니다.

```js
window.ETF_DATA = {
  updatedAt: '2026-08-28T08:00:00Z',
  source: 'live',                     // 'live' | 'sample'
  sources: { kr: {...}, global: {...} },
  labels: { region:{}, assetClass:{}, flag:{}, theme:{} },  // 화면 셀렉트 박스의 원본
  themeOrder: ['semiconductor', 'ai', ...],
  etfs: [{
    id: 'KR:069500',
    code: '069500', market: 'KR',     // KR | US | HK | JP | SS | SZ
    name: 'KODEX 200', nameKo: null,
    manager: '삼성자산운용',
    indexName: '코스피 200',           // 원천 표기 그대로
    index: 'KOSPI 200',               // 정규화한 이름 (필터가 쓰는 값)
    region: 'korea',                  // 투자 지역 (상장지가 아니다)
    assetClass: 'equity',
    themes: ['semiconductor'],        // 여러 개 붙을 수 있다
    flags: ['covered', 'hedged'],     // 레버리지·인버스·커버드콜·환헤지·액티브 등

    price: 109000, changeRate: 1.32,
    aum: 25579700000000,              // 순자산총액 (국내는 원, 해외는 currency 통화)
    ter: 0.15,                        // 총보수 %
    premium: -0.27,                   // 괴리율 %
    trackingError: 0.39,
    dividendYield: 0.78,

    // 기간수익률 — 두 기준을 모두 들고 간다. 화면에서 토글한다.
    ret: {
      price: { D1:1.32, W1:0.87, M1:1.51, M3:-16.27, M6:16.7,
               YTD:80.57, Y1:155.48, Y3:51.64, Y5:23.98, Y10:17.93 },
      nav:   { ... },
    },

    sectors:   { IT: 64.55, INDUSTRIALS: 13.92, ... },   // 국내외 키를 하나로 맞췄다
    countries: { KR: 98.93, ... },                       // 국내만
    flow:      { d1:.., m1:.., m3:.., ytd:.., y1:.. },   // 자금유입(원). 국내만

    // 이 도구의 본체
    holdings: [{ code:'005930', name:'삼성전자', weight:33.66, shares:6924 }, ...],
    top10Weight: 72.17,               // 상위10 합계 = 집중도
    holdingCount: 10,
  }],
};
```

### 수익률 계열 정책

| 계열 | 뜻 | 범위 |
|---|---|---|
| `ret.price` | **시장가 등락률 · 분배금 제외** | 국내·해외 공통 · **기본 기준** |
| `ret.tr` | 총수익률 · 분배금 재투자 | **해외만** |
| `ret.nav` | NAV(기준가) 등락률 · 분배금 제외 | 국내만 |

기본이 `price` 인 것은 **두 시장에 모두 있는 유일한 계열**이기 때문입니다.
3년·5년은 연율입니다.

#### 업계 표준은 총수익률인데 왜 기본이 아닌가

표준은 분배금을 재투자한 총수익률(Total Return)이 맞습니다. 그런데 **국내
총수익률을 줄 원천을 찾지 못했습니다.** 확인한 것을 그대로 적습니다.

- 네이버는 주지 않습니다. 시장가·NAV 어느 쪽에도 분배금이 반영되지 않습니다
  (분배율 4.6% 표본에서 두 계열의 차이 중앙값 0.02%p — 차이는 괴리율뿐).
- 야후 일봉으로 직접 만들어 봤습니다. 심볼은 잘 잡히고(1,158/1,163), 배당
  이벤트도 943종목에서 나왔습니다. 그런데 검산은 여전히 "분배금 미반영"
  이었습니다(분배율 4.59% 표본 128종목, 차이 −0.53%p, 비율 −0.12). 야후의
  국내 분배금 자료가 **정작 분배율이 큰 상품에서 부족**합니다. 같은 계산으로
  미국은 비율 0.94 가 나오므로 계산기 문제가 아닙니다.
- KRX 는 러너에서 열리지 않아(400 LOGOUT / 403) 확인하지 못했습니다.

**틀린 총수익률을 "표준 기준" 이라는 이름으로 내거는 것이 빈칸보다 나쁩니다.**
그래서 국내에는 싣지 않았습니다. 화면은 시장가를 기본으로 하고, 총수익률을
고르면 국내가 왜 비는지 알려 줍니다.

#### 그래서 생기는 한계 — 고분배 상품

시장가 기준에는 분배금이 빠져 있어, 커버드콜·고배당 상품이 실제 성과보다
낮게 보입니다.

```
PLUS 고배당주위클리커버드콜   분배율 23.3%   시장가 1년 −24.08%   분배금 포함 시 약 −0.7%
```

국내에만 분배율 5% 이상이 72종목입니다. 화면은 이들 상세에 분배율과 경고를
함께 띄웁니다. **순위표에서 이들의 자리는 실제보다 낮습니다.**

제대로 채우려면 운용사 공시·KRX·에프앤가이드처럼 분배금 이력을 주는 원천이
필요합니다. 이것이 이 도구에 남은 가장 큰 미완입니다.

#### 검산

```bash
node scripts/check_etf_return_basis.mjs
```

분배율을 지렛대로 `ret.tr` 이 정말 총수익률인지 판정합니다 — 분배금이
반영됐다면 `tr − price` 가 분배율만큼 나와야 합니다. **"총수익률이라고 실렸는데
총수익률이 아닌 것"을 막는 자리**입니다. 총수익률이 아예 없는 시장은 판정
대상이 아닙니다(화면이 그 기준을 내걸지 않으므로 거짓말이 나가지 않습니다).
수집 워크플로가 이 검산에서 멈추면 데이터를 커밋하지 않습니다.

## 유의사항 (ETF 페이지)

**편입종목은 상위 10개까지입니다.** 나머지 비중은 이 화면에 없습니다. 비중은 직전
영업일 기준 납입자산 구성(PDF)이며 실시간 보유 내역이 아닙니다. 겹침 비율도 상위
10종목만으로 계산하므로 **실제 포트폴리오 중복의 하한**입니다.

본 화면은 정보 제공 목적의 참고 자료이며 투자 권유가 아닙니다. 실제 상품 내용은
각 상품의 투자설명서와 운용사 공시가 우선합니다.

> **사내 활용 시 확인 필요** — 실제 판매 중인 상품 정보를 고객에게 노출하는 화면은
> 금융투자협회 광고 심의 및 사내 컴플라이언스 검토 대상일 수 있습니다.
> 대외 배포 전에 준법감시 부서 확인을 권장합니다.
