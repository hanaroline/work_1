# 종목 통합 리포트 대시보드

주식 종목명 또는 종목코드를 입력하면 해당 종목의 **시세 · 증권사 투자의견/레포트 · 시황(뉴스) · 재무제표**를
**한 장의 리포트**처럼 보여주는 단일 HTML 대시보드입니다. 빌드 도구 없이 `index.html` 하나로 동작합니다.

## 화면 구성

| 섹션 | 내용 |
|------|------|
| **종목 요약** | 종목명·코드·시장(KOSPI/KOSDAQ), 현재가·등락, 시가총액, PER/PBR/EPS, **조회 기준 시각** |
| **시세 · 기술적지표** | 가격 차트(1M/3M/6M/1Y) + **이동평균 MA5/20/60** + **RSI(14)** + 거래량, 52주 최고/최저, **지수 대비 초과수익률** |
| **외국인 · 기관 수급** | 일별 순매수 대금(외국인/기관) 차트 + 외국인 지분율 추이, 5일/20일 누적 순매수 |
| **증권사 투자의견** | 목표주가 밴드(최저·평균·최고 vs 현재가), 상승여력, 매수/중립/매도 의견분포, 최근 레포트 목록 |
| **시황 · 뉴스** | 종목 관련 최신 뉴스 헤드라인 |
| **재무제표** | 연간 손익(매출·영업이익·순이익) 차트 + 표, 재무상태(자산·부채·자본), ROE·부채비율 |

### 주요 기능
- **증권사 리포트 매일 자동 요약(📰)** — 아래 「증권사 리포트 다이제스트」 참고
- **관심종목 즐겨찾기(★)** — 브라우저에 저장(localStorage), 상단 칩에서 원클릭 조회
- **종목 비교(⇄)** — 최대 4종목을 기준=100 리베이스 차트 + 지표 표로 비교
- **지수 대비 보기** — 가격/지수대비(KOSPI·KOSDAQ 리베이스) 토글, 초과수익률 표시
- **PDF 저장/출력(🖨)** — 화면 그대로 A4 리포트로 저장·인쇄(`@media print`)
- 라이트/다크 테마 전환(◐), 종목명 자동완성, 6자리 코드 직접 입력

## 실행 방법

### 방법 1) 단일 파일 (가장 간단)

`standalone.html` **한 파일**에 CSS·JS·차트 라이브러리·데이터가 모두 인라인되어 있습니다.
별도 서버 없이 파일을 브라우저로 열기만 하면(더블클릭) 바로 동작합니다.

```
standalone.html  ← 이 파일만 열면 됨
```

### 방법 2) 분리 파일 + 로컬 서버 (개발용)

`index.html`은 `data/*.js`, `vendor/*.js`를 외부에서 로드하므로 로컬 서버로 열어야 합니다
(파일 프로토콜로 열면 브라우저 보안정책에 막힐 수 있음).

```bash
# 저장소 루트에서
python3 -m http.server 8000
# 브라우저에서 http://localhost:8000 접속
```

> `standalone.html`은 `index.html` + `data/*.js` + `vendor/chart.umd.js`를 합쳐 생성한 산출물입니다.
> 소스를 수정할 때는 `index.html` / `data/*.js`를 고친 뒤 다시 합치면 됩니다.

## 증권사 리포트 다이제스트 (매일 자동 요약)

`docs/reports/index.html` — **그날 나온 증권사 리포트를 모아 요약해 보여 주는 화면**입니다.
대시보드 상단의 **📰 리포트 요약** 단추로 들어갑니다.

```
GitHub Actions(증권사 리포트 수집)  ─매일 08:40 · 17:10 KST→  data/reports/latest.json
                                                                    │
                                                    docs/reports/index.html 이 읽어 그림
```

| 무엇 | 어디서 |
|---|---|
| 리포트 목록 | **네이버 리서치** 여섯 판(종목분석 · 산업분석 · 시황정보 · 투자정보 · 경제분석 · 채권분석) + **미래에셋증권 리서치**(리서치 리포트 · 글로벌 리서치) + **하나증권 리서치** |
| 해외 리포트 | 미래에셋 **글로벌 리서치** 판 전체, 그리고 티커 꼬리표가 붙은 줄(`NVDA.US` · `688017.CH` · `00981 HK`) — 카드에 **해외** 딱지가 붙습니다 |
| 서두 총평 | 그날 판·한 주 판 머리의 **「한눈에」** — 건수 · 갈래 · 주제 · 목표주가 · 겹친 종목을 문장으로 엮은 것 |
| 논점 브리핑 | 총평 아래 **주제별 실제 리포트 문장** — 어느 증권사가 무엇을 말했는지, 눌러서 원문으로 갑니다 |
| 요약 | **리포트 본문에서 원문 문장 여섯을 골라** 이은 추출 요약 (`scripts/fetch_reports.py`) — 판단·실적·전망·위험에 몫을 나눠 뽑습니다 |
| 핵심 수치 | 본문에 **적혀 있는** 상승여력·목표배수·밸류에이션을 그대로 옮긴 것 (셈은 하지 않습니다) |
| 주간 인기 | 지난 이레치를 합쳐 **조회수 순 18장** + 주간 셈(건수·증권사·목표주가 상하향·많이 다뤄진 종목) |
| 목표주가 · 투자의견 | 본문에서 정규식으로 추출 (「목표주가 37만원」 같은 만·억 단위까지 환산) |
| 애널리스트 실명 | 미래에셋 리서치 목록 (네이버에는 없는 값) |
| 세부 리포트 | 카드를 누르면 **네이버 상세**, 「원문 PDF ↓」는 **증권사 PDF**, 「미래에셋 원문 ↓」은 **하우스 원문** |

### 출처를 셋으로 두는 까닭

같은 리포트가 두 곳에 다 있으면 **한 줄로 합칩니다** — 네이버 쪽에는 본문 요약이,
하우스 쪽에는 애널리스트 실명과 원문 PDF가 있어 둘 다 아깝기 때문입니다.
미래에셋·하나에만 있는 것(해외 종목 리포트 등)은 새 줄로 섭니다.

**증권사 자체 게시판은 열한 곳을 찔러 둘만 열렸습니다** — 미래에셋과 하나증권입니다
(삼성 · NH · 한국투자 · 유안타 · 메리츠 404, KB 500, 대신 403, 키움은 빈 쪽).
하나 쪽은 표가 아니라 `<ul><li>` 얼개라 앞선 탐색에서 빈 쪽으로 보였습니다.

네이버 목록은 **모바일 JSON API**(`m.stock.naver.com/api/research/*`)로 받습니다.
HTML 표를 긁는 것보다 튼튼하고 제목이 잘려 오지 않습니다. API가 막히면 예전
HTML 표 파서로 그대로 내려앉습니다.

> 붙여 보고 접은 곳 — **한경 컨센서스**는 http·다른 호스트·다른 얼개까지 넷 다 HTTP 500,
> **한국IR협의회**는 세 길 모두 시간 초과, **다음 금융**은 500/404,
> **KRX 기업분석보고서**는 404 였습니다. 네이버에는 해외 리서치 API 길이 없습니다
> (`global` · `overseas` · `world` 모두 404).
> `scripts/probe_reports.py` 로 러너에서 확인했고, 살아나면 같은 자리에 붙입니다.

> **외국계 IB(골드만 · 모건스탠리 · JP모건 등)의 한국물 리포트는 넣지 못했습니다.**
> 기관 전용이라 공개 목록이 없습니다. 지금 「해외」로 잡히는 것은 **국내 증권사가
> 해외 기업·업종을 다룬 리포트**입니다 — 다른 것이니 섞어 읽지 마십시오.

화면에서 할 수 있는 것 — **조회**(종목명·종목코드·증권사·애널리스트·제목, 자동완성 딸림),
판별·증권사별 걸러 보기, **인기순(기본)**/최신순/목표주가 변경순 정렬, 「본문 발췌」 펼쳐 보기,
종목명 옆 **종목 대시보드**로 이동(`index.html?code=005930`), 지난 날짜 판 다시 보기.

종목으로 조회하면 그 종목이 **한 줄로 섭니다** — 몇 곳이 다뤘는지, 목표주가 평균·최저·최고,
투자의견 분포. 조회하는 동안 「오늘의 주요 리포트」는 접혀 결과가 화면 위로 올라옵니다.

**요약은 새로 쓴 문장이 아니라 원문 문장을 고른 것입니다.** 러너에는 모델이 없어
문장을 짓지 않습니다 — 지어낸 요약이 리포트 자리에 앉는 것보다 원문 여섯 줄이
안전하기 때문입니다. **PDF 로만 보는 사람은 「세부 리포트」를 누를 수 없으므로**
카드만 읽고도 요지가 잡히도록 여섯 줄까지 싣고, 첫 줄(대개 판단)은 굵게 세웁니다.
길이만 늘리면 같은 말이 되풀이되므로 갈래별로 몫을 나누고, 제목과 겹치는 문장과
서로 닮은 문장은 버립니다. 목표주가·투자의견도 기계가 뽑은 값이라 원문과 다를 수 있으니,
판단은 반드시 세부 리포트 원문으로 하십시오.

### 서두에 「무슨 이야기인지」를 싣는 까닭

「한눈에」는 처음에 **몇 건인지만** 말했습니다 — 74건, 시황이 21건, 주제는
금리·반도체. 정작 알고 싶은 것은 무슨 이야기인가입니다.

그래서 총평 아래에 **논점 브리핑**을 답니다. 주제마다 그 주제를 다룬 리포트를
모아, 가장 많이 읽힌 것부터 판단 문장을 **증권사·종목과 함께 그대로** 옮깁니다.
지어낸 문장이 아니라 리포트가 한 말이고, 눌러서 원문으로 갑니다. 목표주가를
움직인 건에는 그 까닭 한 줄을, 여러 곳이 함께 본 종목에는 증권사별 한 줄을
붙여 시각차가 드러나게 합니다.

고르는 데 걸린 것 셋을 막아 두었습니다.

- **시황 리포트 한 건이 여러 주제에 걸립니다.** 금리·반도체·금융에 같은 줄이
  세 번 실렸습니다 — 주제를 넘나들며 겹치지 않게 합니다.
- **시세 나열이 뽑힙니다.** 「KOSPI 6,912pt (+1.53%), KOSDAQ 837pt」 같은 줄은
  주제 이야기가 아닙니다 — 글자가 절반은 되어야 읽을 거리로 칩니다.
- **목표주가 줄이 두 번 실렸습니다.** 그 줄이 그날 가장 중요한 대목이니
  목표주가 쪽이 먼저 집고, 주제 쪽은 다른 목소리로 채웁니다.

### 주간 인기 리포트

그날 판만 보면 그 주의 화두를 알 수 없습니다 — **오늘 올라온 리포트는 아직 아무도
읽지 않았기 때문**입니다. 조회수는 날이 갈수록 쌓이므로 인기 목록은 자연히 며칠 전
것으로 채워지고, 그게 맞습니다.

한 판에 담기는 것은 네이버 목록의 앞쪽 몇 쪽뿐이라 엿새 전 리포트는 이미 밀려나
없습니다. 그래서 `data/reports/<날짜>.json` 으로 남겨 둔 **지난 판들을 합쳐** 이레를
채웁니다(같은 리포트는 조회수가 큰 쪽과 요약이 있는 쪽을 남깁니다).

주간 상위는 **본문을 먼저 엽니다** — 갈래마다 몫을 주어 도는 탓에 경제분석·시황정보의
주간 상위가 번번이 본문 열기 상한 밖으로 밀렸습니다(열여덟 장 중 일곱 장).

### 재검산 — 실린 숫자와 문장을 원자료에 대고 맞춘다

```bash
python3 scripts/verify_reports.py data/reports/latest.json
```

수집 워크플로가 판마다 돌려 `data/reports/verify.txt` 에 남깁니다. 어긋난 것이
있으면 나가는 값이 1 입니다 — **산출물을 내기 전에 여기부터 봅니다.**

무엇을 보는가.

| 갈래 | 보는 것 |
|---|---|
| 가. 수집 | 빠진 칸 · 주소 중복 · 날짜꼴 · 수집일보다 뒤인 날짜 · 조회수 |
| 나. 셈 | 전체·그날 건수, 갈래·원천·증권사별 건수, 주제 건수, 목표주가 상하향, 겹친 종목 — **실린 값과 다시 센 값이 같은가**. 머리 요약 *문장에 박힌 숫자*까지 본다 |
| 다. 인용 | 요약이 **본문 문장만으로 되짚어지는가**, 첫 줄이 요약 안에 있는가, 수치 조각과 목표주가가 원문에 적힌 그대로인가, 브리핑 인용이 그 리포트에서 왔는가 |
| 라. 오염 | 첨부파일명·컴플라이언스 머리글·사이트 길잡이줄·연락처·마크업 부스러기 |
| 마. 출처 | 모든 주소가 알려진 원문 서버인가, 「해외」 딱지에 근거가 있는가 |
| 바. 주간 | 스냅숏을 다시 합쳐 센 건수, 기간 밖 유입, 조회수 내림차순, 주간 브리핑 인용 |

되짚기(다)가 이 검산의 핵심입니다. 요약을 문장 부호로 잘라 본문에서 찾으면 안
됩니다 — 요약은 본문의 **떨어진 자리**에서 고른 문장을 이어 붙인 것이라, 마침표
없이 끝나는 소제목 뒤에 다른 대목이 붙으면 한 덩이로 보입니다. 그래서 본문을
수집기와 **똑같은 규칙**으로 잘라 문장 꾸러미를 만들고, 요약을 그 꾸러미만으로
쌓아 올려 봅니다. 한 글자라도 남으면 그 자리에서 걸립니다.

이 검산이 증명하는 것과 못 하는 것을 갈라 둡니다. **증명합니다** — 인쇄되는 셈이
실린 목록과 맞고, 인쇄되는 문장·수치가 리포트에 글자 그대로 있고, 모든 항목에
원문 주소가 달려 있음. **증명하지 않습니다** — 증권사가 한 말이 맞는지. 그건 이
도구의 일이 아니며, 카드마다 원문 주소를 다는 까닭입니다.

첫 판에서 둘이 걸렸습니다.

- **하나증권 카드 마흔여덟 장이 모두 같은 곳을 가리켰습니다.** 목록 쪽에 리포트마다
  열리는 주소가 없어 걸개 주소를 넣어 둔 탓입니다. 내려받기 주소가 곧 그 리포트이니
  그것을 원문 자리로 삼습니다.
- **한 주 셈이 한 건 적었습니다.** 무더기를 `nid` 하나로만 갈랐는데 원천마다 번호를
  따로 매깁니다 — 네이버의 95903 과 다른 곳의 95903 이 한 칸을 다투었습니다.
  원천을 붙여 가릅니다(`pool_key`).

늘 남는 참고 두 가지. **조회수는 네이버에만 있습니다** — 미래에셋·하나 제 목록에는
없는 값이라 그 줄들은 인기순에서 맨 뒤로 밀립니다. 그리고 본문은 앞 1200자만
보관하므로 그 뒤에서 온 문장은 **대조하지 못한 것으로 따로 셉니다**(했다고 세지
않습니다).

### 건네줄 파일 만들기 — 한 파일 HTML + PDF 셋

```bash
bash scripts/make_reports_outputs.sh            # 최신 판
bash scripts/make_reports_outputs.sh 2026-08-15 # 그날 판
```

`out/` 아래에 넷이 생깁니다(`.gitignore` 에 있습니다).

| 파일 | 무엇 |
|---|---|
| `미래에셋_증권사리포트_YYYYMMDD.html` | **데이터까지 넣은 한 파일** — 서버 없이 더블클릭하면 열리고 조회·걸러 보기가 다 됩니다 |
| `…_요약.pdf` | 머리 요약 · 주요 리포트 12장 · 목표주가를 움직인 리포트 (2쪽 안팎) |
| `…_주간인기.pdf` | 주간 셈 · 많이 다뤄진 종목 · **조회수 순 18장** (2쪽 안팎) |
| `…_전체.pdf` | 위의 것 + 주간 + 전체 목록 (40쪽 안팎) — **차례**와 **갈래별 묶음**이 들어갑니다 |

PDF 에서도 제목과 「원문 PDF」는 눌러서 원문으로 갑니다. 화면의 조회창·걸개·
단추는 인쇄에서 빠지고, 카드는 쪽 경계에서 잘리지 않으며, 다크 테마여도
종이는 늘 밝은 바탕으로 나옵니다.

> 인쇄에서는 카드를 격자가 아니라 **흐르는 단**으로 놓습니다. 격자는 쪽 경계에서
> 제대로 쪼개지지 않아, 요약을 여섯 줄로 늘리자 마지막 줄의 카드가 꼬리말 위로
> 넘쳐 겹쳤습니다.

## 데이터 소스

무료 공개 소스를 우선 사용하고, 실패 시 **섹션별로 샘플 데이터로 폴백**합니다.
각 섹션에는 `실시간` / `샘플` 배지가 표시됩니다.

| 섹션 | 실시간 소스 | 폴백 |
|------|-------------|------|
| 시세/현재가/차트 | **네이버 모바일 `m.stock.naver.com/api`** 우선, Yahoo `chart` 보조 | 내장 샘플 |
| 외국인/기관 수급 | 네이버 `api/stock/{code}/trend` | 내장 샘플 |
| 지수(KOSPI/KOSDAQ) | Yahoo `chart/^KS11 · ^KQ11` | 내장 샘플 |
| 재무제표 | Yahoo `quoteSummary` (손익/재무상태) | 내장 샘플 |
| 투자의견/목표주가 | Yahoo `quoteSummary` (financialData, recommendationTrend) | 내장 샘플 |
| 시황/뉴스 | Google News RSS(`news.google.com/rss/search`) | 내장 샘플 |
| 증권사 레포트 목록 | 네이버 금융 리서치 (러너가 매일 수집 → `data/reports/`) | 예시 데이터 + 네이버 리서치 딥링크 |

모든 소스는 **병렬 호출 + 4초 타임아웃**으로 요청하며, 실패한 섹션만 개별적으로 샘플로 대체합니다(전체 화면은 항상 정상 렌더). 요약 헤더에 조회 기준 시각과 출처가 표시됩니다.

> 증권사 원문 리포트(PDF)는 공개 API가 없어, 목록은 예시로 채우고
> [네이버 금융 리서치](https://finance.naver.com/research/)로 연결되는 딥링크를 제공합니다.

### 브라우저 CORS 안내

순수 브라우저(단일 HTML)에서 위 API를 직접 호출하면 **CORS로 차단**되는 경우가 많습니다.
이를 위해 `index.html`의 `PROXIES` 배열에 **CORS 프록시 폴백**이 설정되어 있습니다.

```js
var PROXIES = [
  function (u) { return u; },                                              // 1) 직접 호출
  function (u) { return "https://corsproxy.io/?url=" + encodeURIComponent(u); },      // 2) 프록시
  function (u) { return "https://api.allorigins.win/raw?url=" + encodeURIComponent(u); } // 3) 프록시
];
```

- 사내망/폐쇄망 등으로 외부 접근이 막히면 세 경로 모두 실패하고 **샘플 데이터**로 표시됩니다(화면은 항상 정상 렌더).
- 안정적인 실시간 연동이 필요하면, 자체 백엔드 프록시(예: `/api/proxy?url=...`)를 만들어 `PROXIES`에 추가하는 것을 권장합니다.
- 미래에셋 **사내 API**가 있다면 `fetchYahoo` / `fetchNews`를 사내 엔드포인트 호출로 교체하면 됩니다.

```
index.html                     # 대시보드 (레이아웃 + CSS + 앱 로직)

docs/reports/index.html        # 증권사 리포트 다이제스트 화면
scripts/fetch_reports.py       # 리포트 수집·요약기 (러너에서 매일 실행)

scripts/make_reports_standalone.py  # 데이터까지 넣은 한 파일 실행본 만들기

scripts/reports_to_pdf.mjs          # A4 PDF 렌더러 (요약본·주간본·전체본)
scripts/request_reports_refresh.sh  # 수집을 지금 돌려 달라고 요청
data/reports/latest.json       # 가장 최근 판 (화면이 읽는 파일)
data/reports/YYYY-MM-DD.json   # 날짜별 보관
.github/workflows/reports.yml  # 매일 자동 수집
```
