# 한국 라디오 & 열린 라디오 웹 플레이어 — 구축 계획서

작성 2026-09-12 · 대상 저장소 `hanaroline/work_1` · 산출물 `radio.html` · 예상 공수 약 3일

지상파 라디오는 **공식 플레이어로 정확히 연결**하고, 공개 스트림(열린 라디오)은
**사이트 안에서 바로 재생**하는 두 갈래 설계. 저장소 관례대로 단일 HTML 한 장 +
GitHub Actions 데이터 수집으로 만든다.

> 전제: "열린 라디오"를 **공개 인터넷 스트림(오픈 스트림)** 으로 읽었다.
> KBS 프로그램 〈열린 라디오〉를 뜻한 것이라면 화면 구성이 달라진다 — 12번 참고.

## 1. 먼저 짚고 갈 제약

"방송국 목록 띄우고 재생"으로 끝나지 않는 이유. 여기서 설계가 갈린다.

| | 제약 | 내용 |
|---|---|---|
| **차단 확정** | 지상파 스트림은 가져올 수 없다 | KBS·MBC·SBS·CBS·EBS·TBS의 실시간 주소는 공개 API가 없고 서명 토큰·Referer 검사·CORS 차단·국내 IP 제한이 걸려 있다. 역추출해 직접 재생시키는 건 약관 위반이며, 토큰이 바뀌는 순간 조용히 멈춘다. |
| **런타임 제약** | https 페이지는 http 스트림을 못 튼다 | GitHub Pages는 https라서 `http://` 스트림은 혼합 콘텐츠로 차단된다. 공개 스트림 상당수가 아직 http다. 목록 단계에서 https만 남긴다. |
| **작업 환경** | 이 세션은 외부 API에 못 붙는다 | 사내 이그레스 정책으로 `radio-browser.info` 접속이 403으로 막힌다(확인함). 저장소가 이미 쓰는 방식대로 Actions 러너가 받아 `data/`에 커밋하고, 화면은 커밋된 JSON만 읽는다. |

## 2. 설계 결론 — 2트랙

성격이 다른 두 종류를 한 화면에서 다르게 다룬다. 섞지 않는 게 핵심.

### Track A · 지상파 · 보도채널 라디오
- **구성** KBS 5개 채널, MBC 2개, SBS 2개, CBS 2개, TBS 2개, EBS·YTN·국악방송 등
- **우리 쪽** 채널 카드 · 주파수 · 편성 시간표 · 프로그램 이름 · 로고
- **재생** 카드를 누르면 **공식 온에어 페이지를 새 창으로 연다**(딥링크)
- **이유** 권리 문제 없음, 토큰 만료·차단으로 깨지지 않음, 방송사 통계에도 정상 집계
- 사이트 내 재생은 하지 않는다 — 의도적 선택

### Track B · 열린 라디오 · 공개 스트림
- **구성** 방송국이 스스로 공개한 인터넷 스트림 — 커뮤니티·대학·종교·장르 전문 채널, 해외 한인방송
- **출처** Radio Browser 공개 DB(무료·키 불필요·CORS 허용) + 직접 큐레이션
- **재생** 페이지 안에서 바로 재생 — 하단 고정 플레이어, 탭을 옮겨도 안 끊김
- **탐색** 검색 · 장르 · 지역 · 즐겨찾기 · 최근 청취

## 3. 구조

기존 `market-data.yml` · `kr100-data.yml`과 같은 패턴. 새로 배울 것이 없다.

```
  GitHub Actions (주 1회 · 수동 실행 가능)
  .github/workflows/radio-data.yml
        │
        │  1. Radio Browser 에서 KR·한국어 스테이션 수집
        │  2. 헬스체크 — 응답코드 · Content-Type · https 여부 · 비트레이트
        │  3. 죽은 주소 제거, 중복 병합, 큐레이션 목록과 합침
        ▼
  data/radio/stations.json      ← 저장소에 커밋 (변경 있을 때만)
  data/radio/curated.json       ← 사람이 관리하는 시드 · 지상파 딥링크
        │
        ▼
  radio.html  (단일 파일 · 빌드 도구 없음 · 기존 팔레트/다크모드 재사용)
        │
        ├─ Track A  카드 → 공식 온에어 새 창
        └─ Track B  카드 → <audio> / hls.js 로 즉시 재생
        │
        ▼
  localStorage : 즐겨찾기 · 최근 청취 · 볼륨 · 테마
```

## 4. 화면

라디오는 "틀어 놓는" 도구다. 화면이 아니라 소리가 주인공이라는 전제로 만든다.

- **상단** 검색창, 탭(지상파 / 열린 라디오 / 즐겨찾기 / 최근), 라이트·다크 토글
- **본문** 카드 그리드 — 채널명, 운영사, 주파수 또는 장르, 비트레이트, 상태 배지(재생 가능 / 점검 중)
- **하단 고정 플레이어** 현재 채널, 재생·정지, 볼륨, 버퍼링 표시, 슬립 타이머(15/30/60분), 오류 시 다음 후보 주소 자동 시도
- **Media Session API** 잠금화면·이어폰 버튼·키보드 미디어 키 조작. 모바일에서 이게 없으면 라디오 앱 구실을 못 한다
- **접근성** 키보드만으로 전 기능, 재생 상태를 `aria-live`로 알림, 400px 폭에서 1열
- **편성표** 지상파 카드에 "지금 방송 중" 표시 (Phase 4, 공개 편성 정보 범위 내)

## 5. 데이터 모델

한 채널에 주소 후보를 여러 개 둔다. 하나 죽어도 소리가 끊기지 않게.

```json
{
  "id": "kbs-coolfm",
  "name": "KBS 쿨FM",
  "org": "KBS",
  "track": "terrestrial",
  "freq": { "seoul": 89.1, "busan": 92.3 },
  "genre": ["음악", "가요"],
  "lang": "ko",
  "homepage": "https://program.kbs.co.kr/...",
  "officialPlayer": "https://onair.kbs.co.kr/...",
  "streams": [
    { "url": "https://...m3u8", "format": "hls", "codec": "aac", "bitrate": 128 },
    { "url": "https://...mp3",  "format": "mp3", "codec": "mp3", "bitrate": 96  }
  ],
  "health": { "checked": "2026-09-12T01:00Z", "ok": true, "ms": 412 },
  "source": "curated"
}
```

`track: "terrestrial"`은 `officialPlayer`만, `track: "open"`은 `streams`만 채운다.

## 6. 재생 엔진

브라우저마다 되는 포맷이 다르다. 분기와 폴백을 처음부터 넣는다.

- **포맷 분기** `.m3u8`이면 HLS — Safari·iOS는 네이티브, 나머지는 cdnjs의 `hls.js`. 그 외(mp3/aac)는 `<audio src>` 그대로
- **CORS 주의** `<audio>` 직접 재생은 CORS와 무관하지만 `hls.js`는 CORS 헤더가 필요하다. 실패하면 같은 채널의 mp3 후보로 내려간다
- **타임아웃** 12초 안에 소리가 안 나오면 다음 후보. 후보를 다 쓰면 "점검 중" 배지를 달고 다음 수집 때 정리 대상으로 표시
- **자동재생 정책** 사용자 조작 없는 `play()`는 브라우저가 막는다. 첫 재생은 반드시 클릭·키 입력 뒤에
- **녹음 기능 없음** 저작권 문제를 만들지 않기 위해 의도적으로 빼는 기능

## 9. 리스크

| 위험 | 발생 양상 | 대응 |
|---|---|---|
| 주소가 조용히 죽는다 | 공개 스트림은 예고 없이 바뀌거나 사라진다. 목록의 10~20%는 늘 죽어 있다고 봐야 한다 | 주 1회 헬스체크로 자동 제거, 채널별 주소 후보 복수 보유, 실패 시 상태 표시 |
| 혼합 콘텐츠 차단 | http 스트림이 https 페이지에서 무음으로 실패. 사용자에겐 "그냥 안 됨"으로 보인다 | 수집 단계에서 https만 통과 |
| 지상파 차단 | 스트림을 직접 붙였다면 토큰 만료·Referer 검사로 언젠가 반드시 멈춘다 | 애초에 붙이지 않는다(Track A 딥링크). 구조적으로 발생하지 않음 |
| 모바일 백그라운드 중단 | 화면을 끄거나 앱을 전환하면 재생이 끊긴다 | Media Session 메타데이터 등록, 재개 버튼 노출. 웹의 한계는 솔직히 안내 |
| iOS HLS 차이 | iOS Safari는 hls.js를 못 쓰고 네이티브 재생만 된다 | 플랫폼 분기 + mp3 폴백, 실기기 확인을 Phase 2 완료 조건에 포함 |
| 권리자 이의 | 공개 스트림이라도 재배포를 원치 않는 곳이 있을 수 있다 | 제거 경로를 페이지 하단에 명시, 요청 시 당일 제거 |

## 10. 준법 점검

기능을 넣기 전에 통과해야 하는 선. 타협하지 않는다.

- [x] **지상파 스트림 직접 재송신 금지** — 공식 플레이어 딥링크만 사용
- [x] **토큰·서명 우회 금지** — 보호된 주소를 역추출하거나 재현하지 않는다
- [x] **녹음·다시듣기 저장 기능 없음** — 실시간 청취만 제공
- [x] **광고 삽입·제거 없음** — 원 방송의 흐름에 손대지 않는다
- [ ] **공개 스트림만 수록** — 방송국이 스스로 공개한 주소인지 Phase 0에서 확인
- [ ] **출처와 이의 제기 경로 표기** — 데이터 출처(Radio Browser), 제거 요청 연락처를 하단에 명시
- [ ] **수집 예절** — 워크플로에서 User-Agent 표기, 주 1회로 호출 억제, 로고는 직접 호스팅하지 않고 이니셜 배지 사용

## 11. 완료 기준

- [ ] 첫 화면에서 **두 번의 조작 안에 소리가 난다** (채널 선택 → 재생)
- [ ] 열린 라디오 목록의 **95% 이상이 실제로 재생된다** (헬스체크 통과 기준)

- [ ] 키보드만으로 전 기능 조작 가능, 재생 상태가 스크린리더에 전달된다
