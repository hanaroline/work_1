# 보이는 라디오 웹 플레이어 — 구축 계획서 (2차)

작성 2026-09-12 · 대상 저장소 `hanaroline/work_1` · 산출물 `radio.html` · 예상 공수 약 4일

라디오 진행을 **TV처럼 보면서 듣는** 사이트. 방송사 공식 유튜브 라이브를 사이트 안에
얹어 영상으로 보고, 영상이 없는 채널은 소리로 듣는다. 단일 HTML 한 장 +
GitHub Actions 데이터 수집.

> **1차에서 바뀐 점** — "열린 라디오"를 공개 오디오 스트림으로 읽었으나 **보이는 라디오**가
> 요건임이 확인되어 영상이 화면의 중심으로 올라왔다. 오디오는 영상이 없을 때의 보조
> 수단으로 내려간다. 편성표가 곁다리 정보에서 **1급 데이터**가 된다.

---

## 1. 먼저 짚고 갈 제약

보이는 라디오는 영상이라서, 오디오보다 가져다 쓸 수 있는 길이 더 좁다.

| | 제약 | 내용 |
|---|---|---|
| **차단 확정** | 방송사 자체 플레이어는 끼워 넣을 수 없다 | KBS Kong·MBC mini·SBS 고릴라는 서명 토큰과 프레임 삽입 차단(`X-Frame-Options`)이 걸려 있다. 뚫으면 약관 위반이고 언젠가 반드시 멈춘다. **대신 같은 방송을 내보내는 공식 유튜브 라이브가 그 자리를 메운다.** |
| **핵심 관문** | 유튜브 라이브는 매 방송마다 주소가 바뀐다 | 임베드는 허용되지만 영상 ID가 방송마다 새로 생긴다. **"지금 이 채널의 라이브 ID"를 계속 알아내는 장치**가 이 프로젝트의 심장이다. |
| **타이밍** | Actions 예약은 늦게 돈다 | 이 저장소 워크플로 주석에 이미 기록돼 있다 — 15:40 예약이 17:15에 돈 적이 있다(95분 지연). 라이브 ID를 예약 수집에만 맡기면 방송이 시작돼도 화면이 빈다. 화면 쪽에 보정 장치가 필요하다. |

## 2. 설계 결론 — 3트랙

### 지상파·보도채널도 사이트 안에서 재생된다

KBS·MBC·SBS·CBS·TBS·YTN은 같은 방송을 **공식 유튜브 라이브로도 내보낸다**. 그 라이브를
정식 임베드로 얹으면 우리 화면 안에서 **영상으로 보이고, 영상을 꺼도 소리로 이어진다.**
밖으로 내보내는 흉내가 아니라 실제 재생이다.

사이트 밖으로 넘기는 경우는 둘뿐 — ① 그 채널이 유튜브 라이브를 하지 않는 시간대,
② 방송사가 외부 사이트 재생을 꺼 둔 채널. 어느 채널이 어느 쪽인지는 Phase 0에서
전부 확인해 화면에 미리 표시한다.

### Track 1 · 주력 — 사이트 안에서 보는 보이는 라디오
- **대상** 지상파·보도채널 포함, 공식 유튜브 라이브를 운영하고 임베드를 허용하는 채널
- **수단** YouTube IFrame Player API — 방송사가 허용한 정식 임베드
- **경험** 16:9 영상, 채널 전환, 전체화면, PIP, 영상 끄고 소리만 듣기
- **조건** 수집 단계에서 `embeddable` 확인을 통과한 채널만

### Track 2 · 빈틈 메우기 — 남는 시간대만 공식 앱으로
- **대상** 같은 채널의 **라이브가 없는 시간대**, 또는 외부 재생을 막아 둔 채널
- **수단** Kong·mini·고릴라 등 공식 시청 페이지를 새 창으로
- **우리 쪽** 프로그램명·진행자·방송 시간·지금 방송 중 표시는 그대로 유지
- **범위** Phase 0에서 채널별 커버리지를 재어 이 시간대를 정확히 안다

### Track 3 · 소리만 듣는 채널
- **대상** 방송국이 공개한 오디오 스트림 — 지역·대학·종교·장르 채널
- **출처** Radio Browser 공개 DB + 직접 큐레이션
- **역할** 영상이 없는 시간대를 메운다

## 3. 구조

기존 `market-data.yml` 패턴 그대로. 다만 라이브 ID 수집은 더 자주 돈다.

```
  GitHub Actions
  radio-live.yml   10분 주기 · 편성 시간대에만 · 수동 실행 가능
        │   YouTube Data API 로 채널별 현재 라이브 조회
        │   videos.list 로 embeddable 확인 → 임베드 가능 여부 확정
        │   (API 키는 GitHub Secrets. 브라우저에는 절대 내리지 않는다)
        ▼
  data/radio/live.json      ← 지금 라이브 중인 채널 · 영상 ID · 제목

  radio-data.yml   주 1회 · 목록과 편성 갱신
        ▼
  data/radio/channels.json  ← 채널 · 주파수 · 공식 시청 주소
  data/radio/schedule.json  ← 요일별 편성 (프로그램 · 시간 · 진행자)
        │
        ▼
  radio.html  단일 파일 · 빌드 도구 없음 · 기존 팔레트/다크모드 재사용
        │
        ├─ 편성표로 "지금 뭐가 방송 중인지" 먼저 계산한다  ← 수집 지연 보정
        ├─ live.json 에 ID가 있으면  → 사이트 안에서 영상 재생  (Track 1)
        ├─ 없거나 임베드 불가면    → 공식 시청 페이지 새 창    (Track 2)
        └─ 영상 자체가 없으면      → 오디오 스트림 재생        (Track 3)
```

편성표를 먼저 계산하는 게 지연 보정의 핵심이다. 수집이 늦어도 화면은 "지금은 이
프로그램 시간"이라는 걸 알고 있으므로, 빈 화면 대신 프로그램 정보와 공식 시청
버튼을 내보낼 수 있다.

## 4. 화면 동작

TV처럼 — 켜면 바로 나오고, 채널은 한 번에 넘어간다.

- **켜면 바로** 지금 영상으로 볼 수 있는 채널이 맨 위, 마지막으로 보던 채널이 자동 선택
- **채널 전환** 숫자키 `1`–`9`, 방향키, 클릭. 전환해도 끊김 없이 다음 영상으로
- **영상 끄기** 영상만 숨기고 소리는 계속 — 데이터 절약, 다른 일 하면서 듣기
- **전체화면·PIP** 작은 창으로 띄워 두고 다른 작업. 보이는 라디오를 실제로 쓰는 방식
- **편성표** 지금 방송 중 / 다음 방송 / 오늘 타임라인. 채널마다 보이는 라디오 운영 시간이 달라 이게 없으면 헤맨다
- **즐겨찾기·최근** localStorage 저장, 서버 없음
- **접근성** 키보드만으로 전 기능, `aria-live` 상태 알림, 400px 폭에서 영상 위·목록 아래로 쌓임

## 5. 데이터 모델

채널은 고정, 라이브는 수시로 바뀐다. 그래서 파일을 나눈다.

```json
// channels.json — 주 1회 갱신
{
  "id": "mbc-sfm",
  "name": "MBC 표준FM",
  "org": "MBC",
  "freq": { "seoul": 95.9 },
  "video": {
    "provider": "youtube",
    "channelId": "UC...",
    "embeddable": true,
    "fallbackUrl": "https://mini.imbc.com/..."
  },
  "audio": { "streams": [ { "url": "https://...m3u8", "format": "hls" } ] }
}

// schedule.json — 주 1회 갱신
{ "channel": "mbc-sfm", "days": [1,2,3,4,5],
  "start": "14:00", "end": "16:00",
  "program": "프로그램명", "host": "진행자", "visible": true }

// live.json — 10분 주기 갱신
{ "channel": "mbc-sfm", "videoId": "abc123",
  "title": "...", "startedAt": "...", "resolvedAt": "..." }
```

## 6. 재생 엔진

- **유튜브 임베드** IFrame Player API로 재생·음량·상태를 우리 UI에서 제어. 채널 전환 시 iframe을 새로 만들지 않고 `loadVideoById`로 갈아끼워야 전환이 빠르다
- **라이브 종료 감지** 방송이 끝나면 플레이어가 종료 상태를 알려 준다. 그때 편성표를 다시 보고 다음 채널이나 오디오로 넘긴다
- **임베드 거부** 외부 재생을 막아 둔 영상은 플레이어가 오류(101/150)를 낸다. 즉시 Track 2로 내려간다. 카드에 미리 표시하되 런타임에서도 확인
- **오디오** `.m3u8`은 Safari 네이티브 / 그 외 `hls.js`, mp3는 `<audio>`. 12초 안에 소리가 안 나면 다음 후보로
- **자동재생 정책** 소리 있는 자동재생은 브라우저가 막는다. 첫 재생은 클릭·키 입력 뒤에
- **녹화·녹음 없음** 저작권 문제를 만들지 않기 위해 의도적으로 빼는 기능

## 8. 일정

| 단계 | 내용 | 공수 | 산출물 |
|---|---|---|---|
| **Phase 0** | 방송사별 공식 유튜브 채널 ID 확인, 라이브가 외부 사이트에서 실제 재생되는지 하나씩 시험. 여기서 Track 1 범위가 확정된다 | 1일 | `channels.json` |
| **Phase 1** | MVP — 단일 HTML 골격(기존 팔레트·다크모드 재사용), 영상 플레이어, 채널 목록, 채널 전환, 즐겨찾기 | 1일 | `radio.html` |
| **Phase 2** | 편성 데이터 작성, 지금 방송 중 / 다음 방송 / 타임라인, 라이브 종료 시 자동 전환, 오디오 폴백, 영상 끄기 토글 | 1일 | `schedule.json` |
| **Phase 3** | `radio-live.yml`(10분 주기) + `radio-data.yml`(주 1회). 변경 있을 때만 커밋 | 0.5일 | 워크플로 2종 |
| **Phase 4** | 전체화면·PIP, 키보드 조작, 모바일·다크 점검, 실기기 확인, `index.html` 링크, README 항목 | 0.5일 | |
| **Phase 5** | 배포 결정 — 현재 `pages.yml`은 `mapo-wm.html` 한 장만 공개하고 `robots.txt`로 수집을 막는다 | — | 결정 사항 |

**Phase 0 확인 항목 두 가지**
1. 각 방송사 라이브가 임베드 허용인지. 막혀 있으면 그 채널은 Track 2로 간다.
2. 채널 ID만으로 현재 라이브를 띄우는 방식이 아직 동작하는지. 동작하면 API 키 없이도 되므로 구조가 훨씬 단순해진다.

## 9. 리스크

| 위험 | 발생 양상 | 대응 |
|---|---|---|
| 임베드를 막아 둔 채널 | 방송사가 외부 사이트 재생을 꺼 두면 우리 화면에서 못 본다. 가장 큰 불확실성 | Phase 0에서 채널별 확인해 범위 확정. 막힌 채널은 Track 2로, 화면에 "공식 앱에서 시청"으로 정직하게 표시 |
| 라이브 ID를 늦게 잡는다 | Actions 예약 지연(이 저장소 95분 사례). 방송이 시작됐는데 화면이 빈다 | 편성표로 먼저 판단해 프로그램 정보와 공식 시청 버튼 노출. 수동 실행 경로 확보. 확인 2가 통과하면 이 위험 자체가 사라진다 |
| API 할당량 초과 | 유튜브 Data API 일일 할당량은 넉넉하지 않다. 전 채널 24시간 10분 조회는 금방 바닥난다 | 편성 시간대에만 조회, 잡은 ID는 방송 종료까지 재사용, 채널별 간격 차등 |
| 오디오 주소가 조용히 죽는다 | 공개 스트림의 10~20%는 늘 죽어 있다 | 주 1회 헬스체크로 자동 제거, 후보 복수 보유 |
| 혼합 콘텐츠 차단 | `http://` 오디오가 https 페이지에서 무음 실패 | 수집 단계에서 https만 통과 |
| 모바일 백그라운드 중단 | 화면을 끄면 영상 재생이 멈춘다. 웹의 구조적 한계 | "영상 끄고 소리만" 모드 + Media Session 등록. 한계는 화면에 솔직히 안내 |

## 10. 준법 점검

- [x] **방송사 자체 플레이어 우회 금지** — 토큰·프레임 차단을 뚫지 않는다
- [x] **중계 서버를 두지 않는다** — 방송사 스트림을 우리 서버로 받아 되뿌리면 기술적으로는 "우리 사이트에서 재생"이 되지만 그건 무단 재송신이다. 이 길은 선택지에 없다
- [x] **정식 임베드만 사용** — 방송사가 임베드를 허용한 공식 유튜브 라이브만 얹는다
- [x] **녹화·녹음·다시보기 저장 없음** — 실시간 시청만
- [x] **광고 건드리지 않음** — 유튜브 광고를 가리거나 건너뛰지 않는다
- [ ] **출처 표시** — 각 영상에 방송사·채널명을 노출하고 원 방송 페이지 링크를 함께 둔다
- [ ] **API 키 관리** — GitHub Secrets에만. 브라우저로 내려가는 코드에 절대 넣지 않는다
- [ ] **이의 제기 경로** — 제거 요청 연락처를 하단에 명시, 요청 시 당일 제거

- [ ] 사이트를 열면 **지금 볼 수 있는 채널이 바로 보이고**, 한 번의 클릭으로 영상이 뜬다
- [ ] **지상파·보도채널이 방송 시간대에 사이트 안에서 재생된다** — KBS·MBC·SBS·CBS·TBS·YTN 중 Phase 0에서 확정한 채널 전체
- [ ] 채널별 **사이트 내 재생 커버리지(하루 몇 시간)** 가 측정되어 화면과 문서에 적혀 있다
- [ ] 임베드가 막힌 채널은 **미리 그렇게 표시되고** 공식 페이지로 정확히 연결된다
- [ ] 채널 전환이 **1초 안에** 이루어진다 (iframe 재생성 없이)
- [ ] 방송이 끝나면 **빈 화면이 남지 않는다** — 편성표를 보고 다음 안내나 오디오로 넘어간다
- [ ] "영상 끄고 소리만" 모드가 동작한다
- [ ] iPhone Safari · Android Chrome · 데스크톱 Chrome 세 곳에서 **실기기 확인**
- [ ] 400px 폭과 **다크 모드**에서 레이아웃이 깨지지 않는다
- [ ] 워크플로가 **한 번 이상 자동 실행되어** 라이브 ID를 잡고 커밋했다

## 12. 확장 — TV·종편·기타 방송

**결론부터: 구조는 그대로 쓸 수 있다. 다만 "사이트 안에서 재생"의 범위가 채널 종류마다
크게 다르고, 라디오보다 훨씬 좁다.** 3트랙 설계가 그대로 적용되므로 새로운 개념은 필요
없다 — 채널 목록에 TV 탭을 하나 더 붙이는 일이다. 추가 공수 **0.5~1일**.

| 구분 | 사이트 안에서 재생 | 근거 |
|---|---|---|
| **뉴스·보도 채널** — KBS/MBC/SBS News, YTN, 연합뉴스TV, JTBC News, 채널A·MBN·TV조선 뉴스 | **가능** — 영상으로 | 대부분 **24시간 공식 유튜브 라이브**를 운영하고 임베드를 허용한다. 라디오 Track 1과 완전히 같은 방식 |
| **공공·전문 채널** — 국회방송, 아리랑TV, 국방TV 등 | **대체로 가능** | 공식 유튜브 라이브 운영 |
| **KBS 1TV·2TV 본방송** | 새 창 | 공식 사이트에서 실시간을 제공하지만 외부 사이트 임베드는 막혀 있다 |
| **MBC·SBS·종편 본방송** (드라마·예능 등) | **불가 — 링크만** | 실시간이 유료 구독 플랫폼(Wavve 등)에 묶여 있다. 임베드 수단이 없고, 우회는 선 밖이다 |

### 넘지 않는 선

- **유료 구독 콘텐츠 우회 금지** — 로그인·결제로 막힌 실시간을 뚫는 방법은 다루지 않는다
- **중계 서버 금지** — 라디오와 동일. 받아서 되뿌리면 무단 재송신이다
- 방송사 정책은 자주 바뀐다. 채널별 가부는 **Phase 0에서 하나씩 확인**해 확정하고,
  화면에는 "여기서 재생 / 공식 사이트에서 시청"을 **미리 정직하게 표시**한다

### 권고

뉴스·보도 채널부터 붙이는 게 좋다. 24시간 라이브라 편성표 의존이 없고, 임베드가 거의
확실하며, 라디오의 보도 채널(YTN·CBS 등)과 자연스럽게 이어진다. 본방송 채널은 링크만
두고 시작한 뒤, 정책이 바뀌면 그때 승격한다.

> **범위 주의** — 여기까지 붙이면 "라디오 사이트"가 아니라 "방송 포털"이 된다.
> 라디오를 먼저 완성(Phase 4)한 뒤 확장으로 붙이기를 권한다.
