# 무엇을 만드는가

한국에서 설정된 공모펀드를 투자지역(국내/해외)으로 나누어 찾아보는 화면을
만듭니다. 원본은 fund.html 이고, 빌드 결과물이 fund-search.html 입니다.
작업 가지는 claude/fund-search-tool 입니다. ETF 가지에는 커밋하지 마십시오 —
다른 세션이 쓰고 있습니다.

# 숫자를 다루는 규칙

가. 없는 것을 0 이라고 말하지 마십시오.
    Number(null) 은 0 이고 Number.isFinite(0) 은 true 입니다.
    값이 없는 것과 값이 0 인 것은 화면에서도 코드에서도 끝까지 갈라 두십시오.

나. 틀린 숫자를 내보내느니 빈칸이 낫습니다.
    채울 수 없으면 비우고, 왜 비었는지 화면에 적으십시오.

다. 감사 규칙이 틀릴 수 있습니다.
    오류가 대량으로 잡히면 규칙부터 의심하고 실물을 보십시오.
    3,196개 중 3,195개가 걸리면 그건 자료가 아니라 규칙이 틀린 것입니다.
    3,200개 중 1개가 걸리면 그건 자료가 틀린 것입니다. 비율이 단서입니다.

라. 펀드는 parentPeerGroupName 이 이미 유형 이름이니 분류를 지어내지 마십시오.

마. 막히거나 원천이 없어 못 만드는 것이 나오면,
    되는 것처럼 만들지 말고 못 한다고 보고하십시오.

바. 보고는 셋으로 나눕니다 — 확인된 것 / 확인 실패 / 확인 안 됨.
    확인 실패에는 왜 실패했는지(차단·유료·형식 불일치)를 같이 적습니다.
    언급하지 않고 넘어가는 것은 확인된 것처럼 전달하는 것과 같습니다.

# 일하는 방식

- 화면을 만들기 전에 숫자를 먼저 검증하십시오.
- 감사(scripts/audit_fund_data.mjs)는 커밋보다 **앞**에 둡니다. 감사가 오류를
  내면 그 뒤의 빌드·시험·커밋이 전부 건너뛰어지고 아무것도 커밋되지 않습니다.
  이것은 고장이 아니라 설계입니다.
- 커밋 메시지는 한국어로 씁니다.
- 브랜드가 드러나는 산출물에는 mas-design 스킬을 씁니다.
- 자료 정합성은 fin-data-integrity 스킬을 따릅니다.

# 이 환경에서 막히는 것

웹 세션에서는 네이버·야후·KRX·금융투자협회·data.go.kr 에 직접 붙지 못합니다
(CONNECT 403 / EGRESS_BLOCKED). 그래서 **수집과 원천 확인은 전부 깃허브
액션에서 돌리고 결과를 저장소에 커밋해서 가져옵니다.** 세션에서 curl 로
원천을 찔러 보고 "안 된다" 고 결론 내리지 마십시오 — 러너에서는 됩니다.

 ── 3-3. 자동 실행 시각표 ─────────────────────────────────────────────────────

 월요일 10:00 KST (= 월요일 01:00 UTC) 에 한 번 돕니다.

   파일 : .github/workflows/fund-weekly.yml   ← **main 가지에 있음**
   시각 : - cron: '0 1 * * 1'

 왜 main 에 있나 (이것이 제일 중요합니다) :
   깃허브는 **기본 가지(main)에 놓인 워크플로우만** schedule 로 부릅니다.
   작업 가지(claude/fund-search-tool)의 fund-daily.yml 에 적혀 있던
   cron: '30 23 * * 0-4' 는 **한 번도 돈 적이 없습니다.** 기록에 남은 실행
   30건이 전부 push 아니면 손으로 부른 것이었습니다. 날마다 도는 것처럼
   보였을 뿐입니다.
   그래서 "부르는 사람" 만 main 에 두고, 일의 내용은 가지 쪽에 그대로 둡니다.
   내용을 main 에 베껴 두면 두 벌이 되어 언젠가 조용히 어긋납니다.

 왜 월요일 아침인가 :
   원천은 기준가를 **직전 영업일** 기준으로 싣습니다. 월요일 아침에 받으면
   금요일 기준가, 곧 그 주의 마지막 확정치가 옵니다. 주말에 부르면 한 주가
   어긋납니다 (2026-09-12 토요일에 받아 보니 기준일이 09-10 목요일로 왔음).

 밀립니다 :
   깃허브 schedule 은 정시에 뜨지 않고 몇 분에서 십수 분까지 밀립니다.
   수집이 10~20분 걸리므로 자료가 들어오는 것은 보통 10시 반 안팎입니다.

 ── 3-6. 비워 두는 네 가지 표식 ───────────────────────────────────────────────

 원천이 이상할 때 그 자리만 비우고 왜 비웠는지 화면에 적습니다. 감사에서는
 오류가 아니라 '참고' 로 올라오고, 재검증에서 다시 확인합니다.

   badWeights      — 한 줄의 비중이 범위 밖 (w >= -1.5 && w <= 1.5 밖)
   weightsDropped  — 한 펀드의 비중 합이 한도 초과
                     (보통 101%, 레버리지·인버스·선물·파생은 310%)
   aumDropped      — derivedNav/derivedAum == basePrice/1000 항등식이
                     상대오차 0.2 를 넘김
   priceDropped    — basePrice < 1

 원천은 보유비중을 **소수로** 줍니다 (0.090869 = 9.09%). toPct() 로 바꿉니다.


 ── 3-7. 이 실행 환경에서 알아 둘 것 ──────────────────────────────────────────

 - 크로미움은 /opt/pw-browsers 에 이미 있습니다. playwright install 을
   부르지 마십시오 — 세션 몫 디스크에 수백 MB 를 또 쌓습니다.
 - playwright 는 node_modules 를 저장소 뿌리에서만 찾습니다. 임시로 찔러 보는
   대본은 /home/user/work_1/chk_tmp.mjs 처럼 뿌리에 두고 끝나면 지우십시오.
 - CLAUDE_CODE_REMOTE=true 가 물려 있습니다. "사람 기계에서처럼" 돌려 보려면
   env -u CLAUDE_CODE_REMOTE 로 벗겨야 합니다.
 - 파이썬 대본(scripts/*.py)은 표준 라이브러리만 씁니다. 린터는 없습니다.
 - mcp__github__actions_list 는 workflow_id·branch·event 거르기를 무시합니다.
   실행이 끝났는지 보려면 깃을 보십시오 :
     git fetch origin claude/fund-search-tool && git log origin/claude/fund-search-tool
   봇(github-actions[bot])의 커밋이 올라와 있으면 돈 것이고, 감사도 통과한
   것입니다 (감사가 막으면 커밋 자체가 없습니다).
