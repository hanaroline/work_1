# 상품설명의무 완전판매 스크립트 — 설치와 계정 이관 안내

> 2026-10-02 작성 · 저장소 `hanaroline/work_1` · 가지 `claude/els-fund-disclosure-i6wtii`

이 문서 하나로 **① 창구에서 쓰는 법**과 **② 클로드 계정을 바꿔도 이어 가는 법**이
모두 됩니다. 먼저 가장 중요한 것부터.

---

## ★ 먼저 알아 두실 것 — 설치할 것이 없습니다

**화면은 HTML 파일 하나입니다.** 설치 프로그램도, 서버도, 인터넷도 필요 없습니다.

```
sales-script-expl-standalone.html   ← 이 파일 하나가 전부 (8.2MB)
```

그리고 더 중요한 것 —

> **이 화면은 클로드 계정과 아무 상관이 없습니다.**
> 계정을 닫아도 파일은 그대로 돌아갑니다. 창구에서 쓰는 데에는
> 클로드도, 인터넷도, 로그인도 필요하지 않습니다.

클로드 계정이 필요한 것은 **데이터를 새로 받아 화면을 다시 만들 때**뿐이고,
그것조차 사람이 직접 할 수 있는 길이 있습니다(아래 4절).

---

## 1. 창구 PC 에 놓기 (3분)

1. `sales-script-expl-standalone.html` 을 USB 나 사내 공유 폴더로 **업무용 PC 에 복사**합니다
2. **더블클릭**합니다 — 기본 브라우저(크롬·엣지)에서 열립니다
3. 끝입니다

확인해 보실 것 — 화면 오른쪽 위에 **「[테스트판]」 글자가 없어야** 배포판입니다.

| | 쓰는 곳 |
|---|---|
| `sales-script-expl-standalone.html` | **창구 배포판** — 직원에게 주는 것 |
| `sales-script-expl-test-standalone.html` | 테스트판 — 바뀐 것을 미리 보는 용도. 창구에 주지 않습니다 |

### 돌아가는 환경

- 인터넷이 **막힌** PC 에서 그대로 동작합니다 (외부 요청 0건)
- 익스플로러는 안 됩니다. 크롬·엣지·웨일 등 최근 브라우저가 필요합니다
- 파일을 메일로 보내면 용량(8.2MB) 때문에 막힐 수 있습니다 — USB·공유폴더를 쓰십시오

## 2. 데이터가 낡으면 — 세 가지 길

화면 자체는 영원히 돌지만, **ELS 회차는 열흘쯤마다 바뀝니다.** 낡은 목록을 그대로
두면 창구가 이미 마감된 회차를 고르게 됩니다.

### 길 ① 사람이 직접 돌린다 (클로드 계정 없이도 됨) ★ 권합니다

GitHub 웹에서 단추 몇 번이면 됩니다.

1. https://github.com/hanaroline/work_1/actions 로 들어갑니다
2. 왼쪽 목록에서 **「월요일 일괄 갱신 (상품설명의무 스크립트)」** 를 고릅니다
3. 오른쪽 **Run workflow** → 가지를 `claude/els-fund-disclosure-i6wtii` 로 두고 실행
4. 8~10분 뒤 끝나면, 저장소에서 새 `sales-script-expl-standalone.html` 을 내려받습니다
   (파일 화면의 **Download raw file** 단추)

**이 길은 클로드와 전혀 무관합니다.** GitHub 계정만 있으면 됩니다.

### 길 ② PR #83 을 병합한다 — 그러면 저절로 돕니다

https://github.com/hanaroline/work_1/pull/83 을 `main` 에 병합하면,
**매일 아침 08:00~10:10 KST 에 여섯 단계가 저절로 돌고 화면이 다시 만들어집니다.**

지금은 왜 안 도는가 — GitHub 은 **기본 가지(main)에 있는 워크플로만** 예약 실행합니다.
이 작업의 워크플로는 아직 작업 가지에만 있어서, 지금껏 클로드 예약이 대신 발동해
왔습니다. 병합하면 그 대역이 필요 없어집니다.

**계정을 닫으실 거라면 이 병합이 가장 중요합니다.** 병합해 두면 클로드가 없어도
데이터가 계속 최신으로 유지됩니다.

## 3. 새 클로드 계정에서 이어 가기

### 3-1. 무엇이 넘어오고 무엇이 사라지는가

| | |
|---|---|
| ✅ **넘어옴** | 저장소의 모든 것 — 코드·데이터·완성 파일·커밋 이력·가지·워크플로·PR·이 문서들 |
| ❌ **사라짐** | 대화 기록, **예약(Routine)**, 발행한 아티팩트 링크, 커넥터 연결, 계정 설정 |

즉 **일은 전부 남고, 「알아서 해 주던 것」만 사라집니다.**

### 3-2. 새 계정에서 할 일 (순서대로)

1. **GitHub 연동** — 새 계정에서 `hanaroline/work_1` 접근을 다시 승인합니다
2. **새 대화를 열고 아래를 그대로 붙여 넣습니다**

```
미래에셋증권 상품설명의무 완전판매 스크립트 작업을 이어서 합니다.
저장소 hanaroline/work_1, 작업 가지 claude/els-fund-disclosure-i6wtii 입니다.

먼저 이 셋을 읽고 맥락을 잡아 주십시오.
  · CLAUDE.md
  · docs/인수인계/00_설치와-계정이관-안내.md
  · docs/인수인계/01_작업-인수인계.md

읽고 나서 지금 데이터가 언제 것인지, 막혀 있는 것이 무엇인지 정리해 주십시오.

지켜 주실 것: 지정 가지에만 커밋·푸시 / PR 은 요청할 때만 /
못 읽은 값은 지어내지 말고 비우기 / 전량을 바꿀 때는 늘어난 것과 줄어든 것을 함께 세기.
```

3. **예약을 다시 겁니다** — 프롬프트 원문이
   `docs/인수인계/02_예약-프롬프트-및-설정.txt` 에 통째로 있습니다.
   그대로 복사해 쓰시면 됩니다.

| 예약 | 주기(KST) | cron(UTC) |
|---|---|---|
| 월요일 일괄 갱신 | 월 08:40 | `40 23 * * 0` |
| 평일(화~금) 갱신 | 화~금 08:40 | `40 23 * * 1-4` |
| ELS 신규 회차 오후 점검 | 평일 14:30 | `30 5 * * 1-5` |
| 펀드 원천 반영 재갱신 | 월 15:30 | `30 6 * * 1` |

**PR #83 을 병합했다면 앞의 둘은 다시 걸지 마십시오** — 워크플로가 스스로 돌아
하루에 두 번 돕니다. 다만 **「신규 회차 알림」은 예약에만 있는 기능**이라,
알림을 받고 싶으시면 세 번째(오후 점검)는 남겨 두는 편이 좋습니다.

### 3-3. 저장소 전체를 이어받는 경우

이 갈래 말고도 일거리가 열다섯입니다. 그때는 저장소 뿌리의
`CLAUDE.md` → `docs/handover/00-저장소-전체-인계.md` 를 먼저 보십시오.
**저장소 밖으로 들고 갈 한 파일 사본은 `인계-보관본.txt`** 입니다.
