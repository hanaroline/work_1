## 2. 판정의 핵심 — 이것만은 알고 시작한다

### 연금수령연차가 모든 것을 가른다

```
연금수령한도 = 과세기간 개시일 현재 평가액 ÷ (11 − 연금수령연차) × 120%
```

연차가 클수록 한도가 커지고, **11년차에 닿으면 한도가 사라진다.** 그래서
계좌 선택의 실익은 사실상 "이 계좌에 넣으면 연차가 몇에서 시작하느냐" 하나로
수렴한다.

연차는 **기산연차**(몇 년차로 출발) + **기산연도**(그 출발이 몇 년도) 로 정해진다.

**기산연차는 1 또는 6**(소득세법 시행령 §40의2④). 6이 되는 경우는 둘뿐이다.

1. 연금계좌 가입일자가 **2013.3.1 이전**
2. 2013.3.1 전 퇴직연금(DB·DC) 가입자가 퇴직급여 **전액**을 **신규 개설**
   계좌에 입금

**두 번째가 중요하다 — 기존 계좌가 없어도 6년차를 받을 수 있다.** 다만
'신규 개설 계좌에 전액' 조건이 붙어, 같은 DB 가입자라도 **이미 쓰던 계좌에
넣으면 1년차**가 되어 추천이 뒤집힌다.

**기산연도는 최초로 연금개시 요건을 갖춘 날이 속하는 해.** 여기가 함정이다 —
**연금개시를 신청하지 않아도 연차는 그 해부터 해마다 자동으로 쌓인다.**
이것을 빠뜨려 한도를 절반으로 계산하던 버그가 있었다.

### 인출 순서는 바꿀 수 없다 (시행령 §40의3)

```
① 세액공제 받지 않은 납입액  → 과세제외
② 이연퇴직소득(퇴직금)       → 퇴직소득세 × 감면
③ 세액공제 받은 납입액+운용수익 → 연금소득세 3.3~5.5% (연 1,500만원 초과 시 16.5%)
```

### 한도는 인출 상한이 아니다

**뺀 돈을 연금수령으로 볼지 연금외수령으로 볼지 가르는 기준선**일 뿐이다.
한도를 넘겨 인출할 수 있고, 넘은 부분만 감면 없이 과세된다. 초기 구현이
한도에서 잘라 버려 과도하게 낙관적인 수령액을 냈다.

### 퇴직소득세 감면 3단계 (§129①5의3)

실제 연금수령 **1~10년차 30% · 11~20년차 40% · 21년차부터 50%**.
20년 초과 50% 구간은 2025년 세법개정으로 신설, 2026.1.1 이후 수령분부터.

'실제 연금수령연차' 는 한도 계산용 연차와 **별개**다. 한도용은 돈을 찾지
않아도 쌓이지만, 감면율은 **실제로 받은 횟수**를 센다.

## 3. 결정된 사항 — 왜 이렇게 되어 있는가

바꾸려 하기 전에 읽어야 할 것들이다. 전부 한 번씩 반대로 해 봤다가 되돌린
것이다.

### 판이 둘이다 (배포본 / 내부용)

사내 Q&A 18건 원문을 화면에서 가리는 방식(비밀번호)은 택하지 않았다. 서버가
없어 내용이 파일 안에 남으므로 편집기로 여는 순간 뚫린다. **잠긴 줄 알고
돌리는 편이 더 위험하다.** 자료 자체를 심지 않는다.

이름을 달리 한 것은 실수를 막기 위해서다. 같은 이름으로 덮으면 지금 손에
있는 것이 어느 판인지 알 수 없고, 배포본인 줄 알고 근거가 든 파일을 보낸다.

### 라이브러리를 쓰지 않고 xlsx 를 직접 쓴다

인터넷 없이 파일 하나로 돌아야 해서 CDN 을 못 쓰고, 번들을 심으면 수백 KB 가
분다. zip 안에 XML 몇 장이라 필요한 만큼만 직접 쓴다(약 400줄, +30KB).
zip 은 **무압축(STORE)** 으로만 쓴다 — 브라우저 압축기가 제각각이다.

**수식으로 살아 있는 것은 인출 스케줄뿐이다.** 판정과 세액까지 엑셀 수식으로
옮기면 같은 규칙이 두 곳에 살게 되어 한쪽이 낡는다.

### 사용법을 PDF 로 빼지 않는다

파일 하나가 돌아다니는 형태라 PDF 를 따로 두면 HTML 만 받은 사람에게는
사용법이 없고, 화면이 바뀔 때마다 그 PDF 는 낡는다. 화면 안에 둔다.

### 날짜는 달력이 아니라 숫자 여덟 자리로 친다

브라우저 기본 `type="date"` 를 쓰면 휴대폰에서 **2003년 가입일을 고르려고
270번 넘게 눌러야 했다.** 이 도구가 다루는 날짜는 대부분 수십 년 전 가입일이라
달력으로 찾는 것 자체가 맞지 않는다.

### 자리표시자는 날짜로 읽힐 수 없는 것만 쓴다

예시 날짜(`2003-07-01`)를 넣었더니 **채워진 값으로 읽혀** 비어 있는 가입일을
'입력했다' 고 본 채 판정을 믿는 일이 있었다. 지금은 `YYYY-MM-DD`.

### 수수료는 IRP 에만 있다

연금저축계좌에는 계좌 단위 수수료가 없고 비용이 편입 상품에 붙는다(기준가에
이미 반영). 두 종류 모두에 칸을 두면 없는 비용을 물린다.

**신규 IRP 는 요율을 묻지 않고 미래에셋 공시에서 낸다.** 상담자가 모르는 값을
묻는 칸이었다. 체차적용이라 3억이라고 전액에 0.15% 가 아니다.

## 4. 고쳤던 큰 오류들 — 다시 넣지 않기 위해

| 오류 | 결과 |
|---|---|
| 연차 누적 누락 | 한도를 절반으로 계산 (6년차 ↔ 9년차) |
| 신규계좌 6년차 특례 누락 | "기존 계좌 없으면 1년차" 로 오판 |
| 한도를 인출 상한으로 취급 | 과도하게 낙관적인 수령액 |
| 퇴직 시점을 오늘로 고정 | 과거 퇴직자의 연차 누적을 놓침 |
| 계좌를 종류별 1개로 제한 | 더 유리한 선택지를 아예 못 봄 |
| 연금저축에 없는 수수료를 물림 | 없는 비용 |
| 1,500만원 초과를 저율 과세 | 어느 쪽을 골라도 나올 수 없는 숫자 |
| DB·DC 가입자 명퇴금 칸 없음 | DC 에서 전액 '불가' 오판 |
| 빈 가입일을 조용히 2013.3.1 이후로 봄 | 절반짜리 답을 조용히 냄 |
| 퇴직소득세만 지방소득세 빠짐 | 한 칸 안에서 기준이 갈림, 약 10% 과소 |
| 원 미만 절사가 1원씩 깎임 | 80,000건 중 10,916건(13.6%) |

**마지막 것은 교차검증이 잡지 못했다.** 규칙표와 화면이 **같은 방식으로**
틀려 있었기 때문이다. 제3의 구현(적분·누적합)으로 1,048건을 맞대어 보고서야
나왔다.

## 5. 휴대폰

| 기기 | 여는 법 |
|---|---|
| 안드로이드 | 파일 저장 → Chrome · 삼성 인터넷으로 열기 |
| **아이폰** | **Documents (Readdle) 앱**에 저장 후 실행 (사용자가 실기 확인) |

**메신저·파일 관리자의 내장 미리보기로는 동작하지 않는다** — 스크립트를 돌리지
않는다. 예비 화면에 해결 절차를 적어 두었다.

아이폰에서 **엑셀·CSV 내보내기가 되는지는 아직 확인되지 않았다.**
내려받기가 `a[download]` 방식인데 iOS 계열이 이 속성을 제대로 다루지 않는
경우가 많다. 확인되면 사용법에 적어야 한다.

### 휴대폰에서 실제로 깨졌던 것 (전부 수정됨)

- 머리 높이가 답답 → 여백 18px → 26/30px (105px → 133px)
- 구역 제목이 한 글자씩 세로로 쪼개짐 → 좁은 화면에서 조작부를 아래로 쌓음
- 탭 이름이 `인출 스케/줄` 로 끊김 → nowrap + 좁은 폭 여백 축소
- 불가 사유가 132px 에 130자 열 줄 → `flex-wrap` 으로 제 줄 (330px 넉 줄)
- 표가 넘치는데 표시가 없음 → `ScrollBox` (**정말 넘칠 때만** 안내를 띄운다)

## 6. 아직 안 끝난 것

### 사람이 확인해야 하는 것

1. **엑셀을 실제 Microsoft Excel 에서 열기** — 복구 메시지 없이 열리는지,
   `스케줄` 시트의 파란 칸 `G4~G22` 를 고치면 표가 다시 계산되는지, 한글과
   숫자 서식이 살아 있는지. 이 컨테이너에 Excel 이 없다.
2. **아이폰에서 엑셀·CSV 내보내기** — 위 참고.
3. **2021.9월 이전 DB→DC 전환자의 DB 가입일**을 실무에서 어떻게 확인하는지.
   앱에는 상담자가 직접 입력하는 칸을 두었다.
4. **퇴직소득세 계산 예제** — 사내에 숫자까지 확정된 사례가 있으면 그것과
   맞대는 검사로 바꾸는 편이 낫다. 지금은 조문에서 세 번 독립 전개해 맞대는
   방식이라 외부 정답과 맞대는 것보다 약하다.
5. **개인형IRP 할인 중복 시 합산인지 곱인지** — 장기할인 12% 와 연금수령개시
   20% 가 함께 걸릴 때 합산이면 32%, 곱이면 29.6%. 공시에 '중복적용 불가'
   표시가 없어 겹치는 것으로 보았고, 수수료를 낮춰 잡지 않도록 **곱**으로 계산.
