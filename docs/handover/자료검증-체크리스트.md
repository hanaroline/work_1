## 1. 수치 — 1차 출처와 대조

- 인쇄될 숫자를 **빠짐없이** 뽑아 목록으로 만든 뒤 하나씩 확인합니다.
- **2차 보도를 1차 출처로 삼지 않습니다.** 지수 공식 수치는 한국거래소,
  미국 물가는 BLS, 정책금리는 각 중앙은행 원문입니다.
- 확인 못 한 것은 비워 두고 출처 주소와 함께 남깁니다 — `CLAUDE.md` 의 대원칙과 같습니다.
- 발표 **시점**과 지표 **대상 기간**을 구분해 적습니다.
  "2026년 7월 발표치 4.2%"는 실제로 **6월 지표(7월 2일 발표)**입니다. 이 혼동이 흔합니다.
- 전월비/전년비를 반드시 밝힙니다. 같은 항목이 전월비 −9.7%, 전년비 +26.7% 일 수 있습니다.

## 2. 계산 — 전수 검산

표에 든 계산은 **한 칸도 빼지 말고** 다시 풉니다. 이번에는 전부 맞았습니다:

- 정당화 PER `1 ÷ (요구수익률 − 성장률)` 12칸
- 원화 기준 수익률 `(1+주가수익률) × (1+환율변동률) − 1` 4개 시나리오
- `PBR = PER × ROE`, 듀폰 3분해
- 포지션 사이징(손실 1~2% ÷ 손절폭 10% → 비중 10~20%), `−50% ↔ +100%`

맞았더라도 **가정**을 각주로 밝히게 합니다 (예: 정당화 PER 은 배당성향 100% 가정).

## 3. 정합성 — 가장 결함이 많이 나오는 층

자료가 **자기가 적은 규칙과 자기가 든 사례**로 서로를 반박하지 않는지 봅니다.
이번에 나온 것들:

- 환율 규칙("환율이 안정되면 외국인이 돌아온다") 바로 옆에 그 **반례**(원화 강세인데
  지수 급락)를 아무 설명 없이 둠
- "10년물이 3개월 안에 100bp 이상 급등하면 충격"이라는 임계값을 적어 놓고, 정작
  사례에서는 +26bp 에 지수가 22% 빠짐 → 임계값 미달이면 안전하다는 오독을 부름
- "고용이 강하면 금리를 못 내린다"를 **고용이 식고 있던 달**의 설명으로 배치
- 현금흐름 부호 조합에서 설명문은 "투자하고"인데 표시는 `+`(자산 매각)

**고치는 법**: 반례를 지우지 말고 **반례로 명시**하면 교육 효과가 오히려 올라갑니다.

## 4. ★ 파일 무결성 — `validate.py` 를 믿지 마십시오

### 무엇이 있었나

사용자가 "25페이지가 안 나온다"고 알려 왔습니다. 네 가지로 확인했는데 **앞의 셋이
전부 이상 없음**이라고 답했습니다.

| 검사 | 결과 | 왜 놓쳤나 |
|---|---|---|
| pptx 스킬 `validate.py` | `All validations PASSED` | 차트 파트를 XSD로 검사하지 않습니다 |
| LibreOffice 렌더링 | 정상 출력 | 잘못된 값을 무시하고 기본값으로 그립니다 |
| python-pptx 파싱 | 정상 | 관대합니다 |
| **공식 XSD 직접 검증** | **차트 6개 전부 INVALID** | ← 여기서 잡혔습니다 |

### 반드시 돌릴 것

```bash
pip install lxml python-pptx     # 둘 다 기본 설치가 아닙니다

python3 - <<'PY'
import glob, zipfile
from lxml import etree
# ★ 스킬 경로는 세션마다 다릅니다. 하드코딩하지 말고 찾으십시오.
#   (2026-10-01 에 /root/.claude/skills/pptx/... 에서 /mnt/skills/public/pptx/... 로 옮겨졌습니다)
xsd = (glob.glob('/mnt/skills/**/dml-chart.xsd', recursive=True) +
       glob.glob('/root/.claude/skills/**/dml-chart.xsd', recursive=True))[0]
schema = etree.XMLSchema(etree.parse(xsd))

z = zipfile.ZipFile('deck.pptx')
for n in [x for x in z.namelist() if '/charts/chart' in x and x.endswith('.xml')]:
    doc = etree.fromstring(z.read(n))
    ok = schema.validate(doc.getroottree())
    print(n, 'VALID' if ok else 'INVALID')
    if not ok:
        for e in schema.error_log: print('   ', e.message[:160])
        schema._clear_error_log()
PY
```

**2026-10-01 재확인:** 위 스니펫을 그대로 돌려 동작을 확인했습니다
(차트가 든 pptx 를 만들어 `VALID` 가 나오는 것까지).

### 이번에 나온 결함 — 전부 **원본**에 있던 것

생성 도구가 만든 것이고, 사람이 손으로 넣은 오류가 아닙니다.

| 결함 | 해당 | 성격 |
|---|---|---|
| `c:lineChart` 에 필수 `c:grouping` 누락 | p.6·7·24·25 | **필수 요소 누락** |
| 선언되지 않은 3번째 `c:axId` | 차트 6개 전부 | 최대 2개인데 3개 |
| 선 계열에 막대 전용 `c:invertIfNegative` | 선 차트 4개 | 잘못된 요소 |
| `c:marker`/`c:dLbls` 순서 역전 | 선 차트 계열 | 필수 순서 위반 |
| `prstDash val="solid,dash,dash"` | **p.25 만** | **25쪽 백지의 직접 원인** |

마지막 것이 결정적입니다. `prstDash` 는 `solid`·`dash` 같은 **단일 열거값**만 받는데,
생성 도구가 계열별 선 스타일 목록을 계열마다 인덱싱하지 않고 통째로 써 버렸습니다.
PowerPoint 는 이런 차트 파트를 읽기를 거부하고 **차트를 버립니다**.

고친 뒤 70/30 기준선이 **점선**으로 나왔습니다 — 원래 의도였는데 잘못된 값이
그것을 눌러 왔던 것입니다.

### ★ 컨테이너는 휘발합니다 — 산출물은 반드시 저장소에

세션이 재개되자 다음이 **전부 사라졌습니다**:

## 6. 고칠 때의 규칙

- **원문 교체는 단언을 걸고** 합니다 — "기존 문구가 정확히 일치할 때만 교체".
  문단 번호로만 찾으면 엉뚱한 곳을 고칩니다.
- 서식을 지키려면 `text_frame.text` 가 아니라 **`run.text`** 에 넣습니다.
  (`text_frame.text` 는 문단을 서식 없는 run 하나로 뭉갭니다.)
- 문장을 늘리면 글상자를 넘칩니다. **폰트 메트릭으로 폭과 줄 수를 재어**
  기존 줄 수를 유지하도록 길이를 맞춥니다. 한글 1em, 숫자·영대문자 약 0.56em,
  영소문자 0.5em 으로 어림하면 ±5% 안에서 맞습니다.
- 문단을 **추가**할 때는 기존 문단의 XML 을 복사(`deepcopy`)해 `<a:t>` 만 바꿉니다.
  불릿·간격 서식이 그대로 따라옵니다.
- python-pptx 로 다시 저장하면 **파일이 작아집니다**(원본이 무압축이면
  1.2MB → 180KB). 내용 손실이 아니라 압축 방식 차이입니다. 확인하려면
  파트 수와 미디어·임베드 파일의 해시를 원본과 대조하십시오.
