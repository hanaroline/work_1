> **한 줄 요약.** 저장소 안에 있는 것은 전부 그대로 넘어간다. **대화 기록·예약(Routine)·
> 아티팩트·채팅으로 받은 파일은 넘어가지 않는다.** 그래서 넘어가지 않는 것만 골라

## 1. ★ 가장 먼저 — 계정을 바꾸면 무엇이 넘어오고 무엇이 사라지는가

물으신 그대로 답하면, **「github 저장소를 연동하면 과거 프롬프트·작업내용·완성파일이
계승되는가」 → 절반만 맞습니다.** 저장소에 있는 것만 계승됩니다.

| | 계승 | 왜 |
|---|:---:|---|
| 코드·스크립트·워크플로 | **O** | git 에 있다 |
| 수집한 자료 (`data/**`) | **O** | git 에 있다 |
| 발행한 화면·문서 (`docs/**`) | **O** | git 에 있다 |
| 작업 가지 60여 개 전부 | **O** | git 에 있다 |
| **저장소 Secrets** (텔레그램·KIS·KRX 키) | **O** | GitHub 쪽에 있다. 다시 넣지 않아도 된다 |
| GitHub Actions 예약(`schedule:`) | **O** | 워크플로 파일 안에 있다 — **계정과 무관하게 계속 돈다** |
| 인계 문서들 (`docs/handover/`) | **O** | 그래서 저장소에 넣었다 |
| **대화 기록 (지금까지의 모든 채팅)** | **X** | 계정에 묶인다 |
| **예약(Routine) 12개** | **X** | 계정에 묶인다. **새로 만들어야 한다** |
| **아티팩트 (브리핑 목록·자료실 색인 등)** | **X** | 계정에 묶인다. 링크가 죽는다 |
| **채팅으로 받은 HTML·PDF 파일** | **X** | `out/` 은 `.gitignore` 이고 컨테이너는 회수된다 |
| 세션 자체 (`session_…`) | **X** | 예약이 「쓰던 대화로 전달」하던 창들이 끊긴다 |

### 그래서 계정을 끝내기 **전에** 해야 할 일

1. **예약 지시문을 옮겨 적는다** → 끝냈다. `docs/handover/예약-Routine-전문-백업.md`
2. **받아 둔 파일 중 손에 꼭 쥐고 있어야 할 것은 지금 내려받는다.**
   다만 **대부분은 다시 뽑을 수 있다** — 자료가 `data/**` 에 남아 있다.
   - 증권사 리포트: `bash scripts/make_reports_outputs.sh 2026-09-28`
   - 브리핑: `bash scripts/make_outputs.sh docs/briefings/<날짜>.html`
   - 시장일지: `python3 scripts/build_journal.py` 뒤 `node scripts/journal_to_pdf.mjs`
3. **아티팩트 중 주소를 고정해 쓰던 두 장**은 새 계정에서 새로 만들고 주소를 갈아야 한다.
   - 브리핑 목록 `d71cdafd-…` · 세션 산출물 색인 `fa511243-84ca-461c-9e58-e373d851e6fa`
4. 새 계정에서 저장소를 연결한 뒤 **예약을 다시 만든다**(위 1번 문서의 13절 차례대로).

> **GitHub Actions 예약은 건드릴 필요가 없다.** main 에 있는 워크플로 44개는
> 계정과 상관없이 계속 돈다. 사람이 다시 만들어야 하는 것은 **Claude 예약**뿐이다.

## 4. 유지해야 할 작업 규칙 — 어느 일감에서나 같다

### 4-1. 자료를 다루는 규칙

1. **짐작하지 말고 재어 본다.** 「16시에 기관 자료가 올까?」 같은 물음에 추측으로
   답하지 않는다. 시각별로 여섯 번 재어 표로 답했다. 이 저장소의 거의 모든 설계가
   그렇게 정해졌다.
2. **검산을 통과하지 못한 자료는 내지 않는다.** 증권사 리포트 42개, 시장일지 ①~⑦,
   펀드 일곱 자리. 오류가 있으면 **짓지 말고 어긋난 자리를 그대로 알린다.**
3. **없는 수치는 지어내지 않는다.** 비워 두고 「확인하지 못했다」고 적는다.
   (예: 종목별 사모펀드 순매수 · VKOSPI · 미수금 · 기타법인 수급)
4. **낡은 값을 오늘 값처럼 쓰지 않는다.** 신선도 검사를 먼저 돌리고, 낡았으면
   수집을 발동해 기다린다. 끝내 안 들어오면 **「(수집 시각) 기준」이라고 판에 적고**
   확보된 범위까지만 낸다. **낡은 줄 모르고 쓰는 것이 못 쓰는 것보다 나쁘다.**
5. **늘어난 것과 줄어든 것을 함께 센다.** 건수만 보면 들어온 수와 빠진 수가 같을 때
   「변화 없음」으로 오독한다. **이름·코드로 맞댄다.**
6. **잠정치와 확정치를 구분해 적는다.** 값이 여러 번 같아도 확정됐다는 뜻이 아니다.

### 4-2. 저장소를 다루는 규칙

- **지정된 가지에만 민다.** 다른 가지로 밀지 않는다.
- **요청하지 않은 PR 을 만들지 않는다.**
- `git push -u origin <가지>` · 네트워크 실패는 2·4·8·16초로 최대 4회 재시도.
- 커밋 꼬리:
  ```
  Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>
  Claude-Session: https://claude.ai/code/session_…
  ```
- **모델 이름을 저장소에 밀어 넣지 않는다** — 커밋·PR·코드 주석 어디에도.
- 러너 커밋 작성자는 `github-actions[bot]`. **고쳐 쓰지 않는다** — 실제로 러너가 한 일이다.
- 되받기(`--rebase`)가 병합 커밋을 펴다가 충돌을 낸 적이 있다. 수집기가 동시에 미는
  저장소에서는 **`--no-rebase`** 가 안전하다.

### 4-3. 실행 환경

- **세션은 바깥 원천에 직접 못 붙는다**(CONNECT 403, KIS 는 9443 포트가 막힌다).
  **러너가 받아 커밋하고 세션이 읽는다.**
- **세션에는 Actions 실행 권한이 없다**(`workflow_dispatch` → 403).
  감시 파일(`data/**/REFRESH` 등)을 밀어서 깨운다.
- **크로미움은 `/opt/pw-browsers` 에 이미 있다.** `playwright install` 을 다시 부르지 않는다.
- **TLS 검증을 끄거나 `HTTPS_PROXY` 를 지우지 않는다.** CA: `/root/.ccr/ca-bundle.crt`
- 임시 파일은 세션 전용 스크래치패드에. `out/`·`out-test/` 는 `.gitignore` 이고
  **컨테이너는 회수되므로 만든 파일은 같은 실행 안에서 건네야 한다.**
- `schedule:` 은 **기본 가지(main)의 워크플로만** 돈다. 작업 가지에서는 push 트리거만 산다.

### 4-4. 보고하는 결 (지금까지 굳어진 것)

- **한국어 문어체로, 짧고 단정하게.** 군더더기 인사 없이 본론부터.
- **숫자는 표로.**
- **틀렸으면 「앞서 ○○라고 한 것은 틀렸습니다」로 고쳐 적는다.** 길게 자책하지 않는다.
- **추정과 사실을 나눠 적는다.** 「…로 보이지만 확인한 것은 아닙니다」.
- **막혔으면 조용히 끝내지 않는다.** 무엇이 어디서 막혔는지 적는다.
- 끝에 **다음에 무엇이 있는지** 한 줄.

# 예약(Routine) 전문 백업 — 계정이 바뀌면 이것만 사라진다

마지막 갱신 2026-10-01 · 계정: 송재섭(마포WM) · 저장소 `hanaroline/work_1`

> **왜 이 문서가 가장 급한가.**
> 저장소에 있는 것(코드·자료·워크플로·문서)은 계정을 옮겨도 그대로 남는다.
> **예약은 Claude 계정에 묶여 있어 저장소 어디에도 없다.** 계정을 끝내면
> 아래 지시문 열두 벌이 통째로 사라지고, 다시 쓰려면 몇 달치 시행착오를
> 되풀이해야 한다. 그래서 **지시문 원문을 글자 그대로** 베껴 둔다.
>
> 새 계정에서는 아래를 **그대로 복사해** 예약을 다시 만든다.
> 옛 ID(`trig_…`)·세션 ID(`session_…`)는 새 계정에서 쓸모가 없으므로
> 참고로만 적는다.

## 0. 한눈에 — 켜져 있는 예약 열둘

| # | 이름 | cron (UTC) | 한국시각 | 전달 방식 |
|---|---|---|---|---|
| 1 | 마포WM 모닝 브리핑 | `30 22 * * *` | 매일 07:30 | 쓰던 대화로 |
| 2 | 마포WM 장마감 시황 브리핑 — 전용 창 | `10 7 * * 1-5` | 평일 16:10 | 쓰던 대화로 |
| 3 | 증권사 리포트 자동 배포 | `0 2 * * 1-5` | 평일 11:00 | 쓰던 대화로 |

| 8 | 펀드 원천 반영 재갱신 | `30 6 * * 1` | 월 15:30 | 쓰던 대화로 |
| 9 | ELS 상품 구조 페이지 주간 갱신 | `0 23 * * 0` | 월 08:00 | 새 대화 |

| 11 | 세션 산출물 자료실 자동 갱신 | `0 23 * * 0,3` | 월·목 08:00 | 쓰던 대화로 |
| 12 | 주간 수집 도달 시각 확인 (한 번) | — | 2026-10-05 11:30 | 쓰던 대화로 |

> **「쓰던 대화로 전달」을 반드시 고를 것.** 매번 새 대화를 띄우는 방식은
> 저장소에 밀어 넣을 자격이 없어 아무것도 만들어 내지 못한 적이 있다.
> 다만 4·9·10 은 새 대화로도 잘 돈다(각각 제 브랜치를 따로 받아 쓰기 때문).
>
> **서버가 「분」을 만든 시각에 붙잡는다.** 11:00 으로 걸어도 11:06 에 돈다.
> 위 표의 「다음 발사 시각」이 몇 분 밀려 보이는 것은 정상이다.

## 2. 결정된 것 — 되돌리지 말 것

### 2-1. 「오후 4시 완성판」은 **불가능하다.** 잠정판 + 완성판 두 단계로 간다

사용자가 **「최소한 4시경에는 외국인·기관 데이터까지 포함한 모든 데이터가
나와야 하는데 가능할까?」**라고 물었다. 짐작하지 않고 **두 원천을 시각별로 재서**
답했고, 답은 **아니오**다.

**네이버(2026-09-21, 여섯 번 실측)**

| 잰 때 | 종목별 외국인 | 종목별 기관 |
|---|---|---|
| 11:51 · 16:07 · 16:52 · 18:07 · 19:26 | 당일 **잠정치** | **전 거래일** |
| 23:45 | 당일 확정 | 당일 확정 |

원천이 **외국인에게만 장중 잠정치를 주고 기관에는 아무것도 주지 않는다.** 그래서
16시 판의 기관 칸은 「마지막으로 확정된 날」이 그대로 보인다. 사용자가
**「기관 데이터는 왜 오늘 데이터가 아닌 9월 18일 자료가 나오는데?」**라고 물은 것이
바로 이 현상이다 — 버그가 아니라 원천의 성질이다.

**한국투자증권 오픈API(2026-09-22, 삼성전자, 여섯 번 실측)**

| 잰 때 | 외국인 순매수수량 | 기관 순매수수량 |
|---|---|---|
| 15:37 · 16:02 · 17:32 · 19:33 | 747,617 | 267,601 |
| **22:05** | **659,851** | **259,459** |

네이버 확정치(22:02 관측) = **259,459** — 22:05 값과 정확히 같다.

> **여기서 내가 두 번 틀렸고, 두 번 다 고쳐 적었다.**
> ① 「기관 종목별은 그날 안에 차지 않는다」 — 틀렸다. 20~23시에 찬다.
> ② 「가장 이른 정직한 발행 시각은 15:40」 — 틀렸다. 15:37~19:33 네 번이
>    같은 값이어서 확정으로 보였지만 **넷 다 잠정치**였고 22:05 에 바뀌었다.
> **안정은 확정의 증거가 아니다.** 값이 여러 번 같아도 확정됐다는 뜻이 아니다.
> 이 교훈은 `docs/journal-playbook.md` 에도 적어 두었다.

**그래서 설계가 이렇다.** 16:00 판은 「그 시각까지의 판」이라고 판에 적고 낸다.
저녁 판이 같은 날짜로 다시 나가 완성한다. 워크플로가 16:00·16:20·16:45·17:15·
18:00·19:20·21:00·22:00·23:00 에 걸려 있고, `scripts/check_journal_ready.py` 가
「둘 다 오늘 확정치인가」를 보고 아니면 **내지 않고 물러선다.** 먼저 낸 판이 있으면
뒤 판이 비킨다. **이 구조를 단순화하지 말 것** — 여러 번 거는 데는 까닭이 있다.

### 2-2. 금액은 KIS 에서 받는다 (별도 가지 `claude/journal-kis-flows`)

네이버는 종목별 수급을 **수량으로만** 준다. 시장일지는 금액을 써야 해서
`수량 × 종가`로 어림했는데, 2026-09-21 삼성전자에서 **어림 9,977억 대 확정 1조 1,063억
— 11% 어긋났다.** KIS `FHKST01010900`(주식현재가 투자자)은 **확정 금액**을 준다.

- 수집기 `scripts/fetch_journal_kis.py` → `data/journal/kis-flows.json`
- 빌더의 `prefer_kis_flows()` 가 **기준일이 같을 때만** 갈아 끼운다. 다르면 네이버를 쓴다.
- 워크플로 `.github/workflows/journal-kis-flows.yml` — 20:30·21:30·22:30 KST.
  **저녁에 도는 까닭은 위 2-1 과 같다.** 이 수집기는 발행을 앞당기지 못한다 —
  **금액을 얻는 것**이 목적이다.
- **실측 25분** 걸린다(400종목 · 종목당 3.7초). 「초당 1건이니 7분」이라고 적었던 것은
  틀렸다 — 유량 제한 재시도(EGW00201)가 자주 걸려 세 배 넘게 든다. `timeout-minutes: 40`.

## 3. 뼈아프게 배운 것 — 같은 데 다시 빠지지 말 것

### 3-1. A4 인쇄 상자의 안쪽 너비는 **726px** 다 (화면 794px 가 아니다)

PDF 가 4쪽이 아니라 **9쪽**으로 구워졌다. 까닭: `@page{size:A4;margin:9mm}` 이면
안쪽 너비가 192mm = **726px** 이고, 이것이 휴대전화용 중단점
`@media (max-width:820px)` 를 때려 **두 단이 한 단으로 무너지고 표 글자가
8.5px→11px 로 커졌다.**

```css
@media screen and (max-width:820px){ … }   /* ← screen 을 반드시 붙인다 */
@page{size:A4;margin:9mm 9mm 7mm}          /* ← .sheet 안쪽 여백과 같게 */
```

`scripts/check_journal_fit.mjs` 는 **794px 에서 재기 때문에 이 결함을 구조적으로 못 본다.**
그래서 `scripts/journal_to_pdf.mjs` 가 **구운 PDF 의 쪽수를 `.sheet` 개수와 맞대어**
다르면 실패시킨다. 이 검사를 빼지 말 것.

### 3-2. 글꼴은 기계마다 다르게 잡힌다 — **CDP 로 실제 글꼴을 물어본다**

`'Inter','Aptos',sans-serif` 는 리눅스에 **하나도 없다.** CI 는 **Noto Sans KR Thin**
(굵기 100)으로, 세션은 **WenQuanYi Zen Hei**(중국어 글꼴)로 떨어졌다. 7.4px 에
굵기 100 이면 읽히지 않는다.

- 데비안 `fonts-noto-cjk` 는 **`Noto Sans CJK KR`** 로 등록된다. `Noto Sans KR` 로 적으면
  DejaVu 로 떨어진다. **이름을 둘 다 적는다.**
- `journal_to_pdf.mjs` 가 CDP `CSS.getPlatformFontsForNode` 로 **실제로 쓰인 글꼴**을
  찍어 준다. 「맞겠지」 하지 말고 그 줄을 읽을 것.

### 3-3. 「매수 − 매도 = 순매수」 검산은 **단위 착오를 못 잡는다**

KIS 의 `*_tr_pbmn` 은 원이 아니라 **백만원**이다. `1e8` 로 나눠 전부 0억원이 됐는데
**1,568칸 전부 매수−매도 검산을 통과했다** — 그 관계는 어느 단위로 재든 성립하기 때문이다.
그래서 `금액 ≈ 수량 × 종가` 로 **차원을 맞대는** 검사를 따로 뒀다(`unit_sane()`).

- `eok_from_pbmn(v) = v / 100`
- 띠는 **0.5~2.0**, 바닥은 **50억원**. 처음 ±30%·바닥 없음으로 했더니 1~5억원짜리
  네 건이 걸렸는데 전부 반올림이 지배하는 줄이었다(하나는 +280% 상승주).
- 지금 392/392 통과.

### 3-4. 러너의 되받기(rebase)가 **병합 커밋을 펴다가** 충돌을 낸다

2026-09-22 08:10 에 러너가 220개 중 213개를 받아 놓고 **밀어 넣지 못했다.**
`git pull --rebase` 가 앞선 병합 커밋을 다시 펴면서 `docs/briefings/*` 에
add/add 충돌을 냈다. 내 워크플로 둘은 **`git pull --no-rebase`** 로 고쳤고,
그 뒤로 **main 을 작업 가지에 병합하지 않는다.**

> **나머지 26개 워크플로는 아직 `--rebase` 다.** 손대지 않았다. 같은 증상이 보이면
> 여기부터 의심할 것.

### 3-5. 장중에는 원천이 **빈 문자열**을 준다

`frgn_ntby_qty = ''` 인데 `stck_clpr` 에는 값이 있다. 그래서 수집기가 395줄을 쓰고도
순위가 통째로 비었다. `has_flows()` 로 거르고, **쓸 만한 줄이 절반이 안 되면
파일을 쓰지 않고 1 로 끝낸다.** 반쯤 빈 파일이 「오늘 자료」로 둔갑하는 것이
못 받는 것보다 나쁘다.

## 5. 환경에서 알아 둘 것

- **세션은 원천에 직접 못 붙는다.** 네이버·KRX 는 CONNECT 403, KIS 는 **9443 포트**라

- **세션에는 Actions 실행 권한이 없다**(workflow_dispatch → 403). 워크플로를 부르려면
  감시 파일을 밀어야 한다: `data/journal/REFRESH` · `data/journal/KIS_FLOWS` ·
  `data/journal/KIS_PROBE` · `data/market/REFRESH`.
- Secrets: `TELEGRAM_BOT_TOKEN` · `TELEGRAM_CHAT_ID` · `KIS_APP_KEY` · `KIS_APP_SECRET` ·
  `KRX_AUTH_KEY`. **저장소 Secrets 는 계정을 옮겨도 그대로 남는다**(GitHub 쪽이다).
  값을 파일에 적지 말 것.
- **텔레그램 전송기는 Secrets 가 없으면 조용히 건너뛴다.** 보내지 않은 것을
  보냈다고 말하지 말 것.
- KIS 토큰은 24시간 캐시한다(발급이 분당 1회로 묶여 있다). 간격 `prod` 0.15초 /
  `vps` 1.1초, 재시도 코드 `EGW00201`.

# 증권사 리포트 다이제스트 — 운영 인계 문서

마지막 갱신 2026-10-01 · 작성 맥락: 쓰던 Claude 유료 계정을 끝내고 새 계정에서
이어 가기 위해, **대화에만 있고 저장소에는 없던 것**을 옮겨 적는다.

> 이 문서는 「무엇을 어떻게 돌리는가」가 아니라 **「왜 그렇게 정했는가」**를 담는다.
> 파이프라인의 구조·파일 배치는 저장소 최상위 `README.md` 의
> 「증권사 리포트 다이제스트」 절에 이미 적혀 있다. 그쪽을 먼저 읽고 이 문서를 본다.

## 0. 새 계정에서 가장 먼저 할 일

1. 새 Claude 계정에 이 저장소(`hanaroline/work_1`)를 연결한다.
2. 이 문서와 `자주쓰는-프롬프트.md`, `시스템설정-백업.md` 를 읽는다.
3. **예약(Routine)을 새로 만든다.** 예약은 계정에 묶여 있어 **계승되지 않는다.**
   만드는 법과 넣을 문장은 `자주쓰는-프롬프트.md` 의 「예약에 넣을 지시문」 그대로.
4. 첫 판을 뽑아 검산 42개가 통과하는지 확인한다.

### 계정이 바뀔 때 넘어오는 것과 안 넘어오는 것

| | 계승 | 비고 |
|---|---|---|
| 저장소의 코드·스크립트·워크플로 | **O** | git 에 있는 것은 전부 |
| `data/reports/*.json` 수집 이력 | **O** | 날짜별 판이 그대로 남는다 |
| `docs/reports/index.html` 화면 | **O** | |
| 이 인계 문서들 | **O** | 그래서 저장소에 넣는다 |
| **대화 기록(이 채팅)** | **X** | 계정에 묶인다 |
| **예약(Routine)** | **X** | 새 계정에서 다시 만들어야 한다 |
| **채팅으로 올렸던 완성 파일** | **X** | 아래 참고 |

**`out/` 는 저장소에 없다.** `.gitignore` 에 들어 있고 컨테이너는 회수된다.
즉 **지금까지 채팅으로 받은 HTML·PDF 파일은 새 계정으로 넘어오지 않는다.**
다만 **자료 자체는 `data/reports/<날짜>.json` 에 남아 있으므로 언제든 다시 뽑을 수 있다**:

```
bash scripts/make_reports_outputs.sh 2026-09-28     # 그날 판을 그대로 재생성
```

받아 둔 파일이 필요하면 **계정을 끝내기 전에 내려받아 두는 편이 안전하다.**

## 1. 이 일이 무엇인가

평일마다 증권사 리포트를 모아 **요약본 한 장 + PDF 셋**으로 만들어 건넨다.

- 요약은 **발췌(extractive)** 다. 본문에 있는 문장을 그대로 옮긴다.
  **새로 쓰지 않고, 셈을 새로 하지 않는다.**
- 원천 여덟 곳: 네이버 리서치 6갈래(종목·산업·시황·투자·경제·채권) +
  미래에셋증권 리서치 + 하나증권 리서치.
- 세션은 사내 이그레스 정책 때문에 원천에 직접 못 붙는다.
  **러너(GitHub Actions)가 대신 받아 저장소에 커밋하고, 세션은 커밋된 JSON 을 읽는다.**

## 2. 날마다 하는 순서 (이대로만 한다)

```bash
cd /home/user/work_1
git fetch origin main && git checkout main && git reset --hard origin/main
BASE=$(git rev-parse origin/main)          # ← 밀어 넣기 **전에** 적어 둔다

bash scripts/request_reports_refresh.sh "11:00 판"

# 러너 커밋을 기다린다. 「리포트 수집 요청」(내가 민 것)과
# 「리포트 수집 2026-…」(러너가 민 것)을 자릿수까지 구별할 것.
until git fetch -q origin main && \
      [ -n "$(git log --format=%h $BASE..origin/main --grep='^리포트 수집 2026')" ]; do
  sleep 30
done

git reset --hard origin/main
python3 scripts/verify_reports.py data/reports/latest.json   # ← 반드시 **먼저**
bash scripts/make_reports_outputs.sh 2026-10-01              # 통과한 뒤에만
```

마지막으로 `out/` 의 네 파일을 사용자에게 올린다.

### 절대 규칙

- **검산이 통과해야만 자료를 낸다.** 나가는 값이 0 이 아니면 내지 않는다.
  42개 「모두 맞음」이라야 통과. 어긋나면 **무엇이 어떻게 어긋났는지 그대로 옮겨 알린다.**
- **숫자는 실린 값과 직접 센 값을 대조해서 적는다.** 요약에 적힌 수를 그대로 믿지 않는다.
- **목표주가 상하향은 본문 근거를 눈으로 확인한 뒤**에만 적는다. 없으면 「없다」고 적는다.
- **어림하거나 지어내지 않는다. 못 한 것은 못 했다고 적는다.**

## 3. 뽑는 시각 — 왜 11:00 인가

실측으로 두 번 옮겼다. 짐작이 아니라 「수집 시각 ↔ 그날 건수」를 세어 보고 정했다.

| 날 | 08:30 | 09:30 | 10:30 | 11:0x | 13:5x | 19:3x | 22:4x |
|---|---|---|---|---|---|---|---|
| 9/21(월) | — | 09:26 **67** | 10:06 95 | — | — | — | 22:47 **143** |
| 9/22(화) | 7 | 30 | 10:18 43 | 11:18 **72** | 13:56 — | — | 22:46 **89** |
| 9/23(수) | 10 | 34 | 09:55 37 · 10:18 43 | 11:24 **64** | — | — | — |
| 9/28(월) | — | — | 10:33 **94** | 11:47 **113** | 13:56 114 | 19:33 **122** | — |
| 9/29(화) | — | — | 10:33 **81** | — | — | — | — |
| 9/30(수) | — | — | 10:52 **89** | 11:23 **91** | — | — | — |
| 10/1(목) | — | — | — | 11:08 **80** · 11:29 **81** | — | — | — |

읽어 낸 것:

- **08시대는 거의 비어 있다**(7~10건). 09:00~09:30 에 크게 늘고, **11시 무렵까지 이어진다.**
- **09:25 판은 하루치의 절반도 못 담는다**(9/21 은 09:26 에 67건인데 최종 143건).
- 10:30 판도 덜 담는다 — 9/28 은 10:33 94건이 11:47 에 113건(**+20%**)이 됐다.
- **오전에 거의 다 들어오는 날이 많다.** 9/22 는 11:52 에 73건이고 22:46 최종이 89건,
  9/28 도 11:47 113건 → 최종 122건. 오후·저녁 증가분은 대체로 한 자릿수~10건대다.
- 다만 **저녁에 리서치 리포트(데일리·주간물)가 더 붙는 날이 있다**(9/28: 9→17건).

그래서 **평일 11:00** 으로 정했다. 「그 시각까지의 판」이지 하루의 완성본은 아니므로,
**보고에 수집 시각을 반드시 적는다.**

### 시각 변경 이력

| 시점 | 예약 | 비고 |
|---|---|---|
| ~9/22 | 09:25 아침 + 22:45 완성본 | 아침 판이 너무 얇았다 |
| 9/23 | 22:45 → **10:30** 으로 이동, 09:25 는 **끔** | 하루 한 번으로 정리 |
| 10/1 | 10:30 → **11:00** | 10:30 도 덜 담는 것이 사흘 내리 확인됨 |

**서버가 예약 시각의 「분」을 만든 시각에 붙잡는다.** 10:30 으로 걸면 10:31,
11:00 으로 걸면 11:06 에 돈다. 정확히 정시에 고정하는 방법은 확인하지 못했다.

## 4. 검산 42개 — 이것이 마지막 방어선

`python3 scripts/verify_reports.py data/reports/latest.json`

여덟 묶음: **가** 수집 정합성 · **나** 셈 재계산 · **다** 인용 무결성 · **라** 오염 ·
**마** 출처 · **바** 주간 · **사** 원천 상태 · **아** 추출 상태.
**사**와 **아**는 「없는 것」을 찾는 검사다 — 원천이 죽었는지, 요약이 안 붙었는지.

통과하면 「모두 맞음」, 어긋나면 **「산출물을 내지 말 것」**을 찍고 나가는 값 1 을 낸다.

### 실제로 걸렸던 것들

| 검사 | 언제 | 무슨 일이었나 | 어떻게 했나 |
|---|---|---|---|
| `사1 모든 원천이 살아 있음` | 9/30 | 미래에셋·하나 **둘이 한꺼번에** 죽음 | **판을 통째로 재호출** → 2분 48초 만에 여덟 곳 정상 |
| `아2 그날 자에 요약이 붙음` | 9/24·9/25 | 「1건 중 0건(0%)」 | **추석 휴장**이라 리포트 자체가 없던 것. 자료를 내지 않음 |

**원천이 죽으면 수집기 안의 재시도로는 안 된다. 판을 통째로 다시 부르면 된다.**
두 번 불러도 안 되면 **자료를 내지 말고 그 사실을 적어 알린다.**

## 5. 겪은 함정 — 같은 실수를 되풀이하지 않기 위해

### 5-1. 「8분 넘으면 멈춘 것」이라고 단정하지 말 것 ★

9/30 에 수집이 18분 걸렸는데 「워크플로가 안 돈다」고 **잘못 보고했다.**
멈춘 것이 아니라 수집 단계가 오래 걸리는 중이었다(원천 둘이 죽어 시간 초과 대기).
9/25 에 「수집이 안 돌았다」고 한 것도 같은 오진이었을 가능성이 크다.

**8분이 지나면 기다리기를 그만두지 말고, 먼저 실행 기록을 열어 본다:**

```
mcp__github__actions_list(method=list_workflow_runs,
                          owner=hanaroline, repo=work_1, resource_id=reports.yml)
→ status 가 in_progress 면 **기다린다.** list_workflow_jobs 로 어느 단계인지 본다.
→ 아예 실행이 없을 때만 진짜 「안 돈 것」이다.
```

다른 파이프라인(매매 타이밍·시세 수집 등)이 도는지도 함께 보면
저장소·계정 문제인지 이 워크플로만의 문제인지 가려진다.

### 5-2. 자정을 넘긴 수집 ★

`fetch_reports.py` 는 **수집한 날짜**로 날짜 파일을 만든다. 00시 이후에 돌면
새 날짜 파일이 시작되어 무더기가 얇아지고, `report_date` 가 **어제**로 잡히기도 한다.
그런 경우에는 `latest.json` 이 아니라 **날짜를 지정해** 뽑는다.

### 5-3. 자료 구조에서 틀리기 쉬운 자리 ★

손으로 대조할 때 실제로 틀렸던 것들이다.

| 틀리기 쉬운 것 | 바른 것 |
|---|---|
| 행의 증권사를 `r['house']` 로 읽음 | **`r['broker']`** |
| 공통 종목을 `multi_house`/`shared_stocks` 로 읽음 | **`summary['crowded_stocks']`** |
| `summary['by_broker'].items()` | **리스트다.** `{x['broker']: x['count'] for x in s['by_broker']}` |
| 행의 `stock` 을 문자열로 봄 | **dict** — `{'code': ..., 'name': ...}` |
| 주간 건수를 `len(weekly['reports'])` 로 셈 | `weekly['reports']` 는 **브리핑용 추린 목록**(18건쯤). 전체 수는 `weekly['count']` |
| 주간 건수를 **주소**로 중복 제거 | `pool_key()` 가 **쿼리 꼬리를 뗀다.** 미래에셋 한 건이 `categoryId` 만 다른 주소 둘로 잡혀 482 대 481 로 어긋났다 — **검산기가 맞고 손 대조가 틀렸다** |

**대조용 한 줄:**

```python
listed = {x['broker']: x['count'] for x in s['by_broker']}
print("증권사 전부 일치:", listed == dict(collections.Counter(r['broker'] for r in td)))
```

### 5-4. `target_from` 은 직전 목표주가가 아니다 ★

값이 `"api"` 인 행이 많은데 **출처 딱지**이지 가격이 아니다.
직전 목표주가는 자료에 수치로 없는 경우가 많다 — **없으면 없다고 적는다.**

### 5-5. 「상향」이라는 낱말에 속지 말 것 ★

9/23 파두 건에서 본문에 **「실적 추정치를 상향 조정했다」**가 있었는데
이것은 **목표주가가 아니라 실적 추정**이다. 근거로 쓰면 틀린다.
진짜 근거는 따로 있었다 — 「목표주가를 11만원으로 상향 조정하며 매수를 추천한다」.

**목표주가 근거는 「목표주가」라는 말이 들어간 문장으로만 댄다.**

### 5-6. 휴장일

`data/calendar/latest.json` 의 `holidays` 에 KRX 휴장일이 들어 있다.
리포트가 1~2건뿐이면 휴장일부터 의심한다. 2026 추석은 9/24(목)·9/25(금)이었고,
그 이틀은 **자료를 내지 않았다**(검산 아2 가 막았고, 그 판단이 맞았다).

### 5-7. 예약 결과를 확인하지 않아 하루를 날린 적이 있다

`send_later` 호출이 「run_once_at must be in the future」로 **거절됐는데 확인하지 않아**
약속한 산출물이 하루 늦었다. **예약을 걸면 돌아온 발사 시각을 반드시 확인한다.**

---

## 6. 산출물에 관해 정해진 것

### 6-1. 절마다 새 쪽에서 시작 (커밋 `3f125731`)

전체본에서 「오늘자 → 주간 인기 → 전체 목록」이 **각각 쪽 맨 위**에서 열린다.
`docs/reports/index.html` 의 인쇄 CSS:

```css
#weekly-wrap, #listTop { break-before: page; page-break-before: always; }
body.pdf-weekly #weekly-wrap { break-before: auto; page-break-before: auto; }
```

둘째 줄이 중요하다 — 주간본은 `#weekly-wrap` 이 **첫** 덩이라 그냥 두면 **앞에 빈 쪽**이 생긴다.

### 6-2. 애널리스트 실명은 **싣는다** (커밋 `459d4a7d`)

한때 실명을 전부 지웠다가 **되돌렸다.** 지워야 할 이름은 애널리스트가 아니라
**자료를 받는 사람의 이름**이었다. 리포트 작성자 실명은 자료의 일부다.

- 화면·PDF 에 「미래에셋증권 김석환」처럼 증권사 뒤에 붙는다 — 그대로 둔다.
- 받는 이의 이름은 산출물에 **원래부터 없다**(PDF 에 작성자 칸 자체가 없음).
  저장소 전체에서 한 군데 있던 8/6 브리핑 인사말은 지웠다.

### 6-3. 파일 넷

```
out/미래에셋_증권사리포트_YYYYMMDD.html        한 파일 HTML (자료가 안에 박혀 있어 두 번 클릭해 열림)
out/미래에셋_증권사리포트_YYYYMMDD_요약.pdf     그날 판만
out/미래에셋_증권사리포트_YYYYMMDD_주간인기.pdf  주간 절만
out/미래에셋_증권사리포트_YYYYMMDD_전체.pdf     위의 것 + 전체 목록
```

날짜를 지정해 뽑으면 자료가 **두 벌** 박혀 HTML 이 두 배가 된다
(`latest.json` 키와 날짜 키 양쪽에). 담긴 내용은 같다. 가볍게 하려면 `최신` 으로 뽑는다.

---

## 7. 저장소·브랜치 규칙

- **운영은 `main` 에서 한다.** 예약 수집(schedule)은 기본 브랜치의 워크플로만 발동한다.
- 커밋 메시지 끝에 붙이는 줄:

```
Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>
Claude-Session: https://claude.ai/code/session_…
```

- **모델 이름을 저장소에 밀어 넣지 않는다** — 커밋 메시지·PR·코드 주석 어디에도.
  (위 `Co-Authored-By` 는 계정이 지정한 형식이라 예외.)
- **요청하지 않은 PR 을 만들지 않는다.**
- `out/`·`out-test/` 는 `.gitignore` 에 있다. 산출물은 저장소에 남기지 않는다.

---

## 8. 사람에게 보고할 때 담는 것

1. **오늘 자 · 전체 · 주간 건수** — 실린 값과 직접 센 값을 대조했다고 밝힌다
2. 증권사 몇 곳 · 죽은 원천
3. **머리 요약(`summary.overview.text`) 원문 그대로**
4. **목표주가를 올리거나 내린 리포트** — 본문 근거 문장까지. 없으면 「없다」
5. **검산 42개 통과 여부**
6. **수집 시각**과 앞날 같은 시각 판과의 비교

추정과 사실을 섞지 않는다. 「…로 보이지만 이건 제가 확인한 게 아니라 추정입니다」처럼
**어디까지가 확인된 것인지 밝힌다.**

# 자주 쓰는 프롬프트 · 예약 지시문 모음

마지막 갱신 2026-10-01 · 새 Claude 계정에서 그대로 복사해 쓰기 위한 보관본.

---

## 1. 날마다 쓰는 짧은 말

실제로 주고받으며 굳어진 표현들이다. 길게 쓸 필요 없다.

| 하고 싶은 것 | 이렇게 말한다 |
|---|---|
| 지금 기준으로 자료 만들기 | `지금 기준으로 자료 뽑아줘` |
| 한 번 더 (최신 반영) | `지금 다시 뽑아줘` / `지금 한 번 더 뽑아줘` |
| 건수만 궁금할 때 | `지금은 리포트 몇 건 정도야?` |
| 예약 시각 확인 | `오늘 증권사 리포트 자동 생성 예약 시간이 몇 시로 설정돼 있어?` |
| 예약 시각 바꾸기 | `평일 11시에 자동예약되도록 걸어둬` |
| 예약 끄기 | `09:25 예약은 꺼줘` |
| 나중에 하기 | `오늘자도 이따 작업해줘. 11시 정도에 하면 좋겠어.` |
| 예약 시각에 맞춰 하기 | `오늘 예약 시간에 작업해줘` |
| 유입 흐름 묻기 | `가장 많이 들어오는 시간은 대략 언제쯤일까?` |
| 마무리 | `오늘은 이걸로 마무리할게` |

### 날짜를 알려 줄 때

세션의 시계가 UTC 기준이라 **한국 날짜와 하루 어긋나 보일 때가 있다.**
헷갈릴 일을 없애려면 이렇게 시작한다:

```
오늘은 2026년 10월 1일이야.
오늘자 최신 증권사 리포트 자동요약해줘.
```

> 받는 쪽은 `TZ=Asia/Seoul date` 로 **반드시 다시 확인**한다. 하네스가 알려 주는
> 날짜는 UTC 기준이라 저녁·밤에는 한국 날짜가 하루 앞선다.

---

## 2. 예약(Routine)에 넣을 지시문 — **전문 그대로**

새 계정에서는 예약을 다시 만들어야 한다. 아래를 **그대로** 붙여 넣는다.

- 예약 이름: `증권사 리포트 자동 배포 (평일 11:00 KST · 이 대화로 전달)`
- cron: `0 2 * * 1-5`  (UTC 02:00 = 한국 11:00, 평일만)
- 전달 방식: **쓰고 있는 대화로 전달**(persistent session).
  새 대화를 띄우는 방식은 쓰지 않는다 — 그쪽은 저장소에 밀어 넣을 자격이 없어
  아무것도 만들어 내지 못했다.

```text
오늘 자 증권사 리포트를 뽑을 시각입니다(평일 11:00 KST). 늘 하던 순서 그대로, main 에서 합니다.

왜 11:00 인가 — 10:30 판이 하루치를 덜 담는 것을 사흘 내리 실측했습니다.
9/28 은 10:33 에 94 건이던 것이 11:47 에 113 건(+20%), 9/30 도 10:52 89 건 →
11:23 91 건으로 그 시각까지 계속 들어오고 있었습니다. 08 시대는 거의 비어
있고(7~10 건), 09:00~09:30 에 크게 늘었다가 11 시 무렵까지 이어집니다.
다만 하루가 끝난 값은 아니므로, 이 판은 「그 시각까지의 판」이지 완성본이
아닙니다 — 보고에 수집 시각을 반드시 적습니다.

1. git fetch origin main && git checkout main && git reset --hard origin/main

2. 수집을 직접 부릅니다 — 예약(GitHub cron)을 기다리지 않습니다.
   BASE=$(git rev-parse origin/main)   # 밀어 넣기 전에 적어 둔다
   bash scripts/request_reports_refresh.sh "11:00 판"

3. 러너가 끝나기를 기다립니다. 「리포트 수집 요청」(내가 민 것)과
   「리포트 수집 2026-…」(러너가 민 것)을 헷갈리지 않게 자릿수까지 봅니다.
     until git fetch -q origin main && [ -n "$(git log --format=%h $BASE..origin/main --grep='^리포트 수집 [0-9]')" ]; do sleep 30; done
   보통 2 분 30 초~3 분 30 초입니다.

   **8 분이 지나도 안 오면 기다리기를 그만두지 말고, 먼저 실행 기록을
   열어 보십시오.** 9/30 에 18 분이 걸린 적이 있는데, 그때 「안 돈다」고
   보고한 것은 틀린 판단이었습니다 — 멈춘 것이 아니라 수집 단계가 오래
   걸리는 중이었습니다. 멈춘 것인지 느린 것인지는 기록을 봐야 압니다.
     mcp__github__actions_list(method=list_workflow_runs, owner=hanaroline,
       repo=work_1, resource_id=reports.yml)
     → status 가 in_progress 면 기다린다. list_workflow_jobs 로 어느 단계인지 본다.
     → 아예 실행이 없으면 그때가 진짜 「안 돈 것」이다.
   끝내 못 받으면 저장소에 있는 가장 최근 판으로 진행하되 「11:00 수집이
   돌지 않아 ○시 ○분 판을 썼다」고 반드시 적어 알립니다.

4. git reset --hard origin/main 뒤 검산을 **먼저** 돌립니다.
   python3 scripts/verify_reports.py data/reports/latest.json
   나가는 값이 0 이 아니면 자료를 내지 않습니다. 어느 검사가 어떻게 어긋났는지
   그대로 옮겨 알리고, 원인을 찾아 고친 뒤 다시 돌립니다. 42 개 「모두 맞음」이
   나와야 통과입니다.

   **사1 에 원천이 죽었다고 나오면** 곧바로 판을 통째로 한 번 더 부르십시오.
   9/30 에 미래에셋·하나 둘이 한꺼번에 죽었는데(18 분 지연의 원인), 다시
   부르니 2 분 48 초 만에 여덟 곳 모두 정상으로 들어왔습니다. 수집기 안의
   재시도로는 안 되고 판을 통째로 다시 부르면 되는 양상입니다. 두 번 불러도
   안 되면 자료를 내지 말고 그 사실을 적어 알립니다.

5. 통과했으면 그날 날짜를 주어 뽑고 SendUserFile 로 네 파일을 올립니다.
   bash scripts/make_reports_outputs.sh <오늘 날짜 YYYY-MM-DD>

6. 보고에 담을 것 — 숫자는 실린 값과 reports 배열을 직접 센 값을 대조해 적습니다.
   - 오늘 자 몇 건 · 전체 몇 건 · 한 주 몇 건 · 증권사 몇 곳 · 죽은 원천
   - 머리 요약(overview 의 text) 원문 그대로
   - 목표주가를 올리거나 내린 리포트 — 있으면 **본문 근거를 눈으로 확인한 뒤**
     그 문장을 옮겨 적고, 없으면 없다고. 「실적 추정치를 상향」 같은 문장은
     목표주가 근거가 아니므로 쓰지 않습니다.
   - 검산 42 개 통과 여부 · 수집 시각 · 앞날 같은 시각 판과의 비교

어림하거나 지어내지 않습니다. 못 한 것은 못 했다고 적습니다.
```

---

## 3. 새 대화를 시작할 때 던지는 첫 말

계정을 옮긴 뒤 첫 대화에서 맥락을 심는 용도.

```text
이 저장소에서 평일마다 증권사 리포트 다이제스트를 만들어 왔어.
docs/handover/증권사리포트-운영인계.md 와 docs/handover/자주쓰는-프롬프트.md 를
먼저 읽고, 거기 적힌 규칙대로 작업해줘.

특히 이 셋은 꼭 지켜줘:
1. 검산 42개가 「모두 맞음」이라야 자료를 낸다. 어긋나면 내지 말고 그대로 알려줘.
2. 숫자는 실린 값과 직접 센 값을 대조해서 알려줘.
3. 목표주가 상하향은 본문 근거를 눈으로 확인한 뒤에만 적어줘. 없으면 없다고.

오늘은 2026년 ○월 ○일이야. 오늘 자 자료를 만들어줘.
```

## 4. 거드는 말 — 상황별

### 자료를 내지 말아야 할 때 (검산 실패)

> 어느 검사가 어떻게 어긋났는지 그대로 알려줘. 자료는 내지 마.

### 원천이 죽었을 때

> 판을 통째로 한 번 더 불러줘. 두 번 불러도 안 되면 자료 내지 말고 알려줘.

### 수집이 늦을 때

> 멈춘 건지 느린 건지 실행 기록부터 확인해줘.

### 과거 날짜를 다시 뽑고 싶을 때

> 2026-09-28 자 판을 다시 뽑아줘.
> (→ `bash scripts/make_reports_outputs.sh 2026-09-28`)

### 쪽 나눔·표기를 손볼 때

> 기존 판은 그대로 두고 out-test 에 새로 뽑아서 비교해줘.

---

## 5. 이 사람과 일할 때의 결

지금까지 오가며 굳어진 것들. 새 계정에서도 같게 유지하면 좋다.

- **한국어로, 문어체로.** 짧고 단정한 문장. 군더더기 인사 없이 본론부터.
- **숫자는 표로.** 시각별 건수 변화는 표가 제일 잘 읽힌다.
- **틀렸으면 틀렸다고 적는다.** 「앞서 ○○라고 한 것은 틀렸습니다」처럼
  고쳐 적되, 길게 자책하지 않고 바로 다음으로 넘어간다.
- **추정과 사실을 구분해 적는다.** 「…로 보이지만 확인한 것은 아닙니다」.
- **먼저 묻기보다 먼저 재어 본다.** 「11시에 뽑으면 더 늘어날까?」 같은 물음에는
  짐작으로 답하지 말고 **실제로 수집을 한 번 돌려 숫자로** 답했다.
- 작업이 끝나면 **다음에 무엇이 있는지** 한 줄로 알려 준다
  (「다음은 내일(금) 11:06 자동 배포입니다」).

# 시스템 설정 백업 — 증권사 리포트 파이프라인

마지막 갱신 2026-10-01 · 계정을 옮겨도 **설정이 어떻게 생겼는지** 남겨 두기 위한 사본.

> **저장소 안에 있는 것(`.claude/`, `.github/workflows/`, `scripts/`)은 그대로 계승된다.**
> 여기에 베껴 둔 것은 「무엇이 어디에 왜 있는지」 빨리 파악하기 위한 지도이고,
> **계승되지 않는 것은 2절의 예약(Routine)뿐**이다. 그쪽만 새로 만들면 된다.

---

## 1. 저장소에 있는 설정 — 그대로 넘어온다

### 1-1. `.claude/settings.json`

```json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "hooks": {
    "SessionStart": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/session-start.sh"
          }
        ]
      }
    ]
  }
}
```

### 1-2. `.claude/hooks/session-start.sh` — 하는 일

웹 세션이 시작될 때 돈다(`CLAUDE_CODE_REMOTE=true` 일 때만).

- **playwright 1.56.1** 을 깐다. 저장소가 `package.json` 을 `.gitignore` 로 빼기 때문에
  새 세션에는 `node_modules` 가 없다. PDF·화면 시험이 전부 playwright 를 부르므로
  이게 없으면 시작하자마자 막힌다. 판 번호는 **워크플로가 쓰는 것과 같게** 맞춰 둔다.
- **크로미움은 내려받지 않는다.** 이 실행 환경에는 `/opt/pw-browsers` 에 이미 있다.
  다시 받으면 수백 MB 를 세션 몫 디스크에 또 쌓는다.

### 1-3. `.github/workflows/reports.yml` — 수집 워크플로

```yaml
on:
  schedule:
    - cron: '40 23 * * 0-4'   # ① 08:40 KST
    - cron: '25 0 * * 1-5'    # ② 09:25 KST  ← 아침 본진
    - cron: '0 4 * * 1-5'     # ③ 13:00 KST
    - cron: '20 8 * * 1-5'    # ④ 17:20 KST
    - cron: '10 1 * * 1-5'    # ②' 10:10 KST — 본진이 흘렀을 때 메움
    - cron: '20 5 * * 1-5'    # ③' 14:20 KST
    - cron: '40 9 * * 1-5'    # ④' 18:40 KST
  push:
    paths:
      - 'data/reports/REFRESH'
      - 'scripts/fetch_reports.py'
      - 'scripts/probe_reports.py'
  workflow_dispatch:

permissions:
  contents: write
concurrency:
  group: reports-data
  cancel-in-progress: false
```

**알아 둘 것 셋:**

1. **`schedule` 은 기본 브랜치(main)의 워크플로만 발동한다.** 다른 가지에서는 push·수동만 된다.
   운영을 `main` 에서 하는 까닭이 이것이다.
2. **세션은 `workflow_dispatch` 를 부를 권한이 없다**(403). 그래서 `data/reports/REFRESH`
   에 한 줄 적어 밀어 넣는 방식으로 수집을 부른다 — `scripts/request_reports_refresh.sh`.
3. **보조 슬롯(②'·③'·④')은 장식이 아니다.** GitHub cron 은 +65~74분 늦거나 아예
   거르기도 한다. 실제로 본진이 흐른 날을 보조 슬롯이 메운 적이 있다.

### 1-4. 손으로 부르는 수집

```bash
bash scripts/request_reports_refresh.sh "왜 부르는지 한 줄"
```

- `data/reports/REFRESH` 에 요청 줄을 붙이고 커밋·푸시한다 → push 트리거가 워크플로를 깨운다
- 커밋 꼬리에 `Co-Authored-By` / `Claude-Session` 을 자동으로 붙인다
- 푸시 실패 시 `0 2 4 8 16` 초 간격으로 다시 시도
- `.github/workflows/reports.yml` 이 현재 가지에 없으면 **거부**한다
- `data/reports/REFRESH` 에 커밋 안 된 변경이 있으면 **거부**한다

### 1-5. 주요 스크립트

### 1-6. 실행 환경에서 알아 둘 것

- 세션은 **원천에 직접 못 붙는다**(사내 이그레스 정책). 러너가 받아 커밋하고 세션이 읽는다.
- 바깥 HTTPS 는 대리 서버를 지난다. **TLS 검증을 끄거나 `HTTPS_PROXY` 를 지우지 않는다.**

- 임시 파일은 세션 전용 스크래치패드에 둔다. `/tmp` 를 직접 쓰지 않는다.
- `out/`·`out-test/` 는 `.gitignore`. **컨테이너는 회수되므로 만든 파일은 같은 세션에서 건네야 한다.**

## 2. 계승되지 않는 것 — 예약(Routine) ★

**예약은 Claude 계정에 묶여 있다. 저장소에는 없다. 새 계정에서 다시 만들어야 한다.**

### 2-1. 지금 쓰고 있는 예약

| | |
|---|---|
| 이름 | 증권사 리포트 자동 배포 (평일 11:00 KST · 이 대화로 전달) |
| cron | `0 2 * * 1-5` (UTC 02:00 = 한국 11:00, 평일만) |
| 전달 | **쓰고 있는 대화로 전달**(persistent session) |
| 상태 | 켜짐 |
| 지시문 | `자주쓰는-프롬프트.md` 의 2절 전문 |

**옛 ID는 적어 두지 않는다** — 새 계정에서는 쓸모가 없다.

### 2-2. 꺼 둔 예약

평일 09:25 아침 배포가 있었으나 **껐다.** 11:00 판 하나로 충분하고,
두 번 돌면 어느 것이 최신인지 헷갈린다. 새 계정에서는 **만들지 않는다.**

### 2-3. 예약을 만들 때 주의할 점

- **「쓰고 있는 대화로 전달」을 고른다.** 매번 새 대화를 띄우는 방식은
  저장소에 밀어 넣을 자격이 없어 **아무것도 만들어 내지 못했다.**
- **서버가 「분」을 만든 시각에 붙잡는다.** 11:00 으로 걸어도 11:06 에 돈다.
  (10:30 으로 걸었을 때는 10:31 이었다.) 정시 고정 방법은 확인하지 못했다.
- **만든 뒤 돌아온 다음 발사 시각을 반드시 확인한다.** 예약이 거절됐는데
  확인하지 않아 약속한 산출물이 하루 늦은 적이 있다.
- 예약은 **하루 한 번**으로 둔다. 더 필요하면 그때그때 말로 부르는 편이 낫다
  — 수집부터 파일까지 4분이면 끝난다.

### 2-4. 예약이 흘렀을 때

2026-09-19(금)에 **계정의 모든 예약이 하나도 발사되지 않은 날**이 있었다.
리포트뿐 아니라 상품설명의무·ELS·마포WM 장마감까지 전부 비었다 —
파이프라인 결함이 아니라 플랫폼 쪽 공백이었다. 그런 날은 **손으로 부르면 된다.**
