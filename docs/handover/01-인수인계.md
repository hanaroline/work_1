## 1. 이 도구가 하는 일

미래에셋증권 지점 직원이 **미스터리쇼핑**에 대응할 때 쓰는 **완전판매 스크립트 자동완성기**입니다.

상품을 고르면 → 그 상품의 공시 문서를 자동으로 찾아 읽고 → 직원이 **그대로 읽으면 되는 대사**를
빈칸까지 채워서 보여 줍니다. 채우지 못한 칸은 빨간 **확인필요 칩**으로 남겨, 직원이 눌러서
직접 넣거나 상담 중에 받아 적게 합니다.

- **상품군** : 펀드 · 파생결합증권(ELS/DLS/ELB) · 원화채권 · 외화채권 · 개인형 IRP
- **평가 기준** : 미스터리쇼핑 평가표 8시트 × 고령/비고령, 기본 100점 + 가점 3점 = **103점**
- **쓰는 곳** : **인터넷이 없는 업무용PC**. 그래서 파일 하나(`sales-script-standalone-v4.html`)만
  더블클릭하면 돌아가야 하고, 외부로 나가는 요청이 **0건**이어야 합니다 (검사 항목에 있습니다).

## 2. 파일이 어떻게 생겼나

### 산출물 (이것이 직원에게 건네는 물건)


> **판 번호 규칙 (사용자가 정한 것)** — *"기존의 작업분은 그대로 두고"*.
> v1·v2·v3 은 **건드리지 않습니다**. 새 작업은 v4 에 싣고, 큰 변화가 생기면 v5 를 새로 만듭니다.

## 3. 꼭 알아야 할 자료 구조 (여기서 많이 틀립니다)

### 3-1. pool 색인 방식

`data/fund-prospectus.js` 와 `data/fund-catalog.js` 는 둘 다 **`window`** 에 붙습니다
(`globalThis` 가 **아닙니다** — 이것 때문에 한 번 2.7 MB 를 통째로 출력하는 사고가 났습니다).

```js
const win = {};
new Function('window', fs.readFileSync('data/fund-prospectus.js','utf8'))(win);
const P = win.FUND_PROSPECTUS;          // { updatedAt, count, rulesStamp, pool:[...], items:{...} }
const V = x => (typeof x === 'number' ? P.pool[x] : x);   // 풀에 든 항목은 숫자가 색인
```

`data/fund-catalog.js` 는 **어느 항목이 풀에 드는지**를 스스로 말합니다:

```js
pooled: ["mgr","fundType","region","riskLabel","objective","cls"]
```

> **주의** — `clsPExp` / `clsAExp` / `clsCExp` / `clsExp` 는 **풀 색인이 아니라 그냥 숫자**입니다.
> 풀에서 꺼내려 들면 엉뚱한 글자가 나옵니다.

### 3-2. 증분 판독의 기준

```js
refs[code] = (docT ? 'T' : 'G') + docId + '@' + docAt
```

설명서가 바뀐 종목만 다시 읽기 위한 지문입니다.

### 3-3. rulesStamp

`js/sales-script-prospectus.js` 의 djb2 해시입니다. **판독 규칙을 고치면 지문이 바뀌고,
그러면 전량 재판독이 강제됩니다.** 현재 값은 `94127-j04dm7`.

> `--codes` 로 몇 종목만 다시 읽을 때는 **일부러 지문을 올리지 않습니다** — 올리면 3,000건이
> 통째로 다시 돌아 두 시간을 날립니다.

### 3-4. 저장통 키

`js/sales-script-app.js` 20행 : `var LS = 'ss_state_v1'`.
**저장을 한 번 해야 생깁니다** — 새로 연 화면의 localStorage 는 비어 있습니다.

## 4. 쌓아 온 판단들 (되돌리지 마십시오)

이 항목들은 모두 **실제로 틀렸다가 고친 것**입니다. 이유 없이 보이면 다시 틀립니다.

### 펀드 보수

1. **클래스 이름 관례(A/C/P…)를 믿지 마십시오.** 설명서마다 다릅니다.
   **한글 이름표 글자만** 믿을 수 있습니다.
2. **재간접·모자형 펀드**는 인정되는 수치가 `총보수`가 아니라 **`합성 총보수·비용`** 입니다.
3. **보수율 가드(`feeRateOk`)** — 보수율 자리에 들어올 수 있는 값은 `0 < n ≤ 10` 인 숫자뿐입니다.
   이게 없을 때 「연 90,045%」 같은 **예시금액**이나 클래스 이름이 그대로 나갔습니다.
   가드는 **화면(`fundCatDoc`)과 저장분 양쪽**에 걸려 있어야 합니다.
4. **IRP 총보수 출처 우선순위** (`js/sales-script-app.js` 의 `clsExp`/`clsExpClass` 파생):

   ```
   설명서 퇴직연금 클래스 → 카탈로그 퇴직연금 클래스 → 설명서 기재 →
   C클래스 대체 → A클래스 대체 → 없음(확인필요)
   ```

   현재 3,192종목 분포 : **531 / 549 / 0 / 1,500 / 108 / 504**
   (17% / 17% / 0% / 47% / 3% / 16%)

   > **"없음"이 늘어나는 것은 후퇴가 아닙니다.** 틀린 값을 말하느니 확인필요로 두는 편이 낫다는
   > 판단으로 일부러 그렇게 했습니다. 가드를 넣으며 446 → 504 로 늘었습니다.

### 투자자성향

- 성향의 의미는 **투자설명서가 아니라 사내 「투자자성향 결과별 안내사항」 원문**에서 옵니다.
  적합성 원칙 프로세스 쪽이지 상품 쪽이 아닙니다.
- 다섯 성향의 원문은 `tools/verify/prof5.mjs` 의 `WANT` 에 그대로 박혀 있습니다 — **정답지**입니다.
- 옛 판이 쓰던 문장 네 개는 `SUPERSEDED` 맵(`js/sales-script-app.js` 745행 근처)에 올려 두고,
  저장된 화면을 열 때 원문으로 **이관**합니다(805-825행).

### ELB / ELS 문구 갈림

| | ELB (원금지급형 파생결합사채) | ELS (고난도) |
|---|---|---|
| 고난도 안내 | 안 함 | 함 |
| 스텝다운 손실사례 | 안 함 | 함 |
| 「일시에 큰 손실」 | 안 함 | 함 |
| 「20% 초과 손실」 | 안 함 | 함 |
| 원금지급형 안내 | 함 | 안 함 |
| 발행사 신용위험 | 함 | 안 함 |

### 확인필요 분류

`missGroup(m)` 이 확인필요를 다섯 갈래로 나눕니다 — `rec`(추천) / `doc`(설명서) / `ask`(고객에게)
/ `ref`(별도 자료) / `once`(한 번만). 배너 머리글 건수 = 묶음 합 = 칩 개수가 **항상 맞아야** 합니다
(`missall2.mjs` 가 봅니다).

### PDF 글자 뽑기

y 좌표 차이로 줄을 나누고, **8px 넘는 가로 공백은 탭**으로 봅니다. 표를 칸으로 가르는 근거입니다.

## 5. 작업 규칙

### 브랜치 · 커밋

- 개발·커밋·푸시는 **`claude/sales-script`** 한 곳에만.
- `git push -u origin <브랜치>`. 실패하면 **네트워크 오류일 때만** 2s → 4s → 8s → 16s 로 4회 재시도.
  정책 거절(403 등)은 재시도하지 않습니다.
- **PR 은 명시적으로 요청받았을 때만** 만듭니다.
- 커밋 메시지·PR·코드 주석·저장소에 올라가는 어떤 산출물에도 **모델 이름을 넣지 않습니다**.

### 전량 재판독을 돌리는 법

판독은 **GitHub Actions 러너**에서 합니다 (이 컨테이너에서는 원천 사이트가 막혀 있습니다).

```
워크플로 : .github/workflows/fund-prospectus.yml  («펀드 투자설명서 판독»)
입력     : mode = full      → 전량 약 3,200건, 2시간 반 ~ 3시간
           mode = incremental → 설명서가 바뀐 종목만, 몇 분
           codes = "표준코드,표준코드"  → 그 종목만 (mode 무시, 규칙 지문 안 올림)
           limit = 0        → 제한 없음
결과     : data/fund-prospectus.js 로 러너가 직접 커밋·푸시
```

- **규칙을 손보는 중에는 `fund-prospectus-sample.yml`(표본 시험)로 몇 분 만에 확인**하고,
  규칙이 확정된 뒤에 전량을 돌립니다. 전량은 자동 실행을 두지 않았습니다.
- 러너 결과는 **`mcp__github__get_job_logs` 로 로그에서 읽습니다.**
  아티팩트 내려받기는 이 환경에서 막혀 있습니다(Azure blob 403).

### 끝낸 뒤 반드시 하는 일

1. `git pull` 로 러너가 올린 판독 결과를 받는다
2. `node tools/verify/audit-stored.mjs` — **저장된 값 자체**를 훑는다 (화면 가드와 별개)
3. `node tools/verify/irp-dist.mjs` — IRP 출처 분포가 설명 가능한지 본다
4. `node scripts/build_sales_script.mjs sales-script-standalone-v4.html` — 다시 묶는다
5. `tools/verify/` 의 브라우저 검사 여섯 개를 돌린다 (§6)
6. 커밋 · 푸시 · 사용자에게 파일 전달

## 8. 함정 모음 (겪은 것만)

- **`globalThis` 아니고 `window`** — 자료 파일을 `new Function` 으로 읽을 때.
- **빌드 때 파일명 인자를 빼먹으면** v1 을 덮어씁니다.
- **`--codes` 는 규칙 지문을 올리지 않습니다** — 올리면 전량 재판독이 강제됩니다.
- **검사 도구가 틀릴 수 있습니다.** `prof5.mjs` 의 성향 이관 검사는 저장통 키를
  `/sales|script/i` 로 찾고 있어서 `ss_state_v1` 을 영영 못 찾았고, 그래서 **아무것도 심지 못한 채
  조용히 X 를 내고 있었습니다** — 제품 결함이 아니라 검사 결함이었습니다.
- **확인필요 칩은 제 이름표를 글자로 내보냅니다.** `innerText` 만 긁으면 이름표가 값처럼 읽힙니다
  (예: 「총보수는 연 **펀드 총보수 (연)**%」). 값인지 칩인지는 `.v.miss` 의 `data-key` 로 가르십시오.
- **전량 재판독은 3,000건 × 2.6초 ≈ 2시간 반** 입니다. 가볍게 돌리지 마십시오.
