## 1. 무엇을, 왜 만들었나

> "내부망 특정 사이트(오프라인 가능)를 만들어, 내가 생성한 파일들을 수동으로 업로드 저장하고,
> 팀원들이 조회·다운로드할 수 있도록. 접속 비밀번호는 내가 설정·변경할 수 있게."

업무망(폐쇄망)에서 **설치 없이** 도는 팀 자료실입니다. 외부 주소를 하나도 부르지 않습니다.
**판이 둘**이고, 둘 중 어느 것을 쓸지는 **업무망 PC 사정**이 정합니다.

| | **서버판** `fileshare/` | **HTML 한 파일판** `fileshare/html/` |
|---|---|---|
| 필요한 것 | 파이썬 3.7+ (표준 라이브러리만) | 브라우저만 |
| 쓰는 법 | `python server.py` → 팀원이 사내 IP 로 접속 | HTML 더블클릭 → 자료를 담아 **새 HTML 생성** → 전달 |
| 공유 방식 | **실시간** — 올리면 즉시 모두에게 보임 | **스냅샷** — 갱신하면 새 파일을 다시 보내야 함 |
| 접속 기록 | 남습니다 (감사 로그) | 남지 않습니다 |
| 비밀번호 | 조회용·관리자 2단계, 화면·콘솔에서 변경 | 열람 비밀번호 1개 (실제 암호화) |
| 지금 상태 | **보류** — 업무망에 파이썬이 없습니다 | **사용 중** |

### 왜 서버판이 보류인가 — 확인된 제약 둘

사용자 환경을 물어 확인한 결과입니다. 추측이 아닙니다.

1. **업무망 PC 에 파이썬이 없습니다.** (`py -V`·`python -V` 둘 다 버전이 안 나옴)
2. **팀이 함께 쓰는 공유 폴더(네트워크 드라이브)가 없습니다.**

이 둘 때문에 서버도, 공유 폴더에 둔 HTML 도 불가능했고, **HTML 파일 자체가 자료실이 되는**
방식만 남았습니다. 나중에 파이썬이 깔리면 서버판으로 옮기는 것이 훨씬 낫습니다
(실시간 공유 + 접속 기록).

## 3. 결정된 것 — 왜 이렇게 만들었나

### 서버판

| 결정 | 이유 |
|---|---|
| 파이썬 **표준 라이브러리만** | 폐쇄망에서 `pip install` 이 안 됩니다. 저장소 규칙(`CLAUDE.md`)이기도 합니다 |
| 비밀번호 **2단계**(조회용·관리자) | 팀원은 열람만, 올리고 지우고 설정 바꾸는 것은 본인만 |
| PBKDF2-HMAC-SHA256 **24만 회** 해시만 저장 | 원문을 남기지 않습니다. 잊으면 `--set-password` 로 콘솔에서 재설정 |
| 업로드는 **multipart 대신 원시 바디** + `X-File-Name` 헤더 | 파이썬 3.13 에서 `cgi` 모듈이 빠졌습니다. 자체 파서를 두지 않으려고 |
| 파일 실체는 **난수 ID** 로 저장 (`data/blobs/<id>`) | 경로 조작을 원천 차단. 원래 이름은 `index.json` 에 |
| 다운로드는 **항상 `attachment` + `nosniff`** | HTML 을 올려도 사이트 안에서 실행되지 않게 |
| ZIP 은 **1회용 토큰**으로 내려받기 | 메모리에 통째로 들지 않고, blob URL 을 쓰지 않습니다 |
| 데이터는 **`data/` 한 폴더**에 | 그 폴더만 복사하면 백업·이전이 끝납니다 (`.gitignore` 에 넣어 커밋하지 않음) |

### HTML 한 파일판

| 결정 | 이유 |
|---|---|
| **파일 = 저장소** | 브라우저 저장소에 넣으면 그 PC·그 브라우저에만 남아 **공유가 안 됩니다** |
| 비밀번호 = **실제 암호화**(PBKDF2 20만 회 + AES-256-GCM) | 자바스크립트 가림막은 소스만 열면 뚫립니다. `file://` 이 secure context 라 Web Crypto 가 돕니다 |
| 목록·폴더명·공지도 **암호화 대상** | 비밀번호 없이는 파일명조차 보이지 않아야 합니다 |
| **판(rev) 번호 + 기준 시각** 표시 | 스냅샷이라 어느 것이 최신인지 받는 쪽이 알 수 없습니다 |
| 저장 뒤 **전달용 안내 문구** 자동 생성 | 판 번호·파일 수·기준 시각을 함께 보내게 |
| ZIP 생성기를 **직접 구현**(STORE+CRC32) | 외부 라이브러리를 못 씁니다. 파이썬 `zipfile` 로 한글 경로까지 열리는 것을 확인했습니다 |

## 4. 함정 — 실제로 터진 것만 적습니다

### 4-1. ★ `run.bat` 이 더블클릭하면 창이 깜빡이고 닫힌다

**LF 줄바꿈 + 한글(UTF-8)** 로 저장한 배치 파일이 원인이었습니다. `cmd` 는 배치를 CRLF 기준
바이트로 읽기 때문에 `goto`·`pause` 까지 가지 못하고 즉시 끝납니다. `chcp 65001` 을 파일
안에서 부르면 더 나빠집니다 — 파서가 읽던 자리를 잃습니다.

> **고친 방법**: `.bat`·`.cmd` 는 **CRLF + ASCII 본문**, `chcp` 없음. 한글 안내는 파이썬이
> 콘솔에 찍습니다. `.gitattributes` 에 `*.bat text eol=crlf` 를 넣어 다시 LF 가 되지 않게 했습니다.

이 교훈은 `인계-보관본.txt` 8-11 에 이미 적혀 있었는데 **그대로 다시 밟았습니다.**
윈도우용 배치를 만들 때마다 먼저 확인하십시오.

### 4-2. 윈도우의 `python` 은 껍데기일 수 있다

Windows 10/11 은 `python` 을 치면 Microsoft Store 를 여는 **스텁**을 기본 제공합니다.
`where python` 으로 찾으면 걸립니다. 그래서 `py -3` → `python` → `python3` 순으로
**실제로 실행해 보고**(`-c "pass"`) 되는 것만 씁니다.

### 4-3. 빈 틀 HTML 과 자료가 담긴 HTML 을 혼동한다 — 사용자가 실제로 겪음

`team-fileroom.html`(빈 틀)에 자료를 넣고 저장하면 **다운로드 폴더에 이름이 다른 새 파일**이
생깁니다. 사용자는 빈 틀을 다시 열고, 동료에게도 빈 틀을 보냈습니다. 둘 다 "아무것도 없다"로
보였습니다.

> **고친 방법**: ① 제목 옆에 **지금 열고 있는 파일 이름** 상시 표시 ② 빈 틀에는 3단계 안내
> 박스 고정 ③ 저장 직후 **만들어진 파일 이름과 "이 파일을 보내세요"** 안내창 ④ 버튼을
> [자료실 파일 **만들기**]로 ⑤ 저장을 잊고 닫아도 IndexedDB 임시 보관에서 [이어서 작업].

### 4-4. 동료가 받은 파일은 자동으로 갱신되지 않는다 (구조)

사용자가 물은 그대로입니다 — **안 됩니다.** 서버가 없으니 전달 시점의 사본입니다.
없앨 수 없는 성질이라, 숨기지 말고 **판 번호·기준 시각·"담당자에게 새 파일을 요청하세요"**
안내로 드러냈습니다.

### 4-5. CSP `style-src 'self'` 가 인라인 style 을 막는다 (서버판)

업로드 진행률 막대를 `el.style.width` 로 그리다 막혔습니다. `<progress>` 엘리먼트로 바꿨습니다.
서버판 화면에는 인라인 style·script 가 하나도 없어야 합니다.

### 4-6. 페이로드 `<script>` 는 앱 스크립트보다 **앞**에 넣어야 한다

생성 HTML 끝에 자료를 붙였더니, 앱이 읽을 때는 아직 파싱 전이라 늘 "자료 없음"이었습니다.
`body` 맨 앞에 넣고, `DOMContentLoaded` 보호도 함께 두었습니다.

### 4-7. 저장하는 순간의 화면 상태가 그대로 굳는다

`document.documentElement.cloneNode(true)` 로 자기 자신을 직렬화하므로, 그때 `disabled` 였던
버튼과 "만드는 중..." 문구가 생성 파일에 박힙니다. 직렬화 전에 버튼 상태·문구·동적 영역
(`[data-dyn]`)·모달을 **초기 상태로 되돌립니다**. `#folderFilter` 의 option 을 비우지 않아
**폴더명이 평문으로 새던 것**도 같은 자리였습니다.

### 4-8. 이 환경의 headless Chromium 은 비ASCII 파일명을 못 읽는다

`Content-Disposition: ...; filename*=UTF-8''<한글>` 을 주면 `download` 로 저장합니다
(ASCII 는 정상). ICU 자료가 없는 빌드 탓이고 **실제 윈도우 브라우저와 다릅니다.**
헤더는 RFC 6266 대로 맞습니다. 그래서 시험은 **파일명이 아니라 내용(바이트)으로** 확인합니다.

### 4-9. 윈도우가 없어 확인하지 못한 것

`run.bat` 더블클릭 자체는 이 환경에서 시험할 수 없습니다. 사용자가 실제로 눌러 봐야 압니다.
(그래서 cmd 로 직접 실행하는 길을 `START-HERE.txt` 와 README 에 함께 적었습니다.)

## 5. 업무망으로 옮기는 법

인터넷망에서 `python3 fileshare/make_package.py` 를 돌리면 `fileshare/dist/` 에 셋이 생깁니다.
사내 파일전송 시스템이 막는 확장자가 제각각이라 **셋 중 되는 것 하나**를 보내면 됩니다.

| 파일 | 언제 |
|---|---|
| `team-fileshare-<날짜>.zip` | 기본 |
| `team-fileshare-standalone.py` | 압축 반입이 막힐 때 (web 자산까지 한 파일에 base64 로 심음) |
| `team-fileshare-standalone.py.txt` | `.py` 가 막힐 때 (받아서 확장자만 바꿈) |
| `CHECKSUMS.txt` | 전송 뒤 SHA-256 대조 |

HTML 판은 `fileshare/html/team-fileroom.html` **한 파일만** 보내면 됩니다.

## 6. 확인한 것

| | |
|---|---|
| 서버판 | `python3 selftest.py` — **45항목 전부 통과**. 로그인·권한 분리·업로드·Range 다운로드·ZIP·CSRF 차단·경로 탈출 차단·로그인 시도 제한·비밀번호 변경·재시작 후 영속성 |
| 서버판 화면 | 실제 Chromium 으로 업로드→목록→ZIP/개별 다운로드→수정→삭제→설정→기록까지. JS 오류 없음 |
| HTML 판 | `node selftest-browser.mjs` — **47항목 전부 통과**. 암호화 저장→잠금 해제→다운로드 **내용 바이트 일치**→재편집·재저장→폴더 생성·이동·이름변경·삭제 후 파일 보존→실행 취소→교체 버전 증가→암호화 시 폴더명 비노출 |
| 생성 ZIP | 파이썬 `zipfile` 로 열어 한글 폴더·파일명과 CRC 확인 |
| 용량 | 자료 20MB → HTML 약 27MB, 저장 약 2초, 여는 데 약 1초 (원본의 약 1.35배) |

`selftest-browser.mjs` 는 Playwright 가 필요합니다. 크로미움은 `/opt/pw-browsers` 에 이미
있으니 `playwright install` 을 부르지 마십시오(저장소 규칙).

## 7. 열려 있는 일

- **가지가 `main` 에 병합되지 않았습니다.** 합칠지 결정이 필요합니다. `fileshare/` 는
  새 디렉터리뿐이라 충돌은 없을 것으로 보이나, 가지가 2026-08-13 판 `main` 기준이라
  병합 전에 최신 `main` 으로 리베이스하는 편이 깔끔합니다.
- 업무망에 파이썬이 깔리면 **서버판으로 옮기는 것**이 낫습니다 — 실시간 공유와 접속 기록이
  필요한 자료실이라면 더욱.
- `run.bat` 더블클릭 동작은 **아직 실기기 확인 전**입니다(4-9).
- HTML 판은 자료가 늘수록 파일이 커집니다. 사내 메일·메신저 첨부 한도를 보고
  **총 50MB 이하**를 권고해 두었습니다.
