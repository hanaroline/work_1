--------------------------------------------------------------------------------
작업범위는 직접 수정하고, 기준시점은 오늘자 기준으로 해 줘.

  ⓑ 표현 정밀화까지 전부 반영 (문장 변경 폭 큼)
  ⓒ before/after 텍스트 표만 받고 편집은 직접

[ 종목 실명표를 다룰 때 ]
--------------------------------------------------------------------------------

# 3. 이 사람과 일할 때의 결
################################################################################

- 한국어 문어체. 숫자는 표로.
- 짐작보다 먼저 재어 본다. 추정과 사실을 갈라 적는다.
- 틀린 것을 찾으면 "무엇이 틀렸다"에서 끝내지 말고 "바른 값은 무엇이고 출처는
  어디"까지 적는다.
- 내가 앞서 한 말이 틀렸으면 조용히 고치지 말고 철회한다고 밝힌다.
  (8/3 세션에서 릴리 시총 날짜를 오독해 지적했다가 철회한 선례가 있음)
- 질문은 작업을 막을 때만 한다. 막지 않는 것은 가정을 적고 진행한다.
- 보고에는 "확인된 것 / 2차 출처만 있는 것 / 확인 실패한 것"을 나눠 적는다.


################################################################################
# 4. 프로젝트 지침 (저장소 CLAUDE.md 에서 이 갈래에 해당하는 것)
################################################################################

- 날짜와 숫자를 지어내지 않는다. 확인하지 못한 것은 비워 두고 출처 주소와 함께
  남긴다. "아마 이쯤일 것"으로 채우지 않는다.
- 작업은 claude/... 가지에서 하고, main 에는 병합으로 넣는다.
- 파이썬은 표준 라이브러리만 쓴다. (단, pptx 작업에 쓰는 python-pptx·lxml 은
  이 갈래 한정으로 pip 설치가 필요 — scripts/ 에 넣지 말고 세션 안에서만 쓸 것)
- 비밀은 저장소 파일에 넣지 않는다. GitHub 저장소 시크릿에만 둔다.
- 회사 망이 *.translate.goog 를 막는다. 번역 프록시를 쓰지 말 것.
- 고치고 나서 실제로 돌려 보고 결과를 보고한다. 시험이 깨지면 깨졌다고 적는다.

★ 이 갈래가 따로 지키는 것
- 산출물은 받는 즉시 저장소에 커밋한다. 대화로만 주고받은 파일은
  컨테이너가 바뀌면 사라진다. (2026-08-03 수정본을 그렇게 잃었음)

# 6. pptx 수정 작업의 정석 (복사해서 쓰는 절차)
################################################################################

# 0) 준비
pip install python-pptx markitdown openpyxl lxml defusedxml

# 1) 내용 읽기
python3 -m markitdown deck.pptx > deck.md

# 2) 풀기
python3 -c "import sys,zipfile; zipfile.ZipFile('deck.pptx').extractall('unpacked')"

# 3) 슬라이드별 <a:t> 인덱스 뽑기
python3 - <<'EOF'
import re
x=open('unpacked/ppt/slides/slide3.xml',encoding='utf-8').read()
for i,m in enumerate(re.finditer(r'<a:t>(.*?)</a:t>',x,re.S)):
    print(i, repr(m.group(1)))
EOF

# 4) (슬라이드, 인덱스, 기존, 새것) 목록을 만들어 정확 일치 치환
#    - 기존 문자열이 다르면 즉시 중단 (sys.exit)
#    - 같은 슬라이드 안에서는 인덱스 큰 것부터 적용
#    - XML 이스케이프: &  -> &amp;   '  -> &apos;

# 5) 다시 묶기 — 반드시 unpacked 안에서
rm -f ../out.pptx && (cd unpacked && zip -Xrq ../out.pptx .)

# 6) 검증
python3 <pptx스킬>/scripts/office/validate.py out.pptx --original deck.pptx
python3 -m markitdown out.pptx | grep -nE "<고쳤어야 할 옛 문자열들>"

주의 : 원본이 무압축 저장(ZIP_STORED)이면 다시 묶은 파일이 훨씬 작아 보입니다.
       파일이 깨진 게 아니라 압축이 걸린 것입니다. 압축 해제 총량을 비교하십시오.

# 7. 자료에서 반복해서 틀리는 자리 (점검 목록)
################################################################################

이 자료를 다시 볼 때 아래부터 의심하십시오. 전부 실제로 틀렸던 자리입니다.

  [ ] 생산액·수출액이 몇 년도 수치인가        (2023년 값이 들어 있었음)
  [ ] "상반기" 수치를 연간처럼 쓰고 있지 않은가 (기술수출 13조)
  [ ] 고점 대비 낙폭을 기간 수익률 자리에 두지 않았는가 (-37.5%)
  [ ] 글로벌 품목 매출의 기준연도            (키트루다 295억 = 2024년)
  [ ] 이미 승인된 약을 개발 중이라 쓰지 않았는가 (오르포글리프론)
  [ ] 이미 발표된 임상 데이터를 "발표 예정"이라 쓰지 않았는가 (MARIPOSA OS)
  [ ] 비상장사에 주가·투자 관련 서술이 붙지 않았는가
  [ ] 계약 총액만 쓰고 계약금 비중을 뺀 곳이 없는가
  [ ] 환율 환산이 슬라이드마다 다르지 않은가
  [ ] 차트의 연도 라벨이 원 시계열과 맞는가
  [ ] 같은 숫자가 두 슬라이드에서 다르게 적혀 있지 않은가 (국민성장펀드)
