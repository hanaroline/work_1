## 3. 구조 — 데이터가 흘러가는 길

```
GitHub Actions (러너)           GitHub 저장소                브라우저
─────────────────────           ─────────────               ──────────
us100-data.yml      ──┐
  날마다 1회           │
  시세·지표·차트·영문  ├──→  브랜치 us100-data       ──→  us-top100.html
  요약 전체 수집       │        data/us100/                  (raw.githubusercontent
                       │          latest.json                 에서 직접 읽음)
us100-quotes.yml    ──┤          quotes.json
  장중 30분마다 가격   │          ranking.json                 ↓ 가능하면
                       │          chart/*.json              야후에 직접 붙어
us100-ranking.yml   ──┘          bars8y/*.json              실시간으로 덮어씀
  날마다 시총 순위 점검
```

**핵심 한 가지.** 화면은 **데이터를 들고 있지 않습니다.** 파일을 동료에게
전달해도, 그 사람의 브라우저가 `raw.githubusercontent.com` 에서 최신
스냅샷을 직접 읽습니다. 그래서 **시세·지표는 계속 갱신됩니다.**
다만 **100종목 목록은 파일 안에 박혀 있어** 목록을 바꾸면 파일을 다시
배포해야 그 사람 화면도 바뀝니다.

### 수집 일정

| 워크플로 | 언제 | 무엇을 |
|---|---|---|
| `us100-data.yml` | 21:30 · 22:30 UTC (화~토) | 100종목 전체 — 시세·지표·차트·영문 요약 |
| `us100-quotes.yml` | 장중 30분마다 | 가격만 |
| `us100-ranking.yml` | 22:00 UTC (화~토) | 시총 순위 — 편입·제외 후보 추림 |

**수동으로 돌리는 법**(세션 토큰은 `workflow_dispatch` 에 403 이라 push 로 부릅니다):

```bash
# 전체 수집
echo "$(date -u +%F) — 사유" >> data/us100/REFRESH && git add -A && git commit -m "…" && git push origin HEAD:main
# 순위 점검
echo "$(date -u +%F) — 사유" >> data/us100/RANK_REFRESH && …
```

## 4. 유지해야 할 작업 규칙

이 화면을 고칠 때 지킨 원칙입니다. 하나하나 이유가 있어서 생긴 것들이니
새 계정에서도 그대로 이어 주십시오.

### 디자인

- **미래에셋증권 디자인 기준**(`mas-design` 스킬)을 따릅니다 — 오렌지 `#F58220`,
  블루 `#043B72`, 모서리 반경 4px 이하, 승인 폰트.
- **차트 라이브러리를 쓰지 않습니다.** SVG 를 직접 그립니다. 파일 하나로
  어디서든 열려야 하기 때문입니다.
- 한/영 전환은 `data-ko` / `data-en` 속성과 `t(ko, en)` 함수로 합니다.
- 인쇄 CSS 를 함께 유지합니다.

### 글의 말투

- 기업 개요(`PROFILE_KO`)는 **[주력사업 한 줄, 개요 서너 문장(150~350자),
  키워드 나열]** 세 줄 구조입니다.
- 영문 요약을 기계적으로 옮기지 않습니다. 100개가 같은 말투·같은 깊이여야
  합니다. 새로 쓸 때는 **기존 항목 여러 개를 먼저 읽고** 맞춥니다.
- 한자어를 섞은 축약(예: "데이터센터發")을 쓰지 않습니다 — 화면의 다른 곳과
  어긋납니다.
- 확신 없는 수치는 쓰지 않습니다.

### 정직성 — 이 화면에서 가장 중요한 규칙

- **예시 데이터를 실제 시세처럼 보이게 하지 않습니다.** 수집본을 못 읽어
  내장 샘플로 그릴 때는 «예시 데이터 — 실제 시세가 아닙니다» 를 먼저 띄우고,
  "가격 방금" 같은 문구를 쓰지 않습니다.
- **값이 어디서 왔는지 항상 적습니다** — 스트림 / 30분 스냅샷 / 일간 스냅샷 /
  브라우저 직접 / 예시.
- 개요를 고칠 때는 수집된 **영문 요약(`profile.desc`)과 대조**합니다. 근거가
  없으면 일반 상식이라도 적지 않거나, 적었다면 그 사실을 알립니다.

### 화면 설정의 처음 상태

- **새 파일을 처음 열면 저장된 설정을 전부 지웁니다.** 브라우저는 `file://`
  로 연 로컬 HTML 을 전부 **한 저장소로 묶기 때문에**, 새로 내려받은 파일이
  옛 파일의 체크박스·즐겨찾기를 그대로 물려받습니다. 그래서 `BUILD` 와 파일
  위치를 합친 도장을 찍어 두고, 도장이 다르면 지웁니다. 지웠으면 화면에
  «무엇을 지웠는지» 한 줄로 알립니다.
  → `var BUILD` · `STORE_KEYS` · `buildStamp()` · `renderRestoredNote()`
- **자동 갱신은 처음에 꺼져 있습니다.** 켜 두면 열어 두기만 해도 계속
  받아옵니다.
- **비교 칸은 비어서 시작합니다.** 예전에는 섹터 상위로 자동으로 채웠는데,
  그러면 «설정이 안 지워진 것»처럼 보여 오해를 샀습니다. 지금은 빈 상태에
  «채우기» 버튼을 둡니다.

### 코드

- **목록을 두 곳에 두지 않습니다.** 수집기는 `us-top100.html` 의 `COMPANIES`
  배열을 읽습니다.
- **같은 계산을 두 곳에 쓸 때는 맞대어 봅니다.** 비율 보정은 수집기
  (`fetch_us100.py` 의 `reconcile_ratios`)와 화면 양쪽에 있고,
  `scripts/check_us100_ratios.mjs` 가 둘이 같은 답을 내는지 검사합니다.
  수집본만 고치면 반쪽만 고친 것입니다 — 브라우저가 야후에 직접 붙어
  같은 값을 다시 받아 덮어쓰기 때문입니다.
- **목록은 도구로만 고칩니다**(5절). 손으로 고치면 네 군데 중 한 곳을 빠뜨립니다.

## 5. 100종목 목록을 바꾸는 법

`us-top100.html` 안에서 종목 하나는 **네 곳**에 흩어져 있습니다 —
`COMPANIES`(심볼·영문명·한글명·섹터), `KEYWORDS`(검색어), `FOREIGN`(해외 본사),
`PROFILE_KO`(기업 개요). 넷 중 하나만 빠져도 화면이 망가지므로
**반드시 `scripts/us100_list_tool.py` 로 고칩니다.**

```bash
# 1. 지금 바꿀 만한 후보 보기
python3 scripts/us100_list_tool.py report

# 2. 계획서를 쓰고 (한글명·개요는 사람 또는 Claude 가 직접 씁니다)
#    plan.json 형식:
#    {"add":[{"sym":"DELL","en":"Dell Technologies","ko":"델 테크놀로지스",
#             "sector":"it","keywords":"서버 스토리지 PC","foreign":null,
#             "profile":["한 줄","서너 문장","키워드 나열"]}],
#     "drop":["INTU"]}
python3 scripts/us100_list_tool.py apply --plan plan.json --dry-run
python3 scripts/us100_list_tool.py apply --plan plan.json

# 3. 개요만 고칠 때 (키워드를 안 적으면 기존 값이 그대로 남습니다)
python3 scripts/us100_list_tool.py edit --plan edit.json

# 4. 고치지 않고 검사만
python3 scripts/us100_list_tool.py validate
```

### 안전장치 — 사람이 바꾸라고 하기 전까지 그대로 둡니다

| 상수 | 값 | 왜 |
|---|---|---|
| `TARGET` | 100 | 목록은 언제나 정확히 100개 |
| `ADD_RANK_MAX` | 100위 | 편입은 지금 시총 100위 안에 든 종목만 |
| `DROP_RANK_MIN` | 130위 | 제외는 130위 밖으로 밀려난 종목만 (순위가 오가는 구간은 건드리지 않습니다) |
| `MAX_SWAPS` | 3 | 한 번에 셋까지 — 화면이 주마다 낯설어지지 않게 |
| `PROTECTED` | TSM, ASML | 사용자가 담아 달라고 한 종목은 순위와 무관하게 둡니다 |
| 거래 확인 | 필수 | 일봉 20개가 받아져야 편입합니다 |

`apply` 는 **편입 수 = 제외 수** 일 때만 돕니다. 고친 뒤 검사에 걸리면
**아무것도 쓰지 않습니다.**

> **거래 확인은 왜 러너가 하는가.** Claude 세션의 이그레스 정책이
> `query1.finance.yahoo.com` 을 막습니다(프록시가 CONNECT 에 403). 그래서
> `check_us100_ranking.py` 가 러너에서 확인해 그 결과를 `ranking.json` 의
> `tradable` 에 적어 두고, 도구는 그 값을 먼저 씁니다.

|---|---|

**아래 글을 그대로 복사해 넣으십시오. 요약하거나 줄이면 그만큼 품질이 떨어집니다.**

```
저장소 hanaroline/work_1 의 주간 작업입니다. 미국 100대 기업 화면(us-top100.html)의 대상 목록을 지금 시가총액 상위 100에 맞춰 갈아 끼웁니다. 바꿀 것이 없으면 아무것도 하지 않고 끝냅니다(빈 커밋 금지).

이 세션에는 GitHub MCP 도구가 없습니다. 모든 확인은 git 명령으로 합니다.

1) 준비
   - `git fetch origin main && git checkout main && git pull --ff-only origin main`
   - 최신 점검 결과:
     `git fetch --quiet origin "+refs/heads/us100-data:refs/remotes/origin/us100-data"`
     `mkdir -p data/us100 && git show origin/us100-data:data/us100/ranking.json > data/us100/ranking.json`
   - ranking.json 의 builtAt 이 사흘 넘게 낡았으면 `data/us100/RANK_REFRESH` 를 한 줄 고쳐 push 해 점검을 먼저 돌리고, 3분쯤 뒤 다시 받으십시오.

2) 후보 확인
   - `python3 scripts/us100_list_tool.py report`
   - "이번 주에 바꿀 것이 없다" 면 여기서 끝냅니다. 커밋하지 말고, 사용자에게 알리지도 마십시오.
   - "후보를 하나도 확인하지 못했다"(야후에 못 나감)면 교체하지 말고 그 사실만 한 줄로 보고하고 끝냅니다. 확인 없이 목록을 바꾸면 안 됩니다.

3) 한글 자산 쓰기 — 이 작업의 핵심입니다
   편입할 종목마다 아래를 직접 씁니다. us-top100.html 의 기존 PROFILE_KO 항목을 여러 개 먼저 읽고 같은 말투·길이·구체성으로 맞추십시오. 영문 요약을 그대로 옮기지 마십시오.
   - ko: 한글 기업명. 국내에서 통용되는 표기(램리서치, 어플라이드 머티리얼즈, 크라우드스트라이크처럼). 통용 표기가 없으면 영문명을 그대로 둡니다 — 어색한 음차보다 낫습니다.
   - sector: us-top100.html 의 SECTORS 맵에 있는 코드(it, comm, cd, cs, hc, fin, ind, eng, mat, util, re).
   - keywords: 검색용 한글 낱말 몇 개.
   - foreign: 본사가 미국이 아니면 ["한글 국가명","English"], 아니면 null.
   - profile: [주력사업 한 줄, 개요 서너 문장(150~350자), 키워드 나열] 세 줄. 개요에는 매출 구조·경쟁력·실적을 좌우하는 변수를 담습니다. 데이터 브랜치의 latest.json 에 있는 profile.desc(영문 요약)와 회사의 공개 정보에 근거해 쓰고, 확신 없는 수치는 쓰지 마십시오.

4) 반영
   - plan.json 을 만들고 `python3 scripts/us100_list_tool.py apply --plan plan.json`
   - 도구가 거부하면 사유를 고쳐 다시 시도하십시오. 도구를 우회해 파일을 직접 고치지 마십시오.
   - `data/us100/REFRESH` 에 오늘 날짜 한 줄을 적습니다 — 이 파일이 push 되면 전체 수집 워크플로가 곧바로 한 번 더 돕니다(세션 토큰으로는 workflow_dispatch 가 403 이라 push 로 부릅니다).

5) 올리기
   - 브랜치 `claude/us100-weekly-list` 에 커밋하고 `git push -u origin claude/us100-weekly-list`,
     그 다음 main 을 그 브랜치로 fast-forward 해 push 합니다(이 저장소의 기존 방식입니다).
   - 커밋 메시지는 한국어로, 무엇을 넣고 뺐는지와 각 종목의 현재 순위·근거를 적습니다.

6) 수집 확인 (git 으로만)
   - push 뒤 8~12분 기다렸다가
     `git fetch --quiet origin "+refs/heads/us100-data:refs/remotes/origin/us100-data"`
     `git show origin/us100-data:data/us100/latest.json` 에서 새 종목이 companies 에 들어왔는지,
     가격·시총·차트가 채워졌는지 확인합니다.
   - 들어오지 않았으면 그 종목을 되돌리는 편이 낫습니다(같은 도구로 반대 방향 plan 을 적용).

7) 보고
   - 교체했으면 사용자에게 한국어로 짧게: 넣은 종목·뺀 종목·순위, 새 판 번호(var BUILD), 수집 확인 결과.
   - 바꿀 것이 아예 없었으면 보고하지 마십시오.
   - **후보는 있었는데 교체하지 않고 끝낸다면, 이유를 반드시 한 줄로 보고하십시오.** 조용히 끝내면 안 됩니다.

규칙
   - 안전장치(100위/130위/최대 3종목/TSM·ASML 보호/시세 확인)는 사람이 바꾸라고 하기 전까지 그대로 둡니다.
   - 목록은 언제나 정확히 100개여야 합니다.
   - 검사를 통과하지 못한 결과는 절대 push 하지 마십시오.
```

## 9. 배포 — 동료에게 줄 때

### 인터넷이 되는 PC

`us-top100.html` 파일 하나만 주면 됩니다. 저장소가 **공개(public)** 라
계정도 토큰도 필요 없습니다.

- 시세·지표·차트·기업 개요 → **계속 갱신됩니다.**
- 100종목 목록 → **파일 안에 있습니다.** 목록을 바꾸면 파일을 다시 주어야
  그 사람 화면도 바뀝니다. 그 전까지 그 사람의 100종목은 그대로입니다.

### 인터넷이 안 되는 업무망

**열립니다. 다만 그 PC 에서 처음 열린 순간의 내용이 아니라, 파일에 아무
데이터도 없는 상태로 열립니다** — 화면은 내장 예시 데이터로 그리고
«예시 데이터 — 실제 시세가 아닙니다» 를 띄웁니다. 구조·사용법을 보여 주기엔
충분하지만 **수치를 믿어서는 안 됩니다.**

업무망에서 실제 수치를 보려면 **오프라인 버전**을 주십시오. 수집본을 파일
안에 넣어 둔 것이라 인터넷 없이도 그날 수치가 그대로 보입니다(대신 그
시점에서 멈춥니다). 만드는 법은 `README.md` 를 보십시오.

### 사내망에서 막히는지 확인하는 법

화면 아래 **⑩ 설정 → «연결 점검»** 버튼을 누르면, 수집 파일 / 야후 직접 /
스트리밍 / 사내 폴더 / 사내 프록시를 차례로 찔러 보고 **무엇이 어떤 식으로
막혔는지**(시간 초과 · 프록시 인증 407 · 차단 403 · 정책 451 · 연결 거부)
표로 보여 줍니다. 결과를 복사해 전산팀에 그대로 보내면 됩니다 —
"인터넷이 안 돼요" 보다 훨씬 빨리 풀립니다.

## 10. 겪은 함정 (같은 실수를 되풀이하지 않도록)

| 함정 | 무슨 일이 있었나 |
|---|---|
| **새 파일인데 설정이 남아 있다** | `file://` 로 연 파일은 **전부 한 저장소를 공유**합니다. 새로 내려받아도 옛 파일의 체크박스가 그대로 켜져 보입니다 → `BUILD` + 파일 위치 도장으로 해결 |
| **지웠는데도 체크가 보인다** | 설정은 멀쩡히 지워졌는데 `cmpFillPeers()` 가 처음에 3종목을 자동으로 담아서 «안 지워진 것»처럼 보였습니다 → 자동 채우기를 없앴습니다 |
| **스냅샷 키 이름을 틀렸다** | 시세 항목은 `cap`·`per`·`fwdPer`·`eps`·`opMargin` 입니다(`marketCap`·`trailingPE` 가 아닙니다). 차트는 `{daily:{d,o,h,l,c,v}}` 입니다(`daily.close` 가 아닙니다) |
| **섹터 코드를 짐작했다** | `ene`·`ut` 가 아니라 **`eng`·`util`** 입니다. 짐작하지 말고 화면의 `SECTORS` 를 읽으십시오 |
| **배열에 쉼표를 안 넣었다** | `FOREIGN` 마지막 항목 뒤에 쉼표가 없어 새 항목을 붙이자 JS 문법 오류 → 도구의 `comma_ready()` 가 처리합니다 |
| **`BRK-B` 를 못 찾았다** | 개요 키가 `'BRK-B':` 처럼 따옴표에 싸여 있습니다 |
| **세션에서 야후에 못 나간다** | 이그레스 정책이 막습니다. 러너를 써야 합니다 |
| **로컬 시험 서버가 «차단 상황»이 아니었다** | 시험용 폴더가 `data/` 를 함께 서빙해 상대 경로로 수집본이 읽혔습니다. 차단 상황은 **빈 폴더에서 `file://`** 로 시험해야 합니다 |

## 11. 질문: 새 계정에 연동하면 과거 작업이 계승되는가

**반은 그렇고 반은 아닙니다.**

- **파일·데이터·자동화·이력 → 전부 계승됩니다.** GitHub 에 있기 때문입니다.
  날마다 도는 수집은 계정과 무관하게 계속 돕니다.
- **대화 기록과 예약은 계승되지 않습니다.** Claude 계정에 묶여 있습니다.
  새 계정은 빈 대화 목록으로 시작합니다.

그래서 이 문서가 있습니다. **새 계정의 첫 대화에서 이 문서를 읽히면,
«왜 그렇게 만들었는지»까지 포함해 맥락이 이어집니다.**
