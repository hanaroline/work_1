[1] 작업 규칙 — 새 대화에서 한 번 못박아 두기
-------------------------------------------------------------------------------

이 작업의 규칙입니다. 대화 내내 지켜 주세요.

· 개발·커밋·푸시는 claude/complete-sales-script-automation-cjsx8e 브랜치에만 합니다.
· git push -u origin <브랜치> 를 씁니다. 네트워크 오류일 때만 2s·4s·8s·16s 로 4회 재시도하고,
  정책 거절(403 등)은 재시도하지 않습니다.
· PR 은 내가 명시적으로 요청할 때만 만듭니다.
· 커밋 메시지·PR·코드 주석 등 저장소에 올라가는 어떤 것에도 모델 이름을 넣지 마세요.
· 기존 작업분은 그대로 둡니다 — sales-script-standalone.html / -v2 / -v3 은 건드리지 않고,
  현재 작업본은 -v4 입니다.
· 빌드는 반드시 파일명을 주어서 합니다:
    node scripts/build_sales_script.mjs sales-script-standalone-v4.html
· 작업이 끝나면 tools/verify/ 의 검사 여덟 개를 돌려 결과를 보여 주세요.
· 설명은 한국어로, 과장 없이. 안 된 것은 안 됐다고 그대로 말해 주세요.

-------------------------------------------------------------------------------

  ※ 규칙을 다듬는 중이라면 전량 대신 표본부터:
    .github/workflows/fund-prospectus-sample.yml — 몇 분이면 끝납니다.

  ※ 몇 종목만 다시 읽을 때:
    mode 는 무시되고 codes 에 표준코드를 쉼표로 주면 됩니다. 규칙 지문은 올라가지 않습니다.

[3] 판독이 끝난 뒤 — 받아서 묶고 검증하기
-------------------------------------------------------------------------------

러너 판독이 끝났습니다. 아래 순서로 해 주세요.

 1. git pull 로 data/fund-prospectus.js 를 받는다
 2. node tools/verify/audit-stored.mjs   — 저장된 값 자체를 훑는다
 3. node tools/verify/irp-dist.mjs       — IRP 총보수 출처 분포
 4. node scripts/build_sales_script.mjs sales-script-standalone-v4.html
 5. tools/verify/ 의 브라우저 검사 여섯 개를 돌린다
 6. 커밋·푸시하고 완성본 파일을 올려 준다

직전 판과 숫자가 달라진 곳은 왜 달라졌는지 함께 설명해 주세요.
