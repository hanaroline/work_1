## 0. 먼저 — 이 갈래는 왜 이렇게 생겼나

요구가 한 줄이었습니다. **「외부 사람은 못 보고 같은 부서 직원끼리는 같이 보게」.**
거기서 출발해 선택지를 하나씩 지우고 지금 모양에 닿았습니다. 되돌아와 다시
논의하지 않도록 **지운 이유**를 남깁니다.

| 검토한 것 | 왜 지웠나 |
|---|---|
| 개인 클라우드(구글드라이브·드롭박스 등) | 금융사 DLP 에 막히고, 막히지 않아도 자료 반출입니다 |
| GitHub 저장소를 직접 보게 하기 | 부서원마다 GitHub 계정이 필요하고, 웹에서 HTML 이 **렌더링되지 않습니다**(소스만 보임) |
| Claude Artifact 로 게시 | 보는 사람도 **Claude 계정**이 있어야 합니다. 부서원 대부분이 안 씁니다 |
| 정적 사이트 + 자바스크립트 비밀번호 확인 | **보안이 아닙니다.** 자료가 평문으로 들어 있어 소스만 열면 그대로 보이고, 파일 주소를 직접 치면 암호 화면을 건너뜁니다 |
| GitHub Pages 로 공개 | 저장소가 공개여야 하고, `pages.yml` 의 `_site` 구조를 무너뜨리면 브리핑·시세가 전부 노출됩니다 (`마포WM-링크페이지-인계.md` 10절) |

**남은 것** — 자료 전체를 **AES-256-GCM 으로 실제 암호화**해 한 파일에 넣는 방식.
암호가 곧 복호화 키라 암호를 모르면 꺼낼 것이 없습니다. 그래서 **파일을 어디에
두어도 됩니다** — 공유 드라이브, 메일 첨부, 아무 웹호스팅. 보는 쪽은 계정이
필요 없습니다.

## 1. 파일 구성

모두 `부서자료실/` 아래입니다.

| 파일 | 하는 일 |
|---|---|
| `분류.json` | **어떤 경로를 어느 분류에 넣을지.** 손댈 곳은 거의 여기뿐입니다 |
| `_목록갱신.py` | `분류.json` 을 읽어 `자료실.html` 안의 목록을 다시 씀 (표준 라이브러리만) |
| `자료실.html` | 저장소용 색인. 원본을 **상대경로로 가리킵니다** |
| `_아티팩트빌드.py` | 가리키던 자료를 **페이지 안에 담아** 단일 HTML 생성 |
| `_암호본빌드.mjs` | 그 결과를 통째로 암호화해 **잠금 화면 한 장**으로 포장 (Node 내장 crypto) |
| `_목록갱신.cmd` / `.ps1` | 윈도우용. **폴더 모드만** 지원합니다 (3절) |
| `자료/` | 폴더 모드로 쓸 때의 빈 분류 폴더 + `.gitignore` |
| `.github/workflows/archive-index.yml` | `main` 에서 자료가 바뀌면 목록을 자동 갱신 |

## 2. 돌리는 법 — 세 단계

```bash
cd 부서자료실
python3 _목록갱신.py                              # ① 목록 갱신
python3 _아티팩트빌드.py /tmp/게시본.html          # ② 자료를 페이지에 담음
node    _암호본빌드.mjs /tmp/게시본.html 부서자료실.html   # ③ 암호 걸기
```

- ③ 에서 `--pw "원하는-암호"` 를 주면 그 암호를, 주지 않으면 20자 암호를
  새로 뽑아 화면에 찍습니다. **12자 미만은 빌드를 거부합니다.**
- 암호는 **파일 어디에도 저장되지 않습니다.** 잃어버리면 복구 수단이 없습니다.

### 2026-10-01 기준 결과

| | |
|---|---|
| 담은 자료 | **90건** — 운영 화면 11 · 브리핑 10 · 인계 문서 21 · 제안 엑셀 3 · 워크플로 45 |
| 크기 | 원본 8.4 MB → 게시본 8.4 MB → **암호본 11.2 MB** |
| 해제 시간 | 올바른 암호 1.9초 / 틀린 암호 0.4초 거부 (실제 브라우저 측정) |

**담지 않는 것 — 의도적입니다.** `data/`(107MB, 수집 원본), `scripts/`(152개),
브리핑 **전판 133판 중 최근 10판만**. 전부 담으면 50MB 를 넘겨 열리지 않습니다.
빠진 것은 저장소에 그대로 있습니다.

## 3. 모르고 손대면 사고가 나는 것

1. **iframe 에 `srcdoc` 을 넣는 순서.** 반드시 **DOM 에 붙이고, 열람창을 띄운
   뒤에** 넣어야 합니다. 떨어져 있는 iframe 이나 `hidden` 인 상태에서 넣으면
   브라우저가 로드를 미뤄 **빈 화면**이 뜹니다. 실제로 이 증상으로 한참 헤맸습니다.

2. **`_목록갱신.cmd`(PowerShell 판)는 폴더 모드만 지원합니다.** `분류.json` 이
   있으면 잘못된 목록을 쓰는 대신 **멈추고** Python 쪽을 안내합니다. 윈도우에서
   설정 모드로 돌리려면 `python _목록갱신.py` 를 쓰십시오.
   (PowerShell 판은 이 환경에 PowerShell 이 없어 **한 번도 실행 검증을 못 했습니다.**)

3. **바이너리 확장자를 `BINARY_EXT` 에 빠뜨리지 마십시오.** 빠뜨리면 엑셀 같은
   파일을 텍스트로 읽어 **깨진 글자가 통째로** 들어갑니다. `.xlsm` 이 실제로 그랬습니다.

4. **`date_from_name` 을 쓰십시오.** git 으로 내려받으면 모든 파일의 날짜가
   **내려받은 시각**이 되어 최신순 정렬이 무의미해집니다. 이름에 날짜가 있는
   자료는 거기서 뽑아야 맞습니다.

5. **`자료실.html` 만 따로 복사하면 링크가 전부 끊깁니다.** 상대경로이므로
   저장소를 통째로 둔 채 열어야 합니다. (암호본은 자료가 안에 있어 해당 없음.)

6. **헤드리스 크로미움의 `--virtual-time-budget` 으로는 이 화면을 검증할 수
   없습니다.** 타이머·비동기 암호 연산이 끝나기 전에 화면을 찍어 **빈 화면으로
   오판**합니다. Playwright 로 실제 브라우저를 몰아야 합니다. 그때
   `executablePath: '/opt/pw-browsers/chromium-1194/chrome-linux/chrome'` 을
   반드시 주십시오(설치된 playwright 가 다른 판의 브라우저를 찾습니다).

7. **암호를 자료와 같은 경로로 보내지 마십시오.** 메일에 파일을 붙였다면 암호는
   전화나 사내 메신저로 따로 보내야 합니다.

## 4. 이 방식의 한계 — 알고 쓰십시오

공용 암호 하나를 나눠 쓰는 구조입니다. 다음은 **고칠 수 없는 성질**입니다.

- **사람별로 끊을 수 없습니다.** 퇴사·전출이 생기면 암호를 바꾸고 **파일을 다시
  만들어 전원에게 다시 돌려야** 합니다.
- **누가 열었는지 기록이 남지 않습니다.**
- **오프라인 대입이 가능합니다.** 암호문을 가진 사람은 시간을 들여 암호를 맞춰
  볼 수 있습니다. 그래서 PBKDF2 를 310,000 회 돌려 한 번의 시도를 느리게 만들고
  암호를 20자로 뽑습니다. **짧은 암호로 바꾸면 이 방어가 무너집니다.**

자료 민감도가 올라가면 **회사 계정으로 인증하는 사내 공간**(SharePoint·사내 위키·
인트라넷 웹서버)으로 옮기십시오. 위 셋이 한꺼번에 해결됩니다.
