## 1. ★ 가장 먼저 — 계정을 바꾸면 무엇이 넘어오고 무엇이 사라지는가

물으신 그대로 답하면, **「github 저장소를 연동하면 과거 프롬프트·작업내용·완성파일이
계승되는가」 → 절반만 맞습니다.** 저장소에 있는 것만 계승됩니다.

| | 계승 | 왜 |
|---|:---:|---|
| 코드·스크립트·워크플로 | **O** | git 에 있다 |
| 수집한 자료 (`data/**`) | **O** | git 에 있다 |
| 발행한 화면·문서 (`docs/**`) | **O** | git 에 있다 |
| 작업 가지 60여 개 전부 | **O** | git 에 있다 |
| **저장소 Secrets** (텔레그램·KIS·KRX 키) | **O** | GitHub 쪽에 있다. 다시 넣지 않아도 된다 |
| GitHub Actions 예약(`schedule:`) | **O** | 워크플로 파일 안에 있다 — **계정과 무관하게 계속 돈다** |
| 인계 문서들 (`docs/handover/`) | **O** | 그래서 저장소에 넣었다 |
| **대화 기록 (지금까지의 모든 채팅)** | **X** | 계정에 묶인다 |
| **예약(Routine) 12개** | **X** | 계정에 묶인다. **새로 만들어야 한다** |
| **아티팩트 (브리핑 목록·자료실 색인 등)** | **X** | 계정에 묶인다. 링크가 죽는다 |
| **채팅으로 받은 HTML·PDF 파일** | **X** | `out/` 은 `.gitignore` 이고 컨테이너는 회수된다 |
| 세션 자체 (`session_…`) | **X** | 예약이 「쓰던 대화로 전달」하던 창들이 끊긴다 |

### 그래서 계정을 끝내기 **전에** 해야 할 일

1. **예약 지시문을 옮겨 적는다** → 끝냈다. `docs/handover/예약-Routine-전문-백업.md`
2. **받아 둔 파일 중 손에 꼭 쥐고 있어야 할 것은 지금 내려받는다.**
   다만 **대부분은 다시 뽑을 수 있다** — 자료가 `data/**` 에 남아 있다.
   - 증권사 리포트: `bash scripts/make_reports_outputs.sh 2026-09-28`
   - 브리핑: `bash scripts/make_outputs.sh docs/briefings/<날짜>.html`
   - 시장일지: `python3 scripts/build_journal.py` 뒤 `node scripts/journal_to_pdf.mjs`
3. **아티팩트 중 주소를 고정해 쓰던 두 장**은 새 계정에서 새로 만들고 주소를 갈아야 한다.
   - 브리핑 목록 `d71cdafd-…` · 세션 산출물 색인 `fa511243-84ca-461c-9e58-e373d851e6fa`
4. 새 계정에서 저장소를 연결한 뒤 **예약을 다시 만든다**(위 1번 문서의 13절 차례대로).

> **GitHub Actions 예약은 건드릴 필요가 없다.** main 에 있는 워크플로 44개는
> 계정과 상관없이 계속 돈다. 사람이 다시 만들어야 하는 것은 **Claude 예약**뿐이다.

## 4. 유지해야 할 작업 규칙 — 어느 일감에서나 같다

### 4-1. 자료를 다루는 규칙

1. **짐작하지 말고 재어 본다.** 「16시에 기관 자료가 올까?」 같은 물음에 추측으로
   답하지 않는다. 시각별로 여섯 번 재어 표로 답했다. 이 저장소의 거의 모든 설계가
   그렇게 정해졌다.
2. **검산을 통과하지 못한 자료는 내지 않는다.** 증권사 리포트 42개, 시장일지 ①~⑦,
   펀드 일곱 자리. 오류가 있으면 **짓지 말고 어긋난 자리를 그대로 알린다.**
3. **없는 수치는 지어내지 않는다.** 비워 두고 「확인하지 못했다」고 적는다.
   (예: 종목별 사모펀드 순매수 · VKOSPI · 미수금 · 기타법인 수급)
4. **낡은 값을 오늘 값처럼 쓰지 않는다.** 신선도 검사를 먼저 돌리고, 낡았으면
   수집을 발동해 기다린다. 끝내 안 들어오면 **「(수집 시각) 기준」이라고 판에 적고**
   확보된 범위까지만 낸다. **낡은 줄 모르고 쓰는 것이 못 쓰는 것보다 나쁘다.**
5. **늘어난 것과 줄어든 것을 함께 센다.** 건수만 보면 들어온 수와 빠진 수가 같을 때
   「변화 없음」으로 오독한다. **이름·코드로 맞댄다.**
6. **잠정치와 확정치를 구분해 적는다.** 값이 여러 번 같아도 확정됐다는 뜻이 아니다.

### 4-2. 저장소를 다루는 규칙

- **지정된 가지에만 민다.** 다른 가지로 밀지 않는다.
- **요청하지 않은 PR 을 만들지 않는다.**
- `git push -u origin <가지>` · 네트워크 실패는 2·4·8·16초로 최대 4회 재시도.
- 커밋 꼬리:
  ```
  Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>
  Claude-Session: https://claude.ai/code/session_…
  ```
- **모델 이름을 저장소에 밀어 넣지 않는다** — 커밋·PR·코드 주석 어디에도.
- 러너 커밋 작성자는 `github-actions[bot]`. **고쳐 쓰지 않는다** — 실제로 러너가 한 일이다.
- 되받기(`--rebase`)가 병합 커밋을 펴다가 충돌을 낸 적이 있다. 수집기가 동시에 미는
  저장소에서는 **`--no-rebase`** 가 안전하다.

### 4-3. 실행 환경

- **세션은 바깥 원천에 직접 못 붙는다**(CONNECT 403, KIS 는 9443 포트가 막힌다).
  **러너가 받아 커밋하고 세션이 읽는다.**
- **세션에는 Actions 실행 권한이 없다**(`workflow_dispatch` → 403).
  감시 파일(`data/**/REFRESH` 등)을 밀어서 깨운다.
- **크로미움은 `/opt/pw-browsers` 에 이미 있다.** `playwright install` 을 다시 부르지 않는다.
- **TLS 검증을 끄거나 `HTTPS_PROXY` 를 지우지 않는다.** CA: `/root/.ccr/ca-bundle.crt`
- 임시 파일은 세션 전용 스크래치패드에. `out/`·`out-test/` 는 `.gitignore` 이고
  **컨테이너는 회수되므로 만든 파일은 같은 실행 안에서 건네야 한다.**
- `schedule:` 은 **기본 가지(main)의 워크플로만** 돈다. 작업 가지에서는 push 트리거만 산다.

### 4-4. 보고하는 결 (지금까지 굳어진 것)

- **한국어 문어체로, 짧고 단정하게.** 군더더기 인사 없이 본론부터.
- **숫자는 표로.**
- **틀렸으면 「앞서 ○○라고 한 것은 틀렸습니다」로 고쳐 적는다.** 길게 자책하지 않는다.
- **추정과 사실을 나눠 적는다.** 「…로 보이지만 확인한 것은 아닙니다」.
- **막혔으면 조용히 끝내지 않는다.** 무엇이 어디서 막혔는지 적는다.
- 끝에 **다음에 무엇이 있는지** 한 줄.
