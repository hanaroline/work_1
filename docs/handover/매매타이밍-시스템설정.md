# 시스템 설정 — 매매 타이밍 파이프라인

**작성 2026-10-01.** 증권사 리포트 쪽 설정은
`docs/handover/시스템설정-백업.md` 에 따로 있습니다. `.claude/settings.json`
과 세션 훅은 **두 파이프라인이 함께 쓰므로** 거기 적힌 것이 그대로
여기에도 해당합니다.

---

## 1. 저장소에 있는 것 — 그대로 넘어옵니다

### 1-1. `.claude/settings.json` (공통)

```json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "hooks": {
    "SessionStart": [
      { "hooks": [ { "type": "command",
        "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/session-start.sh" } ] }
    ]
  }
}
```

`session-start.sh` 는 세션이 열릴 때 playwright·크로미움이 이미 있는지
보고 없을 때만 깝니다. **크로미움은 `/opt/pw-browsers` 에 미리 깔려
있으므로 `playwright install` 을 부르면 안 됩니다.**

### 1-2. 워크플로와 일정

시각은 **UTC** 입니다. KST = UTC + 9.

| 워크플로 | cron (UTC) | 하는 일 |
|---|---|---|
| `kr100-ranking.yml` | `10 7 * * 1-5` | 국내 목록 점검 (16:10 KST) |
| `kr100-data.yml` | `45 6 * * 1-5` | 국내 시세 (15:45 KST) |
| `kr-prices-naver.yml` | `40 9` · `10 11` · `40 12` `* * 1-5` | 국내 일봉 3회 |
| `us100-ranking.yml` | `0 22 * * 2-6` | 미국 목록 점검 |
| `us100-data.yml` | `30 21` · `30 22` `* * 2-6` | 미국 시세 (서머타임 두 벌) |
| `us100-bars-long.yml` | `10 21` · `10 22` `* * 2-6` | **미국 8해치 일봉** |
| `kis-timing-kr.yml` | `20 22 * * 2-6` | 국내상장 ETF 곁 목록 |
| `kis-timing-ov.yml` | `45 22 * * 2-6` | 해외 ETF 곁 목록 |
| `kis-timing.yml` | `0 13 * * 1-5` **+ `workflow_run`** | 매매 타이밍 갱신 |
| `kis-timing-backtest.yml` | 없음 — 손으로만 | 전략 선정·초과수익 재기 |
| `kr100-weekly.yml` | `workflow_run` | 주간 목록 자동 교체 |

> **서머타임 때문에 두 벌을 둡니다.** 미국 마감(16:00 ET)이 EDT 면
> 20:00 UTC, EST 면 21:00 UTC 입니다. 둘 다 걸어 두고 늦은 쪽이 한 번 더
> 받는 셈으로 둡니다.

### 1-3. `workflow_run` 사슬 — **이름으로 겁니다**

```
kis-timing.yml ← 국내 일봉 네이버 판 수집
               ← 미국 일봉 긴 판 수집 (백테스트용)
               ← 미국 100대 기업 시세 수집
               ← 자산배분 ETF 신호
               ← 해외 ETF 곁 목록 수집 (매매 타이밍)
               ← 국내 상장 곁 목록 수집 (매매 타이밍)

kr100-weekly.yml ← 국내 100대 기업 가격 갱신, 국내 100대 기업 시세 수집
signals.yml      ← 종목별 수급 수집, 국내 일봉 네이버 판 수집
calendar-data.yml← 증권사 리포트 수집, 국내 100대 기업 가격 갱신, 시세 수집
boards-summary.yml ← 매매 신호 백테스트
```

**`name:` 을 고치면 이 사슬이 말없이 끊깁니다.** 파일 이름이 아니라
워크플로 이름으로 걸려 있습니다.

### 1-4. 데이터 가지

자료는 `main` 이 아니라 **따로 둔 가지**에 있습니다.

| 가지 | 무엇 |
|---|---|
| `kr100-data` | 국내 종목 일봉·시세·실적 |
| `us100-data` | 미국 종목 일봉·시세 · `bars8y/`(백테스트용 8해치) · `ranking-top.json` |
| `calendar-data` | 일정 |

**이 가지들은 이력을 남기지 않습니다.** 갱신할 때마다 **부모 없는 커밋
하나로 갈아끼우고** 직전 커밋은 회수됩니다(`publish_data_branch.sh`).
그래서 날마다 받아도 저장소가 불어나지 않습니다.

읽을 때는 이렇게 받아야 `origin/<가지>` 가 섭니다.

```bash
git fetch origin '+refs/heads/us100-data:refs/remotes/origin/us100-data'
git show origin/us100-data:data/us100/bars8y/_meta.json
```

> `git fetch origin us100-data` 만 하면 `FETCH_HEAD` 만 서고
> `origin/us100-data` 는 안 생깁니다. **refspec 을 손으로 적으십시오.**

### 1-5. 자료를 지우지 않게 하는 장치

`publish_us100_data.sh` 의 `KEEP_FILES` 에 `bars8y`·`ranking-top.json` 이
들어 있습니다. **빠뜨리면 다음 수집이 지웁니다.** 새 자료를 데이터 가지에
올릴 때는 여기에 넣었는지 반드시 확인하십시오.

### 1-6. 주요 스크립트

| 스크립트 | 하는 일 |
|---|---|
| `build_kis_timing.py` | 백테스트·오늘의 세팅 → `latest.json` |
| `build_verdict.py` | 종목 판정 → `verdict.json` |
| `kis_timing_data.py` | 시장별 일봉을 읽어 옴 (**`bars8y` 를 `chart/` 보다 먼저 봅니다**) |
| `fetch_us100.py` | 미국 수집 엔진 — 국내도 이것을 바꿔 끼워 씁니다 |
| `fetch_kr100.py` | 위 엔진에 국내 시장 프로필만 끼움 |
| `fetch_us_bars_long.py` | 미국 8해치 일봉 |
| `update_kr100_list.py` | 주간 목록 교체 (`--check` · `--selftest`) |
| `check_kr100_ranking.py` / `check_us100_ranking.py` | 목록 점검 |
| `build_signals.py` | 종목 이름표·신호 (`--selftest`) |

### 1-7. 망 없이 도는 시험 — `pr-check` 에 걸려 있습니다

```bash
python3 scripts/fetch_us100.py --selftest          # 비율 항등식 14가지
python3 scripts/fetch_us_bars_long.py --selftest   # 창 미끄러짐/잘림
python3 scripts/keep_newer_snapshot.py --selftest  # 새것 가리기
python3 scripts/build_signals.py --selftest        # 이름표 빠짐없이 읽는가
python3 scripts/update_kr100_list.py --selftest    # 관심종목이 교체기에 버티는가
python3 scripts/update_kr100_list.py --check       # 목록 앞뒤 맞는가
node   scripts/check_us100_ratios.mjs              # 화면과 수집기가 같은 비율
```

## 2. 계승되지 않는 것

### 2-1. 비밀값 — 새 환경에 다시 넣어야 합니다

```
KIS_APP_KEY       한국투자증권 앱키
KIS_APP_SECRET    한국투자증권 앱시크릿
FRED_API_KEY      FRED
GITHUB_TOKEN      GitHub 가 자동으로 줍니다 — 넣을 것 없음
```

**저장소 Secrets 는 GitHub 소유라 그대로 남습니다.** 워크플로는 새
계정에서도 그대로 돕니다. 다시 넣어야 하는 것은 **Claude 실행 환경**에
따로 둔 값이 있을 때뿐입니다.

> **채팅에 붙여 넣지 마십시오.** 대화 기록과 컨테이너에 남습니다.
> 본인 PC 에서 GitHub 설정에만 넣으십시오.

### 2-2. 예약(Routine)

매매 타이밍 쪽은 **예약을 쓰지 않습니다.** 전부 GitHub Actions 일정으로
돌아가므로 계정이 바뀌어도 그대로 돕니다. (브리핑 쪽은 예약 3개를 쓰므로
`docs/handover/시스템설정-백업.md` 2절을 보십시오.)

### 2-3. 세션·대화 기록

넘어가지 않습니다. 이 문서들이 그 자리를 대신합니다.

## 3. 실행 환경에서 알아 둘 것

| 무엇 | 어떻게 |
|---|---|
| 크로미움 | `/opt/pw-browsers` 에 이미 있음 — `playwright install` 금지 |
| playwright | 저장소 밖에서 `import` 하면 못 찾습니다. **저장소 뿌리에서** 돌리십시오 |
| 산출물 내려받기 | Azure 블롭이 막힙니다(`403`) — 데이터 가지에 올려 `git show` 로 읽습니다 |
| 야후 소켓 | `wss://streamer.finance.yahoo.com` 차단 — 화면 검사에서 무시해도 되는 오류 |
| 일정이 안 뜸 | 손으로 `workflow_dispatch`. **원인 미확인** |
| 디스크 | 세션마다 정해진 몫. `df` 의 Avail 0 은 고장이 아니라 몫을 다 쓴 것 |

## 4. 되돌려야 할 일이 생기면

| 무엇 | PR |
|---|---|
| 우주 100 → 200, 관심종목 자리, 이름표 고침 | #80 |
| 화면도 같은 비율 잣대 · 줄 세운 목록 내기 | #77 |
| 창 미끄러짐과 잘림 가르기 | #61 |

데이터 가지는 **이력이 없으므로 되돌릴 수 없습니다.** 잘못 올렸으면
수집을 다시 돌려 덮어쓰는 것이 유일한 길입니다.
