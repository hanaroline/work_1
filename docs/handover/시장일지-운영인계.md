## 2. 결정된 것 — 되돌리지 말 것

### 2-1. 「오후 4시 완성판」은 **불가능하다.** 잠정판 + 완성판 두 단계로 간다

사용자가 **「최소한 4시경에는 외국인·기관 데이터까지 포함한 모든 데이터가
나와야 하는데 가능할까?」**라고 물었다. 짐작하지 않고 **두 원천을 시각별로 재서**
답했고, 답은 **아니오**다.

**네이버(2026-09-21, 여섯 번 실측)**

| 잰 때 | 종목별 외국인 | 종목별 기관 |
|---|---|---|
| 11:51 · 16:07 · 16:52 · 18:07 · 19:26 | 당일 **잠정치** | **전 거래일** |
| 23:45 | 당일 확정 | 당일 확정 |

원천이 **외국인에게만 장중 잠정치를 주고 기관에는 아무것도 주지 않는다.** 그래서
16시 판의 기관 칸은 「마지막으로 확정된 날」이 그대로 보인다. 사용자가
**「기관 데이터는 왜 오늘 데이터가 아닌 9월 18일 자료가 나오는데?」**라고 물은 것이
바로 이 현상이다 — 버그가 아니라 원천의 성질이다.

**한국투자증권 오픈API(2026-09-22, 삼성전자, 여섯 번 실측)**

| 잰 때 | 외국인 순매수수량 | 기관 순매수수량 |
|---|---|---|
| 15:37 · 16:02 · 17:32 · 19:33 | 747,617 | 267,601 |
| **22:05** | **659,851** | **259,459** |

네이버 확정치(22:02 관측) = **259,459** — 22:05 값과 정확히 같다.

> **여기서 내가 두 번 틀렸고, 두 번 다 고쳐 적었다.**
> ① 「기관 종목별은 그날 안에 차지 않는다」 — 틀렸다. 20~23시에 찬다.
> ② 「가장 이른 정직한 발행 시각은 15:40」 — 틀렸다. 15:37~19:33 네 번이
>    같은 값이어서 확정으로 보였지만 **넷 다 잠정치**였고 22:05 에 바뀌었다.
> **안정은 확정의 증거가 아니다.** 값이 여러 번 같아도 확정됐다는 뜻이 아니다.
> 이 교훈은 `docs/journal-playbook.md` 에도 적어 두었다.

**그래서 설계가 이렇다.** 16:00 판은 「그 시각까지의 판」이라고 판에 적고 낸다.
저녁 판이 같은 날짜로 다시 나가 완성한다. 워크플로가 16:00·16:20·16:45·17:15·
18:00·19:20·21:00·22:00·23:00 에 걸려 있고, `scripts/check_journal_ready.py` 가
「둘 다 오늘 확정치인가」를 보고 아니면 **내지 않고 물러선다.** 먼저 낸 판이 있으면
뒤 판이 비킨다. **이 구조를 단순화하지 말 것** — 여러 번 거는 데는 까닭이 있다.

### 2-2. 금액은 KIS 에서 받는다 (별도 가지 `claude/journal-kis-flows`)

네이버는 종목별 수급을 **수량으로만** 준다. 시장일지는 금액을 써야 해서
`수량 × 종가`로 어림했는데, 2026-09-21 삼성전자에서 **어림 9,977억 대 확정 1조 1,063억
— 11% 어긋났다.** KIS `FHKST01010900`(주식현재가 투자자)은 **확정 금액**을 준다.

- 수집기 `scripts/fetch_journal_kis.py` → `data/journal/kis-flows.json`
- 빌더의 `prefer_kis_flows()` 가 **기준일이 같을 때만** 갈아 끼운다. 다르면 네이버를 쓴다.
- 워크플로 `.github/workflows/journal-kis-flows.yml` — 20:30·21:30·22:30 KST.
  **저녁에 도는 까닭은 위 2-1 과 같다.** 이 수집기는 발행을 앞당기지 못한다 —
  **금액을 얻는 것**이 목적이다.
- **실측 25분** 걸린다(400종목 · 종목당 3.7초). 「초당 1건이니 7분」이라고 적었던 것은
  틀렸다 — 유량 제한 재시도(EGW00201)가 자주 걸려 세 배 넘게 든다. `timeout-minutes: 40`.

**NOT FOUND 로 비워 두고 그 사실을 판에 적는다.** 지어내지 않는다.

## 3. 뼈아프게 배운 것 — 같은 데 다시 빠지지 말 것

### 3-1. A4 인쇄 상자의 안쪽 너비는 **726px** 다 (화면 794px 가 아니다)

PDF 가 4쪽이 아니라 **9쪽**으로 구워졌다. 까닭: `@page{size:A4;margin:9mm}` 이면
안쪽 너비가 192mm = **726px** 이고, 이것이 휴대전화용 중단점
`@media (max-width:820px)` 를 때려 **두 단이 한 단으로 무너지고 표 글자가
8.5px→11px 로 커졌다.**

```css
@media screen and (max-width:820px){ … }   /* ← screen 을 반드시 붙인다 */
@page{size:A4;margin:9mm 9mm 7mm}          /* ← .sheet 안쪽 여백과 같게 */
```

`scripts/check_journal_fit.mjs` 는 **794px 에서 재기 때문에 이 결함을 구조적으로 못 본다.**
그래서 `scripts/journal_to_pdf.mjs` 가 **구운 PDF 의 쪽수를 `.sheet` 개수와 맞대어**
다르면 실패시킨다. 이 검사를 빼지 말 것.

### 3-2. 글꼴은 기계마다 다르게 잡힌다 — **CDP 로 실제 글꼴을 물어본다**

`'Inter','Aptos',sans-serif` 는 리눅스에 **하나도 없다.** CI 는 **Noto Sans KR Thin**
(굵기 100)으로, 세션은 **WenQuanYi Zen Hei**(중국어 글꼴)로 떨어졌다. 7.4px 에
굵기 100 이면 읽히지 않는다.

- 데비안 `fonts-noto-cjk` 는 **`Noto Sans CJK KR`** 로 등록된다. `Noto Sans KR` 로 적으면
  DejaVu 로 떨어진다. **이름을 둘 다 적는다.**
- `journal_to_pdf.mjs` 가 CDP `CSS.getPlatformFontsForNode` 로 **실제로 쓰인 글꼴**을
  찍어 준다. 「맞겠지」 하지 말고 그 줄을 읽을 것.

### 3-3. 「매수 − 매도 = 순매수」 검산은 **단위 착오를 못 잡는다**

KIS 의 `*_tr_pbmn` 은 원이 아니라 **백만원**이다. `1e8` 로 나눠 전부 0억원이 됐는데
**1,568칸 전부 매수−매도 검산을 통과했다** — 그 관계는 어느 단위로 재든 성립하기 때문이다.
그래서 `금액 ≈ 수량 × 종가` 로 **차원을 맞대는** 검사를 따로 뒀다(`unit_sane()`).

- `eok_from_pbmn(v) = v / 100`
- 띠는 **0.5~2.0**, 바닥은 **50억원**. 처음 ±30%·바닥 없음으로 했더니 1~5억원짜리
  네 건이 걸렸는데 전부 반올림이 지배하는 줄이었다(하나는 +280% 상승주).
- 지금 392/392 통과.

### 3-4. 러너의 되받기(rebase)가 **병합 커밋을 펴다가** 충돌을 낸다

2026-09-22 08:10 에 러너가 220개 중 213개를 받아 놓고 **밀어 넣지 못했다.**
`git pull --rebase` 가 앞선 병합 커밋을 다시 펴면서 `docs/briefings/*` 에
add/add 충돌을 냈다. 내 워크플로 둘은 **`git pull --no-rebase`** 로 고쳤고,
그 뒤로 **main 을 작업 가지에 병합하지 않는다.**

> **나머지 26개 워크플로는 아직 `--rebase` 다.** 손대지 않았다. 같은 증상이 보이면
> 여기부터 의심할 것.

### 3-5. 장중에는 원천이 **빈 문자열**을 준다

`frgn_ntby_qty = ''` 인데 `stck_clpr` 에는 값이 있다. 그래서 수집기가 395줄을 쓰고도
순위가 통째로 비었다. `has_flows()` 로 거르고, **쓸 만한 줄이 절반이 안 되면
파일을 쓰지 않고 1 로 끝낸다.** 반쯤 빈 파일이 「오늘 자료」로 둔갑하는 것이
못 받는 것보다 나쁘다.

## 5. 환경에서 알아 둘 것

- **세션은 원천에 직접 못 붙는다.** 네이버·KRX 는 CONNECT 403, KIS 는 **9443 포트**라
  대리 서버가 막는다. **러너가 받아 커밋하고, 세션은 커밋된 파일을 읽는다.**
- **세션에는 Actions 실행 권한이 없다**(workflow_dispatch → 403). 워크플로를 부르려면
  감시 파일을 밀어야 한다: `data/journal/REFRESH` · `data/journal/KIS_FLOWS` ·
  `data/journal/KIS_PROBE` · `data/market/REFRESH`.
- Secrets: `TELEGRAM_BOT_TOKEN` · `TELEGRAM_CHAT_ID` · `KIS_APP_KEY` · `KIS_APP_SECRET` ·
  `KRX_AUTH_KEY`. **저장소 Secrets 는 계정을 옮겨도 그대로 남는다**(GitHub 쪽이다).
  값을 파일에 적지 말 것.
- **텔레그램 전송기는 Secrets 가 없으면 조용히 건너뛴다.** 보내지 않은 것을
  보냈다고 말하지 말 것.
- KIS 토큰은 24시간 캐시한다(발급이 분당 1회로 묶여 있다). 간격 `prod` 0.15초 /
  `vps` 1.1초, 재시도 코드 `EGW00201`.

## 6. 새 계정에서 이어 갈 때 — 차례

1. 저장소를 연결하고 `claude/elegant-ritchie-7p11xf` 를 받는다.
2. 이 문서와 `docs/journal-playbook.md` 를 읽는다.
3. **main 으로 올릴지 먼저 정한다**(위 0절). 올려야 평일 자동 발행이 산다.
4. 손으로 한 판 내 본다 — `data/journal/REFRESH` 에 한 줄 덧붙여 push,
   3~5분 뒤 `git pull` 해서 `data/journal/latest.json` 의 기준일을 확인.
5. `python3 scripts/verify_journal.py` 가 **오류 0** 인지 본다. 오류가 있으면 짓지 않는다.
6. 16시 판이면 **「그 시각까지의 판」이라고 판에 적는다.** 기관 칸이 전 거래일이면
   그것이 정상이라는 것도 적는다.
