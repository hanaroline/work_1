# 인수인계 — ETF 편입종목 조회

이 저장소의 여러 갈래 가운데 **ETF 편입종목 조회** 갈래를 이어받는 사람이
읽는 문서입니다. 저장소 전체 지도와 계정 이전 절차는 루트의 `CLAUDE.md` 와
`docs/handover/00-저장소-전체-인계.md` 에 있습니다 — 그쪽이 먼저입니다.

마지막 갱신: 2026-10-02 · `main` 에 병합됨 (작업 가지 `claude/etf-holdings-lookup-tool-wwtz57`)

---

## 1. 무엇을 만들었나

`etf.html` — 국내·미국·홍콩·일본·중국 상장 ETF 1,353종목의 **상위 10개
편입종목과 비중**을 한 화면에서 보는 도구. 탭 7개(ETF 찾기 / 비교·중복도 /
종목→ETF / 랭킹 / 분류 점검 / 수익률 기준 / 사용법), 한·영 토글, 인쇄.

배포본은 `etf-holdings-search.html` — **파일 하나로 인터넷 없이 열립니다.**
자료·CSS·자바스크립트가 전부 안에 들어 있고 바깥을 부르는 곳이 없습니다.

```bash
node scripts/build_etf_data.mjs   # 수집분 병합 + 분류 태깅 -> data/etf.js
node scripts/build_etf_page.mjs   # etf.html + data -> etf-holdings-search.html
```

## 2. 이어서 하면 좋을 일 (우선순위 순)

1. **자료 갱신이 막혀 있습니다.** `data/etf.js` 가 2026-09-13 기준입니다.
   까닭은 감사가 오류를 잡아 워크플로의 커밋 단계가 건너뛰어지기 때문입니다.
   남은 오류는 셋인데 둘은 **장중에 돌려서** 나는 것입니다(아래 4번).
   **한국장 마감(15:30 KST) 뒤에 `etf-daily.yml` 을 수동 실행하면 커밋됩니다.**
2. **`유입-과대` 오류 1건** — 427120 RISE AI플랫폼의 `flow.y1` 이 설정액의
   20배입니다. 원천 값이 이상한 것으로 보이며 아직 안 봤습니다.
3. **예약 수집이 이 브랜치에서는 안 돕니다.** GitHub 의 cron 은 기본 브랜치
   에서만 발동합니다. 이 브랜치를 `main` 에 합쳐야 매일 자동 갱신이 삽니다.
   지금은 밀어 넣을 때(push)만 갱신됩니다.

## 3. 이 프로젝트에서 **반드시** 지켜야 할 규칙

이 규칙들은 전부 **실제로 사고가 난 뒤에** 생겼습니다. 지우지 마십시오.

### 없는 값은 비운다
추정치·대체값을 절대 채우지 않습니다. 빈 화면은 고칠 수 있지만 그럴듯한
틀린 숫자는 아무도 못 잡습니다. 부득이 다른 원천에서 채우면 **①출처를
화면에 밝히고 ②왜 원래 원천이 못 채웠는지 적고 ③순위·평균 같은 한 줄로
세우는 자리에서는 뺍니다.**

### 수익률은 총수익률(TR) 하나만 화면에
`price`·`nav` 는 자료에만 남깁니다. 한때 셋을 나란히 놨다가 "어느 걸 봐야
하냐"가 매번 문제였습니다. 3·5·10년은 기하평균 연율입니다.

### 반쪽짜리 수집으로 어제 자료를 덮지 않는다
수집률이 기준(국내 70%)에 못 미치면 파일을 **아예 쓰지 않고** 끝냅니다.
국내·해외 파일을 나눠 한쪽이 실패해도 다른 쪽은 남습니다.

### 자료 질문은 재현 가능한 증거로 답한다
"아마 ~일 것이다" 로 넘기지 않습니다. 러너에서 실제로 찔러 보고,
결과를 `tools/discovery/` 에 기록으로 남깁니다.

### 이전 작업분은 그대로 두고 앞으로 수정하는 분부터 반영한다
(사용자가 처음에 세운 원칙)

## 4. 환경 — 알고 있어야 할 제약

| 제약 | 내용 |
|---|---|
| **이그레스 차단** | 이 세션에서 네이버·야후·KRX·Azure 블롭이 전부 `CONNECT 403`. 수집은 **GitHub 러너에서만** 가능합니다 |
| **수집 방아쇠** | `etf-daily.yml` 의 `workflow_dispatch`, 또는 `scripts/collect_etf_*`·`etf_lib`·`build_etf_data`·`audit_etf_data` 를 고쳐 push |
| **장중 금지** | 한국장(09:00~15:30 KST) 중에 돌리면 `자료-장중값섞임`·`자료-기준일제각각` 오류로 커밋이 막힙니다. 마감 뒤에 돌리십시오 |
| **KRX** | 러너에서도 안 열립니다(통계 `400 LOGOUT`, OTP→CSV `403`). 국내는 네이버 |
| **야후** | 한국 종목 편입종목 0개. 한국 코드에 `.KQ`/`.KS` 를 붙이면 상장 ETF 가 아니라 **뒤의 펀드**가 잡힐 수 있어 `instrumentType` 확인 필요 |

## 5. 겪은 사고와 대응 (되풀이하지 말 것)

| 사고 | 대응 |
|---|---|
| `Number(null)===0` 이라 빈 봉이 "값 있는 봉"으로 통과 | `v != null && Number.isFinite(Number(v))`. 종가·비중 양쪽에 걸림 |
| 야후가 당일 봉을 만들고 종가를 `null` 로 둠 | `pendingBarOf()` 로 기록. "해외가 하루 늦는다"는 유령을 쫓게 됨 |
| 비중 미공시를 0으로 세어 **"겹침 0.0%"** | 모르면 개수만 세고 비율은 비움 |
| 정지 종목이 "총보수 1위"에 앉음 | 순위에서 제외. 단 **정지 표시는 1종목뿐**, 거래량 0은 7종목이고 6개는 채권이라 빼면 오히려 틀림 |
| 펀드 전체를 센 설정액이 순위 상위 9자리 차지 | `aumScope!=='etf'` 는 순위에서 빼고 목록엔 "펀드 전체 기준" 표기 |
| 이름 부분문자열 오분류 3건 | `PLUS 고배당주`→US, `Dividend Equity`→IT, `금융/은행`→금. 영·숫자는 단어 경계 확인 + 공백 제거형 병행 |
| 인쇄하면 탭 7개가 다 나옴 | `@media print` 에서 `[hidden]` 을 되살리지 말 것 |
| **5년·10년 총수익률이 1,353종목 전부 빔** | 야후를 `5y` 로 받아 기준봉이 없었음. `max` 로 올려 Y5 547 / Y10 265 채워짐 |
| 그 대가로 **2019년에 끝난 죽은 이력**을 물고 옴 | `isStaleHistory()` — 마지막 봉이 180일보다 오래되면 받지 않은 것으로 침 |

## 6. 검증 — 고칠 때마다 돌리는 것

```bash
node scripts/audit_etf_data.mjs       # 전수 감사. 오류 0 이 기준선
node scripts/test_etf_page.mjs        # 브라우저 연기 시험 167개
node scripts/test_etf_page.mjs --built
node scripts/test_etf_offline.mjs     # 진짜로 끊고 file:// 로 열기 11개
node scripts/test_etf_returns.mjs     # 수익률 계산기 41개
node scripts/test_etf_taxonomy.mjs    # 분류 회귀 45개
node scripts/check_etf_return_basis.mjs
node scripts/check_prompt_coverage.mjs [프롬프트파일]   # 프롬프트가 화면을 다 말하나
```

감사에 최근 더한 두 규칙은 **제 실수를 잡아낸 것**이라 값어치가 있습니다.

- **기간별 채움** — 전 종목이 똑같이 비면 종목별 규칙은 못 잡습니다.
  5년이 통째로 비어 있던 것을 아무도 못 본 까닭입니다.
- **기준일-과거** — 원인(기준일)을 증상(상장전 수익률)보다 먼저 짚습니다.
