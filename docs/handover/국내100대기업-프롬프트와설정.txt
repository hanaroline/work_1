 2. 날마다·주마다 쓰는 짧은 말
-------------------------------------------------------------------------------

  최신치로 업데이트해줘
      → kr100-data.yml 수동 실행. 장 마감(15:30 KST) 뒤에 부르면 마감값이 들어감

  수집 워크플로 돌려서 실제 데이터 들어오는지 확인해줘
      → 돌린 뒤 latest.json 의 summary(시세/지표/뉴스 n/100)까지 보고하게 함

  지금 목록이 시총 상위 100 과 맞는지 봐줘
      → python scripts/check_kr100_ranking.py

  이번 주 목록 교체가 돌았는지 확인해줘
      → kr100-weekly 실행 중 «일한 판»(16초 안팎)과 «건너뛴 판»(6초)을 구분해 보고

  00000, 00000 이 들어오면 뭐라고 적힐지 미리 보여줘
      → python scripts/update_kr100_list.py --probe 052690,039030

  오프라인 판 다시 만들어서 올려줘
      → kr100-offline.yml 수동 실행 (수집 없이 30~60초)

  두 판 다 올려줘
      → 실시간 판 kr-top100.html + 오프라인 판 kr-top100-offline.html

 3. 일을 시킬 때 꼭 붙이는 말 (이것들이 사고를 막았습니다)
-------------------------------------------------------------------------------

  실제로 돌려 보고 결과를 알려줘
      "고쳤다"로 끝내지 않게 합니다. 이 저장소의 기본 약속입니다.

  재서 보여줘 / 몇 px 넘치는지 숫자로
      눈대중으로 CSS 를 고치면 안 고쳐집니다. 실제로 넘침을 재게 합니다.

  인터넷 끊은 브라우저에서 열어서 확인해줘
      오프라인 판은 반드시 외부 요청을 전부 차단한 채로 확인합니다.

  없는 값은 지어내지 말고 «미조회»로 둬
      커버리지 수치는 추측하지 말고 실측하게 합니다.

  고치기 전에 영향 범위부터 말해줘
      fetch_us100.py 는 국내·미국이 함께 씁니다. 한쪽만 보고 고치면 다른 쪽이 깨집니다.

  main 에 병합해줘
      예약(schedule·workflow_run)은 **기본 가지에서만** 발동합니다.
      작업 가지에 둔 채로는 아무 일도 일어나지 않습니다.

 4. 프로젝트 지침 — 어기면 사고가 났던 것들
-------------------------------------------------------------------------------

 (1) 날짜와 숫자를 지어내지 않습니다. 확인 못 한 것은 비우고 출처를 남깁니다.

 (2) 자동으로 지은 글은 자동이라고 밝힙니다.
     PROFILE_KO 항목의 네 번째 자리 'auto' → 화면이 "사람이 쓴 요약이 아니다"라고 적음.

 (3) 파이썬은 표준 라이브러리만. 깔 것이 없어야 합니다.

 (4) 화면 하나는 파일 하나. 외부 라이브러리를 들이지 않습니다(폰트 CDN만 예외).

 (5) 큰 산출물은 main 히스토리에 쌓지 않고 데이터 브랜치에 부모 없는 커밋으로.
     calendar-data · kr100-data · us100-data

 (6) 시세·브리핑 자료는 GitHub Pages 로 노출하지 않습니다.
     사람이 받아 갈 파일은 데이터 브랜치의 고정 주소에 둡니다.

 (7) 비밀은 저장소 파일에 넣지 않습니다. GitHub 저장소 시크릿에만.

 (8) 회사 망이 *.translate.goog 를 막습니다. 번역 프록시를 쓰지 마십시오.

 (9) 치환할 때는 count == 1 을 확인합니다.
     (빈 문자열 치환으로 README 가 62MB 가 된 적이 있습니다.)

(10) CSS 의 좁은 화면 규칙은 기존 @media 블록 **뒤에** 둡니다. 앞에 두면 덮입니다.

 6. 교체 규칙과 조정 자리
-------------------------------------------------------------------------------

 들어오는 조건   시총 90위 안        ADD_RANK   (수동 실행 입력 add_rank)
 나가는 조건     시총 110위 밖       DROP_RANK  (수동 실행 입력 drop_rank)
 한 번에         최대 5종목          MAX_SWAP   (수동 실행 입력 max_swap)
 목록 크기       항상 100

 모두 scripts/update_kr100_list.py 머리에 있습니다.
 완충 구간(90~110)이 100위 언저리에서 매주 오가는 종목을 걸러 줍니다.

 8. 손으로 돌리는 명령
-------------------------------------------------------------------------------

 python scripts/fetch_kr100.py                 전체 수집
 python scripts/fetch_kr100_quotes.py          가격만
 python scripts/check_kr100_ranking.py         목록 점검
 python scripts/update_kr100_list.py           목록 교체
 python scripts/update_kr100_list.py --check   정합성만 확인
 python scripts/update_kr100_list.py --dry-run 뭘 바꿀지만
 python scripts/update_kr100_list.py --probe 052690,039030   미리 보기
 python scripts/make_offline_html.py --market kr --out kr-top100-offline.html

 데이터를 로컬로 받아 띄울 때:
   git fetch origin kr100-data
   git checkout origin/kr100-data -- data/kr100
   python3 -m http.server 8000      # http://localhost:8000/kr-top100.html


-------------------------------------------------------------------------------
 9. 이 사람과 일할 때의 결
-------------------------------------------------------------------------------

 · 추측보다 실측을 받습니다. "아마 맞을 것"보다 "재 보니 몇 px" 을 원합니다.
 · 안 된 것은 안 됐다고 적습니다. 반쯤 된 것을 됐다고 적지 않습니다.
 · 고친 뒤에는 브라우저로 열어 보고, 수집기는 한 번 돌려 보고 보고합니다.
 · 사고가 났던 자리는 코드 주석에 «왜 이렇게 두었는지»를 남깁니다.
   (같은 함정을 다음 사람이 다시 밟지 않도록.)
 · 요청 범위를 임의로 넓히지 않습니다. 필요해 보이면 먼저 말하고 확인을 받습니다.
