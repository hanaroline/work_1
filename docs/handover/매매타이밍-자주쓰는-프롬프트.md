# 자주 쓰는 프롬프트 — 매매 타이밍·종목 판정

**작성 2026-10-01.** 시황 브리핑 쪽 프롬프트는
`docs/handover/자주쓰는-프롬프트.md` 에 따로 있습니다. 이 문서는
**매매 타이밍·종목 판정·우주 관리**에서 쓰던 말만 모은 것입니다.

「이 사람과 일할 때의 결」은 저쪽 문서 5절에 적힌 그대로이고, 여기서도
같습니다 — **한국어 문어체, 숫자는 표로, 짐작보다 먼저 재어 본다,
추정과 사실을 갈라 적는다.**

---

## 1. 새 대화를 시작할 때 던지는 첫 말

새 계정·새 대화에서 **가장 먼저** 이것을 던지십시오. 맥락이 한 번에 붙습니다.

```
저장소 hanaroline/work_1 에서 매매 타이밍 파이프라인을 이어서 할 거야.
먼저 docs/handover/매매타이밍-운영인계.md 를 처음부터 끝까지 읽어.
그다음 data/kis_timing/latest.json 의 지금 성적과 열려 있는 PR 을 보고,
지금 상태를 표로 정리해 줘.
```

브리핑 쪽까지 함께 볼 때는 이렇게.

```
docs/HANDOVER.md 와 docs/handover/ 아래 문서를 전부 읽어.
이 저장소에 파이프라인이 둘 있다는 것부터 파악하고 시작해.
```

## 2. 날마다 쓰는 짧은 말

| 하고 싶은 것 | 말 |
|---|---|
| 오늘 신호 보기 | `오늘 매매 신호 정리해 줘` |
| 특정 종목 보기 | `삼성전기 지금 어때?` |
| 수집 돌리기 | `시세 수집 돌려줘` |
| 성적 다시 재기 | `백테스트 다시 돌려줘` |
| 자료가 묵었는지 | `자료 언제 기준이야?` |
| PR 처리 | `초록이면 머지해줘` |

### 종목을 물을 때

이 저장소는 **목표주가·전망을 내지 않습니다.** 물으면 그렇다고 답하게
되어 있습니다. 물을 때는 이렇게 물으면 가장 쓸 만한 답이 옵니다.

```
주성엔지니어링 주가 흐름이 좋은데, 자료로 확인되는 게 뭐야?
신호·수급·기본지표를 다 보고, 없는 건 없다고 해줘.
```

### 추천을 물을 때

```
국내 시총 100위 안에서 차트의 기술적 지표와 기본적 지표를 함께 보고
매수 추천할 만한 종목 5개와 근거 알려줘.
```

> 답이 오면 **검증 초과수익이 얼마인지** 함께 물으십시오. 그 값이 작으면
> (국내주식 +0.74%p) 신호의 무게도 그만큼입니다.

## 3. 작업을 시킬 때 — 결과가 좋았던 말투

### 우주에 종목을 더할 때

```
SFA반도체도 우주에 넣어줘.
단, 시총 100위라는 규칙이 깨지지 않게 해줘.
```

> **「규칙이 깨지지 않게」를 꼭 붙이십시오.** 이 말이 없으면 목록에 한 줄
> 끼워 넣고 끝냅니다. 붙이면 관심종목 자리를 따로 만들고, 주간 교체기가
> 빼 가지 않도록 막고, 그것을 시험으로 묶습니다.

### 고친 것이 정말 고쳐졌는지 확인시킬 때

```
그 보호막을 떼고 돌려서 실제로 실패하는지 보여줘.
```

> 이 저장소의 시험은 **대부분 이렇게 만들어졌습니다.** 통과하는 것만
> 보면 그 시험이 무엇이든 재고 있는지 알 수 없습니다.

### 숫자를 낼 때

```
그 숫자 저장소 자료에서 나온 거야? 없으면 없다고 해줘.
```

### 머지·수집을 한꺼번에 시킬 때

```
초록이면 머지하고 세 개 다 돌려줘
```

## 4. 거드는 말 — 상황별

### 자료가 묵었을 때

```
지역 지수 날짜랑 맞대 봐. 시장 전체가 밀린 건지 종목만 그런 건지.
```

### 워크플로가 안 떴을 때

```
일정이 안 뜬 것 같아. 손으로 돌리고, 왜 안 떴는지도 같이 봐줘.
```

### 성적이 갑자기 좋아졌을 때

```
전체 구간 말고 검증 구간 숫자로 다시 말해 줘.
```

### 전략을 바꾸고 싶을 때 (주의)

```
전략 조합은 규칙으로만 정해. 조합을 뒤져서 좋은 걸 고르지 마.
```

> 한 번 해 봤고 **거래 1건으로 +45%p** 가 나왔습니다. 성적이 아니라
> p-해킹입니다.

### 막혔을 때

```
막힌 거면 막혔다고 말해 줘. 조용히 넘어가지 말고.
```

## 5. 보안 — 반드시 지킬 것

**KIS 앱키를 채팅에 붙여 넣지 마십시오.**

대화에 붙여 넣어도 소용이 없고(세션이 그 값을 저장소 비밀값으로 옮기지
못합니다), 위험합니다 — **대화 기록과, 얼마 뒤 회수되는 컨테이너에
자격증명이 남습니다.**

앱키는 **본인 PC 에서 GitHub 저장소 설정의 Secrets 에만** 넣으십시오.

```
필요한 비밀값
  KIS_APP_KEY       한국투자증권 앱키
  KIS_APP_SECRET    한국투자증권 앱시크릿
  FRED_API_KEY      FRED (매크로 자료)
  GITHUB_TOKEN      GitHub 가 자동으로 줍니다 — 넣을 것 없음
```

새 계정에서 환경을 다시 만들 때도 같습니다. 세션이 「키를 알려 달라」고
하면 그 요구 자체가 잘못된 것이니 **거절하시고**, 저장소 Secrets 에
넣으셨다고만 알려 주십시오.

## 6. 하지 말아야 할 요청 — 해 봤지만 안 되는 것

| 요청 | 왜 안 되나 |
|---|---|
| 「목표주가 얼마야?」 | 그런 기능이 없습니다. 컨센서스는 `verdict.json` 에 있지만 그것은 증권사 값을 옮긴 것뿐입니다 |
| 「전망 좀 해 줘」 | 재는 것은 초과수익뿐입니다 |
| 「우주 밖 종목 분석해 줘」 | 시세가 없습니다. 리포트만 있으면 그것만 답합니다 |
| 「워크플로 이름 좀 바꿔 줘」 | `workflow_run` 사슬이 **말없이** 끊깁니다 |
| 「이 전략 조합이 더 낫던데」 | 3절 참조 |
