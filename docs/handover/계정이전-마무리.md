## 1. 저장소 안의 인계 자료는 지금 상태와 맞습니다

옛 계정에 살아 있는 예약 12개를 하나씩 다시 불러(get_trigger) 저장소의 사본과 견주었습니다.

| 견준 것 | 결과 |
|---|---|
| `docs/claude-handoff/routines.json` 의 지시문 12개 | **글자 하나까지 같음** (updated_at 도 같음) |
| `인계-보관본.txt` 3절 | `python3 scripts/build_handoff_archive.py --check` → 어긋남 없음 |

그러니 예약은 **[예약-전체목록.md](예약-전체목록.md)** · **[routines.json](../claude-handoff/routines.json)** 그대로
다시 만들면 됩니다. 여기에 새로 적을 지시문은 없습니다.

## 2. 저장소 밖으로 내려받아 둔 것 — 대화 기록도 이제 남아 있습니다

옛 문서에는 "되찾을 수 없는 것은 대화 기록과 아티팩트 주소"라고 적혀 있습니다.
**대화 기록은 이번에 내려받았습니다.** 사용자 컴퓨터에 있고, 저장소에는 올리지 않았습니다
(시세·브리핑 내용이 섞여 있어 저장소에 두지 않는다는 규칙 때문입니다).

| 파일 | 내용 |
|---|---|
| `받은자료-목록.html` | 아래 전부의 이름·내용·여는 법·크기·검증값. **이것부터 여십시오** |
| `claude-code-sessions.zip` | Claude Code 세션 79개 대화 기록 요약판(도구 입출력을 줄인 것) |
| `claude-code-sessions-FULL-01~04of04.zip` | 같은 79개의 **원문 전체판** + 세션이 Write·Edit 로 만든 파일 1,032개 복원본 |
| `claude-artifacts-01~02of02.zip` | 아티팩트 174개 HTML |
| `work_1-all.bundle.part00~18` | 저장소 전체 이력(모든 가지·커밋). `join_windows.bat` 로 합침 |
| `work_1-files-B-01~12of12.zip` | 저장소 파일(git 없이 보기) |

세션 79개 = 일반 세션 70개 + 예약 작업이 새 세션을 열어 실행한 9개입니다.

**새 계정에서 지난 대화를 참고하게 하려면** 원문 전체판에서 그 세션의 `.md` 하나를
새 대화에 첨부하고 "이 기록을 읽고 이어서 해 줘"라고 하면 됩니다. 79개를 한꺼번에 넣지 마십시오 —
너무 커서 오히려 맥락을 잃습니다.

**내려받지 못한 것**
- **Claude 채팅(claude.ai 대화)** — 설정 → 개인정보 → **데이터 내보내기**로 사용자가 직접 받아야 합니다. 옛 계정이 닫히기 전에.
- **새 세션을 여는 예약의 예전 실행분** — 예약마다 마지막 실행 1회만 조회됩니다.
- 저장소에 올리지 않은 **이진 파일**(이미지·PDF 등) — 기록에 내용이 없습니다.

## 3. 새 계정에서 할 일 — 순서대로

1. **GitHub 연동** — claude.ai 에서 GitHub 를 연결하고 `hanaroline/work_1` 접근을 허용합니다.
   저장소와 저장소 시크릿(KIS 키 등)은 GitHub 쪽에 있으므로 **그대로 살아 있습니다.**
2. **Claude Code 웹 환경을 만듭니다** — 세션 시작 준비는 `.claude/hooks/session-start.sh` 가 저절로 합니다.
   네트워크 정책·환경 변수는 [ACCOUNT-SETUP.md](../claude-handoff/ACCOUNT-SETUP.md) 5절을 보십시오.
3. **첫 대화에 아래를 붙여 넣습니다.**

   ```text
   저장소 hanaroline/work_1 에서 일을 이어받는다. 이전 계정은 2026-10-02 에 닫혔다.
   CLAUDE.md → docs/handover/계정이전-마무리.md → docs/handover/00-저장소-전체-인계.md
   → docs/claude-handoff/ACCOUNT-SETUP.md 순서로 끝까지 읽어라. 요약본으로 대신하지 마라.
   다 읽었으면 (1) 새 계정에서 다시 붙여야 할 것(커넥터·스킬·환경)과
   (2) 다시 만들어야 할 예약 12개를 표로 보여 주고, 내가 확인하면 예약부터 만든다.
   예약 지시문은 docs/claude-handoff/routines.json 의 prompt 를 글자 그대로 쓴다.
   ```

4. **커넥터·스킬** — Gmail·Gamma 커넥터를 다시 연결하고, 사용자 스킬 2종(mas-design ·

5. **예약 12개 다시 만들기** — 아래 4절을 먼저 보십시오. **전용 창에 붙는 예약은 창을 먼저 엽니다.**
6. **고정 주소 두 개를 새로 발행하고 저장소에 적습니다** — 5절.
7. 다음 날 07:30 모닝 브리핑과 16:10 장마감이 정상으로 돌았는지 확인합니다.

예약을 만들어야** 결과가 그 창으로 옵니다. 같은 창을 쓰던 예약은 새 계정에서도 한 창에 묶으십시오.

## 5. 옛 계정이 닫히면 깨지는 주소

아티팩트 주소는 옛 계정 것이라 계정과 함께 열리지 않게 됩니다. **HTML 원본은 저장소에 있으니**
새 계정에서 다시 발행하고 주소만 바꿔 적으면 됩니다.

| 무엇 | 옛 주소가 적힌 곳 | 새 계정에서 할 일 |
|---|---|---|
| **브리핑 목록 한 장**(고정 주소) | `docs/briefings/index.json` 의 `archive_page.url` (`d71cdafd-…`) | `docs/briefings/archive.html` 을 새로 발행 → 받은 주소를 `archive_page.url` 에 적기. 이후 모닝·장마감 예약이 그 주소에 덮어씁니다 |
| **세션 산출물 자료실 색인**(고정 주소) | 자료실 예약 지시문 6번 (`fa511243-…`) · `routines.json` | 가지 `claude/organize-session-artifacts-fbg82m` 의 `docs/session-artifacts/tools/build_hub.py` 로 색인을 다시 만들어 발행 → **새 주소로 예약 지시문의 그 줄을 바꿔서** 예약을 만들기 |
| 날짜별 브리핑 주소 | `docs/briefings/index.json` 의 `briefings[].url` (82개) | 지난 판을 다시 발행할 필요는 없습니다. 사이드바 「지난 브리핑」이 옛 주소를 가리키게 될 뿐이니, 필요하면 `url` 을 `null` 로 비우고 `build_archive_nav.py` 를 다시 돌리십시오 |

> 예약 지시문을 글자 그대로 쓰라는 원칙의 **유일한 예외**가 자료실 색인 주소 한 줄입니다.
> 옛 주소 그대로 두면 새 계정은 그 아티팩트를 덮어쓸 권한이 없어 매번 실패합니다.
