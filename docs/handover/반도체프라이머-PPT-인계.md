## 2. 결정된 사항 — 세 파일의 계보

세 파일은 일직선이 아니라 **갈라진 가지**였습니다. 판별 근거는 둘입니다.

**(1) 패키지 생성 시각(`docProps/core.xml`)** — 편집 도구가 날짜를 건드리지 않아 계보가 남습니다.

| 파일 | 생성 시각 | 정체 |
|---|---|---|
| `..._revised.pptx` | 01:59:15 | 초기판에서 갈라진 **사실확인 수정본** |
| `..._2026.pptx` | 02:24:53 | 25분 뒤 **구조를 다시 짜서 재생성한 v2** |
| `..._1_reviewed.pptx` | 02:24:53 (상속) | **v2 에 검수를 얹은 최신 산출물** ← 최종본 |

**(2) 구조 차이** — `_2026`·`_reviewed` 에는 **PART 3 통상 리스크(232조·301조 관세)** 장과
**7월 급락 3부작(1/3·2/3·3/3)** 이 있고, `_revised` 에는 관세 문구가 **0건**입니다.

> **결론: `_1_reviewed.pptx` 가 최종본입니다.** (`_1` 은 같은 파일을 다시 내려받을 때 붙는 꼬리입니다)

**함정이 하나 있었습니다.** v2 는 `_revised` 를 *편집한* 것이 아니라 **새로 생성**한 것이어서,
`_revised` 에만 있던 사실 수정이 최종본에 **반영되지 않았습니다.** 그래서 단순히 최종본을
쓰면 이미 고쳐 둔 오류가 되살아납니다. 병합이 필요했던 이유입니다.

## 5. ★ 유지해야 할 작업 규칙 — PPTX 를 눈으로 검수할 때

**이 덱은 본문 전체를 `Spoqa Han Sans Neo` 로 지정합니다(run 참조 1,225개).** 그런데
세션 컨테이너에 그 폰트가 없어 LibreOffice 가 폭이 **10~20% 넓은** DejaVu Sans / Noto Sans CJK
로 대체했고, 그 상태의 그림만 보면 **멀쩡한 문구가 넘친 것처럼 보입니다.** 그대로 믿었다면
정상인 문장을 잘라내는 잘못된 수정을 할 뻔했습니다.

> **규칙: 실제 지정 폰트를 깔기 전에는 렌더링 그림으로 넘침·겹침을 판정하지 않습니다.**

덱이 쓰는 폰트는 이렇게 확인합니다.

```bash
python3 -c "
import zipfile,re,collections
z=zipfile.ZipFile('deck.pptx'); c=collections.Counter()
for i in range(1,31):
    for m in re.finditer(r'<a:latin typeface=\"([^\"]*)\"', z.read(f'ppt/slides/slide{i}.xml').decode('utf8')):
        c[m.group(1)]+=1
print(c)"
```

### 세션에서 PPTX 를 그림으로 보려면 — 세 가지를 깔아야 합니다

```bash
# 1) LibreOffice Impress — 기본 이미지에 없습니다(없으면 'source file could not be loaded')
apt-get update && apt-get install -y libreoffice-impress

# 2) 한글 폰트 — 없으면 한글이 두부(□)로 나와 검수가 무의미합니다
apt-get install -y fonts-noto-cjk fonts-nanum fonts-crosextra-carlito

# 3) ★ 덱이 지정한 실제 폰트 — Spoqa 는 npm 에만 있습니다(registry.npmjs.org 는 프록시 우회 대상)
curl -sSO https://registry.npmjs.org/spoqa-han-sans/-/spoqa-han-sans-3.3.0.tgz
tar xzf spoqa-han-sans-3.3.0.tgz --wildcards "package/*SpoqaHanSansNeo*"
```

**Spoqa 는 깔기만 해서는 굵은 글씨가 안 붙습니다.** 배포본의 name 테이블이 망가져 있어
Regular 이 자기를 Bold 라 주장하고(fsSelection BOLD 비트), Bold 는 `Spoqa Han Sans Neo Bold`
라는 **별개 패밀리**로 등록됩니다. 그대로 두면 굵은 글씨가 Noto Bold 로 떨어집니다.
fontTools 로 다음을 맞춰 주십시오 — nameID 1 = `Spoqa Han Sans Neo`, nameID 2 = `Regular`/`Bold`,
`usWeightClass` = 400/700, `fsSelection` 의 BOLD·REGULAR 비트, `head.macStyle` 의 bold 비트.
맞춘 뒤 `fc-cache -f` 하고 **LibreOffice 프로필을 새로 만들어**(`-env:UserInstallation=…`) 변환합니다.

제대로 붙었는지는 **결과 PDF 의 폰트 이름**으로 확인합니다. 글자 수의 99% 이상이
`SpoqaHanSansNeo-Regular`/`-Bold` 로 찍혀야 합니다.

```bash
python3 -c "
import pymupdf,collections
d=pymupdf.open('deck.pdf'); c=collections.Counter()
for p in d:
    for b in p.get_text('dict')['blocks']:
        if b['type']==0:
            for l in b['lines']:
                for s in l['spans']: c[s['font']]+=len(s['text'])
print(c.most_common())"
```

### 넘침·겹침은 눈이 아니라 좌표로 찾습니다

`pdftoppm` 이 없으므로 `pip install pymupdf` 로 PDF 를 그림으로 만들고, **글자 상자와 도형
사각형의 좌표를 직접 비교**합니다. 세 가지를 봅니다.

1. 글자 상자가 **자기를 담은 가장 작은 도형**의 아래·오른쪽을 넘는가 (가장 작은 것을 골라야
   합니다. 페이지 전체 사각형을 집으면 전부 통과해 버립니다)
2. 글자 상자끼리 **서로 겹치는가**
3. 슬라이드 가장자리를 **벗어나는가**

표는 이 검사에 **걸리지 않습니다.** 표 글자는 자기 칸 안에 얌전히 있고, 커진 것은 표
전체이기 때문입니다. 13p 결함이 그랬습니다. **표가 있는 장은 `<a:tr h="…">` 의 합과 아래
도형의 `y` 를 손으로 비교하십시오.**

### 고칠 때

- `ppt/slides/slideN.xml` 의 `<a:t>` 를 **문자열 치환**합니다. run 을 쪼개거나 합치지 않으면
  글꼴·색·굵기가 그대로 보존됩니다.
- 치환 전에 `count(old)==1` 을 **단언**하십시오. 같은 문구가 여러 곳이면 엉뚱한 데가 바뀝니다.
- 다시 묶을 때 **원본의 파트 순서를 유지**합니다(`zin.infolist()` 순회).
- `xml.etree` 로 OOXML 을 왕복시키면 네임스페이스 접두사가 바뀌어 덱이 깨집니다. 읽기만 하거나
  `defusedxml` 을 쓰십시오.
- 끝나면 `python /root/.claude/skills/pptx/scripts/office/validate.py out.pptx --original src.pptx`.
  `--original` 을 주어야 원본이 본래 갖고 있던 흠이 내 잘못으로 보이지 않습니다.
- 바뀐 파트가 **의도한 것뿐인지** 바이트로 확인합니다(나머지 파트는 원본과 동일해야 합니다).
