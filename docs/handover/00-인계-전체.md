## 1. 계정을 바꾸면 무엇이 넘어가는가 ★

**결론: 저장소에 든 것은 전부 넘어갑니다. 계정에 묶인 것은 하나도 안 넘어갑니다.**

### 넘어가는 것 — 새 계정에서 저장소만 연동하면 그대로 살아납니다

| 무엇 | 규모 |
|---|---|
| 모든 코드·화면·산출물 | 저장소 전체 |
| 작업 지침 | `docs/briefing-playbook.md` 외 인계 문서 7종 |
| 지금까지 만든 시황 브리핑 | 130판 (`docs/briefings/*.html`) |
| 빌더·검사기 스크립트 | 152개 (`scripts/`) |
| 자동화 워크플로 | 82종 (`.github/workflows/`) — **GitHub 쪽이라 계정과 무관하게 계속 돕니다** |
| 시세·상품 이력 | `data/` + 데이터 전용 가지 (`kr100-data`·`us100-data`·`calendar-data`) |
| 작업 가지 | `claude/*` 72개 |
| 커밋 이력 전부 | 과거 어느 시점 자료도 git 에서 꺼낼 수 있습니다 |
| 세션 시작 준비 | `.claude/settings.json`, `.claude/hooks/session-start.sh` |

> **중요** — GitHub Actions 워크플로 82종은 **계정을 바꿔도 멈추지 않습니다.**
> 저장소에 붙어 있고 GitHub 이 돌리기 때문입니다. 시세 수집·ELS 수집·주간 교체는
> 계정 공백기에도 계속 쌓입니다.

### 넘어가지 않는 것 — 옛 계정 소유입니다

| 무엇 | 어떻게 할 것인가 |
|---|---|
| **예약(Routine) 11개** ★ | 계정 소유. **4절 표를 보고 새로 만드십시오.** 이것이 가장 중요합니다 |
| **대화 기록 · 세션 70회** | 되살릴 수 없습니다. 이 문서들이 그 자리를 대신합니다 |
| **발행한 아티팩트 81건** | `claude.ai/artifact/…` 주소는 옛 계정 것이라 **새 계정에서 열리지 않을 수 있습니다**. 판 자체(HTML)는 저장소에 멀쩡합니다 |
| 전용 대화 창 | 새로 만들어 예약을 붙입니다 |

**그래서 질문에 정확히 답하면 — 저장소 데이터·완성 파일·작업 내용·커밋 이력은
계승됩니다. 과거 「프롬프트」는 저장소에 적어 둔 것만 계승되고(이 문서들이 그것입니다),

## 4. 예약(Routine) 전체 — 계승되지 않으므로 다시 만들 것 ★

2026-10-01 기준으로 **켜져 있는 예약 11개 + 일회성 1개**입니다.
cron 은 **UTC** 기준이며, 괄호 안이 한국 시각입니다.

| 예약 이름 | cron (UTC) | 한국 시각 | 전달 방식 |
|---|---|---|---|
| 마포WM 모닝 브리핑 | `30 22 * * *` | 매일 07:30 | **전용 창** |
| 마포WM 장마감 시황 브리핑 | `10 7 * * 1-5` | 평일 16:10 | **전용 창** |
| 증권사 리포트 자동 배포 | `0 2 * * 1-5` | 평일 11:00 | 쓰던 대화 |
| 월요일 08:40 상품설명의무 스크립트 갱신 | `40 23 * * 0` | 월 08:40 | 쓰던 대화 |
| 평일(화~금) 08:40 상품설명의무 스크립트 갱신 | `40 23 * * 1-4` | 화~금 08:40 | 쓰던 대화 |
| ELS 신규 회차 오후 점검 | `30 5 * * 1-5` | 평일 14:30 | 쓰던 대화 |
| ELS 신규 회차 점검·검증 | `30 7 * * 1-5` | 평일 16:30 | 새 대화 |
| ELS 상품 구조 페이지 주간 갱신 | `0 23 * * 0` | 월 08:00 | 새 대화 |
| 미국 100대 기업 — 주간 목록 자동 교체 | `0 23 * * 0` | 월 08:00 | 새 대화 |
| 펀드 원천 반영 재갱신 | `30 6 * * 1` | 월 15:30 | 쓰던 대화 |
| 세션 산출물 자료실 자동 갱신 | `0 23 * * 0,3` | 월·목 08:00 | 쓰던 대화 |

프롬프트 원문은 — 브리핑 둘은 `docs/routine-prompts.md`,
증권사 리포트는 `docs/handover/자주쓰는-프롬프트.md` 2절에 있습니다.

### 예약을 만들 때 반드시 지킬 것

- **모닝과 장마감은 각각 전용 창에 붙입니다.** 한 창에 몰면 맥락이 뒤섞이고,
  실패해도 눈에 안 띕니다.
- **「쓰고 있는 대화로 전달」을 기본으로 고릅니다.** 매번 새 대화를 띄우는 방식은
  저장소에 밀어 넣을 자격이 없어 **아무것도 만들어 내지 못한 적이 있습니다.**
  (위 표에서 「새 대화」로 적힌 것은 저장소 쓰기가 필요 없는 가벼운 것들입니다.)
- **서버가 「분」을 만든 시각에 붙잡습니다.** 11:00 으로 걸어도 11:06 에 돕니다.
- **만든 뒤 다음 발사 시각을 반드시 확인하십시오.** 예약이 거절됐는데 확인하지 않아
  약속한 산출물이 하루 늦은 적이 있습니다.
- 이름에 「월·수·금」이라 적힌 ELS 점검 예약의 실제 cron 은 **평일 전부**입니다.
  옮길 때 이름을 고치든 cron 을 고치든 **둘을 맞추십시오.**

> **2026-09-19(금)에 계정의 모든 예약이 하나도 발사되지 않은 날**이 있었습니다.
> 파이프라인 결함이 아니라 플랫폼 쪽 공백이었습니다. 그런 날은 손으로 부르면 됩니다.

## 5. 유지해야 할 작업 규칙

갈래를 가리지 않고 지켜 온 것들입니다. **대부분 사고가 나서 생긴 규칙입니다.**

### 5-1. 저장소·커밋

- 운영 가지는 **`main`**. 예약 작업은 `main` 에서 합니다
  (GitHub cron 은 기본 가지의 워크플로만 발동합니다).
- 새 작업은 `claude/<주제>` 가지에서 하고, 지정된 가지 밖으로 밀지 않습니다.
- 커밋 꼬리에 `Co-Authored-By` 와 `Claude-Session` 두 줄을 붙입니다.
- **모델 이름을 저장소에 밀어 넣지 않습니다** — 커밋 메시지·PR·코드 주석 어디에도.
- **요청하지 않은 PR 을 만들지 않습니다.**
- 커밋 메시지는 한국어 평서문으로, 무엇을 왜 바꿨는지 적습니다.

### 5-2. 숫자를 다루는 법 — 이 일의 핵심

- **「표는 자료에서, 글은 사람이」.** 표·비율·개수·날짜 이름표는 빌더가
  자료 파일에서 만듭니다. 숫자를 문장에 손으로 적으면 다음 날 어긋납니다.
- **검산을 통과하지 못하면 산출물을 내지 않습니다.** 어느 검사가 어떻게 어긋났는지
  그대로 알리고, 원인을 찾아 고친 뒤 다시 돌립니다.
  (브리핑은 검증 5종, 증권사 리포트는 검산 42개)
- **값이 확실하지 않으면 비워 두고 사유를 적습니다.** 지어내지 않습니다.
  ELS 지급률처럼 상품마다 표기기준이 다른 값은 **일부러 자동 계산하지 않고**
  「투자설명서에서 옮겨 적으세요」로 표시합니다.
- **추정과 사실을 갈라 적습니다.** 「…로 보이지만 확인한 것은 아닙니다」.
- **먼저 묻기보다 먼저 재어 봅니다.** 「11시에 뽑으면 더 늘어날까?」 같은 물음에는
  짐작으로 답하지 말고 실제로 한 번 돌려 숫자로 답했습니다.
- **수집 시각이 곧 자료의 성격입니다.** 날짜 이름표가 오늘이어도 장중 호가일 수
  있습니다. **거래량으로 마감을 확인하십시오**(S&P500 정규장 ≈ 26~32억 주).

### 5-3. 대외 민감한 것

- **꼬리말에 사람 이름을 싣지 않습니다**(2026-09-23 결정). 부서명만 싣습니다.
  단, 기사에 나오는 애널리스트 이름 등은 그대로 둡니다.
- **생성형 AI 고지를 모든 판에 넣습니다**(2026-09-30 추가). 문구는 받은 그대로,
  히어로 아래와 꼬리말 **두 자리**에.
- 조회 화면은 **정보 제공용 사내 참고 자료**입니다. 고객 대외 배포 시
  준법감시 확인이 필요합니다.

### 5-4. 막혔을 때

- **조용히 끝내지 않습니다.** 무엇이 어디서 막혔는지 한국어로 적습니다.
- **「8분 넘으면 멈춘 것」이라고 단정하지 않습니다.** 실행 기록을 먼저 봅니다 —
  18분 걸린 날이 있었고, 그때 「안 돈다」고 보고한 것은 틀린 판단이었습니다.
- 끝내 자료가 안 들어오면 포기하지 말고, 「무엇이 언제 기준이라 어디까지만
  확보됐다」를 **명시한 뒤** 확보된 범위까지 내보냅니다.

### 5-5. 말투

한국어 문어체. 짧고 단정한 문장, 군더더기 인사 없이 본론부터.
숫자는 표로. 틀렸으면 「앞서 ○○라고 한 것은 틀렸습니다」로 고쳐 적되 길게
자책하지 않습니다. 작업이 끝나면 다음에 무엇이 있는지 한 줄로 알려 줍니다.

## 6. 환경 제약 (이 실행 환경에서 겪은 것)

- **세션은 네이버·다음·KRX·야후에 직접 붙지 못합니다**(CONNECT 403).
  원천 확인은 **러너(GitHub Actions)에서만** 됩니다. 러너가 받아 커밋하고
  세션이 읽는 구조입니다.
- **`workflow_dispatch` 를 API 로 부르지 못합니다**(403). 워크플로가 지켜보는
  파일에 한 줄 적어 밀어 넣어 깨웁니다 — `scripts/request_*_refresh.sh`.
- **`gh` CLI 가 없습니다.** GitHub 작업은 MCP 도구(`mcp__github__*`)로 합니다.
- **TLS 검증을 끄거나 `HTTPS_PROXY` 를 지우지 않습니다.**
  CA 묶음은 `/root/.ccr/ca-bundle.crt`.
- 크로미움은 `/opt/pw-browsers` 에 이미 있습니다. `playwright install` 을
  다시 부르지 않습니다(세션 몫 디스크를 수백 MB 씩 먹습니다).
- **컨테이너는 회수됩니다.** 남길 것은 반드시 커밋하고, 건넬 파일은
  **같은 세션 안에서** 올려야 합니다.
- 세션 시계가 UTC 라 저녁·밤에는 한국 날짜가 하루 앞섭니다.
  `TZ=Asia/Seoul date` 로 다시 확인합니다.
