## 1. 계정이 바뀔 때 넘어오는 것과 안 넘어오는 것

**결론부터: 저장소에 든 것은 전부 넘어온다. 계정에 묶인 것은 넘어오지 않는다.**

| | 계승 | 비고 |
|---|---|---|
| 수집기·생성기·검사기 (`scripts/*`) | **O** | git 에 있는 것은 전부 |
| 자동 갱신 워크플로 (`.github/workflows/cc-etf-monthly.yml`) | **O** | 예약이 **GitHub 쪽**에 있어 계정과 무관하게 돈다 |
| 원천 자료 `data/cc_etf.json` | **O** | 달마다 커밋되므로 **과거 어느 달 판도 git 이력에서 꺼낼 수 있다** |
| 분배·시세 곳간 `data/etf_dist_cache.json` | **O** | 이게 살아 있어야 다음 수집이 3분에 끝난다(4-1절) |
| **완성 파일 두 개** — `고객제안서_월배당ETF.xlsx`, `docs/etf-proposal.html` | **O** | 저장소 최상위·`docs/` 에 **커밋되어 있다**. 채팅으로 받은 사본이 아니라 저장소 본체다 |
| 이 인계 문서들 | **O** | 그래서 저장소에 넣는다 |
| 세션 시작 준비 (`.claude/`) | **O** | |
| **이 대화 기록 · 지난 프롬프트** | **X** | 계정에 묶인다. **이 문서와 프롬프트 모음이 그 자리를 대신한다** |
| **예약(Routine)** | **X** | 다만 이 일은 예약이 **필요 없다** — 갱신은 GitHub Actions cron 이 한다 |
| 채팅으로 올려 받은 파일 | **X** | 저장소에 같은 파일이 있으므로 **잃는 것이 없다** |

> **이 일은 계정 이전의 타격이 가장 적은 축에 든다.** 다른 일(시황 브리핑)은 발행한
> 아티팩트 주소가 옛 계정 소유라 링크를 잃지만, 여기서는 완성 파일 둘 다
> **저장소에 커밋된 실물**이라 주소에 기대지 않는다. 새 계정에서 저장소만 붙이면
> 그대로 내려받을 수 있다.

### 그래도 계정을 닫기 전에 해 둘 것

- 마지막 판의 엑셀·HTML 을 **손으로도 한 벌 내려받아 둔다.** 저장소에 있으니
  이론상 필요 없지만, 새 계정 연동이 늦어지는 동안에도 담당자 업무는 돌아간다.
- GitHub 계정(`hanaroline`) 자체는 그대로 둔다. **Claude 계정과 GitHub 계정은
  다른 것**이다. 워크플로는 GitHub 에서 도는 것이라 Claude 쪽이 끊겨도 매월 1일
  갱신은 계속된다 — 다만 **실패했을 때 알아채고 고칠 사람이 없어질 뿐**이다.

## 2. 이 일이 무엇인가

투자금액을 넣으면 **매월 얼마를 받게 되는지**를 보여 주는 자료 한 벌.

```
ETFCHECK (비공개 API)
   │  러너에서 playwright 로만 받을 수 있다 (3-1절)
   ▼
scripts/collect_cc_etf.mjs ──► data/cc_etf.json      ← 두 산출물의 유일한 원천
                            └► data/etf_dist_cache.json  (곳간)
   │
   ├─► scripts/build_etf_proposal.py       ──► 고객제안서_월배당ETF.xlsx   (담당자용)
   └─► scripts/build_etf_proposal_html.py  ──► docs/etf-proposal.html      (고객용)
            │
            └ scripts/check_etf_proposal.py + scripts/check_etf_html.mjs
              두 산출물이 **같은 수**를 내는지 교차 검사한다. 통과 못 하면 커밋 안 한다.
```

- **엑셀**은 담당자가 종목을 고르고 금액을 넣어 쓰는 계산 도구다. 노란 칸만 고친다.
- **HTML** 은 고객에게 보여 주는 읽기 전용 화면이다. 브라우저에서 `Ctrl+P` → PDF.
- 갱신은 **매월 1일 10:00 KST**, GitHub Actions 가 자동으로 한다.

## 3. 넘길 수 없는 전제 — 반드시 지킬 작업 규칙

여기 적힌 것은 취향이 아니라 **실제로 사고가 났던 자리**다. 새 계정의 첫 대화에서
이 절을 그대로 붙여 넣는 것을 권한다(프롬프트 모음 2절에 붙여넣기용 전문이 있다).

### 3-1. ETFCHECK 은 세션에서 못 붙는다 — 수집은 **러너에서만** 돈다

사내 이그레스 정책 때문에 Claude 세션 컨테이너는 ETFCHECK 에 닿지 못한다.
수집·탐침은 **전부 GitHub Actions 러너에서** 돌린다
(`workflow_dispatch` 또는 `scripts/collect_cc_etf.mjs` 를 고쳐 푸시).

**우회로를 찾지 않는다.** 프록시를 바꾸거나 TLS 검증을 끄는 식으로 돌아가려 하면
안 된다 — 회사 정책이고, 막혀 있는 것이 정상이다.

### 3-2. `scripts/collect_cc_etf.mjs` 를 **로컬에서 절대 실행하지 않는다**

이 파일은 최상위에 바로 실행되는 코드가 있어서, `node` 로 부르는 순간
크로미움이 뜨고 수집을 시작한다. 한 번 실수로 띄워 죽인 적이 있다.
읽기만 한다. 돌려야 하면 러너로 보낸다.

### 3-3. VBA(.xlsm) 금지 · FILTER/스필 금지

- **.xlsm 은 사내 배포가 막힌다.** 매크로로 풀고 싶은 문제가 나와도 수식으로 푼다.
- **FILTER·UNIQUE 같은 스필 함수를 쓰지 않는다.** 담당자·고객의 구형 엑셀에서
  `_xlfn.` 으로 깨진다. 그래서 종목 검색이 `OFFSET` 기반 정의된 이름으로 되어 있다.

### 3-4. 수집이 실패하면 **옛 자료를 그대로 둔다**

`data/cc_etf.json` 을 건드리지 않고 끝낸다. 엑셀도 다시 만들지 않는다.
**반쯤 비어 있는 제안서가 고객에게 나가는 것보다, 직전 달 자료가 남는 편이 낫다.**
다만 잡은 빨갛게 남긴다 — 자료가 조용히 낡으면 안 된다.

### 3-5. 엑셀과 HTML 은 **같은 수**를 내야 한다

`check_etf_proposal.py` 가 엑셀 수식을 실제로 풀어 검산값을
`discovery/etf-expected.json` 에 적고, `check_etf_html.mjs` 가 HTML 을 브라우저로
열어 화면에 찍힌 값과 맞춰 본다. **둘 중 하나만 고치면 안 된다.**

### 3-6. 작업 가지와 푸시

- 개발은 `claude/intelligent-maxwell-dnreiw` 에서 한다(새 계정에서는 새 가지를
  받게 된다 — 그때는 그 가지 이름으로 읽는다).
- **정기 갱신은 `main` 의 워크플로 파일만 본다**(4-6절). 그래서 고친 것은
  결국 `main` 에 가 있어야 한다.
- PR 은 **요청받았을 때만** 연다.

## 4. 결정된 사항과 그 까닭

### 4-1. 원천의 벽은 **속도가 아니라 호출 수**에 걸린다 (실측)

처음에는 "너무 빨리 부르면 막힌다"고 보고 종목 사이에 250ms 를 넣었다.
재 보니 그게 아니었다.

| 판 | 쉬는 시간 | 호출 수 | 결과 |
|---|---:|---:|---|
| 옛 판 | 250ms | 2,596통 | **632/662 에서 벽** · 40분 |
| 곳간 도입 후 | 60ms | 1,590통 | 완주 · 14분 12초 |
| 시세 곳간이 더운 판 | 60ms | 12통 | 완주 · 2분 52초 |
| 그다음 판 | 60ms | 4통 | 완주 · 2분 37초 |

**벽은 1,590통과 2,596통 사이에 있다.** 느리게 부르는 것은 아무 도움이 안 되고
시간만 태운다. 그래서 `GAP_MS` 기본값을 60 으로 두었고(`ETF_GAP_MS` 로 바꿀 수 있다),
**줄여야 할 것은 호출 수**라는 결론으로 곳간을 넣었다.

> 다시 벽에 부딪히면 **쉬는 시간을 늘리지 말고 호출 수를 세어 본다.**
> 수집 끝에 `원천 호출 약 N통` 이 찍힌다.

### 4-2. 곳간의 판 번호를 **둘로 나눈다** (`CACHE_V` / `MKT_V`)

- `CACHE_V` — 분배 이력(종목당 4통)
- `MKT_V` — 시세에서 낸 결론(종목당 2통), `MKT_TTL_DAYS = 30`

**하나로 쓰면 안 된다.** 시세 칸이 바뀌었다고 판 번호를 올리면 분배 이력까지
버려져서, 종목당 2통이면 될 판이 6통이 된다. 지난 판에서 실제로 그렇게 벽에
부딪혔다. **무효화는 무효로 만들 것에만 걸어야 한다.**

### 4-3. 곳간에는 **원자료가 아니라 결론**을 담는다

250일치 시세를 664종목어치 그대로 담으면 곳간이 수십 MB 가 되고, 그 덩치가
달마다 통째로 커밋된다. 대신 거기서 낸 결론만 담는다 —
`{navVol, pxVol, volDays, jumps, turnover60, day0}`, 종목당 열 줄 남짓.

### 4-4. 시세 곳간 유효기간 30일 — 그리고 **묵은 것은 묵었다고 적는다**

7일로 두었더니 **매월 1일 정기 갱신이 늘 곳간 밖**이었다(지난 수집이 18일이면
13일째라 곳간을 못 쓴다). 곳간을 둔 목적이 그 판인데 그 판만 비껴간 셈이다.
30일이면 그 판도 안에 들어와 3분에 끝난다.

대신 변동성과 거래대금이 최대 한 달 묵는다. 둘 다 1년·60일을 보는 값이라 며칠
시세로는 소수점이 움직일 뿐이고, **고객이 보는 현재가·순자산·분배금·과세비율은
곳간을 안 거치므로 늘 기준일 자료다.**

그래도 종목마다 `marketAsOf`(그 시세를 받은 날)를 싣고, 수집 끝에 가장 묵은 것이
며칠인지 찍는다. **「묵어도 된다」와 「얼마나 묵었는지 모른다」는 다르다.**

### 4-5. 모르는 값은 **비운다** — 과세비율

과세비율을 못 구한 종목을 1 로 적어 두었더니 화면에서 「전액 과세」와 똑같이
100% 로 보였다. **모르는 것이 사실로 둔갑한다.** 못 구한 종목은 칸을 비우고,
계산 쪽에서 빈칸을 1 로 읽어 **세금을 많이 매기는 쪽**으로 셈한다(고객에게
불리한 방향으로 틀리지 않는다). 유의사항 문구도 **실제로 확보된 만큼만** 말한다.

### 4-6. **정기 갱신은 `main` 의 워크플로만 돈다**

GitHub Actions 의 `schedule` 은 **저장소 기본 가지에 있는 워크플로 파일만** 본다.
작업 가지에만 있는 워크플로는 cron 이 영원히 안 뜬다. 한동안 월간 자동 갱신이
실제로는 한 번도 안 돌고 있었고, 이 사실을 늦게 알았다.

**고친 것은 반드시 `main` 에 가 있어야 한다.** 확인 방법은 5절.

### 4-7. 장 보호 — 노란 칸만, **암호는 걸지 않는다**

잠금 표시는 원래 모든 칸에 켜져 있지만 **장 보호를 켜지 않으면 효력이 없다.**
한동안 표시만 있고 실제로는 무엇이든 지워졌다. 값의 거의 전부가 수식이라 한 칸만
지워져도 그 줄이 조용히 0원이 된다.

노란 입력칸(제안서 26칸 · 종목조회 63칸)만 잠금을 풀었다.
**막으려는 것은 실수지 사람이 아니므로 암호는 걸지 않는다** — 정말 고쳐야 하면
[검토] > [시트 보호 해제] 한 번이면 된다.

### 4-8. 「종목 검색」과 「계산」의 범위를 **분리한다**

- `검색결과` (OFFSET 기반) — 드롭다운 **목록만** 좁힌다
- `선택가능종목` — 담긴 종목의 **계산**이 보는 전체 목록

**둘을 한 범위로 묶으면 안 된다.** 묶으면 담아 놓은 뒤 검색어를 바꾸는 순간
담긴 종목의 수치가 엉뚱한 종목 것으로 바뀐다 — **화면은 멀쩡해 보이면서.**
검사기가 이 경우를 일부러 잡는다(`담긴 종목의 주수 × 원천 현재가 = 투자금액`).

### 4-9. 검색은 **먹었다는 신호**를 글자로 준다

검색은 ▼ 목록만 좁히므로 글자를 쳐 넣어도 화면이 곧바로 변하지 않는다.
담당자가 "아무 반응이 없다"며 고장으로 여겼다. 그래서 검색 칸 옆 안내를
살아 있는 글자로 바꿨다 — 걸린 건수를 말하고, 0건이면 ▼ 를 누르라고 하지 않는다.

### 4-10. 검사기는 **사람이 쓰는 대로 고약하게** 시험한다

통과만 하고 못 잡는 시험은 시험이 아니다. 담기는 **떨어진 네 줄(1·3·7·12번째)**을
담아 본다 — 붙은 줄만 시험하면 「건너뛴 줄에서만 틀어지는」 버그를 못 잡는다.
검색은 네 경우(많이 걸리는 말·안 걸리는 말·빈 칸·담은 뒤 검색어 변경)를 본다.

> 검사기를 고쳤으면 **일부러 망가뜨려 잡히는지 확인한다.** 생성기를 세 군데
> 망가뜨린 사본으로 돌려 셋 다 잡히는 것을 확인한 전례가 있다.

몇 분에서 **십수 분 이상** 밀린다. 한두 시간 밀리는 날도 있다.

워크플로가 하는 일: 수집 → 엑셀·HTML 다시 만들기 → **검사 두 벌** →
(통과해야) 커밋. 커밋 단계는 원격 최신에 맞춘 뒤 **생성기와 검사기를 다시 돌려서**
올리므로 그 단계만 6분 남짓 걸린다. 전체 15분 안팎.

### 손으로

```
Actions > 월배당 커버드콜 ETF 제안서 갱신 (매월 1일) > Run workflow > Branch: main
```

**가지를 `main` 으로 고르는 것이 중요하다.** 정기 갱신과 같은 경로를 밟아 봐야
그 경로가 살아 있는지 알 수 있다.

### 제대로 돌았는지 보는 곳

- 잡 요약(Summary)에 **기준일 · 후보 수 · 채택 수 · 상위 25종목 표**가 찍힌다.
- 수집 끝 로그에 `원천 호출 약 N통`, `시세 기준일 … (가장 묵은 것 N일)`.
- `main` 에 `chore(etf): 월배당 ETF 제안서 갱신 (YYYY-MM)` 커밋이 생기면 성공.

## 6. 막혔을 때

| 증상 | 까닭과 할 일 |
|---|---|
| **엑셀에서 「공유 위반」 — 파일 이름이 빈 칸** | 대개 저장 자체가 막힌 것이다. 창 제목에 **「제품 인증 실패」**가 떠 있는지 본다. 그러면 엑셀이 기능 축소 모드(보기·인쇄만)라 **어떤 파일도 저장이 안 된다.** 파일 탓이 아니다 — 엑셀 정품 인증을 푼다. (실제로 이 진단을 한 번 틀렸다. 파일 내부에는 `fileSharing`·`readOnlyRecommended`·`lockStructure` 가 **없다**.) |
| 급할 때 | HTML 을 브라우저로 열어 `Ctrl+P` → PDF 로 저장해 건넨다 |
| 엑셀을 열자마자 보호 해제하고 싶다 | [검토] > [시트 보호 해제]. **암호 없다**(4-7절) |
| 수집이 중간에 멈춘다(`632/662` 같은 자리) | 호출 수 벽이다. 쉬는 시간을 늘리지 **말고** `원천 호출 약 N통` 을 본다. 곳간이 비어 있을 때(판 번호를 올린 직후) 그렇게 된다 — 4-1·4-2절 |
| 정기 갱신이 1일에 안 떴다 | ① 밀렸을 수 있으니 몇 시간 기다려 본다 ② `.github/workflows/cc-etf-monthly.yml` 이 **`main` 에** 있는지 본다(4-6절) ③ Actions 에서 워크플로가 `active` 인지 본다 ④ 그래도 안 되면 `Run workflow` 로 손수 돌린다 — **결과는 같다** |
| 검사기가 `Missing Reference OFFSET` 을 뱉는다 | 정상이다. `formulas` 패키지가 OFFSET 을 못 풀 뿐이고, 그래서 `검색결과`(OFFSET 기반)는 직접 검증하지 못한다. 대신 그 효과를 **드롭다운 건수**로 재어 본다. 수식 한 판 푸는 데 25초쯤 걸린다 |
| 로컬에서 수집하고 싶어진다 | **하지 않는다.** 3-1·3-2절 |
