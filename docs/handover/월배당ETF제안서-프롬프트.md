## 1. 새 대화를 열 때 — 이 한 덩어리를 그대로 붙여 넣는다

새 계정의 첫 대화에서 아래를 통째로 넣는다. **줄이거나 요약하지 않는다.**
여기 적힌 네 가지를 모르면 첫 시도에서 반드시 막힌다.

```text
미래에셋증권 월배당 커버드콜 ETF 고객제안서 일을 이어서 합니다.
먼저 저장소의 이 세 문서를 읽고 시작하십시오.

  README.md 의 「월배당 커버드콜 ETF 고객제안서」 절
  docs/etf-proposal.md
  docs/handover/월배당ETF제안서-운영인계.md

지킬 것 네 가지입니다.

1. ETFCHECK 은 사내 이그레스 정책 때문에 이 세션에서 못 붙습니다. 수집과 탐침은
   전부 GitHub Actions 러너에서만 돌립니다. 프록시를 바꾸거나 TLS 검증을 끄는
   식으로 우회하지 마십시오.
2. scripts/collect_cc_etf.mjs 를 로컬에서 절대 실행하지 마십시오. 최상위에
   바로 실행되는 코드가 있어 부르는 순간 크로미움이 뜨고 수집이 시작됩니다.
   읽기만 하십시오.
3. VBA(.xlsm)는 사내 배포가 막혀 쓸 수 없습니다. FILTER·UNIQUE 같은 스필 함수도
   쓰지 마십시오 — 구형 엑셀에서 _xlfn. 으로 깨집니다.
4. 엑셀과 HTML 은 반드시 같은 수를 내야 합니다. 둘 중 하나만 고치지 마십시오.
   check_etf_proposal.py 와 check_etf_html.mjs 가 교차 검사합니다.

개발은 작업 가지에서 하고, PR 은 제가 요청할 때만 여십시오.
정기 갱신은 main 의 워크플로만 돌기 때문에, 고친 것은 결국 main 에 가 있어야 합니다.
```

## 2. 날마다 쓰는 짧은 말

실제로 주고받으며 굳어진 표현들이다. 길게 쓸 필요 없다.

| 하고 싶은 것 | 이렇게 말한다 |
|---|---|
| 이번 달 판 돌리기 | `최신치로 업데이트해줘` / `돌려줘` |
| 완성 파일 받기 | `최신치 파일 올려줘` / `엑셀, html 파일 올려줘` |
| 한쪽만 다시 받기 | `html 파일 다시 올려줘` / `엑셀 파일도 다시 올려줘` |
| 진행 상황 | `얼마나 남았어?` / `예상 소요 시간은?` |
| 끝나면 알려 달라 | `결과 나오면 알려주고 갱신본 올려줘` |
| 수치까지 같이 | `수집 결과 수치도 같이 알려줘` |
| 러너에서도 통과했나 | `러너 판도 통과했는지 확인해줘` |
| 기능이 진짜 되는지 | `종목 조회에서 담기 눌렀을때 제대로 들어가는지 확인해줘` |
| 그 시험을 상비하기 | `검사기에도 이 시험들 추가해줘` |
| 정기 갱신 점검 | `매월 1일 정기 갱신도 정상적으로 작동하는지 확인해줘` |
| 합치기 | `PR 열어서 합쳐줘` |
| 가지 정리 | `작업 가지도 main에 맞게 정리해줘` |
| 느릴 때 | `좀 더 빠르게 효율적으로 처리할 수 있는 방법은 없는지 고민해봐` |

### 날짜를 알려 줄 때

세션 시계가 UTC 라 **한국 날짜와 하루 어긋나 보일 때가 있다.** 헷갈릴 일을
없애려면 첫 줄에 날짜를 박는다. 받는 쪽은 `TZ=Asia/Seoul date` 로 다시 확인한다.

```
오늘은 2026년 10월 1일이야. 이번 달 판 돌려줘.
```

### 되묻기를 줄이는 말버릇

- **「확인해줘」는 「돌려서 실제로 확인해줘」로 읽힌다.** 추측이 아니라 러너
  로그나 실제 수식 계산으로 답하게 된다. 그 편이 느리지만 틀리지 않는다.
- **「없는지 고민해봐」**는 바로 고치지 말고 **먼저 안을 내놓으라**는 뜻으로
  통했다. 안을 받은 뒤 `1,2 적용해줘` 처럼 번호로 고르면 된다.

## 3. 예약(Routine) — 이 일은 **필요 없다**

갱신은 **GitHub Actions 의 cron** 이 한다. Claude 쪽 예약은 계정에 묶이지만
이쪽은 저장소에 묶여 있어 **계정이 바뀌어도 그대로 돈다.**

```yaml
# .github/workflows/cc-etf-monthly.yml
on:
  schedule:
    - cron: '0 1 1 * *'        # 매월 1일 10:00 KST (KST=UTC+9, 서머타임 없음)
  workflow_dispatch:
  push:
    branches: ['claude/intelligent-**']
    paths:    ['scripts/collect_cc_etf.mjs']    # 수집기를 고치면 바로 검증된다
```

굳이 Claude 예약을 하나 두고 싶다면 **갱신이 아니라 「확인」**으로 둔다.
갱신을 두 군데서 돌릴 이유는 없다(원천 호출만 두 배가 된다).

- 예약 이름: `월배당 ETF 제안서 — 정기 갱신 확인 (매월 1일 12:00 KST)`
- cron: `0 3 1 * *`
- 전달 방식: **쓰고 있는 대화로 전달**(persistent session)

```text
매월 1일 ETF 제안서 정기 갱신이 제대로 돌았는지 확인할 시각입니다.

1. GitHub Actions 의 「월배당 커버드콜 ETF 제안서 갱신 (매월 1일)」 워크플로에서
   오늘 자 schedule 판이 있는지, 결론이 success 인지 봅니다.
2. main 에 chore(etf): 월배당 ETF 제안서 갱신 (YYYY-MM) 커밋이 생겼는지 봅니다.
3. 잡 요약의 기준일·후보 수·채택 수와, 수집 로그의 「원천 호출 약 N통」·
   「시세 기준일 … (가장 묵은 것 N일)」 을 읽어 알려 주십시오.
4. 안 떴으면 몇 시간 밀린 것일 수 있으니 기다려 보고, 그래도 없으면 Branch: main
   으로 손수 돌리십시오. 결과는 같습니다.
5. 다 되면 고객제안서_월배당ETF.xlsx 와 docs/etf-proposal.html 두 파일을 올려 주십시오.

수집은 러너에서만 돕니다. 세션에서 ETFCHECK 에 붙으려 하지 마십시오.
```

## 4. 시스템 설정 사본 — 저장소에 있으므로 **그대로 계승된다**

여기 베껴 둔 것은 「무엇이 어디에 왜 있는지」 빨리 파악하기 위한 지도다.

### 4-1. `.claude/settings.json`

```json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "hooks": {
    "SessionStart": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/session-start.sh"
          }
        ]
      }
    ]
  }
}
```

### 4-2. `.claude/hooks/session-start.sh` — 하는 일

웹 세션이 시작될 때만 돈다(`CLAUDE_CODE_REMOTE=true`).

- **playwright 1.56.1** 을 깐다. 저장소가 `package.json` 을 `.gitignore` 로 빼기
  때문에 새 세션에는 `node_modules` 가 없다. HTML 검사기가 playwright 를 부르므로
  이게 없으면 시작하자마자 막힌다. 판 번호는 **워크플로가 쓰는 것과 같게** 맞춘다.
- **크로미움은 내려받지 않는다.** 이 환경에는 `/opt/pw-browsers` 에 이미 있다.
  다시 받으면 수백 MB 를 세션 몫 디스크에 또 쌓는다.

### 4-3. 수집기의 손잡이 (`scripts/collect_cc_etf.mjs`)

| 이름 | 값 | 무엇 |
|---|---:|---|
| `CACHE` | `data/etf_dist_cache.json` | 곳간 파일 |
| `CACHE_V` | 2 | **분배 이력** 판 번호 |
| `MKT_V` | 1 | **시세 결론** 판 번호 — 분배와 **반드시 따로 둔다** |
| `MKT_TTL_DAYS` | 30 | 시세 결론 유효기간 |
| `GAP_MS` | 60 | 종목 사이 쉬는 시간. 환경변수 `ETF_GAP_MS` 로 바꾼다 |
| `MIN_UNIVERSE_AUM` | 300억 | 모집단: 순자산 300억 **∨** 월배당 분류(0609002) |

> 판 번호를 올리면 **그 판의 곳간이 통째로 버려진다.** 올리기 전에 호출 수가
> 얼마나 늘어나는지 세어 본다(종목당 분배 4통 · 시세 2통).

### 4-4. 워크플로 단계와 걸리는 시간

| 단계 | 대략 |
|---|---|
| 준비(checkout · node · python · playwright · 파이썬 꾸러미) | 2분 |
| ETFCHECK 수집 | 곳간이 더우면 **3분**, 비었으면 **14분+** |
| 엑셀·HTML 다시 만들기 | 10초 |
| 검사 두 벌 | **6~7분** (엑셀 수식을 실제로 풀기 때문. 한 판 25초) |
| 커밋(원격 최신에 맞춰 **다시 만들고 다시 검사**) | **6~7분** |

**합쳐 15분 안팎.** 커밋 단계가 오래 걸리는 것이 정상이다 — 그냥 `git commit`
하는 단계가 아니라 생성기와 검사기를 한 번 더 돌린다.

### 4-5. 비밀값

**이 일에는 비밀값이 없다.** ETFCHECK 은 화면이 쓰는 비공개 API 를 러너의
브라우저가 그대로 타는 방식이라 토큰을 따로 보관하지 않는다
(앱이 `authorization: Bearer` 와 `checkclient` 헤더를 붙인다 — 맨 `fetch` 로는 403).

## 5. 산출물을 어디서 꺼내나

| 무엇 | 어디 |
|---|---|
| 담당자용 엑셀 | 저장소 최상위 `고객제안서_월배당ETF.xlsx` |
| 고객용 화면 | `docs/etf-proposal.html` |
| 그 둘의 원천 | `data/cc_etf.json` |
| 지난 달 판 | `git log --oneline -- data/cc_etf.json` 에서 그 달 커밋을 찾아 `git show <커밋>:data/cc_etf.json` |
| 엑셀만 다시 만들기 | `python scripts/build_etf_proposal.py` (3초, 수집 안 함) |
| HTML 만 다시 만들기 | `python scripts/build_etf_proposal_html.py` |
| 검사 | `python scripts/check_etf_proposal.py` → `node scripts/check_etf_html.mjs` |

**생성기와 검사기는 세션에서 그대로 돌아간다**(원천에 안 붙는다).
러너가 필요한 것은 **수집뿐**이다.
