# 법령 조회 — 국가법령정보센터 OPEN API

자료에 법 조문을 인용할 때, 검색 요약이 아니라 **국가법령정보센터 원문**을 쓰기 위한
경로입니다. 시세 수집과 같은 구조입니다 — 러너가 받아 저장소에 커밋하고, 세션은
커밋된 파일을 읽습니다.

## 왜 이렇게 하는가

세션은 `law.go.kr` 에 직접 붙지 못합니다. 사내 이그레스 정책이 CONNECT 를 막습니다
(curl·WebFetch 모두 403). GitHub 러너는 그 정책 밖에서 돌기 때문에 러너가 대신 받습니다.

검색 결과 요약으로 조문을 인용하면 안 되는 이유는 하나입니다. **시행일이 다르면 다른
조문입니다.** 검색 요약에는 시행일이 없거나 개정 전 조문이 섞입니다. 여기서는 시행일자·
공포번호를 조문과 함께 저장해, 인용할 때 어느 판인지 같이 밝힐 수 있게 합니다.

## 처음 한 번 — 인증키

1. `open.law.go.kr` 에서 OPEN API 를 신청합니다. 인증키(OC)는 발급받는 것이 아니라
   **직접 정하는 아이디**이고, 호출할 때 `OC=<값>` 으로 들어갑니다.
2. 저장소 **Settings → Secrets and variables → Actions** 에 `LAW_OC` 로 넣습니다.
   워크플로가 그 이름으로 읽습니다. 없으면 첫 단계에서 이유를 찍고 멈춥니다.

키가 사는지는 브라우저에서 바로 확인됩니다:

```
http://www.law.go.kr/DRF/lawSearch.do?OC=<키>&target=law&type=JSON&query=자본시장
```

## 쓰는 법

```bash
# 무엇을 받아 뒀는지
python3 scripts/law_lookup.py --list

# 조문 원문 — 머리글에 시행일자가 같이 나온다
python3 scripts/law_lookup.py 자본시장법 55
python3 scripts/law_lookup.py 자본시장법 55의2      # 제55조와 제55조의2 는 다른 조문
python3 scripts/law_lookup.py 자본시장법 55-58

# 받아 둔 전부에서 말 찾기
python3 scripts/law_lookup.py --grep 손실보전

# 조문 목록만
python3 scripts/law_lookup.py 자본시장법
```

`--list` 아래에 "못 받은 것" 이 있으면 그 법령은 **확보되지 않은 것**입니다. 인용하지
말고 다시 수집하거나, 자료에 미확인으로 표시합니다.

## 다시 받기

법령은 매일 바뀌지 않으므로 **매주 월요일 07:00 KST** 에 한 번 돕니다. 개정이 있었거나
받을 법령을 늘렸으면 직접 부릅니다:

```bash
bash scripts/request_law_refresh.sh     # 러너에 수집을 부른다 (1~2분)
git pull && python3 scripts/law_lookup.py --list
```

세션 토큰에는 Actions 쓰기 권한이 없어 `workflow_dispatch` 를 API 로 부르면 403 입니다.
그래서 워크플로가 지켜보는 `data/law/REFRESH` 를 한 줄 고쳐 밀어 넣습니다. 시세 쪽
`request_market_refresh.sh` 와 같은 수법이고, 다른 점은 **지금 있는 브랜치에** 올린다는
것뿐입니다.

## 받을 법령 늘리기

`data/law/targets.json` 의 `법령` 배열에 이름을 넣습니다. 국가법령정보센터에 등록된
정식 명칭을 그대로 적습니다(띄어쓰기 차이는 맞춰 줍니다).

```json
{ "이름": "상법", "target": "law" }
```

`target` 은 `law`(법률·시행령·시행규칙), `admrul`(행정규칙 — 고시·규정),
`ordin`(자치법규)입니다. 이 파일을 고쳐 push 하면 수집이 바로 돕니다.

목록에 넣지 않고 한 번만 받아 볼 수도 있습니다(러너에서):

```bash
python scripts/fetch_law.py --query 상법
```

## 저장물

| 경로 | 내용 |
|------|------|
| `data/law/index.json` | 받아 둔 법령 목록 + 시행일자·공포번호·조문수, 실패한 것은 사유까지 |
| `data/law/raw/<법령명>.json` | API 응답 **원문 그대로** — 1차 출처. 뜯은 결과가 의심되면 여기로 돌아온다 |
| `data/law/articles/<법령명>.json` | 조문 단위로 끊은 것. `law_lookup.py` 가 읽는다 |
| `data/law/text/<법령명>.txt` | 사람이 읽는 전문 |
| `data/law/targets.json` | 받을 법령 목록 |

이번 수집에서 실패한 법령의 **지난 기록은 지우지 않습니다.** 어제 받아 둔 조문이 오늘
API 가 한 번 흔들렸다고 사라지면 인용하던 자료가 통째로 끊깁니다.

## 파서 점검

응답의 겉모양은 법령 종류마다 다르고 안내서와도 조금씩 어긋납니다. 열쇠 이름을 하나
박아 두면 그 종류에서만 조용히 빈 파일이 나오므로, 나무 전체를 훑어 조문처럼 생긴
마디를 찾는 방식으로 짰습니다. 망 없이 파서만 돌려 볼 수 있습니다:

```bash
python3 scripts/fetch_law.py --selftest
```

워크플로도 수집 전에 이것을 먼저 돌립니다.

## 인용할 때

조문을 자료에 옮기면 **시행일자를 같이 적습니다.** `law_lookup.py` 가 찍는 머리글이
그대로 인용 표기가 됩니다.

> 자본시장과 금융투자업에 관한 법률 제55조 (시행 2026. 8. 4., 법률 제21324호)

받아 둔 것은 **받은 시점의 현행본**입니다. 그 뒤의 개정은 다시 수집해야 반영됩니다.
`index.json` 의 `수집시각` 이 오래됐으면 인용 전에 한 번 다시 부르십시오.
