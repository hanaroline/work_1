# MARKET DAILY — 모닝시황·마감시황 카드뉴스

세로로 스크롤하는 단일 HTML 카드뉴스입니다. 기존 마포WM 브리핑
(`docs/briefings/`)과 **별개 산출물**이며, 시세 수집과 검증 규칙은 함께 씁니다.

```
표지        MARKET DAILY + 날짜 + 헤드라인 5줄
마켓보드    1단 기준선 7종 · 2단 무빙 3종목(+공통 배경 한 줄)
빅테크보드  종목·종가·등락률·코멘트 + 기억할 포인트 3~4줄   (마감판은 대형주 보드)
뉴스카드    5장
검증 노트   표마다 기준 시점과 출처
고지문      내부 참고용, 특정종목 매매 권유 아님
```

## 하루 돌리는 순서

```bash
cd "$(git rev-parse --show-toplevel)"
git pull -q origin main

# 1. 수집이 오늘 것인지 본다. 낡았으면 아래 REFRESH 로 부른다.
python3 -c "import json;d=json.load(open('data/us_movers/latest.json'));print(d['session_date'],d['generated_at_kst'])"
bash -c "printf '요청 %s\n' \"$(TZ=Asia/Seoul date)\" > data/market_daily/REFRESH"   # 고쳐서 push 하면 수집이 돈다

# 2. 글을 쓴다 (숫자는 쓰지 않는다 — 표가 채운다)
#    data/market_daily/narrative-<거래일>-<판>.json

# 3. 만든다
python3 scripts/build_market_daily.py --edition morning
python3 scripts/build_market_daily.py --edition close --date <거래일>

# 4. 검산한다. **실패하면 배포하지 않는다.**
python3 <fin-data-integrity>/scripts/check_claims.py docs/market-daily/<거래일>-<판>.claims.json
python3 scripts/audit_numbers.py docs/market-daily/<거래일>-<판>.html data/market/<기준 스냅샷>.json

# 5. 전달용 문구를 뽑는다 (메일 본문·메신저)
python3 scripts/market_daily_digest.py --edition <판> --date <거래일>
```

## 숫자와 글은 출처가 다릅니다

**표의 숫자는 수집 파일에서만 나옵니다.** 빌더에는 숫자를 손으로 적을 자리가
없습니다. 글은 `data/market_daily/narrative-*.json` 에서 오고, 글에 숫자를
박아야 하면 그 파일의 `claims` 배열에 출처·기준일과 함께 등록합니다.
등록하지 않은 숫자는 검산이 잡지 못하므로, **되도록 표에 맡기고 글에서는
방향만 말하십시오.**

빌더는 HTML 과 함께 주장 대장(`*.claims.json`)을 냅니다. 인쇄되는 등락률은
전부 「종가 ← 전일 종가」 파생 항목으로 등록되므로 `check_claims.py` 가
산술을 다시 계산해 대조합니다.

## 여기서 실제로 틀렸던 것들

이 절은 장식이 아닙니다. 아래는 **만드는 동안 실제로 산출물에 들어갔다가
잡아낸** 오류입니다.

**날짜 필드가 없는 블록에서 오늘 장중값을 읽었습니다.**
`data/market/latest.json` 의 `sectors`·`usdkrw_naver`·`rates_kr`·
`market_internals` 에는 날짜가 없습니다. 장중에 수집된 파일을 그대로 읽으면
**오늘 실시간 값**이 나옵니다. 초고가 9월 18일 업종 1위를 「소프트웨어
+10.27%」로 적었는데 그것은 9월 21일 장중 값이었고, 9월 18일 확정치는
통신장비 +6.94% 였습니다. **기준일 스냅샷(`data/market/<날짜>.json`)에서
읽으십시오.**

**한글 이름이 대장 id 를 무너뜨렸습니다.**
id 를 만들 때 영숫자가 아닌 글자를 `_` 로 바꾸기만 해서 「삼성전자」·
「현대차」·「기아」가 **모두 같은 id** 가 되었고, 뒤에 등록된 종목이 앞의
것을 덮어썼습니다. 검산기가 삼성전자의 등락률로 기아의 인쇄값을 대조하며
불일치를 냈고, 그 덕에 잡혔습니다. 지금은 비ASCII가 섞이면 짧은 해시를
붙입니다.

**국내 스크리너의 시총 순위는 시총 순위가 아닙니다.**
네이버 종목 목록 API 는 한 번에 100건까지만 주고 그 100건은 **등락률
상위**입니다. 거기서 시총으로 다시 세우면 「급등락한 종목 중 시총 상위」가
나옵니다 — 실제로 삼성전자 대신 삼성전자우·가온전선이 올라왔습니다. 마감판
대형주 보드는 시세 파일(`stocks`)의 **고정 10종목**에서 읽습니다.

**같은 날짜 봉이 수집 시각에 따라 달라집니다.**
WTI 9월 18일 봉은 9월 19일 수집분에서 95.47달러, 9월 20일 수집분에서
96.08달러였습니다. 24시간 거래되는 항목은 마감 뒤에도 손질됩니다. 빌더는
대상 거래일을 **전부** 담은 스냅샷 중 **가장 이른 것**(마감 직후 수집분)을
고릅니다.

**검색이 하루 전 마감을 오늘 것으로 돌려줍니다.**
「2026년 9월 18일 뉴욕증시 마감」 검색이 9월 17일 종가(다우 51,778.04 ·
S&P 7,637.76)를 돌려줬습니다. 국내 조간이 전날 뉴욕장을 다루기 때문입니다.
**거래소 원천을 채택하고 기사 수치는 버리십시오.**

**기사의 등락률은 장중일 수 있습니다.**
암호자산 관련주를 매체는 +12~13%로 적었지만 마감 확정치는 +16.39% 였습니다.
반대로 WTI 를 「−1.8%」로 적은 기사가 있었는데, 그 값($100.08)은 국내 마감
시각(15:30 KST)의 시세였고 뉴욕 정산가는 95.47달러였습니다. **기사는 배경에
쓰고 숫자는 시세 파일에서 가져오십시오.**

**산출물은 HTML 입니다 — 원고에 마크다운을 쓰지 마십시오.**
`**강조**` 가 별표째로 찍혔습니다.

## 표 하나는 한 출처로

사양의 "지수·개별 종목 시세는 각 표 안에서 반드시 한 출처로 통일" 을 이렇게
지킵니다.

- **기준선 표** — 스냅샷 **한 파일**에서만 읽습니다. 그 파일에 대상 거래일
  값이 없는 항목은 다른 파일에서 끌어오지 않고 비워 두고, 검증 노트에
  적습니다.
- **무빙·빅테크 표** — 종가와 등락률이 **야후 시세 한 번의 응답**에서
  나옵니다. 나스닥 스크리너는 후보를 고르는 데만 쓰고 그 숫자는 인쇄하지
  않습니다.
- **마감 기준선** — 같은 아시아 시간대에 닫히는 지수 7종으로 맞췄습니다.
  원/달러는 넣지 않습니다. 야후 `KRW=X` 는 24시간 시세라 서울 외환시장
  마감이 아닙니다(플레이북 0-1절). 매매기준율은 뉴스카드에서 다룹니다.

## 수집

```
scripts/fetch_us_movers.py  → data/us_movers/   모닝: 어제의 무빙 · 빅테크 10종목
scripts/fetch_kr_movers.py  → data/kr_movers/   마감: 국내 무빙
.github/workflows/market-daily-data.yml         둘을 함께 돌린다
```

세션은 야후·나스닥·네이버에 직접 붙지 못하므로(CONNECT 000) 수집은 러너가
합니다. `data/market_daily/REFRESH` 를 고쳐 push 하면 워크플로가 돕니다 —
세션 토큰에는 Actions 쓰기 권한이 없어 `workflow_dispatch` 는 403 입니다.

**마감시황은 `market_status` 가 `CLOSE` 인 수집분만 씁니다.** 같은 API 가
장중에는 실시간을 주므로, 장중 값을 「오늘 마감」으로 실으면 하루가
어긋납니다. 빌더가 이것을 확인하고 어긋나면 쓰지 않습니다. 장중 수집분은
파일 이름에 `-intraday` 가 붙습니다.

국내 전 종목 스크리너가 없는 날에는 시세 파일(`stocks`) 유니버스로
대체하고, **「시장 전체 순위가 아닙니다」를 산출물에 적습니다.**

## 전달 — 아직 손이 필요한 곳

`scripts/market_daily_digest.py` 가 세 파일을 냅니다.

```
<거래일>-<판>.mail.html       메일 본문 (인라인 스타일)
<거래일>-<판>.mail.txt        평문 대체
<거래일>-<판>.messenger.txt   메신저용 — 헤드라인 5줄 + 보드 10종목 등락률
```

**카드뉴스 HTML 첨부는 이 세션에서 하지 못합니다.** Gmail 도구가 첨부를
base64 로 호출에 직접 실어야 하는데, 40KB 파일은 약 5만 자가 되어 무결하게
옮길 방법이 없습니다(한 글자만 어긋나도 파일이 깨집니다). 지금은 메일 본문에
요약을 싣고 카드뉴스 경로를 적습니다. 자동으로 첨부까지 하려면 **러너에서**
Gmail API 를 부르는 단계를 워크플로에 더하고 인증을 저장소 시크릿에 넣어야
합니다.

**메일 본문에 `background:` 를 쓰지 마십시오.** Gmail 이 지웁니다 — 흰
글씨를 얹어 두면 흰 배경에 흰 글씨가 됩니다. `<table bgcolor="...">` 는
살아남습니다.

**카카오톡 전송 도구는 이 세션에 없습니다.** `messenger.txt` 를 그대로
복사해 「나와의 채팅」에 붙여 넣으십시오.
