## 3. 아티팩트를 어떻게 할 것인가 — 선택지 셋

판 **131개**(발행본 81개)의 HTML 은 저장소에 그대로 있습니다. 주소만
새로 받으면 됩니다.

| 방법 | 품 | 결과 |
|---|---|---|
| **① 앞으로 것만 발행** (권함) | 없음 | 오늘부터 만드는 판만 새 주소. 지난 판은 저장소 파일로 열람 |
| ② 최근 것만 다시 발행 | 10~20분 | 최근 2~4주치만 링크 복구 |
| ③ 81판 전부 다시 발행 | 수십 분 + 토큰 많이 | 목록 한 장이 전부 살아남 |

②③ 을 고르면 이렇게 합니다.

```bash
# 단독 HTML 만들기 (브라우저 없이, 빠름)
python3 scripts/make_standalone.py docs/briefings/<판>.html
# → 만들어진 파일을 Artifact 로 발행하고, 받은 주소를
#   docs/briefings/index.json 의 그 판 url 에 적는다
python3 scripts/build_archive_nav.py     # 판마다 실리는 목록 다시 생성
python3 scripts/build_archive_page.py    # 목록 한 장 다시 생성
```

**①을 고르면** `index.json` 의 옛 주소를 그대로 두되, 목록 한 장 상단에
«이 아래 주소들은 옛 계정 것이라 열리지 않습니다»를 적어 두는 편이 낫습니다.
안 그러면 열어 보고 당황합니다.

## 5. 반드시 지켜야 할 규칙 — 어기면 사고가 났던 것들

지침에 다 있지만, **실제로 사고가 났던 것**만 추렸습니다.

### 5-1. 「표는 자료에서, 글은 기사에서」

표·날짜 이름표·비율·개수·주도 종목은 **빌더가 `latest.json` 에서 만듭니다.**
사람은 **서술만** 씁니다. 숫자를 문장에 손으로 적으면 다음 날 어긋납니다.

### 5-2. 수집 시각이 곧 자료의 성격입니다 — **거래량으로 마감을 확인하십시오**

날짜 이름표가 오늘이어도 **장중 호가일 수 있습니다.** 신선도 검사기는
날짜만 봅니다.

- **S&P500 정규장 ≈ 26~32억 주.** 2~3억 주면 장중입니다(10분의 1)
- 실제 사고: 9/22 판이 뉴욕 개장 **17분 뒤** 값으로 나갔습니다
  (S&P +0.66% 로 찍혔으나 마감은 **+1.49%**)
- 9/30 과 10/1 에도 07:30 시점 파일이 장중값이라 재수집해 다시 지었습니다

### 5-3. 수집기의 `prev_close` 가 하루 밀리는 일이 있습니다

**이틀치가 하루치로 표시되고, 부호까지 뒤집힙니다.**

- 9/24: 15개 항목(나스닥·다우·SOX·러셀·MOVE·ASML·미국 업종 ETF 9개).
  **SOX 가 +0.81% 로 찍혔으나 실제는 −1.23%**
- 같은 결함이 **코스피·코스닥에도** 있었는데 대조 방식 때문에 검사에서
  빠져 9/24·9/25 판에 그대로 실렸습니다(코스피 +1.04% → 실제 **+0.90%**).
  두 판 모두 9/30 에 정정했습니다
- **대조 방법**: 직전 영업일 스냅샷의 **종가**와 맞춰 보십시오.
  git 이력에서 그 시각 `latest.json` 을 꺼낼 수 있습니다

### 5-4. 원자재 표는 아침 수집분에서 거의 항상 못 씁니다

07:40 수집은 뉴욕 상품시장이 닫힌 뒤의 **아침 전자거래**입니다.
**거래량을 보십시오** — WTI 600~2,000계약, 브렌트 30~130계약이면 호가입니다
(정상은 WTI 30만 계약대). 브렌트는 근월물 교체까지 겹쳐 −8% 같은 값이
찍힙니다. **등락률만 보지 말고 거래량을 함께 보십시오.**

### 5-5. 업종 「가정용품」은 자료가 깨져 있습니다

9/21 **+145.12%**, 9/23 **+162.28%**, 1주 누적이 **+88~450%** 로 찍힙니다.
9/29·9/30·10/1 판에서 세 번 걸렀습니다.
**표에서 지우지 마십시오** — 지우면 다음 판에서 조용히 돌아옵니다.
그대로 두되 «읽지 마십시오»를 본문과 검증 절에 적습니다.
**원천은 아직 확인하지 못했습니다.**

### 5-6. 표와 본문이 어긋나지 않게 하십시오

재검증에서 **세 번** 잡힌 유형입니다. 표의 하위 몇 줄을 본문이 설명하지
않으면, 읽는 사람은 설명 없는 줄을 먼저 봅니다. 업종·종목 표의 **맨 위
몇 줄은 반드시 본문이 언급**하거나, 왜 읽지 말아야 하는지 적으십시오.

### 5-7. 종목 표의 「사유」(`why`)는 확인된 것만

지수를 따라 움직였을 뿐인 종목에 이야기를 붙이면 **그 자체가 틀린 정보**입니다.
기사로 확정되지 않으면 **비워 두고** 검증 절에 «비웠다»고 적습니다.

### 5-10. 검증 다섯은 **겹치지 않습니다 — 다 돌리십시오**

| 검사기 | 무엇을 보나 |
|---|---|
| `recheck.py` | 절·표 개수, 한/영 짝, 날짜 정합, 꼬리말 |
| `audit_numbers.py` | 서술의 숫자 vs 자료. **오탐이 섞입니다** |
| `dupcheck.py` | 판 안 중복, 지난 판 반복 비율 |
| `stale.py` | 「어제/내일」 같은 상대 표현이 오늘 기준으로 맞는지 |
| `sweep.mjs` | 340~1920px 를 20px 씩 훑어 넘침 0 확인 |

**`audit_numbers.py` 의 단골 오탐** — 개수만 보지 말고 하나씩 보십시오.
- 방향을 **말로** 쓴 자리(「0.86% 내려」) → 부호 없는 숫자를 `+` 로 읽습니다
- **부분 문자열**: 「건강관리**기술**」이 기술 업종으로, 「**에너지**장비」가
  에너지 업종으로, 「대형**기술**주」가 미국 기술 ETF 로 잡힙니다
- **SK하이닉스 ADR** 은 미국 상장분이라 국내 값과 다릅니다

**소급 제작 판에서는** `audit_numbers.py` 에 **그때 스냅샷을 두 번째 인자로**
주십시오. 안 그러면 현재 시세와 대조해 전부 어긋나게 나옵니다.
```bash
python3 scripts/audit_numbers.py docs/briefings/<판>.html <그때 스냅샷>.json
```

| 해외 | `narrative-2026-09-27-global.json` |
| **장마감** | **`narrative-2026-09-30.json`** — 접미사 **없음** |

즉 접미사가 없는 파일은 **장마감판 자리**입니다. 아침 판을 접미사 없이
쓰면 그날 장마감 판과 한 파일을 다투게 됩니다 — 8/28 과 9/8 에 실제로
그랬습니다. **모닝·해외는 반드시 접미사를 붙이고, 장마감은 붙이지
않는 것이 지금까지의 관례**입니다(`-close` 로 써도 빌더는 찾습니다).

### 5-14. 업종 등락률에 **±30% 천장**이 걸려 있습니다

9/23 수집분에 「가정용품 **+162.93%**」가 들어왔습니다. 국내 주식의 하루
가격제한폭이 ±30% 이므로, 종목을 시가총액으로 묶은 업종 지수는 **어떤
날에도 30% 를 넘을 수 없습니다.** 넘으면 산술이 아니라 **수집이 틀린
것**입니다.

`scripts/briefing_prepare.py` 의 `SECTOR_LIMIT_PCT = 30.0` 과 `_sectors()`
가 이것을 거릅니다. 설계 의도를 지켜 주십시오.

- 거르는 것은 **산술적으로 불가능한 값뿐**입니다. 「수상쩍은 값」을
  빼지 않습니다 — 9/30 의 「가정용품 −14.24%」는 한도 안이므로 **표에
  그대로 실었습니다**
- 돌려주는 차례는 원천의 `bottom5` 와 **같습니다**(덜 내린 것이 위).
  뒤집으면 지난 판들과 표가 거꾸로 섭니다
- 거른 줄이 있으면 **검증 절에 적습니다**. 조용히 빼지 않습니다

9/21~9/22 수집분에 되돌려 보아 **한 줄도 빠지지 않음**을 확인했습니다
(되돌이 없음).

### 5-15. 종목 표 「사유」줄에 **그 종목의 값이 아닌 숫자를 적지 않습니다**

핵심본의 두 칸 표에서는 사유 줄이 **그 종목의 등락률 바로 옆**에 섭니다.
사유에 다른 숫자가 있으면 읽는 사람이 두 숫자를 같은 것으로 봅니다.
실제로 세 번 잡았습니다.

| 판 | 사유에 적혀 있던 것 | 바로 옆 그 종목 값 |
|---|---|---|
| 현대건설 | 「건설업이 4.30%」 | +4.54% |
| LG전자 | 「전자제품 −3.14%」 | −3.46% |
| SK하이닉스 | 「ADR 3.45%」 | +1.20% |

업종·ADR 수치는 **본문에서** 말하고, 사유 줄은 숫자 없이 씁니다.

### 5-16. 반올림을 **마지막에** 하십시오

9/21 정정 카드에 「25.9% 감소」라고 적었는데,
20,811,215 ÷ 28,104,963 − 1 = −25.9518% 이므로 **26.0%** 입니다.
중간값을 눈으로 깎아 쓰지 말고 계산기를 끝까지 돌리십시오.

### 5-17. 내 글의 **긴 수식이 340px 를 넘깁니다**

9/21 판에서 문서 넘침 210px 이 났는데, 원인은 표가 아니라 검증 노트에
내가 쓴 토막이었습니다 —
`(7,007.72&minus;3,365.73)&divide;(9,385.59&minus;3,365.73)=60.5%`.
줄바꿈 자리가 없어 한 덩어리로 섭니다. **`&minus;` `&divide;` `=` 양옆에
공백을 넣으십시오.** 그러면 넘침이 0 이 됩니다.

### 5-13. 막히면 **조용히 끝내지 마십시오**

무엇이 어디서 막혔는지 대화에 한국어로 적으십시오. 사용자가 화면을 보고
있습니다. 시세가 끝내 안 들어오면 포기하지 말고 «시세 파일이 (수집 시각)
기준이라 (항목)은 (날짜) 값입니다»를 머리말과 검증 노트에 **명시한 뒤**
확보된 범위까지만 내보냅니다.

## 6. 환경 제약 (이 실행 환경에서 겪은 것)

- **`workflow_dispatch` 를 API 로 부르지 마십시오** — 세션 토큰에 Actions

### 6-1. 실행이 **한 자리에서 되풀이해 끊깁니다** — 중간 저장 셋

장마감 창에서 9/21 · 9/23 · 9/28 · 9/30 **네 번**, 모두 **같은 자리**에서
끊겼습니다 — `SendUserFile` 바로 뒤, **아티팩트 발행 직전**입니다.
그래서 `scripts/save_progress.sh` 로 **세 번** 중간 저장을 합니다.

| | 언제 | 무엇을 |
|---|---|---|
| ① | 서술 파일을 쓴 직후 | `data/briefing/narrative-<날짜>.json` |
| ② | **검증 뒤 · 발행 전** | 만든 HTML·PDF 와 `index.json`(이때 `url` 은 `null`) |
| ③ | 아티팩트 주소를 받은 뒤 | `index.json` 의 `url` 을 채워 |

**`index.json` 의 `url: null` 이 「발행만 남았다」는 표식**입니다. 다음
회차(또는 다른 창)가 그것을 보고 **발행부터** 이어 갑니다. 네 번 다
이렇게 복구됐습니다.

**차례를 바꾸지 마십시오.** 발행을 먼저 하면 `url` 이 채워져, 다음 회차가
「이미 만들어 올렸습니다」로 보고 **파일을 사용자에게 보내지 않은 채**
끝냅니다. 사용자에게 파일이 가는 것이 먼저입니다.

### 6-2. 창이 **둘이라 같은 판을 두 번 낼 수 있습니다**

모닝 창과 장마감 창이 같은 저장소를 봅니다. 9/30 에 실제로 났습니다 —
제가 전체본·핵심본을 발행했는데, 다른 창이 **이미 같은 판을 발행해
`origin/main` 에 적어 둔 뒤**였습니다. 아카이브 쪽 발행이 충돌로 막혀서야
드러났습니다.

**발행 전에 반드시 `git fetch origin main` 하고 `index.json` 에 그 판이
이미 있는지 보십시오.** 중복 발행된 아티팩트는 **사용자 확인 없이 지우지
마십시오.**

### 6-3. `git pull` 이 갈라진 가지에서 막힐 때

9/30 에 로컬 1,927 · 원격 1,988 로 갈라져
`Need to specify how to reconcile divergent branches` 가 났습니다.
**내 작업이 이미 `origin/main` 에 들어가 있는지 먼저 확인**한 뒤
(`git log origin/main --oneline | grep …`), 들어가 있으면
`git reset --hard origin/main` 으로 맞춥니다. 확인 없이 되돌리면
커밋이 날아갑니다.
