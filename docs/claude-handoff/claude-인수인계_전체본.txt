## 3. 결정된 사항 (바꾸려면 의식적으로 결정할 것)

### 3-1. 산출물 보존 원칙 ★ 가장 중요

> **기존 산출물은 건드리지 않습니다. 새 요구는 새 파일·새 아티팩트로 만듭니다.**

사용자가 여러 번 명시한 규칙입니다. 1권을 고쳐 2권을 만들지 않았고, 합본·도해·길잡이도
각각 별도 파일로 만들었습니다. 이미 발행한 것을 고쳐야 할 때만 **같은 파일 경로로 다시 발행**해
링크를 유지합니다(경로가 바뀌면 새 URL이 생깁니다).

### 3-2. 디자인 시스템 — "원장(ledger)" 콘셉트

5종 문서가 한 시리즈로 읽히도록 토큰·서체를 고정했습니다. **새로 만드는 문서도 이 값을 그대로 쓰세요.**

```css
/* 라이트 */
--paper:#F5F7F3;  --surface:#FFFFFF; --band:#EDF2EB;
--ink:#1A1F1B;    --ink-2:#4C574F;   --ink-3:#7E8A80;
--rule:#DCE3DA;   --rule-2:#C4CFC2;
--accent:#14614A; --accent-2:#0E4735; --accent-soft:#E3EEE8; --on-accent:#F3F8F4;
--amber:#87590F;  --amber-soft:#F7F0DD; --alert:#98311F;
/* 다크 */
--paper:#0F1210;  --surface:#161A15; --band:#1B201A;
--ink:#E7EBE3;    --ink-2:#A8B2A6;   --ink-3:#7B857A;
--rule:#2A312A;   --rule-2:#3B443A;
--accent:#6FC9A0; --accent-2:#9EDCBF; --accent-soft:#152A1F; --on-accent:#0F1210;
--amber:#D4A45D;  --amber-soft:#2A2314; --alert:#E38D79;
```

- **서체** 제목 `Noto Serif KR` / 본문 `IBM Plex Sans KR` / 수식·데이터 `IBM Plex Mono` (Google Fonts)
- **다크 모드** `:root` 라이트 정의 → `@media (prefers-color-scheme:dark)` 안에서 `:root:not([data-theme="light"])` 로 토큰 재정의 → `:root[data-theme="dark"]` 로 한 번 더. 색은 반드시 토큰으로만 쓰고 미디어쿼리 안에서 컴포넌트를 스타일링하지 않습니다.
- **레이아웃** 좌측 스티키 분류 레일 + 본문 2열(구문 ↔ 설명·예시), 녹색 행 밴딩, 상단 스티키 검색바, 모바일에서는 레일이 가로 칩 행으로

> 미래에셋 **브랜드** 산출물(브리핑·제안서)은 이 원장 팔레트가 아니라 `mas-design` 스킬의
> 오렌지/블루 기준을 따릅니다. 두 체계를 섞지 마세요.

### 3-3. 검색 엔진 (길잡이·합본에 내장)

아티팩트 런타임에는 **모델 호출 기능이 없습니다**(쓸 수 있는 건 `artifact`·`downloads`·`mcp`뿐).
그래서 "AI 검색"은 페이지 안의 매칭 엔진으로 구현했습니다. 구조:

1. **1단(strict)** 입력 그대로 본문에 있는지 → 초성 토큰 앞자리 → 편집거리 1 이내 오타
2. **2단(loose)** 1단이 0건일 때만 — 유사어 24묶음 확장, 붙여쓴 합성어 분해(고객등급→고객+등급), 편집거리 2
3. 결과 라벨에 `· 유사 검색` 표시, 섹션 제목은 부제(`—` 뒤)를 잘라서 키에 포함

검증 질의: `브이룩업`(→XLOOKUP) `수익율`(오타) `ㅁㅋㄹ`(초성→매크로) `ㅍㅇㅋㄹ`(→파워 쿼리)
`콜리스트` `만기알림` `고객등급` `인쇄가 잘려요` / 무관한 입력(`점심 뭐먹지`)은 0건이어야 정상.

### 3-4. 금융 수치·규정값 취급

- **규정으로 바뀌는 값은 수식에 박지 않습니다** — 호가단위 구간, 세율, 수수료율, 상품 약관은
  셀/표로 분리하고 "거래소·사내 최신 기준 확인" 문구를 함께 답니다.
- 호가단위 구간표는 **유가증권시장 예시**로만 싣고, 코스닥은 상위 구간이 다르다고 명시했습니다.
- ELS 판정 산식은 **표준형 스텝다운 기준**이며 리자드·월지급 등 변형은 약관 대조가 필요하다고 명시했습니다.
- 숫자가 들어가는 자료를 만들 때는 `fin-data-integrity` 스킬 절차(주장 대장 → 검산 → 빌드)를 따릅니다.

### 3-5. 컴플라이언스 문구 (고객 대상 자료에 반드시 유지)

- 고객 안내 문구는 **준법감시 승인 문안**을 벗어나지 않게 — 수익률·전망 표현, 광고성 정보 표기, 수신 동의
- 개인정보 마스킹은 **표시용일 뿐** — 외부 반출 전 값으로 붙여넣고 원본 열 삭제
- VBA는 **사내 보안정책·개인정보 규정 확인 후** 사용, Outlook 자동발송은 `.Send` 대신 `.Display`(초안) 권장
- 매크로 실행은 **되돌리기 불가** — 사본에서 먼저

## 4. 유지해야 할 작업 규칙

1. **기존 산출물 보존** — 3-1 참조. "기존 작업분은 그대로 두고"가 기본값입니다.
2. **브리핑은 플레이북이 단일 출처** — 규칙을 바꿀 때 Routine 프롬프트가 아니라
   `docs/briefing-playbook.md`를 고칩니다. Routine은 "플레이북을 처음부터 끝까지 읽고 따르라"고만 지시합니다.
3. **발행 전 렌더 확인** — 만든 HTML은 headless Chromium으로 스크린샷을 찍어 눈으로 확인합니다.
   (`/opt/pw-browsers/chromium-*/chrome-linux/chrome --headless --screenshot=... file://...`)
   실제로 이 방식으로 표를 관통하는 화살표, 마스트헤드 여백 붕괴(`p` 기본 마진), 검색 과매칭을 잡았습니다.
4. **검색·엔진류는 질의 세트로 시험** — 코드만 보고 넘기지 않고 20여 개 질의를 돌려 결과 수를 확인합니다.
5. **문서 톤** — 한국어, 실무자 대상. 각 항목은 "왜 그런지 한 줄 + 바로 복사 가능한 수식".
   경고는 노란색 `note warn`으로 분리합니다.
6. **파일은 단일 HTML로** — 외부 의존 없이 더블클릭으로 열리게. 폰트만 CDN, 실패해도 대체 서체로 동작.
7. **작업 파일은 저장소에** — 컨테이너의 스크래치패드는 세션이 끝나면 사라집니다.
   남겨야 할 것은 반드시 커밋합니다. (이번에 8월 작업 파일이 전부 사라져 아티팩트에서 회수했습니다.)

## 4. Routine(예약 작업) 복원 — 19건

프롬프트 전문은 **`ROUTINES.md`**, 기계 판독용 원본은 **`routines.json`** 에 있습니다.
새 계정에서 같은 이름·같은 시각·같은 프롬프트로 다시 등록하면 복원됩니다.

사용 중이던 주요 Routine (KST 기준):

| 시각 | 이름 | 비고 |
|---|---|---|
| 매일 07:30 | 마포WM 모닝 브리핑 | 기존 대화로 전달(persist) |
| 평일 16:10 | 마포WM 장마감 시황 브리핑 | 전용 창 |
| 평일 11:00 | 증권사 리포트 자동 배포 | 이 대화로 전달 |
| 평일 14:30 | ELS 신규 회차 오후 점검 | |
| 평일 16:30 | ELS 신규 회차 점검·검증 | |
| 월 15:30 | 펀드 원천 반영 재갱신 | |
| 월·목 08:00 | 세션 산출물 자료실 자동 갱신 | |

| 월 08:00 | ELS 상품 구조 페이지 주간 갱신 | |
| 월 08:40 / 화~금 08:40 | 상품설명의무 스크립트 갱신 | 2건 |

중지(폐기) 상태였던 구판 7건도 기록에 남겨 두었습니다 — 다시 만들 필요 없습니다.

**등록 시 주의**
- 저장은 UTC 크론입니다. UTC 22~23시대 작업은 KST로 **다음 날**이 되므로 요일이 하루 밀립니다.
  (예: 모닝 브리핑 `30 22 * * *` = KST 매일 07:30, 자료실 갱신 `0 23 * * 0,3` = KST 월·목 08:00)
  `ROUTINES.md`에 KST와 UTC를 나란히 적어 두었으니 그대로 쓰면 됩니다.
- "이 대화로 전달" 유형은 **새 계정에서 먼저 대화를 하나 만들고** 그 대화에 묶어야 합니다.
- 브리핑 Routine의 프롬프트는 "플레이북을 읽고 따르라"는 지시가 핵심입니다.
  **규칙 변경은 Routine이 아니라 `docs/briefing-playbook.md`를 고치세요.**
