## 3. 예약 11개 — 이것이 핵심입니다

계정에 등록된 예약은 18개, **켜진 것이 11개**입니다. cron 은 UTC 로 저장돼 있습니다.

| # | 예약 | KST | cron(UTC) | 창 | 지시문 |
|---|---|---|---|---|---|
| 1 | 마포WM 모닝 브리핑 | 매일 07:30 | `30 22 * * *` | 모닝 전용 | 백업 §1 |
| 2 | 마포WM 장마감 브리핑 | 평일 16:10 | `10 7 * * 1-5` | 장마감 전용 | 백업 §2 ★ |
| 3 | 증권사 리포트 자동 배포 | 평일 11:00 | `0 2 * * 1-5` | 리포트 전용 | 백업 §3 |
| 4 | 상품설명의무 (월) | 월 08:40 | `40 23 * * 0` | ELS·펀드 | 백업 §4 ★ |
| 5 | 상품설명의무 (화~금) | 화~금 08:40 | `40 23 * * 1-4` | ELS·펀드 | 백업 §5 ★ |
| 6 | ELS 신규 회차 오후 점검 | 평일 14:30 | `30 5 * * 1-5` | ELS·펀드 | 백업 §6 ★ |
| 7 | ELS 신규 회차 점검·검증 | 평일 16:30 | `30 7 * * 1-5` | 새 세션 | 백업 §7 ★ |
| 8 | ELS 상품 구조 페이지 주간 갱신 | 월 08:00 | `0 23 * * 0` | 새 세션 | 백업 §8 ★ |
| 9 | 펀드 원천 반영 재갱신 | 월 15:30 | `30 6 * * 1` | ELS·펀드 | 백업 §9 ★ |
| 10 | 미국 100대 기업 주간 교체 | 월 08:00 | `0 23 * * 0` | 새 세션 | 백업 §10 ★ |
| 11 | 세션 산출물 자료실 갱신 | 월·목 08:00 | `0 23 * * 0,3` | 산출물 전용 | 백업 §11 ★ |

★ = **종전 인계 문서에 지시문이 없었거나 낡아 있던 것** (9개). 2026-10-01 에 메웠습니다.

특히 **2번(장마감)** 은 `docs/routine-prompts.md` §3 이 「모닝과 같은 뼈대 + 차이 여섯」
으로만 적어 두었는데, 실제 지시문은 2026-09-18 에 크게 늘었습니다 — **3단계 중간
저장**(`save_progress.sh`), **핵심본이 기본이고 전체 판이 보관본**, `SESSION_FLOOR`
신선도 검사. 문서대로 복원하면 그 개선이 전부 사라집니다. **백업 파일 §2 를 쓰십시오.**

### 전용 창을 먼저 만드십시오

고정 창에 붙는 예약 7개는 **대화를 먼저 열어야** 합니다.

```
모닝 전용 창          → 예약 1
장마감 전용 창        → 예약 2
증권사 리포트 창      → 예약 3
ELS·펀드·상품설명 창  → 예약 4·5·6·9   (한 창을 같이 씁니다)
세션 산출물 창        → 예약 11
```

창을 가르는 까닭은 맥락이 섞이지 않게 하는 것도 있지만 **실패가 보이게 하려는
것**이 더 큽니다. 장마감은 원래 매번 새 창을 띄웠는데, 8/20 16:10 실행분이
산출물을 남기지 못했는데도 그 창을 열 일이 없으니 **아무 일도 없었던 것처럼
보였습니다.**

### 꺼진 예약 7개는 다시 만들지 마십시오

전부 [폐기]되었거나 대체된 구판입니다. 증권사 리포트 09:25 판도 **일부러 껐습니다**
— 11:00 판 하나로 충분하고, 두 번 돌면 어느 것이 최신인지 헷갈립니다.

## 5. 이 환경에서 알아 둘 것

- **세션은 외부 사이트에 직접 못 붙습니다**(네이버·KRX·야후 등, CONNECT 403).
  러너가 받아 커밋하고 세션이 읽습니다.
- **`workflow_dispatch` 를 API 로 부르지 마십시오** — 세션 토큰에 Actions 쓰기
  권한이 없어 403 입니다. `REFRESH` 파일을 push 해서 깨웁니다.
- **`gh` CLI 가 없습니다.** GitHub 작업은 `mcp__github__*` 로 합니다.
- **TLS 검증을 끄거나 `HTTPS_PROXY` 를 지우지 마십시오.**
- 크로미움은 `/opt/pw-browsers` 에 이미 있습니다. `playwright install` 을 다시
  부르지 마십시오.
- **세션의 저장소 복제는 얕습니다.** 이 세션은 깊이 73(최근 이틀치)이었습니다.
  **과거 스냅샷을 꺼내려면 먼저 깊이를 늘려야 합니다**:
  `git fetch --unshallow` 또는 `git fetch --deepen=500`.
  (저장소 자체의 역사는 온전합니다 — 잘린 것은 컨테이너의 복제본뿐입니다.)
- **컨테이너는 회수됩니다.** 만든 파일은 **같은 실행 안에서** 사용자에게 보내고,
  남길 것은 반드시 커밋하십시오.
