## 저장소에 들어 있음 — 새 계정에서도 그대로 동작

### `CLAUDE.md` (저장소 루트)

Claude Code 가 **모든 새 세션에서 자동으로 읽는** 파일입니다. 작업 규칙이 여기
들어 있어, 계정이 바뀌어도 규칙은 따라옵니다. 규칙을 바꾸고 싶으면 이 파일을
고치십시오.

### `.claude/settings.json`

```json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "hooks": {
    "SessionStart": [
      { "hooks": [ { "type": "command",
          "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/session-start.sh" } ] }
    ]
  }
}
```

### `.claude/hooks/session-start.sh`

웹 세션이 시작될 때마다 도는 준비 스크립트입니다. 하는 일은 둘입니다.

1. **Playwright 1.56.1 설치** — 이 저장소는 `package.json` 과 `package-lock.json` 을
   `.gitignore` 로 빼기 때문에, 새 세션의 작업본에는 그 파일들도 `node_modules` 도
   없습니다. 화면 검증·수집기·PDF 생성이 전부 Playwright 를 부르므로 미리 깝니다.
   버전은 `.github/workflows` 의 러너와 같게 맞춥니다 — 다르면 여기서 통과한 검사가
   거기서 깨집니다.
2. **크로미움은 내려받지 않습니다.** 실행 환경에 이미 있습니다
   (`PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers`). `playwright install` 을 다시 부르면
   세션 몫 디스크에 수백 MB 를 또 쌓습니다.

사람의 기계에서는 돌지 않습니다(`CLAUDE_CODE_REMOTE` 가 `true` 일 때만).

> 이 훅은 **가지(브랜치)마다 같은 내용**이어야 합니다. 갈라 두면 한쪽만 고쳐지고
> 다른 쪽은 낡습니다.

### 네트워크 (이 실행 환경의 제약 — 계정과 무관하게 적용)

아웃바운드가 사내 프록시로 묶여 있습니다.

| 막힘 | 됨 |
|---|---|
| Yahoo Finance · SEC EDGAR(`data.sec.gov`) · Nasdaq API · stooq · Alpha Vantage | **WebSearch** |
| **WebFetch — 전 도메인** | |

→ **실질적으로 WebSearch 가 유일한 수집 경로입니다.** 그래서 이 대시보드는 매일
자동 갱신되는 구조가 아니라 분기마다 손으로 갱신합니다.

지킬 것:

- TLS 검증을 끄지 않습니다.
- `HTTPS_PROXY` 를 해제하지 않습니다.
- 403 / 405 / 407 은 **정책 거부**입니다. 재시도하지 말고 `/root/.ccr/README.md` 를
  보십시오. 프록시 상태는 `curl -sS "$HTTPS_PROXY/__agentproxy/status"` 로 봅니다.

WebSearch 로 수집할 때는 `allowed_domains` 로 제공사를 한 곳에 묶으십시오.
계열 혼용을 막는 가장 확실한 방법입니다.

```
allowed_domains: ["stockanalysis.com"]
```

> **알아 둘 것** — 검색 요약은 같은 페이지를 두 번 물어도 **다른 스냅숏**을 돌려줄
> 수 있습니다(2026-10-01 에 실제로 겪었습니다). 계열을 맞춰야 하는 값은 한 번에
> 받고, 어긋나면 올리지 않습니다.
