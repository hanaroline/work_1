## 1. 이 산출물이 무엇인가

미국 대형주 **25개사**의 직전 분기 실적을 한 화면에 모은 사내 참고용 대시보드입니다.
파일 하나(`us-earnings.html`)로 열리고, 인터넷도 서버도 필요 없습니다 — 데이터가
HTML 안에 박혀 있습니다.

보여 주는 것은 네 묶음입니다.

| 묶음 | 내용 |
|---|---|
| 시즌 스코어보드 | 자체 집계 6칸 + 외부 기관 지수 집계 6칸(유니버스가 달라 섞지 않음) + 「성장 가속도」 차트 |
| 기업 표 | 25개사 × 12칸(발표일·매출·컨센서스·서프라이즈·성장률·선행 P/E·P/S·PEG·투자매력도 등) + 성장률 × 서프라이즈 산점도 |
| 매출액 분야 분석 | 섹터별 매출 합계 · 섹터별 성장률 중앙값 |
| 인사이트 · 출처 | 카드 6장 · 한 줄 요약 · 계열 정책 · 확인하지 못한 항목 |

한국어/영문 토글, 인쇄 CSS, 모바일 대응이 모두 들어 있습니다.

## 2. 구조 — 수치의 단일 출처

```
scripts/build_earnings.py      ← 모든 수치가 여기서만 나온다
        │
        ├─→ data/earnings/claims.json   주장 대장(검산 대상, 현재 345건 + derived 52건)
        ├─→ data/earnings/latest.json   화면용 데이터
        └─→ us-earnings.html         <script id="earnings-data"> 안에 주입
```

```bash
python3 scripts/build_earnings.py
python3 scripts/check_claims.py data/earnings/claims.json   # 통과해야 배포
```

**화면 HTML 에는 손으로 적은 숫자가 없습니다.** 문장도 `{token}` 으로 데이터를 읽어
씁니다. 이 구조를 지키는 것이 이 작업의 전부입니다 — 깨지면 데이터를 갱신해도
문장이 옛 숫자를 그대로 말합니다.

## 3. 지금까지 내린 결정 (바꾸려면 이유를 알고 바꿀 것)

### 수집·계열

- **밸류에이션은 한 제공사(stockanalysis.com)·한 날짜로 고정.** 같은 시점에
  NVDA 선행 P/E 가 출처마다 18.12 / 23.8 / 24.50 / 48.30 (2.7배 차이), PLTR P/E 가
  147.69 / 177.89 / 249 로 갈렸습니다. 섞으면 순위가 통째로 바뀝니다.
- **채택하지 않은 대조용 수치도 `REJECTED` 에 등록합니다.** 화면 문장이 그 값을
  인용하기 때문입니다(손으로 적으면 묵습니다).
- **분기별 시계열은 쓰지 않습니다.** 검색 요약이 회계분기 라벨을 섞습니다
  (NVDA 의 FY27 Q2 를 "Q1 FY2026" 으로 표기하는 것을 확인). 대신 라벨 모호성이
  없는 **LTM 한 점**을 같은 제공사·같은 날짜로 받습니다.
- **컨센서스 제공사는 기업마다 다릅니다**(LSEG·Zacks·StreetAccount·Visible Alpha).
  한 기업 안에서는 한 출처만 쓰고, 기업 간 비교는 서프라이즈율로만 합니다.

### 점수

- **모멘텀 70 + 밸류에이션 30.** 모멘텀은 서프라이즈 25 · 성장률 35 · 가이던스 25 ·
  EPS 서프라이즈 15 를 **확인된 축 사이에서만** 재분배합니다. 미확인을 0점으로
  깔면 '자료가 적은 기업'이 '나쁜 기업'으로 둔갑합니다.
- **커버리지 50 미만이면 점수를 내지 않습니다**(`MIN_COVERAGE`).
- **V 점수는 업종 중립.** 섹터 기준배수(대형주 중앙값) 대비 상대배수로 봅니다.
  대시보드 25개사만으로는 표본이 모자라 `PEERS` 로 동종업체를 더 받아
  섹터별 5개사 이상(`MIN_PEERS`)을 채웠습니다.
- **P/S · EV/EBITDA · PEG 는 점수에 넣지 않습니다.** P/S·EV/EBITDA 는 선행 P/E 와
  비싼 정도를 중복으로 세고, PEG 는 제공사가 산식을 공개하지 않습니다.

### 표현

- **가속도 = 직전분기 전년동기비 − LTM 성장률.** 단, **LTM 스냅숏보다 뒤에 발표된
  분기는 보류합니다**(`rep > VAL_ASOF`). 그 분기는 LTM 창에 아직 없어서, 빼면
  가속도가 아니라 기저효과가 나옵니다. 밸류에이션을 다시 받으면 저절로 풀립니다.
- **섹터 성장률은 중앙값.** 단순평균은 구성원 한 곳의 극단값에 끌려갑니다
  (마이크론 +379% 가 정보기술 평균을 +81.4% 로 올려, 9사 중 8사가 그 아래인
  '평균'이 나왔습니다). 평균은 버리지 않고 막대 툴팁에 함께 띄웁니다.
- **산점도 가로축은 '바로 아래 값의 2배를 넘는 꼭대기'에서 끊습니다.** 그 밖의
  점은 오른쪽 끝에 점선으로 고정하고 라벨에 실제 값을 적습니다. 자리는 잘라도
  수치는 감추지 않습니다. (울타리 `Q3+1.5·IQR` 는 NVDA·PLTR 같은 '빠르지만 정상
  범위'인 점까지 잘라 쓰지 않았습니다.)
- **차트 배치** — 「성장 가속도」는 스코어보드 끝(요약 타일 바로 옆), 산점도는
  기업 표 바로 아래. 요약 숫자와 그 내역을 떼어 놓지 않습니다.

### 하지 않기로 한 것 (이유와 함께)

| 하지 않은 것 | 이유 |
|---|---|
| FactSet·Zacks 보고서 **회차 발표일** 기입 | 수치는 확인됐지만 회차 날짜를 확정하지 못했습니다. 지어내는 대신 `market_level` 로 등록하고 화면에 한계를 남겼습니다 |
| UNH 영업이익 증가율을 반올림값에서 유도 | 5.2 → 8.0 으로 나누면 53.8% 가 나와 회사 발표치(+55%)와 어긋납니다. 회사 발표치를 그대로 싣습니다 |
| 분기별 매출 시계열 | 회계분기 라벨 오염 (위 참조) |
| P/S·EV/EBITDA 를 점수에 추가 | 비싼 정도 중복 계산 |

## 4. 지난 세션에서 실제로 났던 사고 (같은 실수를 피하려고 남깁니다)

- **인사이트 카드 두 장이 데이터와 반대였습니다.** "AI 인프라는 아직 가속 구간" —
  그런데 AVGO −8.2%p 가 화면에서 가장 큰 둔화였습니다. "AI 밖에서는 한 자릿수가
  정상값" — 실제로는 한 자릿수가 4곳뿐이고 20% 이상이 14곳이었습니다.
  → 이후 **모든 카드 문장을 데이터에서 계산**하게 바꿨습니다.
- **각주가 철회된 주장을 계속 달고 있었습니다.** 카드를 고쳤는데 각주는 그대로였습니다.
  → 각주·섹션 문구·타일 부제까지 전부 토큰으로 바꿨습니다.
- **대장 ID 가 실행마다 바뀌었습니다**(파이썬 `hash()` 의 시드 무작위화).
  → `hashlib.md5` 로 고정했습니다.
- **영문 모드에서 표가 정확히 2px 넘쳤습니다.** 원인은 `low coverage` 배지의
  `white-space:nowrap` 이었습니다. 열 너비를 의심하느라 한참 돌았습니다.
- **AVGO 티커 라벨이 가속도 차트에서 통째로 가려졌습니다.** 음수 막대의 값 라벨이
  왼쪽으로 그려져 범주 라벨을 덮었습니다. 차트를 화면 위로 옮기고 스크린샷을 찍어서
  겨우 발견했습니다 → **눈으로 보지 않으면 못 찾는 버그가 있습니다.**

## 5. 2026-10-01 갱신에서 한 일과 남긴 것 (2026-10-03 재확인)

**한 것**

- 마이크론 FY26 Q4(9/30 발표) · 코스트코 FY26 Q4(9/24 발표) 두 행을 새 분기로 교체.
  코스트코는 매출 컨센서스가 **총매출 기준**이라 실제치도 총매출(957.2억달러)로
  맞췄습니다 — 순매출(939억달러)과 대조하면 계열이 어긋납니다.
- 그 데이터가 드러낸 세 가지(가속도 보류 · 섹터 중앙값 · 산점도 축 절단)를 고쳤습니다.
- 섹터 집계 14건을 대장에 새로 등록(331 → 345건).

**남긴 것 — 다음에 할 일**

- **밸류에이션 블록은 2026-09-17 스냅숏 그대로입니다.** 10/1 에 25종목을 다시
  조회했더니 **같은 페이지가 조회마다 다른 스냅숏을 돌려줬습니다**(코스트코 선행
  P/E 39.46 / 43.25, 세일즈포스 15.65 / 17.45, 릴리 시가총액 1.06조 / 1.02조).
  한편 HD·INTC·JNJ·GS 는 9/17 값 그대로였습니다. 일부만 새 값으로 바꾸면
  '한 제공사·한 날짜' 전제가 깨져 섹터 중앙값과 순위가 뒤틀리므로 올리지
  않았습니다. 한계는 `LIMITS` 에 등록해 화면 '확인하지 못한 항목' 맨 위에 싣습니다.
  → **다음 갱신 때 25종목을 한 번에 받을 수 있으면 그때 함께 올리십시오.**
- 참고로 10/1 조회에서 본 값 중 9/17 과 크게 벌어진 것: AMD 시가총액
  850.67 → 약 1,030십억달러, 브로드컴 LTM 매출 75.47 → 약 89.10십억달러,
  넷플릭스 334.45 → 약 291.56십억달러. **채택하지 않았습니다** — 한 번에 받을 때
  다시 확인할 지점입니다.
- 2026년 3분기(캘린더) 실적 시즌은 10월 중순부터입니다. 수록 25개사 중 첫 발표는
  **10/13 JP모건·골드만삭스**(확정)입니다. 일정과 1·2차 갱신 계획은
  [`03-갱신일정.md`](03-갱신일정.md) 에 따로 정리했습니다 — 걸어 둔 알림이
  계정과 함께 사라지므로, 재발동용 프롬프트도 거기 적어 두었습니다.

**2026-10-03 재확인 — 바뀐 것 없음**

- 10/1~10/2 에 실적을 낸 S&P 500 대형주는 액센츄어 · 맥코믹 · 나이키인데
  **셋 다 이 화면의 25개사가 아닙니다.** 수록 기업 중 새로 발표한 곳은 없습니다.
- 밸류에이션을 다시 시도했으나 **같은 이유로 또 중단했습니다.** 세일즈포스
  시가총액이 세 번의 조회에서 210.40 / 188.94 / 191.55십억달러로 갈렸고, 일부
  값에는 제공사가 9월 22일 같은 옛 기준일을 찍어 두었습니다. 코스트코는 이번에
  두 번 다 9/17 값(43.25 / 29.63)을 돌려줘, 10/1 에 본 39.46 / 27.30 쪽이
  오히려 이상치였습니다.
- 그래서 **내용은 그대로이고 `CHECKED` 만 올렸습니다.** 화면 머리에
  "기준일 2026-10-01 · 재확인 2026-10-03" 으로 나옵니다 — `ASOF` 는 내용이
  마지막으로 바뀐 날, `CHECKED` 는 마지막으로 다시 본 날입니다. 바뀐 것이 없는데
  기준일만 올리면 화면이 실제보다 최신인 것처럼 읽힙니다.

## 6. 갱신할 때 반드시 지킬 것

1. 숫자는 `scripts/build_earnings.py` 에서만 바꿉니다. HTML 을 고치지 않습니다.
2. 밸류에이션·동종업체 배수는 **한 번에, 같은 날짜로** 받습니다. 못 받으면 올리지 않습니다.
3. `FACTS`·`GRAISE_TXT`·`REJECTED`·`*_NOTE` 도 같이 갱신합니다 — 전부 화면에 인쇄됩니다.
   **카드 문장은 건드리지 않습니다.** 이 값들을 읽어 스스로 다시 쓰입니다.
4. 영문(`EN`·`CN_EN`)을 같이 고칩니다. 한/영 토글에서 한글이 남으면 안 됩니다.
5. 빌드 → 검산 → **브라우저로 한국어·영문 두 모드를 눈으로** 확인합니다.
   토큰 잔여 0 · `NaN`/`undefined` 0 · 산점도 라벨 겹침 0 · 가로 스크롤 없음.
