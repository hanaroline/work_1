# 업무 보고 자료

Claude Code 로 한 작업을 **위에 보고**하기 위한 발표 자료입니다.

| 파일 | 내용 |
|------|------|
| `2026-10-01-업무자동화-구축결과보고.pptx` | 8장 보고 덱 (기준일 2026.10.01) |
| `build_work_report_deck.js` | 위 덱을 만드는 생성기. 수치를 고쳐 다시 돌리면 같은 서식으로 다시 나옵니다 |

> 이 폴더는 **보고 자료**입니다. `docs/reports/` 는 증권사 리포트 다이제스트 화면이라
> 서로 다른 것입니다 — 9/10 판까지는 한 폴더에 섞여 있었고 10/1 에 갈라 두었습니다.

## 다시 만들기

```bash
npm install pptxgenjs                       # 최초 1회
node docs/work-report/build_work_report_deck.js "docs/work-report/2026-10-01-업무자동화-구축결과보고.pptx"
```

텍스트·도형·차트가 모두 **편집 가능한 네이티브 요소**로 들어갑니다(이미지로 박은 슬라이드 없음).
브리핑 발행 실적 차트도 PowerPoint 네이티브 차트라 표를 열어 데이터를 직접 고칠 수 있습니다.
슬라이드마다 **발표 노트**가 붙어 있습니다.

### 확인해 두어야 할 세 가지

**① 기간의 앞쪽 — 6월.** 덱 표지는 `2026.06 – 10.01` 로 적었으나, 세션 기록으로
확인되는 작업은 **7월 9일부터**입니다. 6월은 별도 산출물 기록이 남아 있지 않아
2장에서 「도입 · 개별 요청」 단계로만 적고, 각주에 그 사실을 밝혔습니다.
6월에 한 작업이 있으면 2장 1단계 설명과 표지 기간을 함께 고치면 됩니다.

**② 절감 약 80시간은 추정치이며, 셈법을 바꿨습니다.** 시세 취합·작성·검증을
사람이 할 때 판당 60분으로 보고 **전체본 80판**(모닝 38 + 장마감 26 + 해외 16)에
곱한 값입니다. 9/10 판까지는 핵심본까지 세어 곱했는데, 핵심본 50판은 전체본에서
자동으로 파생되므로 이번 판에서는 **세지 않았습니다**. 더 보수적인 셈법입니다.
실측값이 아니며, 브리핑 외 산출물(완전판매·조회 화면·분석 모델)의 절감분은
실측값이 없어 넣지 않았습니다.

**③ 펀드 건수 불일치는 해소됐습니다.** 9/10 판에서는 조회 화면 수집분
(`data/fund.js`, 3,192건)과 완전판매 카탈로그(`data/fund-catalog.js`, 3,194건)가
갈려 조회 기준만 실었습니다. 10/1 현재 양쪽 모두 **3,194건**으로 맞춰졌으므로
덱에도 3,194 를 싣습니다.

### 6장(분석·판정 모델)을 읽을 때

이 장의 수치는 **백테스트 결과**이며 실현 수익이 아닙니다. 덱에도 그대로
적었습니다 — 타이밍 신호는 매수후보유보다 **적게 법니다**(국내 −22~−30%p).
16가지 조합을 검정해 다중비교 보정을 통과한 것은 **없습니다**. 모델의 쓸모는
수익이 아니라 **낙폭 축소**에 있다는 것이 이 장의 요지이고, 유리한 숫자만
골라 싣지 않는 것이 작성 원칙이었습니다.
