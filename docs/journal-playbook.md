# 국내 시장일지 — 만드는 법

미래에셋증권 마포WM의 **국내 시장일지**를 만드는 규칙입니다. 시황 브리핑
(`docs/briefing-playbook.md`)과는 다른 자료입니다 — 브리핑이 「오늘 무슨
일이 있었나」를 읽는 글이라면, 시장일지는 **「수급과 거래량으로 그날의
주요종목을 짚는」 표**입니다.

이 문서를 고치면 다음 실행부터 반영됩니다.

---

## 0. 무엇을 언제 내는가

| 언제 | 무엇 | 어디에 |
|---|---|---|
| 국내 거래일 15:40 KST | 종목 순위 수집만 | `data/journal/<날짜>.json` |
| 국내 거래일 **16:00 KST** | 시장일지 발행 | `docs/journal/<날짜>.html` · `.txt` · 텔레그램 |
| 16:20 KST | 16:00 판이 늦었을 때의 두 번째 | 같음 |

**휴장일에는 내지 않습니다.** 정리할 「오늘 장」이 없습니다(브리핑의
아침 판과 다른 점입니다). 수집기는 예약이 돌아도 기준일이 전 거래일이면
같은 파일을 다시 쓰고 끝나며, 발행 관문이 기준일 어긋남을 경고합니다.

산출물은 세 쪽입니다.

```
1쪽  본지     — A4 한 장. 지수·수급·주요종목·테마·이슈
2쪽  대시보드 ① 수급   — 종목별 기관·외국인 매매, 쌍매수·쌍매도, 기관 안쪽, ETF
3쪽  대시보드 ② 순위   — 상승률·거래대금 상위 20, 신고가·상한가·거래량 급증
```

---

## 1. 무엇으로 짓는가 — 파일 셋

세션은 사내 이그레스 정책 때문에 KRX·네이버·야후에 직접 붙지 못합니다
(CONNECT 403). **다시 시도하지 마십시오.** 러너가 받아 커밋한 것을 읽습니다.

| 파일 | 담긴 것 | 누가 채우나 |
|---|---|---|
| `data/market/latest.json` | 지수·환율·금리·예탁금·신용잔고·투자자 합계·업종·기사 | `scripts/fetch_market.py` (「시세 수집」) |
| `data/journal/latest.json` | 종목 순위·종목별 수급·ETF·테마 | `scripts/fetch_journal.py` (「시장일지 수집」) |
| `data/flows/kr100.json` | 대형주 100 종목별 외국인·기관 순매수 **누적** | `scripts/fetch_stock_flows.py` |

셋의 **기준일이 같은지 먼저 봅니다.** 어긋나면 빌더가 머리말에 적습니다.
낡은 줄 모르고 쓰는 것이 못 쓰는 것보다 나쁩니다.

## 2. 원천과 그 한계 — 적어 두지 않으면 반드시 잊습니다

2026-09-21 에 브라우저 관찰과 요청 스윕으로 확인한 것입니다
(기록: `data/journal/raw/journal_api.txt` · `journal_xhr.txt` ·
`journal_xhr2.txt` · `journal_api2.txt`).

### 종목 순위 — `stock.naver.com/api/domestic/market/stock/default`

한 줄에 등락률·거래대금·거래량·전일대비 거래량증가율·52주 최고가·상한가
구분이 모두 들어 있어, **상승률·거래대금·거래량 급증·신고가·상한가가
주소 하나로 풀립니다.** 순위는 우리가 매깁니다.

- **`startIdx` 로 넘길 수 없습니다.** 올리면 빈 응답이 옵니다. 한 번에
  받는 양은 `pageSize` 가 정하고, 2000 까지 받았습니다. 그래서 코스피·
  코스닥을 따로 받아 잇습니다(2026-09-21 기준 2,762 종목).
- 그러므로 이것은 **시가총액 상위 표본**이지 거래소 상장 전종목이
  아닙니다. 산출물 각주에 받은 종목 수를 적습니다.
- `orderType` 은 `up` · `down` · `priceTop` · `marketSum` 만 열립니다.
  `marketType=ETF` 는 400 입니다.

### 종목별 기관·외국인 — `…/market/trend/trendForeignOrg`

```
?investorType=FOREIGNER|ORGANIZATION&tradeType=KRX&marketType=KOSPI|KOSDAQ
&startIdx=0&pageSize=20&periodType=DAY
→ sections.buyRankList / sellRankList
```

- `investorType` 은 **둘뿐**입니다. `INSTITUTION` · `PENSION` ·
  `PRIVATE_EQUITY` 따위는 모두 400 입니다.
- **장중에는 `accTradeAmount` 가 0 이고 `estimated` 가 참**입니다. 그때
  순위는 금액이 아니라 **수량** 기준이고, 빌더는 수량 × 종가로 어림한 값에
  「≈」를 달고 표 이름에 「수량 기준」이라 적습니다.
- 매도 쪽은 **값이 음수로** 옵니다. 부호를 그대로 두고 내림차순으로 세우면
  가장 적게 판 종목부터 늘어섭니다(실제로 그렇게 나왔습니다). 크기 순으로
  세웁니다.
- 외국인과 기관의 **기준일이 서로 다를 수 있습니다** — 장중에 외국인은
  오늘, 기관은 전 거래일이었습니다. 줄마다 기준일을 달아 둡니다.
- 「쌍매수」는 **두 명단(각 20)에 함께 든 종목**입니다. 전 종목에서 둘 다
  순매수한 종목을 센 것이 아니며, 표 각주에 그렇게 적습니다.

### ETF — `…/stockSecurity/etfs/v2/domestic`

- `listingType` 은 `tradingValueDesc` · `aumDesc` · `changeRateDescUpAll`
  등만 열립니다. `changeRateDesc` 는 400 입니다.
- **`index` 로 넘길 수 없습니다** — `index=100` 이면 빈 응답에 `hasNext`
  도 거짓입니다. 순위마다 판을 따로 받고, 각 판의 **위 100 줄**이 보는
  전부입니다(상장 1,171 종목 가운데).
- 레버리지·인버스는 **이름으로** 거릅니다(레버리지·인버스·2X·곱버스).
  원천의 `leverage-types`(P1 일반·P2 레버리지2X·N1/N2 인버스)는 목록
  응답에 붙어 오지 않습니다.

### 받지 못하는 것 — 비워 두고 NOT FOUND 를 답니다

| 항목 | 왜 |
|---|---|
| **종목별 사모펀드 순매수** | 거래소에만 있고 거래소는 수집 서버 IP 를 막습니다. **시장 합계**까지만 싣습니다(`기관 안쪽 순매수` 표) |
| 연속 순매수 (전 종목) | 원천이 하루치만 줍니다. 누적본(`kr100.json`)이 있는 **대형주 100 종목**만 셉니다 |
| VKOSPI | 무료 원천이 없습니다 |
| 미수금·반대매매 | 네이버에 없고 금투협은 웹방화벽이 막습니다. 신용잔고를 대용으로 씁니다 |

## 3. 문턱과 판정 — 왜 그렇게 골랐는가

| 표 | 규칙 | 까닭 |
|---|---|---|
| 상승률·하락률 상위 | **거래대금 10억원 이상** | 문턱이 없으면 하루 몇백만원 거래되는 우선주와 잠든 종목이 상위 20 을 채웁니다. 그 줄은 「오늘 시장이 본 종목」이 아닙니다 |
| 거래량 급증 | 거래대금 **100억원 이상** 가운데 전일 거래량 대비 증가율 상위 | 같은 까닭. 문턱이 없으면 평소 5천만원 돌던 종목이 1등을 합니다 |
| 52주 신고가 | 종가 ≥ 52주 최고가 **이면서 당일 상승** | 원천의 52주 최고가 칸은 최근 며칠을 반영하지 못할 때가 있어, 오름세 조건이 없으면 이미 뚫고 내려온 종목이 며칠씩 이어서 잡힙니다 |
| 상한가 | 원천의 `upDownGb=1` | 가격제한폭이 호가 단위 때문에 29.81·29.9 로 나와 등락률 문턱으로는 가를 수 없습니다 |

## 4. 검산이 빌드보다 먼저입니다

```bash
python3 scripts/verify_journal.py              # 끝 상태 1 이면 짓지 않는다
python3 scripts/verify_journal.py --warn-only  # 장중 확인용
```

잡는 것 — 전부 **추가 조회가 필요 없는** 것들입니다.

- 파일 사이 기준일 어긋남
- 인쇄될 등락률이 종가·전일대비와 맞지 않음
- 거래량 증가율이 거래량·전일거래량과 맞지 않음
- 신고가·상한가 판정이 값과 어긋남
- 순위표가 실제로 그 열로 정렬되어 있지 않음
- **투자자별 순매수 합이 0 에서 멂** — 개인+외국인+기관+기타법인(7000·7100)
  은 0 이어야 합니다. 멀면 장중 집계와 확정치가 섞인 것입니다
- 기관 안쪽 합이 기관계와 다름
- 단위 뒤섞임(억원 자리에 원)

**투자자 구분 코드는 `scripts/fetch_market.py` 와 같은 묶음을 씁니다.**
두 파일이 다른 셈을 하면 같은 판 안에서 코스피 수급이 두 값으로 갈립니다.

```
개인   8000
외국인 9000 + 9001(기타외국인)      ← 9000 만 쓰면 하루 수십억씩 어긋난다
기관계 1000 금융투자 · 2000 보험 · 3000 투신 · 3100 사모
       · 4000 은행 · 5000 기타금융 · 6000 연기금
기타   7000 · 7100                   ← 기관계에 넣지 않는다
```

## 5. 판형 — 「A4 한 장」은 약속입니다

```bash
node scripts/check_journal_fit.mjs docs/journal/<날짜>.html
```

쪽마다 안쪽 높이를 재어 A4(297mm)를 넘는지 봅니다. 넘으면 표의 줄 수를
줄이거나(빌더의 `cap`) 표를 `dt dense` 로 돌립니다. 넘친 줄만 다음 쪽으로
흘러가면 아무도 읽지 않는 꼬리가 생깁니다.

색·글꼴은 미래에셋 기준을 그대로 씁니다 — 오렌지 `#F58220`, 블루
`#043B72`, 표 머리 `#FAB072`, 1px 오렌지 섹션 룰, 한/영 토글 우상단.
**본문 크기만 인쇄 밀도에 맞춰 줄였습니다**(웹 기준 19px 대신 표 8.5px) —
A4 한 장에 표 열두 개를 세우는 자료라 웹 호흡을 그대로 쓸 수 없습니다.

## 8. 원천이 또 끊기면

네이버는 개편을 자주 합니다 — 2026-09-10 에 상한가 화면이, 09-18 에
투자자별 일별시세가 끊겼습니다. **주소를 짐작해 찍지 마십시오.** 다섯
바퀴를 헛돈 적이 있습니다. 같은 방법을 씁니다.

```bash
# 화면을 열어 그 화면이 보내는 요청을 그대로 적는다 (러너에서만 돈다)
printf '요청: %s\n' "$(TZ=Asia/Seoul date '+%F %T KST')" >> data/journal/PROBE
git add data/journal/PROBE && git commit -m "원천 관찰 요청" && git push
# → data/journal/raw/ 에 기록과 응답 본문이 남는다
```

`scripts/probe_journal_xhr.mjs`(화면 관찰) ·
`scripts/probe_journal_xhr2.mjs`(화면 안에서 직접 호출) ·
`scripts/probe_journal_api.py` · `scripts/probe_journal_api2.py`(평문 요청
스윕)가 차례로 돕니다. 찾은 자리는 **평문 요청으로도 열리는지 확인한 뒤에**
수집기에 붙입니다 — 브라우저에서만 열리는 자리는 날마다 돌릴 수 없습니다.
