# 마포WM 시황 브리핑 작성 지침

미래에셋증권 마포WM의 시황 브리핑을 만드는 자동 세션이 따르는 규칙입니다.
매일 07:00(모닝)과 16:00(장마감) 두 개의 Routine이 이 문서를 읽고 실행합니다.

이 문서를 고치면 다음 실행부터 반영됩니다. Routine 프롬프트를 건드릴 필요가 없습니다.

---

## 0. 휴장일

오늘이 한국 증시 휴장일이면 브리핑을 만들지 말고, 그 사실만 보고하고 종료합니다.

---

## 1. 시세 파일을 먼저 읽습니다 — 뉴스보다 우선

이 세션은 사내 이그레스 정책 때문에 KRX·네이버·야후·인베스팅닷컴에 직접 붙지
못합니다(CONNECT 403). **다시 시도하지 마십시오.** 대신 GitHub Actions 러너가
매 거래일 시세를 받아 이 저장소에 커밋해 둡니다.

```bash
cd "$(git rev-parse --show-toplevel)"
git pull -q origin main
python3 -m json.tool data/market/latest.json | head -120
```

`data/market/latest.json` 에 담긴 것:

| 키 | 내용 |
|---|---|
| `indices` | kospi, kosdaq, usdkrw, sp500, nasdaq, dow, sox, vix, dxy, usdjpy, wti, brent, gold, ust10y, ust2y — 각각 `date` `open` `high` `low` `close` `volume` `prev_close` `change` `change_pct` |
| `stocks` | 시총 상위 10종목의 종가·등락률·거래량 |
| `sectors` | 네이버 업종 79개 등락률 (`all` / `top5` / `bottom5`) |
| `investors_kospi` | 코스피 투자자별 순매수 최근 6거래일 — `retail`/`foreign`/`institution`, **단위 억원** |
| `market_internals` | `kospi` / `kosdaq` 각각 — `breadth`(상한·상승·보합·하락·하한 종목 수), `investor_flows`(당일 개인/외국인/기관), `program_trading`(차익/비차익/전체), `intraday`(고가·저가), `fifty_two_week`(52주 고저). **단위 억원** |
| `rates_kr` | 국내 시장금리 — `cd91` `call` `ktb3y` `corp3y` `cofix_balance` `cofix_new`, 단위 %. **국고채 10년(`ktb10y`)은 원천이 없어 대개 비어 있습니다** |
| `sources` | 원천별 성공/실패와 실패 사유 |

**이 수치는 거래소 원천이므로 뉴스 보도보다 우선합니다.** 배지는
`<span class="vf ok">MARKET DATA</span>` 로 표시합니다. 뉴스와 값이 다르면
이 파일을 채택하되 차이를 검증 노트에 적습니다.

**날짜를 반드시 확인하십시오.** `indices.kospi.date` 가 대상 거래일과 다르거나
`generated_at_kst` 가 오늘이 아니면 파일이 갱신되지 않은 것입니다. 그 사실을
검증 노트에 명시하고 뉴스 검색으로 진행합니다.

`sources` 에 실패로 기록된 항목은 재시도하지 마십시오. **KRX(`krx:allstocks`)는 러너 IP를 막아 상시 실패**합니다 — 정상이며, 필요한 값은 야후·네이버가 모두 채웁니다. **국고채 10년**도 공개 원천이 없어 대개 비어 있습니다(네이버 시장지표에 3년만 있고, 인베스팅닷컴은 러너에서 403). 비어 있으면 NOT FOUND로 두십시오.

## 2. 검색은 파일에 없는 것에 씁니다

시세는 위 파일에서 나오므로, **WebSearch는 숫자가 아니라 맥락을 구하는 데** 씁니다.

- 특징주가 왜 움직였는가 (개별 재료, 공시, 해외 뉴스)
- 업종이 왜 갈렸는가
- 증권사 코멘트·목표주가·투자의견 변경
- 수급 해설, 신용융자·반대매매 등 레버리지 지표
- 일정과 컨센서스, 제도·WM 업계 뉴스
- 파일에 없는 수치 — 상한가·하한가 **종목명**(개수는 파일에 있습니다),
  국고채 10년, 선물 외국인 순매수, 신용융자 잔액·반대매매

**검색을 얕게 하지 마십시오.** 항목별로 각각 별도 검색을 돌리고, 한 번에 안
잡히면 표현을 바꿔 재시도합니다. 「데이터센터」·「스팟」·「마감시황」류 기사가
수치를 가장 많이 담고 있습니다 — EBN 데이터센터, 머니투데이 [스팟], 뉴스핌·
아주경제·이투데이·국민일보·아이뉴스24. 매체명을 검색어에 넣어 보십시오.

기사 본문 직접 조회(WebFetch)는 대부분 HTTP 403입니다. 검색 결과 요약을
근거로 삼되 그 사실을 검증 노트에 적습니다.

## 3. 검증 규칙

1. **배지 체계** — 시세 파일 출처는 `vf ok` + MARKET DATA. 뉴스는 서로 다른
   2개 매체가 일치해야 `vf ok` + 2 SOURCES, 1곳뿐이면 `vf solo` + 1 SOURCE,
   불일치는 `vf bad` + CONFLICT, 못 찾으면 `vf none` + NOT FOUND, 방향만
   확인되면 DIRECTION ONLY.
2. **없는 수치는 절대 지어내지 않습니다.** 비워 두고 배지를 답니다. 등락률만
   확인되고 종가를 모르면 종가 칸을 비웁니다. 표 전체를 못 채우면 표를 뺍니다.
3. **날짜 대조 필수.** 검색엔진이 다른 날·다른 해 기사를 오늘 것으로 끌어옵니다.
   확인된 마감 수치와 방향이 어긋나는 결과는 폐기하고 검증 노트에 기록합니다.
   기사 URL의 번호가 같은 날 다른 기사들과 동떨어져 있으면 다른 날짜일
   가능성이 큽니다.
   - 실제 사례: "8월 6일 국고채" 검색이 5월 6일 기사를 반환
   - "8월 7일 삼성전자" 검색이 실제 마감과 정반대인 다른 날 기사를 반환
   - "미 7월 고용 결과" 검색이 아직 발표되지 않은 지표의 다른 연도 결과를 반환
4. **장중 집계치와 마감 확정치를 섞지 않습니다.** 수급 조합의 합이 0 근처에서
   맞는지 산술 검산하고, 맞지 않는 조합은 장중치로 보고 채택하지 않습니다.
5. **아직 발표되지 않은 지표의 결과를 쓰지 않습니다.** 컨센서스와 발표 예정
   시각만 적고 "미발표"로 표시합니다.
6. **작성 시각은 실제 작성한 시각**을 적습니다. 예정 시각을 옮겨 적지 않습니다.

## 4. 누적 등락률 기준선

- **주간 누적(WTD)은 직전 금요일 종가 기준**입니다. 월요일 종가를 기준선으로
  잡으면 월요일 당일 등락이 기준값 안에 이미 반영돼 있어 누적에서 빠집니다 —
  계산 오류입니다.
- 월간 누적은 전월 말 종가, 연초 대비는 전년 말 종가 기준.
- 기준일과 기준 지수를 항상 함께 표기합니다.
  예: `주간 누적 (7/31 종가 6,595.45 → 8/7) −5.10%`
- N거래일 누적이라고 쓸 때는 제시한 일간 등락 개수와 구간이 반드시 일치해야
  합니다.
- 주간 표는 맨 위에 직전 금요일 종가를 기준선 행(`tr class="base"`), 맨 아래에
  주간 누적 합계 행(`tr class="sum"`)을 둡니다.
- **코스피와 코스닥의 주간 성적을 반드시 함께** 제시합니다. 두 시장 방향이
  갈리는 국면에서는 지수 하나로 "시장이 좋았다/나빴다"고 말할 수 없습니다.

## 5. 지수와 종목을 대조합니다

지수 등락률만 쓰면 사실을 왜곡할 수 있습니다. **지수는 내렸는데 상승 종목이
더 많은 날**, 또는 그 반대의 날이 자주 나옵니다.

`market_internals` 의 `breadth` 가 이 점검의 핵심입니다. **상승 종목 수와 하락
종목 수를 지수 등락률과 나란히 놓으십시오.** 지수가 내렸는데 상승 종목이 더
많으면 대형주 몇 개가 지수를 눌렀다는 뜻이고, 그 반대면 시장 전반이 약했다는
뜻입니다. `sectors` 의 top5/bottom5 와 `stocks` 의 개별 등락률도 함께 봅니다.

**코스피와 코스닥의 breadth 를 각각 확인하십시오.** 한쪽은 상승 우세이고
다른 쪽은 하락 우세인 날이 자주 나옵니다 — 두 시장을 뭉뚱그리면 틀립니다.

`program_trading` 의 차익·비차익도 유용합니다. 비차익이 크게 마이너스면
바스켓 매도(외국인 프로그램 매도)가 지수를 눌렀다는 신호입니다.

어긋나면 요약과 고객 응대 섹션에 그 사실을 명시합니다.

고객 응대에서 손익을 논할 때는 하나의 숫자로 뭉뚱그리지 말고, **보유 성향별
(대형주 중심 / 중소형주 중심)** 또는 **진입 시점별(판단 기준 종가 → 최신 종가
대비 %)** 로 나눠 표로 제시합니다. 고객은 매수 전날 종가를 보고 결정합니다.

## 6. 화면 규격

- 외부 폰트·CDN·이미지를 넣지 않습니다(아티팩트 CSP가 차단합니다).
- 좌측 목차 사이드바, 우측 상세 패널, 드릴다운, 요약/전체 PDF 버튼, 한/영
  토글, 다크 모드를 유지합니다.
- 상단 카드가 5개면 `stat-grid`, 6개면 `stat-grid six`.
- 발행 전 Playwright(`executablePath:'/opt/pw-browsers/chromium'`)로 1680px·
  820px 스크린샷을 찍어 레이아웃을 확인합니다.
- 확정된 투자 판단으로 단정하지 않습니다. 고객 응대 항목에는 "확정된 판단이
  아닙니다"로 시작하는 단서를 답니다.
- 문체는 한국어 존댓말 서술, 영문 병기.

## 7. 두 브리핑의 역할

### 모닝 (평일 07:00 KST) — 아티팩트 `dca66b4e-550e-42ed-96d9-b24918392756`, favicon 📈

전 거래일 국내 마감 + 밤사이 미국 마감 + 오늘 일정으로 **하루를 준비하는** 자료.
14개 섹션: 01 한눈에 보는 핵심 / 02 국내 증시 / 03 수급·레버리지 / 04 종목·섹터 /
05 글로벌 증시 / 06 금리·환율·원자재 / 07 하우스 시각 / 08 애널리스트 액션 /
09 일정·체크포인트 / 10 리스크 점검 / 11 WM 업계 / 12 고객 응대 포인트 /
13 데이터 검증 노트 / 14 출처.

전날 16:00 장마감 브리핑을 함께 읽어 **거기서 잠정치·미확보로 남긴 항목을
확정치로 보완**하고, 보완한 항목을 13번에 표시합니다.

### 장마감 (평일 16:00 KST) — 아티팩트 `5ebc6deb-3931-4e56-ae1f-afbb420fd92b`, favicon 🔔

**오늘 장에서 실제로 무슨 일이 있었는지**를 정리해 마감 후 고객 응대와 일일보고에
쓰는 자료. 10개 섹션: 01 마감 요약 / 02 지수·시장 내부 / 03 투자자별 수급 /
04 특징주 / 05 이번 주 정리 / 06 환율·금리·원자재 / 07 오늘 밤·다음 주 /
08 고객 응대 포인트 / 09 데이터 검증 노트 / 10 출처.

장중 흐름(시가·고가·저가·종가, 되밀린 폭), 확정 수급, 특징주와 사유에 무게를
둡니다. 마감 30분 뒤라 일부 수급은 잠정치이므로 "마감 30분 시점 집계로 잠정치일
수 있음"을 명시하고, 미보도 항목은 다음 날 아침 브리핑에서 보완한다고 적습니다.

사이드바 「같은 날 자료」에 서로의 링크를 유지합니다.

Artifact 도구에 해당 브리핑의 `url` 과 `favicon` 을 지정해 **같은 링크를

## 9. 검증 노트에 반드시 남길 것

(a) 시세 파일에서 가져온 항목과 파일의 `generated_at_kst`
(b) 전날 브리핑에서 보완한 항목 (모닝만)
(c) 날짜 오염 등으로 걸러낸 검색 결과
(d) 확인 못 한 항목과 사유 — 몇 번 검색했는지도
(e) 계산으로 만든 값과 산식
(f) 상충 수치와 채택/미채택 사유
(g) **데이터 계보** — 어떤 항목이 어느 원천에서 왔는지. 표로 정리합니다:
    야후(지수 OHLC·미국·원자재·미 국채) / 네이버(업종·등락 종목 수·투자자별·
    프로그램 매매·국내 금리) / 언론 보도(사유·코멘트·일정) / 계산(누적·스프레드).

**(g) 를 쓸 때 주의 —** 수집 서버가 도입된 뒤로 "브리핑 수치는 전부 웹 검색에서
나온다", "업종별 등락률·등락 종목 수·금리는 구조적으로 채울 수 없다", "관리자
허용 목록 변경이 필요하다" 는 **모두 사실이 아닙니다.** 그렇게 쓰지 마십시오.
정확히는 이렇습니다 — 브리핑 세션은 시세 사이트에 직접 붙지 못하지만, 정책
바깥에서 도는 수집 서버가 대신 받아 저장소에 커밋하므로 **허용 목록 변경 없이도
시세가 확보됩니다.** 이그레스 차단은 수집 서버를 따로 두는 *이유*로만 언급하고,
브리핑의 *한계*로 서술하지 마십시오.

(h) **아직 받지 못하는 항목** — 항목 / 이유 / 현재 대응 / 해결 방법을 표로.
    현재 알려진 것: 국고채 10년(공개 원천 없음 — 한국은행 ECOS API 키를 받으면
    해결), 선물 외국인 순매수(공개 원천 없음 — 프로그램 비차익으로 대용),
    신용융자·반대매매(금투협 freeSis 수집 미구현), KRX 전종목 시세(수집 서버
    IP 차단 — 야후·네이버가 대체하므로 불필요).

이전 판의 수치를 정정했다면 "정정" 카드를 검증 노트 맨 앞에 둡니다.
