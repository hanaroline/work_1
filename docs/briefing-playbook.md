# 마포WM 시황 브리핑 작성 지침

미래에셋증권 마포WM의 시황 브리핑을 만드는 자동 세션이 따르는 규칙입니다.
**07:30 아침 Routine은 주말·휴장일을 포함해 매일** 돌고, 16:10 장마감 Routine은
국내 거래일에만 돕니다. 두 Routine 모두 이 문서를 읽고 실행합니다.

이 문서를 고치면 다음 실행부터 반영됩니다. Routine 프롬프트를 건드릴 필요가 없습니다.

---

## 0. 휴장일에는 **판을 바꿉니다** — 거르지 않습니다

**아침 Routine은 매일 돌고, 어느 날이든 산출물이 나옵니다.**
「휴장일이라 만들지 않았습니다」로 끝내지 마십시오.

| 오늘 | 만들 것 | 파일 이름 |
|---|---|---|
| 국내 거래일 | **모닝 마켓 브리핑** — 전 거래일 국내 마감 + 간밤 미국 마감 + 오늘 일정 | `<날짜>-morning.html` |
| 주말·휴장일 | **해외 증시 브리핑** — 간밤 미국·유럽·아시아 마감 + 다음 국내 거래일 준비 | `<날짜>-global.html` |

구성은 7-3절에 있습니다. **제목(`<title>`)과 히어로도 「해외 증시 브리핑」으로**
바꾸십시오 — 모닝 제목이 그대로 남으면 목록에서 두 판이 같은 이름으로 뜹니다.

**주말에 국내 항목이 갱신되지 않는 것은 정상입니다.** 신선도 확인(0-1절)에서
국내 줄이 어긋나도 그것만으로 멈추지 마시고, **미국 직전 마감이 들어와 있는지**를
기준으로 판단하십시오. 국내 수치는 **직전 거래일 마감**으로 이름표를 달아 씁니다.

**장마감 Routine은 다릅니다** — 국내 장이 열리지 않았으면 정리할 「오늘 장」이
없으므로, 그 사실만 보고하고 종료합니다.

## 0-1. 시세 파일이 오늘 것인지 **먼저** 확인합니다

**글을 쓰기 전에 반드시 이 단계를 거칩니다.** 예약 수집이 늦게 도는 일이
잦습니다. 8월 10일에는 15:40 예약이 **17:15** 에야 만들어져(95분 지연) 16:00
장마감 루틴이 금요일 값을 보고 있었고, 산출물 없이 끝났습니다. 같은 날
06:40 예약도 07:01 에 돌아 07:00 모닝 루틴과 아슬아슬하게 엇갈렸습니다.

```bash
cd "$(git rev-parse --show-toplevel)"
python3 scripts/check_market_fresh.py close     # 장마감 판
python3 scripts/check_market_fresh.py morning   # 모닝 판
```

수집기는 언제나 **main** 에 커밋하므로 이 스크립트도 `origin/main` 을 봅니다.
작업 브랜치에 있어도 됩니다 — main 쪽이 더 새것이면 작업본
`data/market/latest.json` 을 그것으로 맞춰 줍니다.

끝 상태가 **0 이면** 그대로 진행합니다. **1 이면 낡은 것입니다** — 아래 순서를
따릅니다.

1. 수집을 지금 돌려 달라고 요청합니다.

   ```bash
   bash scripts/request_market_refresh.sh
   ```

   **`workflow_dispatch` 를 API 로 부르지 마십시오 — 세션 토큰에는 Actions
   쓰기 권한이 없어 403 입니다.** 대신 이 스크립트가 워크플로가 지켜보는
   `data/market/REFRESH` 를 main 에 밀어 넣어 발동시킵니다. 지금 브랜치는
   건드리지 않습니다. 실제로 8월 11일 06:24 요청이 4초 만에 시작해 56초에
   끝났습니다.

2. 갱신될 때까지 기다립니다. 수집은 보통 1~3분 걸립니다.

   ```bash
   python3 scripts/check_market_fresh.py --wait close
   ```

3. 그래도 끝 상태가 1 이면 **낡은 값을 오늘 값처럼 쓰지 마십시오.** 기대
   마감일이 휴장일인지부터 보고, 휴장이 아닌데 갱신되지 않았다면 브리핑
   머리말과 검증 노트에 «시세 파일이 (수집 시각) 기준이라 (항목) 은 (날짜)
   값입니다» 라고 명시한 뒤, 확보된 범위까지만 씁니다.

낡은 줄 모르고 쓰는 것이 못 쓰는 것보다 나쁩니다. 브리핑이 늦는 것은 고칠 수
있지만, 금요일 숫자를 월요일 것이라고 말한 브리핑은 고칠 수 없습니다.

**야후 지수 심볼의 빈 종가 — 고쳤지만 알아 두십시오.** 야후는 장이 끝난
뒤에도 **지수** 일봉의 종가를 한동안 `null` 로 줍니다. 마감가는 `meta.
regularMarketPrice` 에만 실립니다. 8월 11일 아침에 `^KS11` `^KQ11` `^N225`
`^HSI` `000001.SS` `^TWII` `^BSESN` `^AXJO` `^STOXX` 가 **전부** 그랬고,
같은 거래소의 개별 종목(`005930.KS` `7203.T` `600519.SS`)은 멀쩡했습니다.
빈 봉을 건너뛰던 수집기가 8월 7일 값을 8월 10일 값으로 읽어, **국내·일본·
중국·홍콩·대만·인도·호주 지수가 하루 뒤처진 채로 브리핑에 나갔습니다.**

지금은 `yahoo_quote` 가 마지막 봉이 비었고 `meta` 가 **거래소 현지 기준
같은 날** 마감을 들고 있으면 그 값을 씁니다. 그렇게 채운 항목에는
`quote_basis` 가 붙으므로, 검증 노트에 표시할 수 있습니다. 아직 열리지
않은 날의 빈 봉은 날짜가 어긋나 걸리지 않습니다.

그래도 **국내 종가·등락률·거래대금은 `index_daily`(거래소 일별시세)를
우선**하십시오. 거래대금은 거기에만 있고, 두 값이 어긋나면 그쪽이
맞습니다. 신선도 확인이 `indices.kospi` 를 참고 항목(`~`)으로 함께 찍는
것은 이 어긋남을 다시 잡아내기 위한 것입니다.

**`indices.usdkrw` 는 서울 종가가 아닙니다.** 야후 `KRW=X` 는 거래소가
`Europe/London` 인 24시간 시세이고, 마지막 봉은 **그 시각의 진행 중
호가**입니다. 아침에 받으면 `date` 가 오늘이고 값도 오늘 새벽 호가입니다 —
어제 서울 외환시장 마감이 아닙니다. **원/달러 마감은 `usdkrw_naver`
(매매기준율)를 쓰고 그 이름으로 부르십시오.** 8월 11일 07:40 기준으로
`indices.usdkrw` 는 1,417.86(진행 중), `usdkrw_naver` 는 1,419.5 였습니다.
`dxy` 도 같은 성격이라 "간밤 흐름"으로만 쓰십시오.

## 0-2. **오늘 판이 이미 있으면 다시 만들지 마십시오**

예약은 하루에 한 번 뜨는 것이 원칙이지만 **실제로는 여러 번 뜹니다.** 2026년
8월 21일 아침 모닝 루틴이 **07:39 · 07:59 · 08:01 세 번** 떴습니다 — 첫 실행이
아직 돌고 있는 사이에 두 번 더 들어온 것입니다. 그대로 두면 같은 날 판을 세 번
만들고, 아티팩트가 셋 생기고, `index.json` 에 같은 날짜가 겹칩니다.

**그래서 무엇이든 만들기 전에 먼저 봅니다.**

```bash
ls docs/briefings/$(TZ=Asia/Seoul date +%F)-*.html 2>/dev/null
```

파일이 **이미 있으면 다시 만들지 마십시오.** 대신 이렇게 합니다.

1. `python3 scripts/recheck.py docs/briefings/<그 파일>` 을 돌려 **성한 판인지** 봅니다.
2. `index.json` 에 그 날짜 항목이 있고 `url` 이 채워져 있는지 봅니다.
3. `git log --oneline -3` 과 `git status --short` 로 **커밋·푸시가 끝났는지** 봅니다.
4. 셋 다 맞으면 **「이미 만들어 올렸습니다」라고 보고하고 끝냅니다.** 파일을 다시
   보내지도 마십시오 — 같은 파일이 두 번 올라갑니다.
5. **어느 하나라도 어긋나 있으면** 그 어긋난 단계부터 이어서 마칩니다(파일은
   있는데 커밋이 없다 → 커밋만, 아티팩트가 없다 → 발행만).

**중간에 끊긴 판을 발견했을 때만 다시 만듭니다.** 판단 기준은 `recheck.py` 입니다
&mdash; FAIL 이 있거나 절 수가 목차와 어긋나면 미완성이니 처음부터 다시 짓고,
오류 0 이면 완성된 판이므로 손대지 않습니다.

같은 이유로 **아티팩트도 날짜+판당 하나만** 냅니다. 이미 `index.json` 에 `url` 이
있으면 새로 발행하지 말고 그 주소를 그대로 두십시오(7-1절).

## 1. 시세 파일을 먼저 읽습니다 — 뉴스보다 우선

이 세션은 사내 이그레스 정책 때문에 KRX·네이버·야후·인베스팅닷컴에 직접 붙지
못합니다(CONNECT 403). **다시 시도하지 마십시오.** 대신 GitHub Actions 러너가
매 거래일 시세를 받아 이 저장소에 커밋해 둡니다.

```bash
cd "$(git rev-parse --show-toplevel)"
git pull -q origin main
python3 -m json.tool data/market/latest.json | head -120
```

| `money_flow` | 증시자금동향 — `latest` 와 `series`(10영업일). `deposit`(고객예탁금) `credit_balance`(신용융자 잔고) `fund_equity`/`fund_mixed`/`fund_bond`, **단위 억원**. 신용잔고는 결제일 기준이라 종가일보다 1~2영업일 늦습니다 — 반드시 `date` 를 같이 쓰십시오.<br>**증감은 `*_delta` 를 쓰십시오. `*_chg` 는 네이버가 준 부호 없는 절대값입니다** — 8/13 판이 예탁금 3조 4,884억 **감소**를 「+34,884 증가」로 내보냈습니다 |
| `news` | 그날 증시 기사 본문. `articles`(제목·URL·본문 6천자), `futures_mentions`, `credit_mentions`. **브리핑 세션은 언론사에 직접 못 붙으므로, 검색 요약보다 이 원문을 우선 인용합니다**.<br>`extraction` 에 어디서 건졌는지가 세어져 있습니다 — `id="dic_area"` 가 정상이고 `fallback` 이 섞였으면 네이버 구조가 바뀐 것입니다. 절반을 넘으면 수집기가 실패로 올립니다 |
| `sources` | 원천별 성공/실패와 실패 사유 |

국내 금리의 **기간 변화**는 `rates_ecos.ktb3y/ktb10y.perf` 에 있습니다 — 단위는 `bp` 이고,
수집기가 기준일마다 ECOS 를 따로 불러 그 앞의 마지막 실측치와 견줍니다. **ECOS 는 자주
끊깁니다** — 비어 있으면 표에 `—` 로 두고 검증 노트에 적으십시오. 무료 인증키를
`ECOS_API_KEY` 로 넣으면 한 번에 받아 와 훨씬 안정적입니다.

`investors_kospi` 는 **약 한 달치**(30영업일), `money_flow.series` 는 20영업일입니다.
**미수금·반대매매는 어디에도 없습니다** — 네이버 증시자금동향 머리행이 날짜/고객예탁금/
신용잔고/펀드 뿐인 것을 확인했고, 금투협은 웹방화벽이 막습니다(`money_flow.missing` 참고).
`NOT FOUND` 로 두고 **신용잔고를 대용**으로 쓰십시오.

`data/market/history.json` 은 **따로 쌓이는 파일**입니다 — 날짜별로 코스피·코스닥 종가,
등락 종목 수(`breadth`), 업종 79개 등락률, 투자자별 순매수, 예탁금·신용잔고를 모아 둡니다.
**추이를 쓸 때 날짜별 스냅숏을 하나씩 열어 손으로 잇지 마십시오.** 8/15 판의
「697 → 563 → 380 → 333 → 677」 계열이 그렇게 만들어졌습니다. 이제 이 파일 한 장이면 됩니다.
넉 달치(120행)를 남기고 시세일을 열쇠로 덮어씁니다.

**이 수치는 거래소 원천이므로 뉴스 보도보다 우선합니다.** 배지는
`<span class="vf ok">MARKET DATA</span>` 로 표시합니다. 뉴스와 값이 다르면
이 파일을 채택하되 차이를 검증 노트에 적습니다.

**주말·휴장일 브리핑에도 똑같이 적용됩니다.** 국내가 쉬는 날 쓰는 해외 증시
브리핑은 검색만으로 만들기 쉬운데, 그렇게 만든 8/8 판은 SOX·VIX·달러인덱스를
"검색 4회 실패" 로 비워 두고 유가는 매체 세 곳이 엇갈려 확정치를 못 걸었습니다.
**셋 다 이 파일에 있었습니다.** 국내가 쉬어도 미국·유럽은 금요일에 열렸고,
수집기는 그 마감가를 받아 둡니다. 검색으로 못 찾았다고 미확보로 적기 전에
이 파일을 먼저 여십시오.

**날짜를 반드시 확인하십시오.** `indices.kospi.date` 가 대상 거래일과 다르거나
`generated_at_kst` 가 오늘이 아니면 파일이 갱신되지 않은 것입니다. 그 사실을
검증 노트에 명시하고 뉴스 검색으로 진행합니다.

**지난 판을 고칠 때는 `latest.json` 이 아니라 날짜별 스냅샷을 쓰십시오.**
수집기는 매 실행마다 `data/market/<날짜>.json` 을 남기고 `latest.json` 을
덮어씁니다. 주말에 만든 판을 월요일에 손보면 `latest.json` 은 이미 다음 주
값입니다 — 실제로 8/8 판을 고치던 중 `usdkrw` 가 1,407.45(금요일 뉴욕 마감)
에서 1,407.78(월요일 개장)로, `fed_implied` 가 3.6325%에서 3.75%로 굴러가
있었습니다. **거래소 종가는 그대로여도 24시간 거래되는 값(환율·선물)은
바뀝니다.** 그 판의 기준일에 해당하는 스냅샷을 열어 쓰십시오.

`sources` 에 실패로 기록된 항목은 재시도하지 마십시오. **KRX(`krx:allstocks`, `krx:futures_investors`)는 수집 서버 IP를 막아 상시 실패**합니다 — 정상입니다. 필요한 값은 야후·네이버·ECOS 가 모두 채우며, 선물 외국인만 대체가 없어 프로그램 비차익(`market_internals.*.program_trading.non_arb`)을 대용 지표로 씁니다.

## 2. 검색은 파일에 없는 것에 씁니다

시세는 위 파일에서 나오므로, **WebSearch는 숫자가 아니라 맥락을 구하는 데** 씁니다.

- 특징주가 왜 움직였는가 (개별 재료, 공시, 해외 뉴스)
- 업종이 왜 갈렸는가
- 증권사 코멘트·목표주가·투자의견 변경
- 수급 해설, 신용융자·반대매매 등 레버리지 지표
- 일정과 컨센서스, 제도·WM 업계 뉴스
- 파일에 없는 수치 — 선물 외국인 순매수, 신용융자 잔액·반대매매

**검색을 얕게 하지 마십시오.** 항목별로 각각 별도 검색을 돌리고, 한 번에 안
잡히면 표현을 바꿔 재시도합니다. 「데이터센터」·「스팟」·「마감시황」류 기사가
수치를 가장 많이 담고 있습니다 — EBN 데이터센터, 머니투데이 [스팟], 뉴스핌·
아주경제·이투데이·국민일보·아이뉴스24. 매체명을 검색어에 넣어 보십시오.

기사 본문 직접 조회(WebFetch)는 대부분 HTTP 403입니다. 검색 결과 요약을
근거로 삼되 그 사실을 검증 노트에 적습니다.

## 3. 검증 규칙

1. **배지 체계** — 시세 파일 출처는 `vf ok` + MARKET DATA. 뉴스는 서로 다른
   2개 매체가 일치해야 `vf ok` + 2 SOURCES, 1곳뿐이면 `vf solo` + 1 SOURCE,
   불일치는 `vf bad` + CONFLICT, 못 찾으면 `vf none` + NOT FOUND, 방향만
   확인되면 DIRECTION ONLY.
2. **없는 수치는 절대 지어내지 않습니다.** 비워 두고 배지를 답니다. 등락률만
   확인되고 종가를 모르면 종가 칸을 비웁니다. 표 전체를 못 채우면 표를 뺍니다.
3. **날짜 대조 필수.** 검색엔진이 다른 날·다른 해 기사를 오늘 것으로 끌어옵니다.
   확인된 마감 수치와 방향이 어긋나는 결과는 폐기하고 검증 노트에 기록합니다.
   기사 URL의 번호가 같은 날 다른 기사들과 동떨어져 있으면 다른 날짜일
   가능성이 큽니다.
   - 실제 사례: "8월 6일 국고채" 검색이 5월 6일 기사를 반환
   - "8월 7일 삼성전자" 검색이 실제 마감과 정반대인 다른 날 기사를 반환
   - "미 7월 고용 결과" 검색이 아직 발표되지 않은 지표의 다른 연도 결과를 반환
4. **장중 집계치와 마감 확정치를 섞지 않습니다.** 수급 조합의 합이 0 근처에서
   맞는지 산술 검산하고, 맞지 않는 조합은 장중치로 보고 채택하지 않습니다.
5. **아직 발표되지 않은 지표의 결과를 쓰지 않습니다.** 컨센서스와 발표 예정
   시각만 적고 "미발표"로 표시합니다.
6. **작성 시각은 실제 작성한 시각**을 적습니다. 예정 시각을 옮겨 적지 않습니다.

## 4. 누적 등락률 기준선

- **주간 누적(WTD)은 직전 금요일 종가 기준**입니다. 월요일 종가를 기준선으로
  잡으면 월요일 당일 등락이 기준값 안에 이미 반영돼 있어 누적에서 빠집니다 —
  계산 오류입니다.
- 월간 누적은 전월 말 종가, 연초 대비는 전년 말 종가 기준.
- 기준일과 기준 지수를 항상 함께 표기합니다.
  예: `주간 누적 (7/31 종가 6,595.45 → 8/7) −5.10%`
- N거래일 누적이라고 쓸 때는 제시한 일간 등락 개수와 구간이 반드시 일치해야
  합니다.
- 주간 표는 맨 위에 직전 금요일 종가를 기준선 행(`tr class="base"`), 맨 아래에
  주간 누적 합계 행(`tr class="sum"`)을 둡니다.
- **코스피와 코스닥의 주간 성적을 반드시 함께** 제시합니다. 두 시장 방향이
  갈리는 국면에서는 지수 하나로 "시장이 좋았다/나빴다"고 말할 수 없습니다.

## 4-1. 주요 종목 시세는 매 판에 넣습니다

지수만으로는 하루를 설명하지 못합니다. 8/7만 봐도 코스피는 &minus;0.60% 인데
LG에너지솔루션 +4.35%, NAVER &minus;7.08% 로 갈렸고, SOX 는 +2.56% 인데 그 안에서
엔비디아 +2.27% 와 AMD &minus;1.21% 가 반대였습니다. **지수 등락률 하나로 업종을
설명하지 마십시오.**

**다섯 개 종목 표를 전부 넣습니다.** 모닝과 장마감, 해외 브리핑 모두
같습니다. 시세 파일에 다 있으므로 검색할 일이 아닙니다.

| 표 | 원천 | 담을 것 |
|---|---|---|
| 국내 주요 종목 | `stocks` (10종목) | 종가·등락률. 단위 원 |
| 미국 주요 종목 | `us_stocks` (12종목) | 단위 달러. 반도체가 갈리면 그 사실을 적습니다 |
| **유럽 주요 종목** | `eu_stocks` (12종목) | **거래 통화 기준**(EUR·GBp·CHF·DKK) |
| **일본 주요 종목** | `jp_stocks` (10종목) | 단위 엔 |
| **중국·홍콩 주요 종목** | `cn_stocks` (10종목) | 본토는 CNY, 홍콩은 HKD |
| 미국 업종 | `us_sectors` (11개 ETF) | 어느 업종에 돈이 붙었는지 |

**유럽·일본·중국 표를 빼지 마십시오.** 8/11 판을 만들면서 일본과 중국을 한
표에 합치고 **유럽 종목 표를 통째로 빠뜨렸습니다.** `eu_stocks` 12종목이
파일에 들어 있는데도 그랬습니다. 09번(유럽·아시아) 절은 **지수 표 하나 +
지역별 종목 표 셋**이 기본 구성입니다.

**종목 표에는 「핵심」 열을 넣습니다 — 다섯 표 전부입니다.** 각 종목의
`note_ko` / `note_en` 이 그 회사가 무엇을 하는 곳인지 한 줄로 담고 있습니다
(53종목 전부. ASML 은 미국·유럽 두 표에 나오므로 종목 수는 54, 이름은 53).
이름과 숫자만 있는 표는 응대 중에 "이 회사가 뭐 하는 곳이냐" 를 다시 찾게
만듭니다. **8/11 판에서 다섯 표 모두 이 열을 빠뜨렸다가 되살렸습니다.**

- **지어내지 마십시오.** `note_ko` 를 그대로 쓰고, 없으면 열을 비웁니다.
- 이 설명은 **사업 내용**입니다. 실적·목표주가·전망을 여기 섞지 마십시오 —
  그런 것은 날마다 바뀌고, 이 열은 바뀌지 않는 것만 담습니다.
- 좁은 화면에서는 `.note` 를 숨깁니다. **열 번호(`nth-child`)로 숨기지
  마십시오** — 중국 표에는 「시장」 열이 하나 더 있어 번호가 어긋납니다.
- 종목을 새로 추가하면 `scripts/fetch_market.py` 의 `STOCK_NOTES` 에 설명을
  같이 넣습니다. 넣지 않으면 그 종목만 칸이 빕니다.

해외 증시 브리핑에는 `eu_stocks`(유럽 12종목), `jp_stocks`(일본 10종목),
`cn_stocks`(중국 10종목)를 더합니다.

**해외 브리핑에는 「지역별 요약」 카드를 넣습니다.** 표가 다섯 개로 늘면 숫자는
충분한데 "그래서 어느 지역이 어땠나" 를 한 번에 볼 자리가 없어집니다. 01번
핵심 카드 바로 아래에 `views` 그리드로 **미국·유럽·일본·중국** 넉 장을 놓습니다.
각 카드는 대표 지수 등락, 그날의 주도·부진 종목, 한 줄 해석으로 구성합니다.
**숫자는 손으로 적지 말고 시세 파일에서 계산하십시오** — 손으로 적으면 아래 표와
어긋납니다.

**아시아는 마감 시각이 다릅니다 — 표를 나란히 놓기 전에 이걸 적으십시오.**
아시아 증시는 15:00~16:00 KST 에 닫히고, 유럽은 00:30 KST, 미국은 05:00 KST 입니다.
미국 지표는 대개 21:30 또는 22:30 KST 에 나오므로 **같은 날짜여도 아시아는 그
뉴스를 모르는 상태로 거래를 끝냅니다.** 8/7이 그랬습니다 — 미국 SOX +2.56% 인
날 도쿄일렉트론은 &minus;1.50%, 어드반테스트는 &minus;2.25% 였습니다. "아시아
반도체가 미국과 반대로 갔다" 고 쓰면 틀립니다.

**통화를 섞지 마십시오.** 일본은 엔, 홍콩 상장은 HKD, 중국 본토(상하이·선전)는
CNY 입니다. `cn_stocks` 에는 홍콩과 본토가 섞여 있으므로 표에 시장을 함께
적고, 비교는 종가가 아니라 등락률로 합니다.

**날짜를 맞추십시오.** 각 종목의 `date` 가 그 판의 기준 거래일과 같아야 합니다.
모닝 브리핑(07:30)의 기준은 **전날** 미국장이고, 시세 파일이 그 뒤에 갱신됐다면
파일에는 **하루 뒤** 값이 들어 있습니다. `date` 를 확인하지 않고 붙이면 하루가
어긋난 표를 싣게 됩니다.

**ASML 은 두 곳에 있습니다.** `us_stocks` 는 미국 예탁증서(ADR, 달러),
`eu_stocks` 는 암스테르담 원주(유로)입니다. 값이 다른 게 정상이며, 둘을 같이
실을 때는 어느 쪽인지 적습니다.

## 4-2. 금리는 재무부 곡선을 씁니다 — 기사에서 추정하지 마십시오

미 국채 금리는 `rates_us` 에 **미 재무부 일별 고시 확정치**가 만기 11개
(1M·3M·6M·1Y·2Y·3Y·5Y·7Y·10Y·20Y·30Y) 전부 들어 있고, `prev_curve` 와
`change_bp` 까지 붙어 옵니다. **여기서 가져오십시오.**

기사에는 장중 값이 섞여 들어옵니다. 8/8 판은 "장중 고점 4.69% → 추정 마감
~4.61%" 라고 적었는데 확정치는 **4.65%(&minus;4bp)** 였습니다. 2년물은 3bp,
30년물은 1.5bp 어긋났습니다. **"추정 마감" 이라는 표기를 쓸 일이 없습니다** —
파일에 확정치가 있습니다.

같이 넣을 것:

- **장단기 스프레드** — `spread_10y_2y_bp` 와 `inverted` 가 계산돼 있습니다.
  직접 빼서 구하지 말고 이 값을 쓰십시오. 곡선이 가팔라졌는지 눌렸는지가
  금리 기대의 방향이고, 지수 등락률보다 오래 갑니다.
- **`fed_implied`** — 연방기금 금리선물 내재 정책금리. "인상 우려 후퇴",
  "인하 기대" 같은 서술을 쓸 때 **그 문장의 근거 숫자**입니다. 근거 없이
  기사 표현만 옮기지 마십시오.

  **반드시 `policy_rate_us.effr_pct`(실효 연방기금금리)와 견주십시오.**
  `fed_implied.vs_effr_bp` 에 그 차이가 bp 로 계산돼 있습니다. 뚜렷한
  마이너스여야 인하 기대이고, 0 근처면 **"변화 없음"** 이지 완화가 아닙니다.

  **단기 국채와 견주지 마십시오 — 틀린 답이 나옵니다.** 8/8 판이 "선물
  내재 3.6325%가 1개월물 국채 3.79%보다 16bp 낮으니 완화 쪽에 가격을 매기고
  있다"고 적었는데, 실제 EFFR 은 3.63% 로 내재금리와 사실상 같았습니다.
  단기 국채는 정책금리보다 높게 거래되는 것이 보통이라, 그 격차는 완화
  기대를 뜻하지 않습니다. 2년물이 EFFR 보다 높은 것도 기간 프리미엄이
  섞여 있으니 **인상 횟수로 환산하지 마십시오.**
- **`breakeven`** — 기대인플레이션(명목 − TIPS 실질). 금리가 내린 날 이 값이
  같이 내렸으면 **물가 기대가 낮아진 것**이고, 그대로면 **실질금리가 내린
  것**입니다. 고객에게 드리는 말씀이 다릅니다. `rates_us_real` 에 실질금리
  곡선 원본이 있습니다(TIPS 발행 만기라 5·7·10·20·30년만 옵니다).
- **`indices.move`** — ICE BofAML MOVE 지수, 채권판 VIX 입니다. 금리가 내린
  날 변동성까지 죽었으면 안도이고, 금리는 내렸는데 변동성이 살아 있으면
  관망입니다. VKOSPI 와 달리 이건 받아집니다.
- **한국 기준금리는 없습니다.** ECOS 722Y001 은 샘플 인증키로 0행을
  돌려줍니다. 콜금리(`rates_kr.call`)를 기준금리로 적지 마십시오 — 근처에서
  움직일 뿐 같은 값이 아닙니다.

곡선 전체를 실으면 어느 구간이 움직였는지가 보입니다. 짧은 쪽이 더 내렸으면
금리 기대가 움직인 것이고, 장기물까지 같이 내렸으면 성장·물가 전망이 움직인
것입니다. 둘은 고객에게 드리는 말씀이 다릅니다.

**교차검증을 답니다.** `indices` 의 `ust5y`·`ust10y`·`ust30y`(야후 `^FVX`
`^TNX` `^TYX`)가 재무부 고시와 대개 2bp 안에서 맞습니다. 맞으면 `2 SOURCES`
로 올리고, 어긋나면 재무부 파일이 갱신되지 않은 것이니 날짜를 확인하십시오.

**`ust3m`(`^IRX`)만 예외입니다.** 재무부보다 15bp 안팎 낮게 나오는데
**불일치가 아니라 표기 기준 차이**입니다 — `^IRX` 는 할인율(discount),
재무부는 채권등가수익률입니다. 한 표에 섞지 말고, 3개월물은 재무부 값을
쓰십시오. **이 격차를 CONFLICT 로 적지 마십시오.**

**장중 고저를 함께 보십시오.** "발표 후 되돌림" 같은 서술은 종가만으로는
근거를 못 댑니다. `indices.ust10y` 의 `high`/`low`/`close` 로 실제 진폭을
적으십시오. 8/7은 종가 기준 &minus;4bp 였지만 장중 고 4.672 → 저 4.603 →
종 4.660 으로 **진폭이 7bp** 였습니다. 채권이 고용 부진을 사들였다가 장
후반에 거의 다 게워낸 날이며, 종가만 보면 이 사실이 사라집니다.

**한미 금리차를 넣으십시오.** 미 국채와 국고채(`rates_ecos`)의 같은 만기를
빼면 됩니다. 원화 방향과 직결되므로 환율 섹션과 함께 읽습니다. 8/7은 10년
기준 +50bp → **+44bp** 로 좁혀졌는데, 미국은 내렸고(&minus;4bp) 국고채는
오른(+1.3bp) 결과였고 같은 날 역외 원달러가 &minus;1.04% 로 원화가 강했습니다.

**국내 시장금리를 같은 섹션에 넣으십시오.** 섹션 이름이 「금리·채권시장」인데
미국만 싣던 판이 있었습니다. 국내가 휴장이어도 **직전 거래일 확정치가 파일에
있습니다** — 미국 수치와 같은 날짜라면 함께 실어야 앞뒤가 맞습니다.

- **신용스프레드는 두 층으로** — 국고채 3년 위로 AA&minus;(`rates_kr.corp3y`)
  와 BBB&minus;(`rates_ecos.corp3y`) 를 각각 bp 로 냅니다. 우량물은 붙어 있는데
  저등급만 벌어지면 시장이 신용을 가려 받고 있다는 뜻입니다.
- **COFIX 는 빠뜨리지 마십시오** — 고객 대출금리에 직결돼 응대에서 실제로
  묻는 값입니다. 잔액기준과 신규취급액을 **둘 다** 싣고 차이를 bp 로 적습니다.
- **자릿수를 원천에 맞추십시오.** 네이버가 소수 둘째 자리까지 주는 값(콜·CD·
  COFIX·회사채)을 셋째 자리로 적으면 없는 정밀도를 지어내는 것입니다.
  ECOS 국고채는 셋째 자리까지 옵니다.
- **10영업일 추이를 접어서 답니다.** `rates_ecos.*.series` 에 만기별 10일치가
  들어 있습니다. 하루치 등락은 "그날 무슨 일이 있었나" 이고, 추이는 "어디로
  가고 있나" 입니다. 본문이 길어지므로 `<details class="exp">` 안에 넣습니다.
  스파크라인은 **인라인 SVG** 로 그리고(CSP가 외부 자원과 차트 라이브러리를
  막습니다) 선 색은 `currentColor` 로 둬 다크 모드를 따라오게 합니다. 세로
  축은 줄마다 따로 맞추고, **높이를 만기끼리 비교하는 그림이 아니라는 사실을
  캡션에 적으십시오.**
- **미국 곡선과 방향을 견주십시오.** 8/7 기준 한국은 1년물이 &minus;1bp 로
  묶인 채 3·5·10년만 &minus;12~&minus;15bp 내려 1년&ndash;10년이 96bp →
  84bp 로 평탄해졌고, 같은 기간 미국은 2년&ndash;10년이 +44 → +46bp 로
  가팔라졌습니다. **두 곡선이 반대로 가는 국면**은 그 자체가 이야깃거리입니다.

## 4-3. 기간 수익률을 표에 함께 싣습니다

**하루 등락률만으로는 지금이 신고가인지 되돌림인지 알 수 없습니다.** 8/14 현대차가
`+8.24%` 였는데 3개월로는 `−36.4%` 였습니다 — 급등이 아니라 되돌림이었고, 하루치
숫자만 실은 표는 그 사실을 감춥니다.

수집기가 야후 일봉 **2년치**에서 계산해 각 지수·종목에 `perf` 를 붙입니다.
원본 계열은 싣지 않고 요약만 싣습니다(`latest.json` 이 12KB 늘었습니다).

| 키 | 뜻 |
|---|---|
| `w1` `m1` `m3` `m6` `y1` | 1주 · 1개월 · 3개월 · 6개월 · 1년 |
| `ytd` | 전년 마지막 거래일 대비 |
| `from` | 자료가 닿는 가장 이른 날 |

- **되짚는 기준은 거래일 수가 아니라 달력입니다.** 휴장일이 나라마다 달라 같은
  「1개월」이 시장마다 다른 기간이 되기 때문입니다. 기준일이 휴장이면 그 앞의
  마지막 거래일을 씁니다.
- **자료가 닿지 않는 구간은 그 항목이 아예 없습니다.** 상장한 지 얼마 안 된 종목이
  그렇습니다. 표에는 `—` 로 두고 **0으로 채우지 마십시오.**
- **국내 ETF 절반은 야후에 3주치밖에 없습니다.** KODEX 200·TIGER 200·KODEX 레버리지·
  KODEX 반도체·TIGER 리츠·KODEX 미국채10년·KODEX 골드가 그렇습니다(`perf.from` 이
  최근 날짜입니다). 1주는 나오고 1개월·연초는 `—` 입니다. **추종 지수의 수익률을
  대신 적지 마십시오** — ETF 는 괴리율과 환헤지 때문에 지수와 다릅니다. 그 칸을
  꼭 채워야 하면 「지수 기준」이라고 이름표를 달아 따로 적으십시오.

### 표에는 네 개만 세웁니다

`w1 · m1 · m3 · ytd`. 여섯 개를 다 세우면 어느 폭에서도 표가 넘칩니다.
`m6` `y1` 은 자료에 남아 있으므로 **본문에서 필요할 때 인용**하십시오.

머리는 `1주 / 1개월 / 3개월 / 연초`. 「연초 대비」로 쓰면 그 한 열 때문에 표가
넘칩니다. 「등락률」(전일 대비) 다음에 두면 **1일 → 1주 → 1개월 → 3개월 → 연초**
사다리가 되어 읽기 좋습니다.

### 설명은 **열이 아니라 이름 밑의 줄**입니다

처음에는 설명을 열로 두고 좁아지면 접었습니다. **그것이 틀렸습니다.** 1620px 아래에서
설명 열을 접었더니 노트북과 **PDF 양쪽에서 「이 지수가 무엇인지」가 통째로 사라졌습니다.**
고객에게 건네는 것은 PDF 입니다 — 거기서 사라지면 없는 것입니다.

**열은 접히지만 줄은 접히지 않습니다.** 그래서 설명을 이름 칸 안에 붙는 작은 줄로
내립니다. 표를 하나하나 고치지 말고 만들어진 HTML 을 한 번에 훑으십시오.

```bash
python3 scripts/inline_notes.py docs/briefings/<날짜>-<구분>.html
```

머리행에서 class 에 `note` 가 든 칸을 찾아 모든 행에서 그 칸을 빼고 첫 칸 안에
`<span class="sub">` 로 옮깁니다. 칸 수가 머리행과 다른 행(colspan·상세행)은
건드리지 않습니다. **표를 만들 때는 종전대로 `class="note"` 열로 쓰고, 마지막에 이
스크립트를 한 번 돌리십시오.**

#### 이름 밑줄을 손으로 만들지 마십시오 — 설명이 두 번 나옵니다

8/20 판이 그랬습니다. 같은 문장을 **`<span class="sub">` 에 한 번, `note` 열에 또
한 번** 넣어 두고 이 스크립트를 돌렸더니, 스크립트가 열을 이름 밑으로 옮기면서
한 벌이 더 붙어 **「달러가 약해지면 오릅니다」가 두 줄로 나왔습니다.** 국내·미국·
유럽·일본·중국 종목 표와 국내 ETF·업종 ETF·환율·원자재까지 **표 열 개 전부**가
그랬습니다.

- 설명은 **`note` 열 한 곳에만** 둡니다. 이름 칸은 이름만 담습니다.
- 등락 사유(`<span class="why">`)처럼 설명 뒤에 붙일 것이 있으면 **그것도 `note`
  열 안에** 넣으십시오. 그래야 순서가 「설명 → 사유」로 맞습니다.
- `hasnote` 클래스도 손으로 달지 마십시오 — 스크립트가 옮기면서 붙입니다.
- 확인은 눈이 아니라 이걸로 하십시오. 만들어진 쪽을 열어 **이름 칸 안에 같은
  문장이 두 번 있는지** 셉니다.

```js
document.querySelectorAll('table.data tbody tr').forEach(tr => {
  const th = tr.querySelector('th'); if (!th) return;
  const t = th.innerText.split('\n').map(x => x.trim()).filter(x => x.length > 8);
  const c = {}; t.forEach(x => c[x] = (c[x] || 0) + 1);
  if (Object.values(c).some(v => v > 1)) console.log(th.innerText.replace(/\n/g, ' | '));
});
```

### 그래도 열이 아홉을 넘으면 줄이십시오

설명을 내려도 열이 너무 많으면 넘칩니다. **CSS 로 버티지 말고 열을 줄이십시오.**

- 미 국채 곡선에서 「EFFR 대비」를 뺐습니다 — 꼬리말에 `EFFR 3.63%, 10년물은 +105bp 위`
  한 줄로 대신합니다.
- 국내 지수에서 「주간 누적」을 뺐습니다 — 꼬리말이 이미 기준일과 값을 밝힙니다.
- 열이 여덟을 넘는 표는 `class="data compact"` 로 세웁니다.

```css
@media (max-width:860px){ table.data .perf{display:none} }   /* 아래 fold_perf.py 를 반드시 같이 */
table.data .perf{padding-left:8px;padding-right:8px}
table.data.compact .perf{padding-left:5px;padding-right:5px}

/* 1400px 위에서는 오른쪽 상세 패널이 열려 본문 칸이 오히려 ~720px 로 **좁아진다**.
   넓은 화면이라고 표가 넓어지는 것이 아니다. */
@media (min-width:1400px) and (max-width:1620px){ table.data .opt{display:none} }
```

**`.perf` 를 `.opt` 로 달지 마십시오.** `.opt` 는 680px 에서 접히는데, 기간 수익률은
그보다 훨씬 일찍 접어야 합니다.

### 접은 기간 열은 이름 밑의 줄로 되살립니다

860px 아래에서 기간 열이 접히면 **폰에서 기간 추이가 통째로 사라집니다.** 설명 열에서
똑같은 일이 있었고 같은 답을 씁니다 — **열은 접히지만 줄은 접히지 않습니다.**

```bash
python3 scripts/inline_notes.py docs/briefings/<날짜>-<구분>.html   # 설명을 먼저 내리고
python3 scripts/fold_perf.py   docs/briefings/<날짜>-<구분>.html   # 기간을 그 밑에 붙이고
python3 scripts/print_fit.py   docs/briefings/<날짜>-<구분>.html   # 인쇄 쪽나눔을 맞춥니다
```

**순서를 지키십시오.** 설명 줄이 먼저 이름 칸에 들어가고 기간 줄이 그 밑에 와야 읽는

줄이 숨고, 좁은 화면에서는 반대입니다. **인쇄는 종이 폭이 ~700px 이지만 기간 열을

한 쌍(`1개월` + `−5.1%`)은 `white-space:nowrap` 으로 붙여 두고 쌍과 쌍 사이에서만
넘깁니다. 붙여 두지 않으면 360px 에서 이름과 값이 다른 줄에 놓입니다.

### PDF 중간의 큰 빈칸 — 「통째로 붙들기」가 원인입니다

인쇄 규칙이 `table,.stat,.view,.callout,.soft-card{break-inside:avoid}` 였습니다.
짧은 블록에는 맞지만 **긴 블록에는 정반대로 작동합니다.** 쪽에 남은 자리가 모자라면
블록을 통째로 다음 쪽으로 미루므로 앞 쪽이 그만큼 비어 버립니다. 8월 15일 판에서
**43쪽 중 24쪽에 12%가 넘는 빈 띠**가 생겼고, 34쪽은 981px 짜리 휴장일 표 하나
때문에 **83%가 비었습니다.**

```bash
python3 scripts/print_fit.py docs/briefings/<날짜>-<구분>.html   # 세 스크립트 중 맨 마지막
```

무엇을 붙들고 무엇을 이어붙일지는 **높이로 가릅니다.**

| 대상 | 처리 |
|---|---|
| 긴 표 | 쪽을 넘겨 잇되 **줄은 쪼개지 않고 머리행을 되풀이**합니다(`display:table-header-group`). 긴 표를 인쇄하는 정공법입니다 |
| 짧은 표(어림 260px 이하) | 종전대로 붙듭니다. 세 줄짜리를 두 쪽에 걸치면 빈칸보다 나쁘고, 짧으므로 밀려도 빈칸이 작습니다 |
| 카드(`.soft-card` `.callout`) | 같은 기준. 긴 것은 이어붙입니다 |
| 격자(`.stat-grid`) | **쪼개면 안 됩니다** — 크로미움이 다음 쪽으로 간 칸의 자리를 앞 쪽에 그대로 잡아 둬 **빈 상자**가 남습니다. 대신 인쇄에서 4열로 세워 낮게 만듭니다 |
| 글 많은 카드 격자(`.views`) | 인쇄에서는 `display:block` 으로 **한 칸씩 가로로 눕힙니다.** 열로 세우면 칸이 좁아 세로로 길어지고 한 줄이 통째로 밀립니다 |

**줄 수만 세면 틀립니다.** 줄이 넷뿐인데 300px 인 표가 있습니다(칸마다 두세 줄씩
들어간 표). 브라우저 없이 재야 하므로 `70 + 줄수×18 + 글자수×0.45` 로 어림합니다.
실측과 견줘 맞춘 계수입니다.

덧붙여 잡은 것 둘:

- **`.sec-num` 에도 `break-after:avoid`** 를 답니다. 빼면 「01」 한 글자만 앞 쪽에
  남습니다 — 실제로 1쪽이 그렇게 나왔습니다.
- **`footer.foot{break-before:avoid}`** — 면책 세 줄만 마지막 쪽에 남는 것을 막습니다.

결과: **43쪽 → 37쪽**, 빈 띠 평균 **21.2% → 8.5%**(마지막 쪽 빼면 6.6%), 12%가
넘는 쪽 **24개 → 6개**, 최대 빈 띠 **83% → 19.8%**(마지막 쪽 제외).

**고친 뒤에는 반드시 재십시오.** 눈으로 넘기면 놓칩니다.

```bash
# 각 쪽에서 잉크가 있는 첫 줄과 마지막 줄 사이의 가장 긴 빈 띠를 잽니다.
# 아래 여백만 재면 쪽마다 붙는 꼬리말 때문에 전부 0으로 보입니다.
```

### 금리는 기간 「수익률」이 아니라 기간 「변화(bp)」입니다

**4.20% 가 4.50% 가 된 것을 「+7.1%」라고 적으면 아무도 못 읽습니다. 「+30bp」입니다.**

## 5. 지수와 종목을 대조합니다

지수 등락률만 쓰면 사실을 왜곡할 수 있습니다. **지수는 내렸는데 상승 종목이
더 많은 날**, 또는 그 반대의 날이 자주 나옵니다.

`market_internals` 의 `breadth` 가 이 점검의 핵심입니다. **상승 종목 수와 하락
종목 수를 지수 등락률과 나란히 놓으십시오.** 지수가 내렸는데 상승 종목이 더
많으면 대형주 몇 개가 지수를 눌렀다는 뜻이고, 그 반대면 시장 전반이 약했다는
뜻입니다. `sectors` 의 top5/bottom5 와 `stocks` 의 개별 등락률도 함께 봅니다.

**코스피와 코스닥의 breadth 를 각각 확인하십시오.** 한쪽은 상승 우세이고
다른 쪽은 하락 우세인 날이 자주 나옵니다 — 두 시장을 뭉뚱그리면 틀립니다.

`program_trading` 의 차익·비차익도 유용합니다. 비차익이 크게 마이너스면
바스켓 매도(외국인 프로그램 매도)가 지수를 눌렀다는 신호입니다.

어긋나면 요약과 고객 응대 섹션에 그 사실을 명시합니다.

**52주 위치를 넣으십시오.** `market_internals.*.fifty_two_week` 의 고·저와
당일 종가로 `(종가&minus;저) / (고&minus;저)` 를 계산합니다. "지금 들어가기에
비싼 자리냐" 는 질문에 등락률로는 답이 안 됩니다. **코스피와 코스닥을 각각
내십시오** — 8/7 기준 코스피는 구간의 50.4%, 코스닥은 28.0% 로 서로 다른
자리에 있었습니다. 두 시장에 같은 말씀을 드리면 어긋납니다.

고객 응대에서 손익을 논할 때는 하나의 숫자로 뭉뚱그리지 말고, **보유 성향별
(대형주 중심 / 중소형주 중심)** 또는 **진입 시점별(판단 기준 종가 → 최신 종가
대비 %)** 로 나눠 표로 제시합니다. 고객은 매수 전날 종가를 보고 결정합니다.

## 6. 화면 규격

- 외부 폰트·CDN·이미지를 넣지 않습니다(아티팩트 CSP가 차단합니다).
- 좌측 목차 사이드바, 우측 상세 패널, 드릴다운, 요약/전체 PDF 버튼, 한/영
  토글, 다크 모드를 유지합니다.
- 상단 카드가 5개면 `stat-grid`, 6개면 `stat-grid six`, 8개면 `stat-grid eight`.
  **카드 수가 열 수로 나누어떨어져야 합니다.** 8개를 3열(`six`)에 넣으면
  3+3+2 로 깨져 오른쪽 아래에 빈 칸이 남습니다. 클래스를 새로 만들 때는
  좁은 화면·패널 모드(`.pane-mode`)용 규칙을 **함께** 넣으십시오. 두 클래스
  선택자(`.stat-grid.eight`)가 `.stat-grid` 하나짜리 미디어쿼리를 이기므로,
  빠뜨리면 휴대폰에서도 4열로 남습니다.
- **표는 그 표가 다루는 대상의 이름을 단 섹션에 둡니다.** 국내 종목 표가
  「반도체·HBM 공급망」 안에 들어가 있어 목차에서 국내 증시를 찾을 수 없던
  적이 있습니다. 섹션에 성격이 다른 표가 붙으면 섹션 이름을 바꾸거나 표를
  옮기십시오.
- 발행 전 Playwright(`executablePath:'/opt/pw-browsers/chromium'`)로 1680px·
  820px·**390px** 스크린샷을 찍어 레이아웃을 확인합니다. 390px 를 빠뜨리지
  마십시오 — 고객 응대는 휴대폰으로 봅니다.
- **표가 휴대폰 화면에 들어가야 합니다. 가로 스크롤을 전제하지 마십시오.**
  `table.data` 에 걸린 `min-width`(기본 560px, `compact` 420px)를 그대로 두면
  390px 화면에서 **마지막 열이 잘립니다** — 주요 종목 표의 등락률이 안 보인다는
  지적이 실제로 나왔습니다. 좁은 화면 규칙 묶음:
  - `min-width:0` 으로 풀고 글씨·여백을 한 치수 줄입니다.
  - 머리 칸의 `white-space:nowrap` 을 풀고 `word-break:keep-all` +
    `overflow-wrap:anywhere` 를 겁니다. 「한화에어로스페이스」가 한 줄을
    고집하면 표가 다시 넓어집니다.
  - **숫자 칸은 `overflow-wrap:normal`** 로 되돌립니다. `anywhere` 가 걸리면
    `1,097,000` 이 한가운데서 끊깁니다. 공백에서만 접히게 두면
    `+151.83 (+0.28%)` 가 두 줄로 얌전히 접힙니다. 검증 배지도 같습니다 —
    안 그러면 `SOURC/ES` 로 끊깁니다.
  - 그래도 넘치면 **다른 열이 이미 말해 주는 열**을 `class="opt"` 로 뺍니다
    (52주 최저·최고 ← 「구간 내 위치」, 전일 종가 ← 「등락」). **열 번호로
    숨기지 말고** 머리 칸과 본문 칸에 같은 class 를 달아 쌍으로 사라지게
    합니다. 검증 배지 열은 마지막까지 남기십시오.
  - 확인은 눈으로 하지 말고 재십시오: 각 표의 `scrollWidth` 가 감싼
    `.table-wrap` 의 `clientWidth` 를 넘지 않아야 하고, 390px·360px 둘 다
    0이어야 합니다.
- **열이 두세 개뿐인 표를 넓은 화면에 그대로 두지 마십시오.** 표는 `width:100%`
  라 열이 적으면 이름 옆이 통째로 비어 보입니다. 「S&P500 업종 ETF」가 업종·
  등락률 두 열뿐이라 여백이 70%였고, 지적을 받았습니다. 빈 자리는 **데이터
  파일에 이미 있는 값**이나 **그 줄을 읽는 법**으로 채웁니다:
  - 종목·ETF 표 → 티커, 종가, 「핵심」·「대표 편입 종목」
  - 지수 표 → 「무엇을 담고 있는가」(구성·성격) 한 줄
  - 수급 표 → 같은 날 지수 종가·등락률·거래대금, 줄마다 「읽는 법」
  - 금리 표 → 정책금리 대비, 한미 금리차처럼 **표 안에서 계산되는 스프레드**
  - 설명 열은 `class="note opt"` 로 달아 휴대폰에서는 빠지게 합니다.
  - 채울 값이 없으면 열을 늘리지 말고 **표를 `compact` 로 두거나 옆 표와
    합치십시오.** 빈 「비고」 칸을 남기는 것이 가장 나쁩니다.
  - 재는 법: 각 칸의 글자 폭을 합쳐 표 너비와 견줍니다. **여백 25% 를 넘으면
    손봅니다.**
- CSS 를 미디어쿼리로 덮을 때 **선택자 우선순위와 순서를 확인하십시오.** 같은
  우선순위면 문서 뒤쪽 규칙이 이깁니다. `.vf{…}` 로 쓴 모바일 규칙이 뒤쪽의
  기본 `.vf` 정의에 밀려 아무 일도 하지 않던 적이 있습니다 —
  `table.data .vf{…}` 처럼 한 단계 구체적으로 씁니다.
  **미디어쿼리보다 뒤에 쓴 평범한 규칙도 같은 이유로 이깁니다.**
  `table.data.compact th,td{padding:8px 11px}` 가 좁은 화면 블록 **뒤에**
  있어서 360px 에서 여백이 줄지 않았고, 표 하나가 8px 넘쳤습니다. 전역
  규칙은 미디어쿼리 **앞에** 모아 두십시오.
- 확정된 투자 판단으로 단정하지 않습니다. 고객 응대 항목에는 "확정된 판단이
  아닙니다"로 시작하는 단서를 답니다.
- 문체는 한국어 존댓말 서술, 영문 병기.

## 6-1. 발행 직전 **한 번 더** — 재검증하고 최종본을 냅니다

**만들면서 도는 검사와 발행 직전에 도는 검사는 다른 것을 봅니다.**

만들면서 도는 것(폭 훑기·중복 줄·JS 오류·열 수)은 「만든 것이 **망가지지
않았나**」를 봅니다. 발행 직전에 한 번 더 도는 것은 「만든 것이 **서로
맞는가**」를 봅니다 — 표와 표, 표와 글, 글과 시세 파일이 어긋나는 자리입니다.
앞의 것이 통과해도 뒤의 것은 걸립니다. 8/20 장마감 판이 그랬습니다: 폭 넘침 0,
중복 0, 열 불일치 0 을 받은 파일에서 재검증기가 **음수를 ASCII 하이픈으로 적은
자리 하나와 판단이 필요한 세 가지**를 더 찾아냈습니다.

```bash
python3 scripts/recheck.py docs/briefings/<오늘 만든 파일>.html
python3 scripts/audit_numbers.py docs/briefings/<오늘 만든 파일>.html
```

**두 개를 다 돌리십시오. 겹치지 않습니다** — `audit_numbers.py` 는 「이름 옆
숫자」를 시세 파일과 맞춰 보고, `recheck.py` 는 구조와 파생 계산을 봅니다.

`recheck.py` 가 보는 것:

| 검사 | 잡는 사고 |
|---|---|
| 절 ↔ 목차 개수·순서, 절 번호 | 절을 더하고 목차를 안 고침 |
| 표의 머리행 ↔ 몸행 열 수, `opt` 짝 | 열이 하나 밀림 |
| 이름 칸 안의 같은 줄 두 번 | `inline_notes` 를 두 번 먹임 |
| `data-lang-ko` ↔ `data-lang-en` 개수 | 영문 모드에서 빈칸으로 보임 |
| ASCII 하이픈으로 적힌 음수 | `&minus;` 대신 `-` |
| 접는 상세 개수 | 요약 PDF 와 전체 PDF 가 같은 파일이 됨 |
| 사이드바 ↔ 인쇄용 「지난 브리핑」 개수, 현재 판 표시 | PDF 에 지난 판 길이 없음 |
| 상한가·하한가: 등락 종목 수 합계 ↔ 종목 명단 개수 | 두 페이지의 갱신 시각이 다름 |
| 미국 계열 날짜에 「전일 마감」 이름표가 있는지 | 하루가 어긋남 |
| 달러인덱스 ↔ 유로/달러 부호 | 24시간 통화쌍과 시각 기준이 다름 |
| 52주 위치·상승하락 비율 재계산 | 손으로 적은 파생 수치 |
| **꼬리말 작성일 ↔ 머리말 작성 시각 ↔ 파일 날짜** | 껍데기를 물려 쓰면서 안 고침 |
| **작성 시각이 지금보다 미래인지** | 예정 시각을 적음 |
| 본문이 절을 번호로 가리키는지 | 절이 늘면 조용히 어긋남 |

#### 작성 시각은 **두 군데**에 있습니다 — 그리고 시계에서 읽으십시오

머리말(`hero-meta`)에만 있는 것이 아니라 **꼬리말(`footer.foot`)에도** 있습니다.
꼬리말은 껍데기에서 물려받는 자리라 **고칠 생각이 나지 않습니다.** 8/20 모닝과
장마감 두 판이 8/19 판의 껍데기를 물려 쓰면서 「2026년 8월 19일(수) 07:45 KST
작성」을 달고 나갔습니다 — 머리말은 8/20 인데 꼬리말은 8/19 인, **한 문서에 작성
시각이 둘인** 상태였습니다.

그리고 **손으로 적지 마십시오.** 손으로 적으면 예정 시각을 적게 됩니다. 8/20 판
하나에서만 두 번 그랬습니다 — 07:58 로 적고 08:49 에 냈고, 19:30 으로 적고
19:27 에 냈습니다. 빌더에서 시계를 읽으십시오.

```python
NOW  = datetime.datetime.now(datetime.timezone(datetime.timedelta(hours=9)))
HHMM = NOW.strftime("%H:%M")
```

조립할 때 꼬리말의 국문·영문 두 줄을 **정규식으로 갈아 끼우고, 1개를 찾았는지
`assert` 로 확인**하십시오. 껍데기에 따라 가운뎃점이 `&middot;` 이기도 하고
`·` 이기도 하므로 둘 다 받습니다.

**FAIL 은 고칩니다. WARN 은 「고치거나, 판에 적거나」 둘 중 하나입니다** —
그냥 넘기지 마십시오. 8/20 장마감 판의 경고 셋은 모두 시세 자체의 성질이라
고칠 수 없는 것이었고, 그래서 검증 노트 (d)·(h)·(i) 로 판에 적었습니다.
**경고를 남긴 채 발행하려면 그 경고가 판의 어느 줄에 적혀 있는지 말할 수
있어야 합니다.**

### 최종본은 고친 **뒤에** 만듭니다

순서를 지키십시오. 고치고 → 다시 만들고 → 재검증이 오류 0 인 것을 보고 →
**그때 `make_outputs.sh` 를 돌립니다.** 먼저 만든 PDF 를 고친 뒤에도 그대로
보내면, 고객이 받는 파일만 옛 판입니다.

```
서술 파일 쓰기 (data/briefing/narrative-<날짜>.json)
      → python3 scripts/build_briefing.py
      → inline_notes → fold_perf → print_fit → build_archive_nav
      → 폭 훑기 · 중복 · JS · 열 수
      → recheck.py + audit_numbers.py + dupcheck.py + stale.py   ← 걸리면 위로
      → make_outputs.sh → SendUserFile → 아티팩트 → 커밋
```

**빌더를 고치는 것과 서술을 쓰는 것을 헷갈리지 마십시오.** 날마다 하는 일은 **서술 파일을
쓰는 것**이고, 빌더는 자료 구조가 바뀌었거나 절을 더할 때만 손댑니다(7절).

이미 파일을 보낸 뒤에 고칠 것이 나오면 **다시 만들어 다시 보내고, 「이것으로
바꿔 쓰십시오」라고 한 줄 붙이십시오.** 조용히 저장소만 고치면 고객 손에는
틀린 판이 남습니다.

#### 「이미 손봤다」는 말을 곧이듣지 마십시오

`print_fit.py` 는 예전에 **FIT_CSS 가 있는지**로 손본 판을 가려냈습니다. 그런데
껍데기(`_chrome_head.html`)를 지난 판에서 물려받으면 **CSS 만 딸려 와서** 정작
표에는 `keep` 이 한 개도 안 붙은 채 「이미 손봤다. 건너뜁니다」를 찍었습니다.
8/21 모닝과 8/22 해외 판이 그렇게 새어 나갔습니다 — 오류도 경고도 없이,
쪽 나눔만 조용히 나빠집니다.

이제는 `<!-- print-fit -->` 표시나 **실제로 붙은 `keep`·`flow` 클래스**가 있을
때만 건너뜁니다. 후처리를 돌린 뒤에는 **찍힌 숫자를 보십시오** — 「표 붙듦 N ·
카드 붙듦 M」이 전부 0 이면 정말로 안 붙은 것입니다.

```bash
grep -c 'class="data[^"]*keep' docs/briefings/<오늘 판>.html   # 0 이면 안 붙었다
```

같은 함정이 다른 후처리기에도 있습니다. **「무엇이 있으면 건너뛴다」의 그 무엇이
껍데기에 딸려 올 수 있는 것이면 안 됩니다.**

#### 스크래치패드의 일회용 스크립트가 표준 모듈을 가릴 수 있습니다

8/22 에 `scripts/fetch_market.py` 를 불러오기만 했는데 **8월 11일 판이
고쳐졌습니다.** 스크래치패드에 예전에 만든 `calendar.py` 가 있었고, 그것이
표준 `calendar` 모듈을 가로챈 것입니다. 파이썬은 실행한 스크립트가 있는
폴더를 `sys.path[0]` 에 넣으므로, 스크래치패드에서 스크립트를 돌리면 그
폴더의 `.py` 가 표준 모듈보다 먼저 잡힙니다. 그 `calendar.py` 는 **불러오는
것만으로 브리핑 파일을 고쳐 쓰는** 일회용 스크립트였습니다.

세 가지를 지키십시오.

1. 일회용 스크립트에 **표준 모듈 이름을 붙이지 마십시오** —
   `calendar` · `json` · `csv` · `types` · `select` · `time` · `math` 따위.
2. 일회용 스크립트는 **`if __name__ == "__main__":` 안에서만** 파일을
   고치게 하십시오. 불러오기만 해도 쓰기가 일어나면 안 됩니다.
3. **후처리를 돌린 뒤 `git status` 를 보십시오.** 오늘 손댈 이유가 없는
   파일이 목록에 있으면 거기서 멈추고 까닭을 찾으십시오.

## 7. 두 브리핑의 역할 — **10절 구조**

> **2026-08-27 개편.** 판이 너무 길고(19절·본문 108,000자·요약 PDF 34쪽) 절끼리 같은
> 말을 되풀이한다는 지적을 받아 **10절로 다시 짰습니다.** 목표는 본문 45,000자 안팎,
> **요약 PDF 12쪽 · 전체 PDF 15쪽**입니다. 옛 19절 구조로 돌아가지 마십시오.

### 판을 물려 짓지 마십시오 — 빌더가 있습니다

어제 파일을 복사해 고치는 방식이 글을 굳게 만든 원인이었습니다(7-2-1절).
그래서 **표·날짜 이름표·비율·개수·주도 종목을 전부 자료에서 만드는 빌더**를 두었습니다.

```bash
python3 scripts/build_briefing.py                      # 오늘 날짜, 모닝
python3 scripts/build_briefing.py --kind global        # 주말·휴장일
python3 scripts/build_briefing.py --date 2026-08-28    # 날짜를 박아서
```

| 파일 | 무엇 |
|---|---|
| `scripts/build_briefing.py` | 절을 짜고 조립합니다. **손대는 일이 드물어야 정상입니다** |
| `scripts/briefing_prepare.py` | 시세에서 파생값과 표를 전부 만듭니다 |
| `scripts/briefing_lib.py` | 서식·날짜·도표. **그날의 서술이 한 줄도 없습니다** |
| `docs/briefing-chrome/` | 껍데기(head·nav·tail)와 CSS. **저장소에 있습니다** |
| `data/briefing/narrative-<날짜>.json` | **그날 손으로 쓰는 것은 이 파일뿐입니다** |

**그날 할 일은 서술 파일을 쓰는 것입니다.** 견본은
`data/briefing/narrative-EXAMPLE.json` 에 있습니다. 키를 비우면 **어제 문장이 남는 것이
아니라** 자료에서 계산한 한 줄이 대신 나가고, 몇 개가 비었는지 검증 노트 (b) 에 숫자로
찍힙니다. 굳을 자리를 아예 없앤 것입니다.

**숫자를 문장에 손으로 적지 마십시오.** 표에 있는 값을 서술에 옮겨 적으면 다음 날
어긋납니다 — 그것이 8/26 판에서 「유가가 다시 밀고 있습니다」(실제로는 &minus;6.53%)를
만든 방식입니다.

### 절 열 개

| # | 절 | id | 담을 것 |
|---|---|---|---|
| 01 | 오늘의 결론 | `today` | 카드 6 + **오늘 09시에 들고 갈 것 셋**. 그날의 축만 |
| 02 | 국내 증시 | `korea` | 지수 · 시장의 폭(등락 종목 수·52주 위치를 **한 표로**) · 종목표 |
| 03 | 수급 · 증시 주변자금 | `flows` | 외국인/기관/개인 · 프로그램 · **예탁금·신용융자·펀드** · **매물대** |
| 04 | 간밤 해외 | `global` | **미국·유럽·아시아 지수를 한 표로** + 미국 종목표 |
| 05 | 실적 · 컨퍼런스콜 | `earnings` | 그날 실적을 낸 기업과 **컨콜 발언**. 없으면 없다고 적습니다 |
| 06 | 금리 · 환율 · 원자재 | `macro` | 셋을 한 절로. 곡선 전체와 달러 상대 통화는 접습니다 |
| 07 | **심층 분석** | `deep` | **조건부** — 큰 이벤트가 있는 날만(7-4절) |
| 08 | 일정 · 체크포인트 | `calendar` | 앞으로 2주 이상. **지난 줄은 스스로 빠집니다** |
| 09 | 고객 응대 | `talking` | 질문 넷. 이 판의 표에서 나온 숫자로만 |
| 10 | 데이터 · 검증 | `verify` | **대부분 접습니다.** 계보와 상시 유의사항 |

**절 번호는 손으로 매기지 않습니다** — 빌더가 문서 순서대로 다시 매기고 목차와 대조합니다.
**본문에서 다른 절을 번호로 가리키지 마십시오.** 이름으로 씁니다: 「(「수급」 절)」.

주말·휴장일에도 **같은 열 개**를 씁니다. 다만 02(국내)가 「되짚기」가 되고 04(해외)가 앞으로
나오며, 제목과 파일 이름이 「해외 증시 브리핑」·`<날짜>-global.html` 이 됩니다(0절).

### 무엇을 뺐는지 — 되돌리지 마십시오

| 뺀 것 | 왜 |
|---|---|
| 유럽 절 · 아시아 절 (따로) | 지수 한 표로 합치고 종목표는 접었습니다. 국내 개장 전에 개별 유럽 종목까지 읽을 사람은 없습니다 |
| 증권사 리포트 절 · 하우스 시각 절 | 05(실적·컨콜)와 07(심층)으로 갈랐습니다. **오늘 근거가 있는 인용만** 싣습니다 |
| 리스크 점검 절 | 09(응대) 안으로 넣었습니다 — 리스크는 고객에게 말할 때 쓰는 것입니다 |
| WM 업계 절 | 날마다 바뀌지 않아 100% 되풀이되던 자리입니다. 재료가 바뀐 날만 07(심층)에 싣습니다 |
| 출처 절 | 10(데이터·검증) 안의 계보 표로 합쳤습니다 |
| 종목 표의 가운데 종목들 | **위아래 여덟씩만** 싣습니다. 가운데는 그날을 설명하지 못합니다 |

### 압축의 규칙 넷

1. **같은 숫자를 두 절에 적지 마십시오.** 01 에서 쓴 값을 02 에서 다시 쓰지 않습니다.
   표가 말하는 것은 표에 맡기고, 꼬리말에는 **표가 말하지 못하는 것**만 적습니다.
2. **꼬리말은 「어떻게 읽는가」에만 씁니다.** 표의 숫자를 되읽는 꼬리말은 지웁니다.
3. **근거는 접습니다.** 추이 표, 만기 11개 곡선, 달러 상대 통화, 지역별 종목표, 검증 노트는
   `<details class="exp">` 안입니다. **상세가 하나도 없으면 두 PDF 가 같은 파일이 됩니다.**
4. **발행 전에 재십시오.** `python3 scripts/dupcheck.py <오늘> <어제>` 로 판 안 중복과
   지난 판 반복을 세고, 그 수를 검증 노트에 적습니다.

## 7-1. 사이드바 「지난 브리핑」

`docs/briefings/index.json` 이 발행 이력입니다. 사이드바 목록은 **이 파일에서
스크립트가 만듭니다.** 손으로 적지 마십시오.

```bash
python3 scripts/build_archive_nav.py --check   # 고칠 곳만 본다
python3 scripts/build_archive_nav.py           # 전체 판의 목록을 다시 만든다
```

스크립트는 `index.json` 을 읽어 각 판의 `<ul class="sidenav-dates">` 를 통째로
갈아 끼웁니다. 그 판의 날짜보다 **뒤에 나온 판은 넣지 않습니다** — 「지난」
브리핑이므로. 자기 자신은 `href="#" aria-current="page"`, 나머지는 그 날짜
전용 아티팩트 주소에 `target="_blank" rel="noopener"` 를 붙입니다. `url` 이
없는 항목만 `<li class="na">…보관본 없음</li>` 이 됩니다.

### 날짜를 잘라 걸지 마십시오

예전 지침은 「최근 4개」였습니다. **그게 잘못이었습니다.** 8/19 판에는 발행
이력 14건 중 4건만 걸려 있었고, 8/6~8/12 는 어느 판에서도 닿을 수 없었습니다.
목록은 **이력 전체**를 겁니다. 사이드바는 `max-height:calc(100vh - 48px)` 에
`overflow-y:auto` 라 길어져도 안에서 스크롤될 뿐 넘치지 않습니다 — 14 항목을
340~1920px 전 구간에서 확인했습니다.

### PDF 에도 같은 목록을 싣습니다

사이드바는 `@media print` 에서 `display:none` 입니다. 그래서 **PDF 에는 지난
판으로 가는 길이 하나도 없었습니다.** 스크립트가 `</main>` 앞에
`<!-- archive-print:start -->…<!-- archive-print:end -->` 블록을 함께 넣습니다 —
화면에서는 숨고 인쇄에서만 두 단으로 나옵니다. 날짜는 **PDF 안에서 눌리는
링크**로 남으므로 UUID 를 글자로 찍지 않습니다.

마지막 쪽은 원래 비므로 빈 띠 검사에서 마지막 쪽은 제외합니다.

### 하루에 한 주소 — 주소를 돌려쓰지 마십시오

예전 지침은 모닝을 늘 `dca66b4e-…` 에, 장마감을 늘 `5ebc6deb-…` 에 덮어쓰게
했습니다. 그래서 **어제 항목의 링크가 오늘 판을 열었습니다.** 실제로 8/19
판의 「08-14」는 8/19 아티팩트를 가리키고 있었습니다 — 앞판에서 목록을
베끼는 사이 같은 주소를 새 판이 덮었기 때문입니다.

**날짜마다 아티팩트를 따로 냅니다.** 보관본은 `<html>`·`<body>` 없는 아티팩트
본문이라 `docs/briefings/<날짜>-<판>.html` 을 그대로 다시 발행하면 됩니다.
`index.json` 의 `url` 을 `null` 로 바꾸는 일은 이제 없습니다.

발행한 뒤 이력을 갱신합니다. 빠뜨리면 다음 판의 사이드바에서 오늘 자료가
사라집니다.

1. 완성본을 `docs/briefings/<날짜>-<morning|close|global>.html` 로 복사합니다.
   세션 작업폴더는 컨테이너가 회수되면 지워지므로 저장소에 둬야 남습니다.
2. 그 파일을 **새 아티팩트로** 발행해 주소를 받습니다.
3. `index.json` 맨 앞에 `{date, session, title, label_ko, label_en, url, file}`
   한 줄을 추가합니다.
4. `python3 scripts/build_archive_nav.py` 를 돌립니다.
5. **목록이 바뀐 판을 전부 다시 발행합니다.** 파일 경로가 같으면 주소는
   그대로입니다. 이 단계를 건너뛰면 저장소만 맞고 화면은 옛 목록입니다.
6. 저장소에 커밋합니다.

### 파일로 건네는 것은 매 판의 마지막 단계입니다

아티팩트만으로 끝내지 마십시오. **모든 판은 단독 HTML 한 개와 PDF 두 개를
만들어 `SendUserFile` 로 보냅니다.** 한 줄이면 됩니다.

```bash
bash scripts/make_outputs.sh docs/briefings/2026-08-12-morning.html
```

`out/` 에 셋이 떨어집니다.

| 파일 | 쓰임 |
|---|---|
| `미래에셋_마포WM_모닝브리핑_20260812.html` | 그냥 열리는 문서. 언어 토글·펼치기·PDF 버튼이 그대로 동작합니다 |
| `..._요약.pdf` | 상세를 접은 **고객 전달용** |
| `..._전체.pdf` | 상세를 모두 펼친 **브리핑 준비용** |

**`<details class="exp">` 를 하나도 두지 않으면 두 PDF 가 같은 파일이 됩니다.**
8/20 판 첫 발행이 그랬습니다 — 「상세 0개 중 0개 펼침」이 찍히고 요약과 전체가
쪽수까지 똑같이 나왔습니다. 만든 뒤 스크립트가 찍는 **「상세 N개」가 0 이면
멈추고 접을 것을 찾으십시오.** 접기 좋은 것은 근거 표입니다 — 추이 표(등락 종목
수·투자자별 8거래일), 만기 11개짜리 재무부 곡선, 검증 노트의 데이터 계보.

스크립트가 알아서 하는 것:

- **한글 글꼴 설치.** 컨테이너에 `fonts-noto-cjk` 가 없으면 PDF 한글이
  중국어 글꼴(WenQuanYi)로 나옵니다. 없으면 설치합니다.
- **playwright 설치.** 브라우저는 `/opt/pw-browsers` 에 이미 있으므로
  내려받지 않습니다(`PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1`).
- **꼬리말 글꼴.** PDF 꼬리말은 본문과 별개의 렌더 문맥이라 페이지 CSS 가
  닿지 않습니다. `to_pdf.mjs` 안에서 따로 지정합니다.

`out/` 은 `.gitignore` 에 있습니다. **컨테이너는 회수되므로 만든 파일은 같은
세션에서 반드시 보내십시오** — 저장소에는 보관본 HTML 만 남고 PDF 는 남지
않습니다. 다시 필요하면 위 명령을 다시 돌리면 같은 것이 나옵니다.

`SendUserFile` 은 HTML 에 `display: "render"`, PDF 는 그대로 둡니다.

## 7-2. 「일정 · 체크포인트」는 앞을 보는 표입니다

**정기적으로 되풀이되는 시각은 일정이 아닙니다.** 「오늘 09:00 국내 증시 개장」,
「오늘 22:30 미국 증시 개장」을 일정표에 넣었다가 지적을 받았습니다 — 매일
같은 시각에 열리는 것은 읽는 사람이 이미 압니다. 이 표에는 **날짜가 정해져
있고 시장을 움직일 수 있는 것**만 넣습니다.

- **기간은 최소 2주**, 가능하면 3주까지 봅니다. 오늘 하루만 적지 마십시오.
- 넣을 것: 지표 발표(CPI·PPI·소매판매·PCE·고용), 중앙은행 회의(FOMC·금통위)와
  의사록, **휴장일**, 지수 정기변경(MSCI)과 옵션·선물 만기, 큰 종목의 실적,
  잭슨홀 같은 정례 행사, 국내 수출입 속보.
- 뺄 것: 개장·마감 시각, 매일 나오는 집계, 이미 지나간 일.
- **휴장일을 빠뜨리지 마십시오.** 국내가 하루 쉬면 그 사이 미국이 몇 번
  마감하는지, 재개장 아침에 며칠치를 한꺼번에 받는지까지 적습니다.
  2026-08-17(월)은 광복절 대체공휴일 휴장이고, 국내는 8/14(금) 마감 뒤
  8/18(화)에 열어 **미국 이틀치를 한꺼번에** 받습니다.
- 열은 `일시(KST) / 구분 / 일정 / 보는 법`. 「구분」은 한국·미국·기업으로
  갈라 두면 훑기 쉽습니다.
- **날짜는 검색으로 확인하고 배지를 답니다.** 서로 다른 두 곳 이상이 일치하면
  `vf ok` + 2 SOURCES, 한 곳뿐이면 `vf solo` + 1 SOURCE. 3절 규칙 그대로입니다.
- **결과를 미리 적지 마십시오.** 컨센서스와 전망은 "전망일 뿐 결과가 아닙니다"를
  붙여 적고, 발표된 것처럼 쓰지 않습니다.
- 시각은 한국시간으로 환산해 적습니다. 미 지표 08:30 ET → 21:30 KST(서머타임),
  FOMC 의사록 14:00 ET → 다음 날 03:00 KST, 미국 장 마감 후 실적 → 국내 새벽.

## 7-2-1. 판을 물려 지으면 **글이 먼저 굳습니다**

표는 자료에서 나오므로 날마다 바뀌지만, **손으로 쓴 문장은 그대로 굴러갑니다.**
어제 판을 복사해 오늘 판을 짓는 방식이라 이 격차가 판마다 쌓입니다. 8/26 판에서
세어 보니 **판 안에서 글자까지 같은 문장이 18곳, 어제 판과 같은 문장이 45%**
였습니다. 발행 전에 아래 넷을 재십시오.

### ① 판 안에서 겹치는 문장을 셉니다

문장 단위로 잘라 그대로 겹치는 것을 셉니다. **표 머리글 말고는 0 이 정상**입니다.

- **기사 본문을 그대로 뜨지 마십시오.** 「앞에서 250자」는 거의 언제나 사진
  설명과 기자 서명입니다 — 「코스피가 215.99포인트(3.12%) 내린 6696.96로 장을
  마감한 24일 오후 서울 중구 하나은행 본점 딜링룸에서…」, 「수원=임세준 기자
  [헤럴드경제=문이림 기자]」. 게다가 기사 앞머리는 어느 기사나 그날 지수
  이야기라 **카드끼리 같은 말이 겹칩니다.** 8/26 판의 중복 18곳 가운데 15곳이
  여기서 났습니다. 사진 설명·서명·소제목을 걷어내고 **주인공이 나오는 문장**만
  골라 오십시오.
- **같은 숫자를 여러 절에 다시 적지 마십시오.** 엔비디아·AMD·마이크론 등락률이
  머리·03·07·09 에 그대로 네 번 나왔습니다. **표가 말하는 것은 표에 맡기고**,
  꼬리말에는 표가 말하지 못하는 것만 적습니다.
- **두 절이 같은 말을 하면 하나를 바꾸십시오.** 14 절 리스크 카드가 09 절 이슈
  카드와 같은 말(「주주환원이지 업황이 아니다 → 엔비디아가 답을 준다」)을 하고
  있었습니다. 리스크 절은 **리스크**를 적는 자리입니다.

### ② 인용은 **말한 날**을 달고 다니게 합니다

8/26 판의 인용 카드 16장 가운데 **오늘 수집분에 근거가 있는 것이 하나도
없었습니다** — 전부 8/21~8/23 것을 물려받은 것이었습니다.

- 겹치는 것을 몰래 지우지 말고 **이름 옆에 말한 날을 붙여 드러내십시오.** 오늘
  것이 앞에 서고, 물려받은 것은 날짜가 붙습니다.
- **날짜는 짐작하지 말고 보관본을 뒤져** 그 말이 처음 실린 판을 찾습니다
  (`grep -l "<특징적인 구절>" docs/briefings/2026-*.html | sort | head -1`).
- 머리말에 **오늘 새로 확인된 것 N건 / 이어 온 것 M건**을 적습니다. 오늘 것이
  0 이면 그렇다고 적고 `vf none` 을 답니다 — 없는 것을 지어내지 않습니다.
- 같은 논지가 겹치는 카드는 뺍니다. 뺐다는 사실도 적습니다.
- **날마다 바뀌지 않는 절**(WM 응대 재료, 데이터 계보)은 그대로 두되, **날마다
  바뀌는 자리가 아니라는 것을 머리말에 적으십시오.** 숨기면 굳은 것으로 읽힙니다.

### ③ 지난 날짜를 앞일처럼 적고 있지 않은지 봅니다

일정표가 제일 먼저 굳습니다. 8/26 판의 일정표 첫 줄이 **사흘째 「오늘 8/24
(월)」** 이었습니다.

- 「오늘」 줄은 **시계에서 만드십시오** — 문자열로 적으면 반드시 굳습니다.
- 일정표는 날짜 칸을 읽어 **오늘보다 앞선 줄이 스스로 빠지게** 하십시오.
- 「나흘에 넷」처럼 **개수를 세는 말**은 날이 지나면 틀립니다. 남은 날로 다시
  세십시오. 이미 끝난 입찰·발표를 앞일에서 빼십시오.
- 「지난주」·「내일」·「이번 주」·요일 이름을 모두 훑어 오늘 기준으로 맞는지
  하나씩 보십시오.

### ④ 방향을 말하는 문장이 자료와 어긋나지 않는지 봅니다

4-3 절의 「표는 자료에서 나오고 글은 안 나온다」가 **제목에서 가장 크게**
터집니다. 8/26 판에서 이렇게 나갔습니다.

| 굳어 있던 문장 | 그날 자료 |
|---|---|
| 「유가가 인플레이션 쪽에서 다시 밀고 있습니다」 | 브렌트 **−6.53%** |
| 「반도체가 반등장에서 빠졌습니다」 | SOX **+1.44%**, 엔비디아 **+2.19%** |
| 「지수는 +0.88% 인데 오른 종목은 넷 중 하나뿐」 | 25일은 **647 대 226** |

- **비율·개수를 손으로 쓰지 마십시오.** 「넷 중 하나」는 반드시 뒤집힙니다.
- **날짜 뒤에 살아 있는 값을 붙이지 마십시오.** 「24일 SOX 는 `I["sox"]
  ["change_pct"]`」는 날짜만 멈추고 숫자는 날마다 바뀝니다.
- **한글과 영문이 서로 다른 숫자를 말하고 있지 않은지** 보십시오. 같은 카드에서
  한글은 「마이크론 −5.8%」, 영문은 「Micron 0.77%」였습니다. 둘 다 자료에서
  읽게 하면 어긋날 수 없습니다.
- **판 안에서 같은 말이 두 가지 자로 재어져 있지 않은지** 보십시오. 머리말의
  주간 −2.46% 는 8/21 종가 대비이고 표의 「1주」 열 −1.85% 는 최근 5거래일
  기준이었습니다. **자가 다르면 자가 다르다고 적으십시오** — 설명이 없으면 읽는
  쪽은 하나가 틀렸다고 봅니다.
- **오늘 자료에 없는 값과 견주지 마십시오.** 각주 하나가 「표의 브렌트와 보도의
  94달러대」를 견주고 있었는데, 그날 브렌트는 86달러였습니다.

### 무엇을 걷어냈는지 검증 노트에 적습니다

숫자로 적으십시오 — 「판 안 중복 18곳 → 0곳, 어제 판과 겹치는 문장 45% → 37%」.
고쳤다는 말보다 **얼마나 고쳤는지**가 다음 판의 기준이 됩니다.

## 7-3. 해외 증시 브리핑 (주말 · 휴장일)

국내 장이 열리지 않는 날 아침 Routine이 만드는 판입니다. favicon 은 모닝과 같은
📈 이고, **아티팩트 주소는 날짜마다 새로 냅니다**(7-1절).

**절 구성은 모닝과 같은 열 개입니다**(7절). 「모닝에서 국내를 뺀 것」이 아니라
**순서만 바꿉니다** — 읽는 사람은 다음 국내 거래일을 준비하는 사람이므로:

```bash
python3 scripts/build_briefing.py --kind global
```

| 바뀌는 것 | 어떻게 |
|---|---|
| 02 국내 증시 | **「국내 증시 되짚기」** 로 이름을 바꾸고 **직전 거래일** 마감을 담습니다 |
| 04 간밤 해외 | **앞으로 나옵니다** — 01 다음이 해외입니다 |
| 08 일정 | **다음 국내 거래일이 언제이고 며칠치를 한꺼번에 받는지**를 맨 앞 줄에 |
| 제목 · 파일 | 「해외 증시 브리핑」 · `<날짜>-global.html` |

**10번에 재개장 산수를 반드시 적습니다.** 다음 국내 거래일이 언제인지, 그 사이 미국이
몇 번 마감하는지, 재개장 아침이 며칠치를 한꺼번에 받는지까지 씁니다.

**날짜를 헷갈리지 마십시오.** 토요일 아침 판의 기준은 **금요일 미국 마감**(한국시간
토요일 새벽 05:00)과 **금요일 국내 마감**입니다. 아시아·유럽은 금요일 현지 마감이고,
미국 지표가 21:30 KST 에 나왔다면 **아시아는 그것을 모르는 상태로 거래를 끝냈습니다**(4-1절).

**해외 휴장일 표는 08절 안에 둡니다.** 앞으로 넉 달치를 뉴욕·도쿄·홍콩·상하이/선전·
런던/유럽 기준으로 싣고 **국내 휴장일도 참고로 함께** 적어 겹치는 구간이 보이게 합니다.
조기마감도 적습니다. 배지는 `1 SOURCE` 이고, **거래소가 나중에 바꾸므로 주문 직전
재확인하라**는 문구를 꼬리말에 반드시 답니다.

### 환율은 표 둘로 가릅니다

한 표에 몰면 부호를 읽는 법이 뒤섞입니다. **원/달러가 내려가면 원화 강세이지만
달러/엔이 내려가면 달러 약세**입니다. 그래서 「원화 환율」과 「달러 상대 통화」를
갈라 세우고, 각 표의 꼬리말에 부호 읽는 법을 적습니다. 「달러 상대」 표 안에서도
`유로/달러`·`파운드/달러` 두 줄만 표기 순서가 뒤집히므로 **맨 뒤로 몰아 두고 그
줄에만 「여기만 반대입니다」를 답니다.**

기간 열은 두 표 모두 `%` 입니다 — 환율은 가격이므로 bp 가 아닙니다.

#### 「통화쌍」 머리말 아래에 지수를 넣지 마십시오

**달러인덱스는 통화쌍이 아닙니다.** 주요 6개 통화를 묶어 만든 **지수**라 「무엇 대
무엇」이 없습니다. 그런데 「달러 상대 통화」 표의 첫 줄이 달러인덱스이므로, 이 표의
첫 열 머리말을 `통화쌍` 으로 달면 **머리말이 첫 줄과 어긋납니다.** 8/20 장마감 판이
그랬습니다.

- 「원화 환율」 표 → 첫 열은 **`통화쌍`**. 여섯 줄 모두 진짜 통화쌍입니다.
- 「달러 상대 통화」 표 → 첫 열은 **`통화쌍 · 지수`**. 꼬리말에 「맨 윗줄만 통화쌍이
  아닙니다」를 적습니다.

**용어는 처음 나올 때 한 번 풀어 주십시오.** 「통화쌍 = 두 통화를 맞바꾸는 비율,
원/달러 1,393 은 달러 1개를 사는 데 원화 1,393원이 든다는 뜻」 한 문장이면 됩니다.
이 한 줄이 「내려가면 원화가 세진 것」이라는 뒤 문장의 근거가 됩니다.

#### 두 표의 **빗금이 서로 반대**입니다 — 이 사실을 적으십시오

「유로/달러가 올라가면 달러가 약해진 것」은 **맞는 말입니다.** 다만 왜 맞는지를
적지 않으면 읽는 사람이 앞 표의 규칙으로 뒤 표를 읽다가 뒤집어 해석합니다.
실제로 그 질문을 받았습니다.

| 표 | 빗금 규칙 | 예 |
|---|---|---|
| 원화 환율 | **뒤** 통화가 1개 (국내 관행) | 원/달러 1,393 = **달러** 1개가 1,393원 |
| 달러 상대 통화 | **앞** 통화가 1개 (국제 관행) | 달러/엔 159 = **달러** 1개가 159엔<br>유로/달러 1.169 = **유로** 1개가 1.169달러 |

그래서 「달러 상대 통화」 표에서는 **달러가 앞이면 숫자↑ = 달러 강세**,
**달러가 뒤인 유로/달러·파운드/달러만 숫자↑ = 달러 약세**입니다. 두 줄에만
「여기만 반대입니다」를 다는 것으로는 부족하고, **「빗금 앞이 1개」라는 규칙과
「위 표는 반대」라는 사실**을 꼬리말에 함께 적으십시오.

검산은 간단합니다 &mdash; 유로/달러가 1.169 인데 「달러 1개가 1.169유로」로 읽으면
유로 1개가 0.86달러라는 뜻이 되어 현실과 어긋납니다. **값을 뒤집어 봐서 말이 되는
쪽이 옳은 읽기입니다.**

#### 달러인덱스는 다른 시계로 돕니다

**국내 마감 시각에 달러인덱스는 갱신되어 있지 않습니다.** 미국 장중에만 움직이는
지수이기 때문입니다. 그래서 장마감 판에서 **유로/달러는 +0.99% 인데 달러인덱스는
&minus;0.07%** 로 찍히는 일이 생깁니다 — 유로가 지수의 절반 이상인데 산술이 맞지
않습니다. 틀린 값이 아니라 **시각 기준이 다른 값**입니다.

- 방향은 **달러인덱스가 아니라 개별 통화쌍**으로 읽으십시오.
- 「간밤 달러인덱스 0.85% 하락」 같은 보도 수치를 쓸 때는 **간밤임을 명시**하고
  표의 등락률 칸과 헷갈리지 않게 하십시오.
- `recheck.py` 가 이 어긋남을 자동으로 잡습니다(WARN).

### 등락 사유는 확인된 것만 답니다

종목 표의 이름 칸에 그날의 사유를 한 줄 붙입니다(`<span class="why">`). **지수를 따라
움직였을 뿐인 종목에 그럴듯한 이야기를 붙이면 그 자체가 틀린 정보입니다.** 못 찾은
종목은 **비워 두십시오** — 열두 종목 중 여섯만 채워도 됩니다. 각 줄에는 배지를 답니다.

### 증권사 리포트 요약 — `news.articles` 에서 뽑습니다

**검색으로 찾지 마십시오.** 증권사 리서치 목록 페이지는 JS 렌더링이라 비어 있고,
검색 요약은 애널리스트 이름을 자주 틀립니다. 수집기가 받아 둔 **기사 본문**에
`○○증권 ○○○ 연구원` 형태로 실명 코멘트가 그대로 들어 있습니다.

```python
BROKER = re.compile(r'(미래에셋|삼성|한국투자|NH투자|KB|신한투자|하나|키움|메리츠|대신|유안타|IBK|현대차|iM|LS|다올|한화|교보|SK)증권')
ANAL   = re.compile(r'[^.\n]{0,140}?(?:연구원|애널리스트|센터장|본부장)[^.\n]{0,220}')
```

- 배지는 **`1 SOURCE`** 입니다. 리포트 원문이 아니라 기사에 실린 대목입니다.
- **목표주가·투자의견은 적지 마십시오** — 기사에 실린 것만으로는 확인이 안 됩니다.
- 컨센서스와 크게 어긋나는 전망치는 **그대로 인용하지 말고 그 사실을 적으십시오.**
- 고객에게 전할 문장 형태(「○○증권 ○○○ 연구원은 …라고 했습니다」)를 절 머리에 답니다.
- 「요지」 열은 **`note` 로 달지 마십시오.** 이 표의 본론이라 이름 밑으로 접히면
  표 오른쪽이 통째로 빕니다. `wrap` 으로 세웁니다.

### 해외 휴장일 표는 일정 절 안에 둡니다

앞으로 넉 달치를 뉴욕 · 도쿄 · 홍콩 · 상하이/선전 · 런던/유럽 기준으로 싣고,
**국내 휴장일도 참고로 함께** 적어 겹치는 구간이 보이게 합니다. 조기마감도 적습니다
(추수감사절 다음 날, 크리스마스 이브). 배지는 `1 SOURCE` 이고, **거래소가 나중에
바꾸므로 주문 직전 재확인하라**는 문구를 꼬리말에 반드시 답니다.

**종목 표 다섯 개는 그대로 다 넣습니다**(4-1절). 국내 표는 08번에 들어갑니다.

**「지역별 요약」 카드를 빠뜨리지 마십시오.** 표가 다섯 개로 늘면 숫자는 충분한데
"그래서 어느 지역이 어땠나"를 한 번에 볼 자리가 없어집니다. 01번 핵심 카드 바로
아래에 `views` 그리드로 **미국·유럽·일본·중국** 넉 장을 놓고, 각 카드는 대표 지수
등락 · 그날의 주도·부진 종목 · 한 줄 해석으로 구성합니다. **숫자는 손으로 적지 말고
시세 파일에서 계산하십시오** — 손으로 적으면 아래 표와 어긋납니다.

**날짜를 헷갈리지 마십시오.** 토요일 아침에 만드는 판의 기준은 **금요일 미국 마감**
(한국시간 토요일 새벽 05:00 마감)과 **금요일 국내 마감**입니다. 아시아·유럽은 금요일
현지 마감이고, 미국 지표가 21:30 KST 에 나왔다면 **아시아는 그것을 모르는 상태로
거래를 끝냈습니다**(4-1절).

**10번에 재개장 산수를 반드시 적습니다.** 다음 국내 거래일이 언제인지, 그 사이
미국이 몇 번 마감하는지, 재개장 아침이 며칠치를 한꺼번에 받는지까지 씁니다.
2026-08-15(토) 판이라면 — 국내는 8/14(금) 마감 뒤 **8/17(월) 대체공휴일**을 건너뛰고
**8/18(화)** 에 열어 **미국 8/14·8/17 이틀치**를 한꺼번에 받습니다.

## 7-4. 심층 분석 절 — **큰 이벤트가 있는 날만**

날마다 넣는 절이 아닙니다. 넣으면 **분량이 늘고 되풀이가 생깁니다.** 아래에 해당하는 날만
서술 파일에 `deep` 키를 채우십시오. 키가 없으면 절 자체가 실리지 않습니다.

**넣는 날**

- 시가총액 상위 기업의 **분기 실적과 컨퍼런스콜**(엔비디아·삼성전자·SK하이닉스·TSMC 등)
- **중앙은행 결정**(금통위·FOMC)과 의장 회견
- **큰 지표**(CPI·PCE·고용)가 예상과 크게 갈린 날
- **정책·규제**가 특정 업종을 통째로 움직인 날
- 지수가 하루 **±3% 이상** 움직인 날 — 그날은 「왜」가 본론입니다

**구성은 넷입니다.** 무엇이 나왔나 → 왜 시장이 그렇게 반응했나 → **국내에는 어떻게 닿나**
→ 무엇이 아직 답해지지 않았나. **세 번째가 이 절을 두는 이유입니다** — 국내 계좌에 닿지
않는 심층 분석은 싣지 않습니다.

**시세는 「무엇이」를 말하지만 「왜」는 말하지 않습니다**(4-3절). 이 절을 쓸 생각이면
반드시 `news.articles` 의 본문을 먼저 여십시오. 수집기가 실적 대목을 골라 둔 것이
`earnings.items` 에 있고, 컨퍼런스콜 발언은 `call_quotes` 에 따로 있습니다.

**전망을 결과처럼 쓰지 마십시오.** 컨센서스는 「전망일 뿐 결과가 아닙니다」를 붙입니다.

## 7-5. 수급과 **증시 주변자금** — 03절

「외국인이 얼마 샀다」만으로는 응대가 안 됩니다. 03절은 **돈이 어디에 있고 어디로
가는지**를 한 자리에 모읍니다.

- **수급은 잔액이 아니라 변화로 읽으십시오.** 8/26 이 그랬습니다 — 외국인이 산 것이
  아니라 **팔던 것을 멈춘 것**(&minus;3.8조 → &minus;1,148억)만으로 지수가 올랐습니다.
  서술에는 **전날·전전날과 나란히** 놓으십시오.
- **증감은 `*_delta` 를 씁니다.** `*_chg` 는 네이버가 준 부호 없는 절대값이라 감소를
  증가로 읽습니다(1절).
- **고객예탁금은 「살 힘」, 신용융자는 「빌린 힘」**입니다. 둘을 같이 놓아야 뜻이 생깁니다.
  결제일 기준이라 종가일보다 1~2영업일 늦으니 **반드시 날짜를 함께** 적습니다.
- **선물 외국인은 못 받습니다.** 프로그램 비차익(`program_trading.non_arb`)을 대용으로
  쓰고 그 사실을 적습니다.
- **10영업일 흐름은 스파크라인으로** 보입니다. 세로 축은 줄마다 따로 맞추므로
  **높이를 줄끼리 견주지 말라**고 꼬리말에 적으십시오.

### 매물대는 **근사입니다** — 그렇게 적으십시오

가격대별 거래량 분포를 주는 무료 원천이 없습니다. 수집기의 `supply_bands` 는 일별
**(종가, 거래대금)을 지수대 여섯으로 묶어** 「최근 어느 구간에서 손이 바뀌었나」를 냅니다.

- 가장 두꺼운 구간과 **현재가 위에 쌓인 비중**(`overhead_share_pct`)까지 계산돼 있습니다.
  위가 두꺼우면 올라갈 때 **본전에 팔려는 물량**을 만납니다 — 그 말까지가 이 표의 한계입니다.
- **「몇 주가 물려 있다」로 읽지 마십시오.** 진짜 매물대가 아닙니다. 검증 노트 (c) 에
  근사임을 적어 두었고, 그 문장을 지우지 마십시오.

## 7-6. 실적 · 컨퍼런스콜 — 05절

**검색으로 찾지 마십시오.** 수집기가 그날 기사 본문에서 회사 이름과 실적 표현이 같은
문장에 있는 대목을 뽑아 `earnings.items` 에 담아 둡니다.

- **문장을 그대로 씁니다.** 요약하지 말고 원문을 인용하십시오. 배지는 `1 SOURCE` 입니다.
- **상회/하회 판정은 기사에 그 말이 있을 때만** 답니다. 컨센서스를 다시 계산하지 않습니다.
- **컨퍼런스콜이 이 절의 본론입니다.** 분기 숫자는 하루면 값에 들어가지만, 콜에서 나온
  **가이던스**는 몇 분기를 갑니다. 8/27 판이 그 예입니다 — 엔비디아 주가를 돌려세운 것은
  매출이 아니라 CFO 가 콜에서 말한 **2028회계연도 70% 성장**이었고, 실적 직후에는 오히려
  &minus;1.27% 였습니다.
- **미국 종목 표는 정규장 마감 값**이라 장 마감 뒤 실적이 들어 있지 않습니다. 그 사실을
  04절 꼬리말에 적고, **05절과 함께 보라**고 안내하십시오.
- 실적이 없는 날은 **없다고 적습니다** — `NOT FOUND` 를 달고 지어내지 않습니다.

**(g) 를 쓸 때 주의 —** 수집 서버가 도입된 뒤로 "브리핑 수치는 전부 웹 검색에서
나온다", "업종별 등락률·등락 종목 수·금리는 구조적으로 채울 수 없다", "관리자
허용 목록 변경이 필요하다" 는 **모두 사실이 아닙니다.** 그렇게 쓰지 마십시오.
정확히는 이렇습니다 — 브리핑 세션은 시세 사이트에 직접 붙지 못하지만, 정책
바깥에서 도는 수집 서버가 대신 받아 저장소에 커밋하므로 **허용 목록 변경 없이도
시세가 확보됩니다.** 이그레스 차단은 수집 서버를 따로 두는 *이유*로만 언급하고,
브리핑의 *한계*로 서술하지 마십시오.

(h) **아직 받지 못하는 항목** — 항목 / 이유 / 현재 대응 / 해결 방법을 표로.
    **현재 시세 항목 중 미확보는 없습니다.** 선물 외국인 순매수까지 들어옵니다
    (`futures`). "선물은 유료 단말이 필요하다", "KRX 가 막아서 못 받는다" 는
    **더 이상 사실이 아닙니다.** 그렇게 쓰지 마십시오.

    반대매매 금액만 어느 시세 화면에도 없어 `news` 의 기사 원문에서 뽑습니다.
    국고채 만기별·상한가 종목명·15:30 시점 유가금·신용융자 잔고·고객예탁금
    ·국내 지표 공표일정·선물 투자자별은 모두 해결됐습니다.

    KRX 공식 오픈API(`data-dbg.krx.co.kr`)는 여전히 **401(인증키 없음)** 입니다.
    막힌 것이 아니라 등록이 안 된 것이고, 무료 키 한 장이면 열립니다.
    지금은 없어도 되지만, 키를 저장소 시크릿(`KRX_AUTH_KEY`)에 넣으면
    선물 항목이 <span class="vf solo">1 SOURCE</span> 에서
    <span class="vf ok">2 SOURCES</span> 로 올라갑니다.

    금투협 freeSis 는 **쓰지 마십시오.** 화면이 exbuilder SPA 라 조회 규격이
    드러나지 않고, 응답은 오는데 값이 전부 null 로 돌아옵니다. 같은 수치를
    네이버 증시자금동향에서 표로 받는 편이 확실합니다.

이전 판의 수치를 정정했다면 "정정" 카드를 검증 노트 맨 앞에 둡니다.

## 10. 살아 있는 예약 — 어느 것이 도는가

예약이 여러 벌 쌓이면 어느 것이 오늘 아침을 만든 것인지 알 수 없게 됩니다.
실제로 모닝 예약이 세 벌, ELS 예약이 세 벌 있었습니다. **현재 도는 것은 셋뿐**이고,
나머지는 이름 앞에 `[폐기]` 를 붙여 꺼 두었습니다.

| 예약 | 주기 (KST) | 하는 일 | 결과를 받는 곳 |
|---|---|---|---|
| 마포WM 모닝 브리핑 — 현행 | **매일** 07:30 | 거래일이면 모닝, 주말·휴장일이면 해외 판 | **모닝 전용 창** (파이프라인을 만든 대화) |
| 마포WM 장마감 시황 브리핑 — 전용 창 | 평일 16:10 | 장마감 브리핑 | **장마감 전용 창** (`session_01JWC6C7hm…`) |
| ELS 상품 구조 페이지 주간 갱신 — 현행 | 월 08:00 | `data/els.js` 재수집 | 새 세션 |

### 두 브리핑은 **창을 갈라** 씁니다

모닝과 장마감은 **서로 다른 고정 창**으로 들어옵니다. 한 창에 몰면 하루에 두 번
긴 작업이 쌓여 맥락이 뒤섞이고, 어느 판의 이야기인지 헷갈립니다.

장마감은 원래 **매번 새 창**을 만들어 돌았습니다. **그게 잘못이었습니다** —
8/20 16:10 실행분이 어딘가에서 돌고 산출물을 남기지 못했는데, 사용자는 그 창을
열어 볼 일이 없으니 **아무 일도 없었던 것처럼 보였습니다.** 그래서 장마감에도
자기 창을 하나 만들어 붙였습니다. 매일 같은 창으로 들어오므로 실행이 실패해도
바로 보입니다.

**주의: `update_trigger` 로는 창을 바꿀 수 없습니다.** 그 도구에는
`persistent_session_id` 항목이 없어 조용히 무시됩니다(이름만 바뀝니다). 창을
옮기려면 `create_trigger` 로 **새로 만들고** 옛 것을 꺼야 합니다.

이름에 `— 현행` 또는 `— 전용 창` 이 붙은 것만 켜져 있습니다. **프롬프트만 바꿀
때는** 삭제하고 다시 만들지 말고 `update_trigger` 로 그 예약의 프롬프트만
바꾸십시오 — 실행 이력이 남고, 사본이 늘지 않습니다.

**예약문과 이 문서가 어긋나면 이 문서가 이깁니다.** 예약문에는 「빠뜨리면 안 되는
것」만 추려 두었고, 세부는 여기에 있습니다. 그래서 예약문 첫머리가 늘
「`docs/briefing-playbook.md` 를 처음부터 끝까지 다시 읽으십시오」로 시작합니다.
반대로 여기서 규칙을 바꾸었는데 예약문이 옛 규칙을 그대로 시키고 있으면 —
8/20 아침의 「같은 아티팩트를 덮어쓰십시오」가 그랬습니다 — 예약문도 같이
고쳐야 합니다. 지침만 고치면 내일 아침이 어제 규칙으로 돌아갑니다.
