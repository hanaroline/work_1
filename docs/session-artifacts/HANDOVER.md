# 인수인계 — 새 클로드 계정에서 이어가기

이 문서는 **클로드 유료 계정을 바꿀 때** 무엇이 따라오고 무엇이 사라지는지, 그리고
새 계정에서 이 작업을 어떻게 이어붙이는지 적은 것입니다.
기준 2026-10-01 · 저장소 `hanaroline/work_1`

## 1. 무엇이 남고 무엇이 사라지는가

가장 먼저 알아야 할 것입니다. **계정을 바꾸면 아티팩트 링크는 전부 끊깁니다.**

| 항목 | 새 계정으로 계승 | 비고 |
|---|---|---|
| GitHub 저장소 — 코드·데이터·생성기·이 문서 | **된다** | 계정과 무관하게 GitHub 에 남습니다 |
| 각 화면의 원본 HTML·빌드 스크립트 | **된다** | 아래 2절의 표가 어느 가지에 있는지 알려 줍니다 |
| 아티팩트(지금까지 올린 70여 개 링크) | **안 된다** | 아티팩트는 계정 소유입니다. 새 계정에서 열 수 없습니다 |
| 대화 기록·과거 프롬프트 | **안 된다** | 이 문서와 `PROMPTS.md` 가 그 대체물입니다 |
| 예약 작업(Routine) | **안 된다** | 새 계정에서 다시 만들어야 합니다. 프롬프트는 `PROMPTS.md` 에 있습니다 |
| 커넥터·스킬 설정 | **안 된다** | 다시 연결해야 합니다 |
| GitHub Actions 워크플로(수집·빌드) | **된다** | 저장소에 있고 계정과 무관하게 돕니다 |

즉 **자료는 다 살아 있고, 링크만 다시 만들면 됩니다.** 모든 화면은 저장소의
생성기로 다시 만들 수 있으므로, 새 계정에서 아래 3절의 순서대로 한 번 돌리면
자료실이 복구됩니다.

### 계정을 닫기 전에 해 두면 좋은 것

1. 지금 쓰는 계정에서 **자료실 색인 아티팩트를 PDF 로 저장**해 두십시오.
   어떤 산출물이 있었는지, 설명이 무엇이었는지가 한 장에 남습니다.
2. 부서에 이미 돌린 링크가 있다면, **끊긴다는 사실을 미리 알리십시오.**
   새 링크를 만든 뒤 다시 돌리면 됩니다.
3. 개별 고객 자료가 담긴 아티팩트(`은퇴자산 운용 제안서`)는 계정과 함께
   사라지는 편이 낫습니다. 따로 보존하지 마십시오.

## 3. 새 계정에서 자료실을 되살리는 순서

```
1. 새 계정에서 GitHub 연동 → hanaroline/work_1 을 붙인다
2. git checkout claude/organize-session-artifacts-fbg82m
3. docs/session-artifacts/tools/ 의 생성기로 각 화면을 다시 만든다
4. 만든 파일을 하나씩 아티팩트로 올린다 (새 URL 이 생긴다)
5. build_hub.py 의 GROUPS 에서 uid 를 새 URL 로 갈아 끼운다
6. python3 build_hub.py && python3 make_index_md.py
7. 색인 아티팩트를 새로 올리고, README.md 를 커밋·푸시한다
8. PROMPTS.md 의 예약 작업 프롬프트로 Routine 을 다시 만든다
```

### 생성기

`docs/session-artifacts/tools/` 안에 있습니다.

| 파일 | 하는 일 |
|---|---|
| `build_hub.py` | 색인 아티팩트(`pages/hub.html`)를 만든다. **`GROUPS` 가 자료실의 원장이다** |
| `make_index_md.py` | `build_hub.py` 의 `GROUPS` 를 읽어 `README.md` 를 다시 만든다 |
| `build_decks.py` | PPTX 를 미리보기 + 원본 내려받기 페이지로 만든다 |
| `build_videos.py` | MP4 를 같은 방식으로 만든다 |
| `build_etf_artifact.mjs` | ETF 화면을 아티팩트용 조각으로 뽑는다 (원본 브랜치의 스크립트는 버그가 있어 이쪽을 쓴다) |

`build_hub.py` 를 돌리려면 `tools/decks/` 에 첨부 파일(dc-proposal.pdf·pptx)이
있어야 합니다. 없으면 이렇게 가져옵니다.

```bash
B=origin/claude/irp-product-proposal-ppt-owsbmc
git show "$B:퇴직연금DC_제안서_위험자산비중별_202607.pdf"  > tools/decks/dc-proposal.pdf
git show "$B:퇴직연금DC_제안서_위험자산비중별_202607.pptx" > tools/decks/dc-proposal.pptx
```

### `GROUPS` 한 줄의 생김새

```python
(제목ko, 제목en, 설명ko, 설명en, 세션ko, 세션en, 날짜, uid, 신규여부)
```

- `uid` 가 `None` 이면 링크 없는 줄이 되고, `신규여부` 자리에 `('꼬리표ko','꼬리표en')`
  튜플을 넣으면 그 꼬리표가 붙습니다(예: `('아티팩트 불가 · 저장소', 'Cannot publish · in repo')`).
- `uid` 는 예전 uuid 도 되고 `https://claude.ai/artifact/...` 완성 주소도 됩니다.
- `신규여부` 가 `True` 면 「신규」, `False` 면 「기존」 꼬리표입니다. 여기서
  **「신규」는 이 자료실이 직접 만들어 올렸다는 뜻**이지 이번 회차라는 뜻이 아닙니다.

## 4. 유지해야 할 작업 규칙

지금까지 지켜 온 규칙입니다. 새 계정에서도 그대로 쓰시면 됩니다.

### 무엇을 올리는가

- **세션 가지의 마지막 커밋 기준 최종 산출물만.** 중간 판·실험본은 넣지 않습니다.
- 이미 아티팩트가 있고 파일이 그보다 새롭지 않으면 **다시 올리지 않고 링크만** 씁니다.
- 같은 산출물의 새 판이면 **같은 아티팩트 URL 에 덮어씁니다.** 링크가 바뀌면
  부서에 돌린 링크가 죽기 때문입니다.
- 연습용 화면(카운터·자기소개 등)은 업무 산출물이 아니므로 올리지 않고,
  「아티팩트가 없는 세션」에 적어만 둡니다.

### 올리기 전에 반드시 하는 것

1. **파일 내용을 본다.** 가시 텍스트, 외부 요청 URL, 자격정보 패턴
   (`api_key`·`secret`·`password`·`bearer`·주민번호·이메일·사설 IP)을 훑습니다.
   걸린 것이 있으면 **어디에 있는지 확인합니다** — 지금까지 걸린 것은 전부
   pdf.js·React 내부 상수이거나 회사 이름(Victoria's Secret)이었습니다.
2. **브라우저로 실제 그려 본다.** 코드만 읽고 넘기지 않습니다.
   아티팩트의 외부 요청 차단을 흉내 내 렌더링하고, 본문 길이·표의 행 수·
   오류 수를 확인합니다. (이 검증을 건너뛰어 ETF 화면이 열흘간 빈 화면으로
   올라가 있던 적이 있습니다 — 5절 참고.)
3. 자체 완결이 아닌 파일은 **standalone 판**을 씁니다. 데이터를 따로 받아 오는
   화면은 아티팩트 안에서 빈 껍데기가 됩니다.

검증에 쓰는 스크립트는 `scratchpad/shot-blocked.mjs` 였습니다. 세션이 바뀌면
사라지므로 `PROMPTS.md` 에 전문을 적어 두었습니다.

### 설명을 쓰는 원칙

- **한계를 숨기지 않습니다.** 실시간 시세가 막힌다는 것, 저장 단추가 안 눌린다는 것,
  어느 날짜 자료인지, 표본이 작다는 것을 설명에 그대로 적습니다.
- 못 한 것은 **못 했다고 적습니다.** 색인 꼬리말의 「밀린 것」 절이 그 자리입니다.
- 틀린 것을 발견하면 **바로잡는 문단을 색인에 남깁니다.**

### 다루기 조심할 것

- `은퇴자산 운용 제안서` 는 특정 가구의 자산 내역이 담긴 개별 제안서입니다.
  이름·연락처는 없지만 총자산·은퇴시점·부부 금융소득이 그대로 있어, 당사자를
  아는 사람에게는 식별됩니다. **상담 관계 밖으로 링크를 돌리지 마십시오.**
- `마포WM 모바일 창구` 의 링크는 실제 계좌개설 주소이고 원본이 검색 노출을
  막아 둔 페이지입니다. 넓게 돌리지 마십시오.
- 아티팩트는 **기본이 비공개**입니다. 공유 설정을 임의로 바꾸지 않습니다.

### 가지와 커밋

- 자료실 작업은 `claude/organize-session-artifacts-fbg82m` 에만 커밋·푸시합니다.
- 다른 세션의 가지에는 손대지 않습니다. 원본 스크립트에 버그가 있어도
  고친 사본을 이 가지의 `tools/` 에 둡니다(`build_etf_artifact.mjs` 가 그 예).
- PR 은 만들지 않습니다.
- **수집기가 작업 가지에 커밋을 쌓는 일이 있습니다.** 체크아웃한 가지에
  「시세 수집」·「리포트 수집」 커밋이 끼어 있으면, 그 커밋들이 `main` 이나
  제 가지에 이미 있는지 확인한 뒤 `git reset --hard origin/<내 가지>` 로
  되돌립니다.

## 5. 겪은 함정 — 다시 밟지 말 것

| 함정 | 무슨 일이 있었나 | 어떻게 피하나 |
|---|---|---|
| **본문 잘림** | ETF 아티팩트가 8/31~9/10 **빈 화면**이었다. 조각 추출 스크립트가 본문을 `</body>` 로 잘라내는데, 자바스크립트 문자열 안에 `</body>` 가 들어오면서 마지막 `<script>` 가 닫히지 않은 채 끊겼다. 브라우저는 그런 조각을 **오류 한 줄 없이** 버린다 | 본문은 **마지막** `</body>` 까지로 잡는다. 빌드 끝에 `<script>` 짝 수를 세어 어긋나면 파일을 만들지 않는다. 그리고 **반드시 렌더링해서 확인한다** |
| **U+FFFD 거부** | 완전판매 스크립트 배포가 `content has U+FFFD` 로 거절됐다. 원본 데이터에 깨진 문자 49개가 있었다 | 올리기 전에 `s.count('�')` 로 세고, 있으면 `�` 자바스크립트 이스케이프로 바꾼다. 문자열·정규식 어디서든 뜻이 같다 |
| **내려받기 단추가 죽음** | `<a download>` + Blob 방식은 아티팩트 뷰어가 막는다 | `capabilities: {"downloads": true}` 를 선언하고, 링크 클릭을 가로채 `claude.downloads.save()` 로 넘기는 중계 스크립트를 붙인다. 전문은 `PROMPTS.md` 에 있다. 확장자는 허용 목록(json·csv·html·pdf 등)이어야 한다 |
| **게시 관문** | 아티팩트를 덮어쓰려면 올라가 있는 판을 먼저 통째로 다시 읽어야 한다. 자료를 파일에 담은 화면은 한 건이 6,000줄이라 비용이 크다 | **같은 대화에서 같은 파일 경로로 다시 올리면** 관문 없이 같은 URL 로 덮어써진다. 그러므로 **올릴 때 쓴 경로를 그대로 유지**하는 것이 좋다 |
| **빈 날짜 판** | 리포트 다이제스트에서 9/24·9/25 는 수집이 당일 리포트를 1~2건밖에 못 받았다 | 날짜 파일이 있다고 그대로 쓰지 않는다. **당일분 건수를 확인**하고 온전한 판을 고른다 |
| **가지 하이재킹** | 수집기가 체크아웃된 내 가지에 커밋을 쌓아, 내 커밋이 조상에서 빠졌다 | 매 회차 시작에 `git log --oneline -1` 로 확인한다. 위 4절의 되돌리기 참고 |
| **컨테이너 초기화** | 세션이 끊기면 scratchpad 가 비고, 올릴 때 쓴 경로 추적도 사라진다 | 중간 산출물은 **저장소에서 다시 만들 수 있게** 해 둔다. 생성기를 쓰고 손으로 만들지 않는다 |

## 6. 아티팩트로 올릴 수 없는 것

| 산출물 | 이유 |
