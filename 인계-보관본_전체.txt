[ 안 넘어오는 것 ] — 옛 Claude 계정 소유
  - 대화 기록 자체          → 이 파일과 docs/handover/ 가 그 자리를 대신합니다
  - 예약(Routine) 전부      → 저장소에 없습니다. 3절 프롬프트로 다시 만드십시오

  - 커넥터·스킬·계정 설정   → 새 계정에서 다시 붙이십시오
  - Claude 메모리·프로젝트  → 새 계정에서 다시 심으십시오 (5절 첫 말을 쓰십시오)
  - 대화에 올렸던 첨부 파일 → 저장소에 커밋하지 않은 것은 사라집니다

 ※ 가장 헷갈리기 쉬운 것 — 반드시 읽으십시오
   "새 계정을 만들어 같은 GitHub 저장소에 연동하면 과거 프롬프트·작업내용·
    완성파일이 계승되는가"

   → **파일과 작업 결과는 계승됩니다. 대화와 예약은 계승되지 않습니다.**

     계승되는 까닭은 연동 때문이 아니라, 지난 세션들이 그것을 **문서로 적어
     저장소에 커밋해 두었기 때문**입니다. 연동은 저장소를 읽게 해 줄 뿐입니다.
     적어 두지 않은 대화는 계정과 함께 사라집니다.

     그래서 새 계정의 Claude 는 "기억하는" 것이 아니라 "읽고 아는" 것입니다.
     2절 순서대로 문서를 읽혀야 비로소 맥락이 섭니다. 읽히지 않으면
     아무것도 모르는 상태에서 시작합니다.

   앞으로도 중요한 결정은 그때그때 저장소에 적어 두십시오.
   이 저장소에서 가장 값진 자산은 코드가 아니라 이 문서들입니다.

   bash scripts/request_reports_refresh.sh "아침 배포 판"

3. 러너가 끝나기를 기다립니다. 밀어 넣기 전 HEAD 를 적어 두고, 그 뒤에
   새 수집 커밋이 붙는지로 봅니다 — 「리포트 수집 요청」(내가 민 것)과
   「리포트 수집 2026-…」(러너가 민 것)을 헷갈리지 않게, 자릿수까지 봅니다.
     BASE=$(git rev-parse origin/main)   # 밀어 넣기 전에
     until git fetch -q origin main && [ -n "$(git log --format=%h $BASE..origin/main --grep='^리포트 수집 [0-9]')" ]; do sleep 45; done
   9/16 에 재어 보니 2분 26초~3분이었습니다. 8분이 지나도 안 오면 기다리기를
   그만두고, 저장소에 이미 있는 가장 최근 판으로 진행하되 「오늘 아침 수집이
   돌지 않아 ○시 ○분 판을 썼다」고 반드시 적어 알립니다.

4. git reset --hard origin/main 뒤 검산을 **먼저** 돌립니다.
   python3 scripts/verify_reports.py data/reports/latest.json
   나가는 값이 0 이 아니면 자료를 내지 않습니다. 어느 검사가 어떻게 어긋났는지
   그대로 옮겨 알리고, 원인을 찾아 고친 뒤 다시 돌립니다. 41개 「모두 맞음」이
   나와야 통과입니다.

5. 통과했으면 배포본을 만듭니다.
   bash scripts/make_reports_outputs.sh
   out/ 아래 한 파일 HTML 하나와 PDF 셋을 SendUserFile 로 올립니다.

6. 보고에 아래를 담습니다. 숫자는 실린 값과 직접 센 값을 대조해 적습니다.
   - 오늘 자 몇 건 · 전체 몇 건 · 한 주 몇 건

   - 목표주가를 올리거나 내린 리포트 (없으면 없다고)
   - 검산 41개 통과 여부
   - 수집 시각과 어제 자 완성본 건수
