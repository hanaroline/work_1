# 보유자산 통합 브리핑 — 단일 파일 버전

기존에는 `briefing.html` + `server.ps1` + `실행.bat` 3개 파일을 같은 폴더에
두어야 했습니다. 이 폴더의 빌더는 그 3개를 **파일 하나**로 합칩니다.

```
보유자산_통합브리핑.bat   ← 이것만 배포하면 됩니다 (약 139 KB)
```

받는 사람은 더블클릭 → 검은 창이 뜨고 브라우저에 대시보드가 열림 → 다 쓰면
검은 창을 닫으면 끝. 사용법은 기존과 완전히 동일합니다.

## 왜 HTML 파일이 아니라 .bat 인가

"HTML 안에 서버를 심는" 것은 불가능합니다. `.html`은 브라우저가 여는 문서일
뿐이어서 포트를 열거나 프로세스를 띄울 수 없고, `file://`로 열면 네이버·야후
API 호출이 브라우저 CORS 정책에 전부 막힙니다. `server.ps1`이 존재하는 이유가
바로 그 CORS 우회(서버가 Referer 헤더를 붙여 대신 호출)입니다.

그래서 **포함 방향을 뒤집었습니다.** HTML을 실행 파일 안에 넣습니다.
사용자 입장에서 "파일 하나"라는 결과는 같습니다.

## 구조

산출된 `.bat` 한 파일 안에 3개 층이 들어 있습니다.

| 위치 | 내용 | 인코딩 |
|---|---|---|
| 앞 ~1.2 KB | cmd 배치 런처 | ASCII / CRLF |
| `#@@PS_BEGIN@@` 뒤 | PowerShell 로컬 서버 (`server.ps1`) | UTF-8 / LF |
| 그 안의 here-string | 대시보드 (`briefing.html`) | UTF-8 / LF |

동작 순서:

1. 더블클릭 → cmd가 앞부분만 실행하고 `exit /b`로 파싱을 멈춘다.
   (`exit /b` 뒤쪽은 cmd가 읽지조차 않으므로 PowerShell·HTML이 배치 명령으로
   해석되는 일이 없다.)
2. 런처가 PowerShell을 띄우고, PowerShell이 **자기 자신(.bat)** 을 UTF-8로
   읽어 마커 뒤쪽을 `%TEMP%\mab_briefing\server_<PID>.ps1`로 풀어 실행한다.
3. 서버는 메모리에 있는 HTML을 `http://localhost:8899/` 로 서비스한다.
   디스크의 `briefing.html`은 필요 없다.

## 빌드

```bash
python3 build_single_file.py     # briefing.html + server.ps1 -> .bat
```

HTML이나 서버를 수정하면 이 스크립트를 다시 돌려 `.bat`을 재생성합니다.
직접 `.bat`을 편집하지 마세요.

## server.ps1 에서 바뀐 부분 (3곳)

원본을 최대한 그대로 두었습니다. 빌더가 자동으로 적용합니다.

1. `$ROOT` — 스크립트가 `%TEMP%`에서 실행되므로, 배치가 환경변수
   `MAB_ROOT`로 알려준 원본 폴더를 쓴다.
2. 라우팅 — `/` 와 `/briefing.html` 요청을 디스크가 아니라 내장 HTML로 응답.
3. 콘솔 배너 문구.

`.bat` 옆에 다른 파일(예: 사용안내 이미지)을 두면 기존처럼 그대로 서비스되므로,
동반 파일을 쓰고 싶으면 그냥 같은 폴더에 두면 됩니다.

## 검증한 것 / 못 한 것

Linux + PowerShell 7.4.6 으로 확인한 내용:

- 페이로드 구문 오류 없음 (`Parser::ParseFile`, 함수 17개 모두 정의됨)
- 배치가 하는 추출을 그대로 재현했을 때 마커가 파일 전체에 1회만 존재
- 서버가 실제로 뜨고, `/` 응답이 원본 `briefing.html`과 **SHA-256 일치**
- `/briefing.html`도 동일 응답, 옆에 둔 추가 파일은 디스크에서 정상 서비스
- 404 / 403(비허용 호스트) / 400(잘못된 코드) 응답 정상,
  API 호출 실패(502) 후에도 서버가 죽지 않음
- 헤더가 순수 ASCII·CRLF, BOM 없음, 명령줄 744자(cmd 한계 8191 이내)

확인하지 못한 것: **실제 Windows + PowerShell 5.1 에서의 구동.** 이 환경에는
cmd.exe와 PowerShell 5.1이 없습니다. 배포 전에 사내 PC에서 한 번 더블클릭해
브리핑 화면이 뜨는지 확인해 주세요.

## 배포 전에 알아둘 점

- **.bat 이 오히려 막힐 수 있습니다.** 메일 첨부·EDR·백신 관점에서 보면 이
  파일은 "배치 안에 스크립트 페이로드를 숨겨 `%TEMP%`에 풀어 실행하는 파일"
  이고, 이는 실제 악성코드의 전형적 패턴과 형태가 같습니다. 기능상 문제는
  없지만 차단·격리될 가능성은 기존 3파일 방식보다 **높습니다.** 사내 배포
  전에 정보보호 부서 확인을 권합니다.
- 차단되면 기존 3파일 방식(`briefing.html` + `server.ps1` + `실행.bat`)이
  그대로 대안입니다. 두 방식 모두 이 폴더에 있습니다.
- `.hta` 단일 파일도 검토했지만 권하지 않습니다. IE(MSHTML) 엔진이라
  `async/await`·`??`·`?.`·화살표 함수를 쓰는 현재 스크립트(약 1,700줄)를
  ES5로 전면 재작성해야 하고, `mshta.exe` 자체가 사내에서 차단된 경우가 많습니다.
- 시세를 미래에셋증권 Open API로 바꾸는 경우, 앱키·시크릿은 반드시 서버
  쪽(PowerShell 부분)에만 두어야 합니다. 또한 현재 서버는 `0.0.0.0`에
  바인딩되어 같은 Wi-Fi에서 접근 가능하므로, 키를 넣는 순간
  `Loopback` 바인딩으로 바꾸거나 인증을 붙여야 합니다.
