[4] 국가법령정보센터 OPEN API
-------------------------------------------------------------------------------
인증키: 저장소 Secrets 의 LAW_OC (open.law.go.kr 에서 직접 정한 OC 값).
        https://github.com/hanaroline/work_1/settings/secrets/actions
        없으면 워크플로 첫 단계에서 이유를 찍고 멈춥니다.

엔드포인트:
  목록  https://www.law.go.kr/DRF/lawSearch.do?OC=<키>&target=<대상>&type=JSON&query=<이름>
  본문  https://www.law.go.kr/DRF/lawService.do?OC=<키>&target=<대상>&type=JSON&MST=<번호>

target:  law(법령) · admrul(행정규칙) · ordin(자치법규) · eflaw(시행일법령)

연혁(과거 시행본) 받는 두 걸음:
  1) lawSearch.do?target=eflaw&query=<법령명>&efYd=<from>~<to>&display=100&page=N
     -> 한 줄이 (시행일자, 공포일자, 공포번호, 법령일련번호=MST)
  2) lawService.do?target=law&MST=<mst>&JO=<6자리>
     -> 그 판의 조문 하나만. 응답이 5KB 대로 줄어듭니다(전문은 1MB 넘음).

JO = 조 4자리 + 가지 2자리
  제157조    -> 015700
  제1조의2   -> 000102
  제167조의8 -> 016708

!! 안 되는 길 — 추가 신청이 필요합니다
   target=eflaw 의 **본문** 과 lsHistory 는 "국가법령정보 공동활용 미신청" 안내가 옵니다.
   open.law.go.kr 에서 「시행일 법령」 본문 API 를 따로 신청해야 열립니다.
   이것 때문에 2023~2024년 소득세법 시행령 §157 조문 원문을 아직 못 봤습니다.


[5] 세션에서 막히는 주소 (러너는 됩니다)
-------------------------------------------------------------------------------
세션 이그레스 정책이 CONNECT 403 으로 막는 곳:
  law.go.kr · open.law.go.kr · stlouisfed.org · federalreserve.gov · bok.or.kr
  bls.gov · ecb.europa.eu

그래서 원문 수집은 GitHub Actions 러너가 합니다. 세션에서 "못 받았다"가 나와도
러너에서는 될 수 있으니, 수집은 REFRESH 를 push 해서 돌리십시오.

law.go.kr 이 통째로 죽는 일이 있습니다. 두 번 겪었고, 17분 전 탐침은 14/14
성공인데 수집은 0/20 이었습니다. 코드 문제가 아닙니다.
  - get() 에 재시도 3회·4초 간격이 들어 있습니다.
  - reachable() 이 먼저 10초짜리로 한 번 물어, 죽었으면 30초만 쓰고 끝냅니다.
  - 워크플로의 연혁·커밋 단계는 if: always() 라 앞이 죽어도 받은 것은 남습니다.

세션 토큰에 Actions 쓰기 권한이 없어 workflow_dispatch 를 API 로 부르면 403 입니다.
git push 는 됩니다 — 그래서 data/law/REFRESH 를 미는 방식을 씁니다.


[6] 꼭 지켜야 하는 지침
-------------------------------------------------------------------------------
[법령]
- 법령은 국가법령정보센터 원문으로만 인용한다. 검색엔진 요약·블로그를 쓰지 않는다.
- 인용할 때 조문번호와 함께 그 조문이 어느 시점 본인지 적는다.
  시행일이 다르면 다른 조문이다.
- 과거 양도분은 반드시 연혁 조문으로 본다. 현행본에는 사라진 문언이 남지 않는다.
- ★ 공포본의 본문에는 아직 시행되지 않은 개정도 들어 있다.
  2022년에 살아 있던 소득세법 시행령 §157 이 그 시점 공포본에서는 "제157조 삭제"로
  나온다(금투세 시행에 맞춘 삭제 예정 문언). 조문시행일자를 보고 한 판 앞선
  공포본으로 물러나며 찾아야 한다. fetch_law_history.py 에 들어 있다.

[수치]
- 인쇄될 모든 숫자는 주장 대장에 한 줄을 갖는다. 대장에 없는 숫자는 쓰지 않는다.
- 순서를 지킨다: 리서치 -> 주장 대장 -> 기계 검산 -> 빌드 -> 인도 전 게이트.
- verdict: unverified 에 render: assert 는 거부된다.
- 검산은 두 방향 모두 돈다. check_claims.py(대장->산출물) + validate.py(산출물->대장).
- 확인하지 못한 것은 "미확인"으로 남긴다. 그럴듯하게 채우지 않는다.

[저장소]
- 날짜와 숫자를 지어내지 않는다.
- 비밀(LAW_OC 등)은 GitHub 저장소 시크릿에만 둔다. 저장소 파일에 넣지 않는다.
- scripts/*.py 는 표준 라이브러리만 쓴다.
- 시세·ELS·브리핑 자료는 웹사이트(GitHub Pages)로 노출하지 않는다.
- 회사 망이 *.translate.goog 를 비업무용으로 막는다. 번역 프록시를 쓰지 않는다.
- 요청하지 않은 Pull Request 는 만들지 않는다.
- 작업은 claude/... 가지에서 한다.
- 만들다 만 것도 커밋하고 push 한다. 컨테이너가 회수되면 작업본은 사라진다.
  2026-10-01 에 실제로 그렇게 되어 빌드 스크립트를 처음부터 다시 지었다.
  그래서 tools/tax-brief/ 를 저장소에 넣었다.
