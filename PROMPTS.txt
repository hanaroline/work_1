[3] FRED API 키 넣기  (미국 CPI·고용상황 확정 발표일)
-------------------------------------------------------------------------------
왜 필요한가:
  BLS 가 러너 IP 에 403 을 줍니다. 그래서 미국 CPI·고용상황·PCE·GDP·소매판매의
  "확정" 발표일은 지금 FRED 경로로만 들어옵니다. 키가 없으면 rule 추정으로만 남습니다.

1) https://fredaccount.stlouisfed.org/apikey 에서 계정을 만들고 API key 발급
   (무료, 승인 대기 없음, 32자리 문자열)
   페이지가 안 열리면 FRED 로그인 후 My Account -> API Keys

2) https://github.com/hanaroline/work_1/settings/secrets/actions
   New repository secret
     Name   : FRED_API_KEY      (철자 그대로. 오타가 있으면 조용히 건너뜁니다)
     Secret : 발급받은 32자리 키
   ※ 그 화면의 Actions / Codespaces / Dependabot 탭 중 반드시 "Actions" 탭.
     Repository secrets 쪽이면 됩니다. Environment secrets 는 필요 없습니다.

3) data/calendar/REFRESH 를 한 줄 고쳐 push -> 바로 수집이 돕니다.

4) 확인: Actions 실행 요약의 fred:* 줄
     키 없음 -> fred 한 줄에 "FRED_API_KEY 가 없어 건너뛰었다"
     키 있음 -> fred:us-cpi / us-empsit / us-pce / us-gdp / us-retail 다섯 줄에 건수

   FRED release id: us-cpi 10 · us-empsit 50 · us-pce 54 · us-gdp 53 · us-retail 8

!! 키는 시크릿에만 두십시오. 저장소 파일에 넣지 마십시오. !!

[5] 시스템 설정 — .claude/settings.json
-------------------------------------------------------------------------------
저장소에 들어 있으므로 계정을 바꿔도 그대로 따라옵니다. 내용은 이렇습니다:

{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "hooks": {
    "SessionStart": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/session-start.sh"
          }
        ]
      }
    ]
  }
}

.claude/hooks/session-start.sh 가 하는 일:
  - 웹 세션(CLAUDE_CODE_REMOTE=true)에서만 돈다. 사람의 기계는 건드리지 않는다.
  - playwright 1.56.1 을 깐다 (워크플로가 박아 쓰는 판과 같게 맞춘 것).
    이미 같은 판이 있으면 건너뛴다.
  - 크로미움은 내려받지 않는다. /opt/pw-browsers 에 이미 있다.
    (PLAYWRIGHT_BROWSERS_PATH. 다시 받으면 수백 MB 를 세션 디스크에 또 쌓는다.)
  - package.json / package-lock.json / node_modules 는 .gitignore 에 있어
    새 세션의 작업본에는 없다. 그래서 이 준비가 필요하다.

크로미움 실행 경로 (화면을 열어 확인할 때):
  /opt/pw-browsers/chromium-1194/chrome-linux/chrome

playwright 로 오프라인판을 확인할 때 주의:
  바깥 요청만 막아야 합니다. page.route('**://**', abort) 로 하면 file:// 도 막혀
  net::ERR_FAILED 가 납니다. page.route('http*://**', ...) 로 좁히십시오.

  workflow_run  증권사 리포트 수집 · 국내 100대 기업 가격 갱신 · 시세 수집 이
                끝날 때마다 불린다 (10시에 실제로 닿는 길)

      이후에 들어왔으면 건너뛴다. 실행 기록이 아니라 산출물로 판단한다.
      (실행 기록을 세면 가드에 걸린 빈 판까지 "돌았다"로 세어 스스로 막힌다 —
       2026-09-28 에 실제로 그렇게 되어 그 주 수집이 통째로 비었다. HANDOFF.md §5)

cron 은 UTC 로만 읽힙니다. KST = UTC+9, 서머타임 없음.
  월요일 10:00 KST - 9h = 같은 월요일 01:00 UTC

[11] MARKET DAILY 를 손으로 돌리는 명령
-------------------------------------------------------------------------------
# 0) 최신 시세 받기 (수집은 main 에서 돕니다)
git fetch origin && git merge --no-edit origin/main

# 1) 무빙·빅테크 수집 부르기 (러너가 합니다 — 세션은 야후·나스닥·네이버에 못 붙습니다)
printf '요청 %s
' "$(TZ=Asia/Seoul date)" > data/market_daily/REFRESH
git add data/market_daily/REFRESH && git commit -m "MARKET DAILY 수집 요청" && git push

# 2) 수집 결과 확인 — 기준일과 '마감분인지'를 꼭 봅니다
python3 -c "import json;d=json.load(open('data/us_movers/latest.json'));print(d['session_date'],d.get('market_state'),d.get('settled'))"
python3 -c "import json;d=json.load(open('data/kr_movers/latest.json'));print(d['trade_date_kst'],d['market_status'])"

# 3) 글 쓰기 (숫자는 쓰지 않습니다 — 표가 채웁니다)
#    data/market_daily/narrative-<거래일>-<판>.json

# 4) 만들기
python3 scripts/build_market_daily.py --edition close   --date 2026-10-01
python3 scripts/build_market_daily.py --edition morning --date 2026-09-18

# 5) 검산 (실패하면 배포하지 않습니다)
python3 <fin-data-integrity>/scripts/check_claims.py docs/market-daily/<날짜>-<판>.claims.json
python3 scripts/audit_numbers.py docs/market-daily/<날짜>-<판>.html data/market/<스냅샷>.json

# 6) 전달용 문구 뽑기
python3 scripts/market_daily_digest.py --edition <판> --date <날짜>


[12] MARKET DAILY 가 지키는 규칙 (요약)
-------------------------------------------------------------------------------
표의 숫자는 수집 파일에서만 나옵니다. 손으로 적지 않습니다.
글에 박는 숫자는 narrative 의 claims 에 출처·기준일과 함께 등록합니다.
확인하지 못한 것은 비워 두고 "확인되지 않았다"고 적습니다. "없다"고 쓰지 않습니다.
기준선 표는 스냅샷 한 파일에서만 읽습니다. 없는 항목은 비우고 검증 노트에 적습니다.
장중 수집분을 종가로 쓰지 않습니다. 두 수집기 모두 상태를 싣고 빌더가 확인합니다.
날짜 필드가 없는 블록(sectors·usdkrw_naver·rates_kr·market_internals)은
  최신 파일이 아니라 기준일 스냅샷에서 읽습니다.
기사 수치와 거래소 수치가 다르면 거래소를 채택하고 차이를 검증 노트에 적습니다.
산출물은 HTML 입니다. 원고에 마크다운 강조(**…**)를 쓰지 않습니다.
메일 본문에 background: 를 쓰지 않습니다. Gmail 이 지웁니다. table bgcolor 를 씁니다.
