# 팀 자료실 (HTML 한 파일 버전)

**설치도 서버도 없이, HTML 파일 하나로 자료를 모아 팀원에게 전달**하는 방식입니다.
파이썬을 설치할 수 없거나 공유 폴더가 없는 환경을 위해 만들었습니다.

- `team-fileroom.html` 을 **더블클릭** → 파일을 넣고 → **[자료실 파일 만들기]**
- 만들어진 HTML 파일 **하나**를 팀원에게 전달 (사내 메신저·메일 등)
- 받은 사람은 **더블클릭 → 비밀번호 입력 → 목록에서 다운로드**

인터넷 연결, 설치, 관리자 권한 모두 필요 없습니다.

---

## ⚠ 가장 헷갈리는 지점 — 파일이 두 개입니다

| 파일 | 정체 | 쓰임 |
|---|---|---|
| `team-fileroom.html` | **빈 틀** (원본) | 새 자료실을 만들 때만 사용. **여기엔 자료가 저장되지 않습니다** |
| `<자료실이름>_20260813.html` | **자료가 담긴 파일** | [자료실 파일 만들기] 를 누르면 **다운로드 폴더**에 새로 생김 |

- 팀원에게 보낼 것은 **아래쪽(자료가 담긴 파일)** 입니다. 빈 틀을 보내면 상대 화면도 비어 있습니다.
- 다음에 자료를 고칠 때도 **자료가 담긴 파일**을 여세요. 빈 틀을 열면 언제나 비어 있습니다.
- 화면 좌측 상단, 자료실 이름 옆에 **지금 열고 있는 파일 이름**이 표시됩니다. 이것으로 구분하세요.
- 빈 틀에서 작업하다 저장을 잊고 닫아도, 다시 열면 **[이어서 작업]** 안내가 뜹니다
  (이 브라우저에만 임시 보관됩니다. 다른 PC 로는 옮겨지지 않습니다).

---

## 1. 자료를 올리는 사람

1. `team-fileroom.html` 더블클릭 (빈 자료실이 편집 모드로 열립니다)
2. **[파일 추가]** → 파일을 끌어다 놓거나 선택. 폴더·설명을 함께 적을 수 있습니다
3. **[자료실 파일 만들기]** → 자료실 이름과 **열람 비밀번호**(선택)를 정하고 **[파일 만들기]**
4. 다운로드된 `<자료실이름>_20260813.html` 을 팀원에게 전달

자료를 바꾸려면 **저장된 그 파일을 다시 열어** [자료 관리] 에서 추가·수정·삭제한 뒤 다시 저장하면 됩니다.
원본(`team-fileroom.html`)은 새 자료실을 만들 때만 쓰면 됩니다.

## 2. 받는 사람

1. 받은 HTML 파일 더블클릭
2. (비밀번호를 걸었다면) 비밀번호 입력
3. 파일명을 누르면 다운로드. 여러 개는 체크 후 **[선택 다운로드 (ZIP)]**

검색·폴더 필터·정렬, 한/영 전환을 쓸 수 있습니다.

---

## 3. 관리 기능 (자료 관리 모드)

[자료 관리] 를 누르면 관리용 도구 줄이 나타납니다.

| 기능 | 설명 |
|---|---|
| **폴더 관리** | 폴더 만들기 · 이름 변경 · 삭제. 폴더를 지워도 안의 파일은 남고 `<폴더 없음>` 으로 이동합니다. 빈 폴더도 유지됩니다 |
| **폴더 이동** | 파일을 체크한 뒤 [폴더 이동] → 기존 폴더 선택 또는 새 폴더 이름 입력 |
| **삭제** | 행의 [삭제] 또는 체크 후 [선택 삭제] |
| **실행 취소** | 추가·삭제·이동·이름변경·설정 변경을 최대 20단계까지 되돌립니다 |
| **파일 교체** | 행의 [교체] 로 같은 항목에 새 버전을 올립니다. 목록에 `v2`, `v3` 로 표시됩니다 |
| **중요 표시(★)** | 눈에 띄어야 할 자료를 목록 맨 위에 고정합니다 |
| **자료실 설정** | 자료실 이름, 담당자, 팀원에게 보일 **공지** 문구 |
| **목록 내보내기** | 현재 목록을 CSV 로 저장합니다(엑셀에서 바로 열림) |
| **전체 다운로드** | 모든 파일을 ZIP 하나로 받습니다 |
| **중복 경고** | 같은 이름의 파일이 있으면 목록 위에 알려 줍니다 |
| **판(rev) 관리** | 저장할 때마다 판 번호가 올라가고, 화면 상단에 `제3판 · 2026-08-13 15:20 기준 · 담당자` 로 표시됩니다 |

## 4. 동료 화면은 자동으로 갱신되지 않습니다

**자료를 추가해도, 동료가 이미 받아 둔 파일에는 반영되지 않습니다.** 서버가 아니라 그 시점의 사본이기 때문입니다.

- 자료를 바꿨다면 **새로 만든 파일을 다시 전달**해야 합니다.
- 어느 것이 최신인지 헷갈리지 않도록 **판 번호와 기준 시각**을 화면 상단에 표시합니다.
- 저장이 끝나면 **전달용 안내 문구**가 자동으로 만들어집니다. [문구 복사] 로 복사해 메신저에 붙여 넣으면
  판 번호·파일 수·기준 시각이 함께 전달됩니다.
- 받은 사람 화면에도 `이 파일은 ○○ 기준입니다. 이후 추가된 자료는 담당자에게 새 파일을 요청하세요.` 안내가 뜹니다.

자료를 자주 갱신하는 자료실이라면, 재전달 없이 최신 상태를 공유하는 **서버 버전**(`fileshare/`, 파이썬 3 필요)이 맞습니다.

## 5. 비밀번호와 보안

비밀번호를 지정하면 **파일 내용이 실제로 암호화**됩니다. 브라우저 표준 암호화(Web Crypto)를 씁니다.

| 항목 | 방식 |
|---|---|
| 키 유도 | PBKDF2-HMAC-SHA256, 20만 회, 16바이트 무작위 salt |
| 암호화 | AES-256-GCM (파일마다 별도 IV, 목록 정보도 함께 암호화) |
| 저장 형태 | 암호문만 base64 로 HTML 안에 들어감 |

- 비밀번호 없이는 HTML 소스를 열어도 **파일명·폴더명·공지조차 보이지 않습니다.**
- 비밀번호를 잊으면 **복구할 수 없습니다.** 원본 파일은 따로 보관하세요.
- 비밀번호를 비워 두고 저장하면 누구나 열 수 있는 파일이 됩니다.

## 6. 이 방식의 한계 (서버 버전과의 차이)

서버가 아니라 **파일 한 개**입니다. 다음은 구조상 불가능하니 감안하고 쓰셔야 합니다.

- 자료를 갱신하면 **새 파일을 다시 전달**해야 합니다 (받은 사람의 사본은 자동으로 바뀌지 않습니다)
- 팀원이 받은 사본을 고쳐도 **다른 사람에게는 영향이 없습니다**
- 누가 열어봤는지 **접속 기록이 남지 않습니다**
- 전달된 뒤에는 회수할 수 없습니다 (비밀번호를 바꿔도 이미 전달된 파일은 옛 비밀번호로 계속 열립니다)

위 기능이 필요하면 상위 폴더의 **서버 버전**(`fileshare/`)을 쓰세요. 파이썬 3 설치가 필요합니다.

## 7. 용량 기준

| 담는 자료 | 만들어지는 HTML | 저장 시간 | 여는 시간 |
|---|---|---|---|
| 5 MB | 약 7 MB | 1초 미만 | 1초 미만 |
| 20 MB | 약 27 MB | 약 2초 | 약 1초 |

자료가 HTML 안에 base64 로 들어가므로 **결과 파일은 원본의 약 1.35배**가 됩니다.
사내 메일·메신저의 첨부 한도를 고려해 **총 50MB 이하**를 권장합니다.

## 8. 동작 환경

- Microsoft Edge, Chrome, Firefox 최신 버전 (사내 표준 브라우저 대부분 해당)
- Internet Explorer 는 지원하지 않습니다
- 인터넷 연결 불필요 (외부 주소를 전혀 호출하지 않습니다)

## 9. 개발자용 점검

```bash
node fileshare/html/selftest-browser.mjs   # Playwright 필요 (인터넷망 개발 환경 전용)
```

파일 추가 → 암호화 저장 → 잠금 해제 → 개별/ZIP 다운로드 내용 일치 → 재편집 후 재저장 →
비밀번호 없는 저장, 폴더·삭제·되돌리기 등 관리 기능까지 47개 항목을 실제 브라우저(`file://`)에서 확인합니다.
